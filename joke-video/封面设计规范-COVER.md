# 封面设计规范（段子短视频）

这份可以单独看，不用先读主 README。命令部分在最后。

---

## 一、四条铁律

**1. 封面绝不能剧透笑点。** 标题里、封面大字里都不许出现笑点词（这条片子就是"舌头"）。
一旦出现，片子就白做了。

**2. 封面大字和标题不能重复。** 标题在信息流里已经显示了，封面再写一遍等于浪费唯一的视觉资源。
两者要唱双簧——**封面卖惨，标题追问**：

> 封面大字：大哥，我完了
> 视频标题：所以这条蛇还有救吗

**3. 用彩色帧，不用定格灰帧。** 灰调在信息流里不跳眼，这是最常见的翻车点。
取帧默认在笑点后 0.6 秒（角色嘴张着、表情最夸张的时候）。

**4. 屏上的字要留排版安全距离。**（2026-08-26 补 —— **这是基本排版原理，本该一开始就在这儿**，
方版第一版做出来字距边只有 5%，是用户看出来的。）

**「不出画布」不等于「安全」。** 字距边要留的不是「别掉出去」的余量，
是**「被啃掉一圈还活着」**的余量。每个投放位都会啃：

| 谁在啃 | 啃掉多少 |
|---|---|
| 平台的圆角、遮罩、外框 | 一圈几十像素，各家不一样 |
| 缩略图裁切（九宫格 3:4、Shorts 1:1） | 整条边 |
| 平台叠上去的角标（时长、订阅、直播） | 一个角 |
| 手机壳曲面屏、深色模式的描边 | 边上一两毫米 |

**三条判据：**

1. **按缩略图尺寸算，不是按出图尺寸。** 1080 上留 60px 看着很宽，
   缩到 200px 只剩 11px —— **就是「快掉出去了」那个观感**。
   要算就算「缩到验收尺寸之后还剩几个像素」。
2. **短边的 8–10%。** 这是起点，不是上限；具体尺寸各档在自己那一节里写死。
3. **安全区只管字，不管画。** 画面满幅出血没关系（它是底）；
   **标题、副标、署名三样都必须落在框里**。
   ⚠ **排版安全优先于「别压到画」** —— 两者冲突时让画，不是让字。

各档现值：

| 档 | 画布 | 安全距离 | 在哪定义 |
|---|---|---|---|
| 竖版三条线 | 1080×1920 | 边距 0.062（67px）＋ §三 那三块遮挡区 | §三 / §七之一 |
| 长片 · 横版 | 1280×720 | 边距 0.062（79px）＋ 右下时长角标 | §九之三 |
| 长片 · 方版 | 1080×1080 | **0.10（108px），四边** | §九之六之二 |

⚠ **每加一个尺寸就要问一遍「这个尺寸的安全距离是多少」** ——
不是把上一个尺寸的比例抄过来。方版那 0.10 就是这么来的：
横版的 0.062 抄到方版，缩到 200px 只剩 10px，**贴边**。

## 二、版式

| 元素 | 规则 |
|---|---|
| 大字 | 4–8 字，字号自适应（最大 150px，最宽占画幅 82%），米白纸片底 + 深墨字，倾斜 -2°，顶边 y=320 |
| 主体 | 推镜 1.9 倍，主角偏左中，配角只露半个头（露太多就把"有人在听"给全了，留悬念） |
| 情绪符号 | 芥黄「?!」，贴在主角头部右上方，带米白描边保证在任何底色上都看得清 |
| 署名 | 右下角小纸片，写**账号名**（按线分：老马线 `碎嘴老马`，其余 `Ellie`），倾斜 **−6°（左低右高）**。做到第十条时观众会认出这是同一个号。不写品类标签——那占地方又不带来辨识度 |

大字文案的写法，按钩子强度排序：

1. **第一人称卖惨** —— 「大哥，我完了」「我可能要凉」→ 代入感最强
2. **第三人称叙述** —— 「蛇生最惨一天」→ 稳，钩子弱一点
3. **互动求助** —— 「在线等，挺急的」→ 直接引导评论区

避开：任何笑点词；「笑死」「绝了」这类纯情绪词（平台判低质）；「99% 的人不知道」（老套且限流）。

## 三、尺寸与安全区

- 出图 **1080×1920**（9:16）
- 个人主页九宫格会裁成 **3:4**（居中 1080×1440）→ **关键内容必须落在这块区域里**，
  否则主页看过去只剩半个角色
- 抖音信息流：**底部约 20%** 被昵称文案盖住，**右侧约 15%** 被点赞评论栏盖住

所以：大字放上部、主体偏左、右下角的署名往左让一档避开点赞栏。
生成的 `-安全区.png` 会把这三块区域画出来，发布前扫一眼就能发现有没有被盖住。

> ⚠ **要发 YouTube Shorts 的话，还有一条更紧的上界。** Shorts 首页卡片把 9:16 裁成
> 正中间的 1080×1080，只留 **y ∈ [420, 1500]**——比九宫格那条 `y ≥ 240` 紧得多。
> 老马线现在的主标题墨迹顶边实测 ≈ y 249（`T.baselineK = 0.22`、字号 182），
> **过得了九宫格，过不了 Shorts**；打开 `titleLow`（`lowBaselineK = 0.4`）顶边到 ≈ y 594，两条都过。
>
> `titleLow` 要不要改成默认、`-安全区.png` 要不要多画 y=420／y=1500 两条线，
> **都还没定案，别先动代码**。来龙去脉见 [`../YouTube封面规范.md`](../YouTube封面规范.md) §十一
> （那份管的是 16:9 横版缩略图，**竖版不适用**，只有 Shorts 这一节跟这三条线有关）。

## 五、命令

### cmd 窗口里直接跑

```cmd
cover.cmd
```

不带参数会依次问你「段子 id」和「封面大字」，跑完自动打开输出目录。

也可以一行带全：

```cmd
cover.cmd snake-poison "大哥，我完了"
cover.cmd snake-poison "蛇生最惨一天" "Ellie"
```

### 或者直接用 npm

```cmd
npm run cover -- jokes/snake-poison.json "大哥，我完了"
```

### 产出

```
projects/<日期>_<id>/cover/<id>-9x16.png     发布用
projects/<日期>_<id>/cover/<id>-3x4.png      个人主页九宫格看到的样子
projects/<日期>_<id>/cover/<id>-安全区.png    带辅助线，检查有没有被 UI 盖住
```

### 可调参数（`src/cover.ts`）

| 参数 | 默认 | 说明 |
|---|---|---|
| `cam.zoom` | 1.9 | 推镜。调到 2.2 主角更大，但配角会看不见 |
| `cam.tx / cam.ty` | 170 / -740 | 主体在画面里的位置 |
| `top`（bigTitle 里） | 320 | 大字纸片的顶边 |
| `at` | 笑点 + 0.6s | 取帧时刻 |
| `mark` | `?!` | 传 `none` 关掉情绪符号 |
| `ACCOUNT`（`src/config.ts`） | `Ellie` | 右下角署名的**缺省**（段子 /《一页故事》）。频道级常量，不写在每条稿件里；临时换用 `JOKE_ACCOUNT="别的名字"` |
| `ACCOUNT_LAOMA`（`src/config.ts`） | `碎嘴老马` | 老马独白线的署名。按 `rig === 'horse'` 自动切，稿件里写了 `cover.tag` 仍旧优先 |

## 六、发布前检查清单

- [ ] 大字里没有笑点词
- [ ] 大字和标题不是同一句话
- [ ] 用的是彩色帧不是灰帧
- [ ] 看一眼 `-3x4.png`：主角的脸和大字都在框内
- [ ] 看一眼 `-安全区.png`：没有东西掉进灰色遮挡区
- [ ] 封面没有角色头部特写（怕蛇/怕虫的人会直接划走）
- [ ] 右下角署名是对的账号名 —— **这条管线上跑着不止一个号**，老马线署 `碎嘴老马`

## 七、封面会自动变成视频第一帧

`npm run build` 出片时会把封面顶在最前面当第一帧——平台多数拿第一帧做缩略图，
所以这一帧值钱。默认只占 **1 帧（约 33ms）**，观众看不见，但平台取得到。

```jsonc
"cover": {
  "title": "大哥，我完了",   // 不写就从第一句自动推（兜底，建议手写）
  "asFirstFrame": true,     // 默认 true，不想要就设 false
  "hold": 0                 // 停留秒数，默认 0（只占 1 帧）
}
```

出片时会顺手把封面存一份到 `projects/<日期>_<id>/cover/`，不用再单独跑一次
`npm run cover`（要 3:4 和安全区那两张才需要单独跑）。

**`hold` 非必要别调。** 设大于 0 会让封面真的停在画面上，脚本会同时把音轨往后移
等长时间保持同步，但短视频开头每多停一秒完播率就掉一截。

## 八、cmd 下的中文问题

Node 读命令行参数走的是宽字符接口，所以**中文参数本身没问题**，
但控制台显示可能乱码。`cover.cmd` 里已经加了 `chcp 65001`。

如果直接用 `npm run cover`，中文提示乱码就先执行一次：

```cmd
chcp 65001
```

文件名里的中文（`-安全区.png`）在资源管理器里正常，只是 cmd 输出可能显示成问号，不影响文件本身。

## 七、老马线的标题排版（贴纸式描边大字）

> **只给老马线。** 段子和《一页故事》仍旧走 §二 的米白纸片大字。
> 代码在 `src/cover.ts` 的 `laomaTitle()`，判据跟署名同一条（`rig === 'horse'`）。

### 一、视觉规格

画布 **1080 × 1920**（竖版）。其他尺寸按**宽度**等比换算。

| 元素 | 规格 |
|---|---|
| 主标题字体 | 思源黑体 Heavy / Black 字重（`Noto Sans SC Black`） |
| 主标题填充 | `#FFD400` |
| 主标题描边 | `#1A1A1A`，宽度 = 字号 × 0.15，`linejoin: round` |
| 主标题字号 | 上限 182px，实际由可用宽度反推（见下） |
| 主标题首行基线 | 画布高 × **0.22**（见 §七之三；`titleLow` 那一档是 0.40） |
| 行高 | 字号 × 1.12 |
| 字间距 | 字号 × 0.03 |
| 副标题字号 | 主标题 × 0.5 |
| 副标题字数 | **6 字上限**（见 §七之二 末尾） |
| 副标题填充 | `#1A1A1A` |
| 副标题描边 | `#FFFFFF`，宽度 = 副标题字号 × 0.26 |
| 副标题位置 | 主标题末行基线下方 字号 × 0.4 |
| 左右边距 | 画布宽 × 0.062（1080 下约 67px） |

**字重是硬要求。** Regular 或 Bold 撑不起这么粗的描边，出来会脏。

⚠ **必须点名到「Black」那个字族名，不能靠 `font-weight="900"` 去够。**
resvg 按字族名找字，`Noto Sans SC` 和 `Noto Sans SC Black` 在系统里是两个独立的族；
只写前者加 900，多数情况下拿到的还是 Regular，**而且不报错**。
字族写在 `config.ts` 的 `FONT_HEAVY`。

### 二、折行与字号

**主标题 4–7 字。**

- ≤ 4 字：不折行
- 5–7 字：折两行，前行取 `ceil(总字数 / 2)`，即**前行不短于后行**
- \> 7 字：字号会被压得太小，贴纸感消失 —— **改标题，不要硬塞**（`laoma:check` 会报）

字号由**可用宽度反推**：

```
可用宽度   = 画布宽 − 边距 × 2
宽度单位   = 中文字记 1.0，半角字符记 0.55
字号       = min(182, 可用宽度 / (最长行宽度单位 + 0.03 × (该行字数 − 1)))
```

⚠ **末尾那一项字间距是实现时补上的**，规范原文的式子里没有。字间距是字号 × 0.03，
n 个字有 n−1 个间隙；按原式反推，**6 字一行会顶出边距约 23px**，
正好撞上 §七之六 自检表的第 2 条。4–5 字的常见情形两种算法都撞 182 的上限，结果一样。

**副标题 6 字上限。** 规范原来只写了字号（主标题 × 0.5＝91px）没写字数，
008 写了 8 字的「前面还有二十三位」，渲出来 728px 宽 —— 贴右边距右对齐之后
左端顶到 x≈270，**压在角色的耳朵和鬃毛上**（角色框 114–465），
§七之三「标题不能压住脸」差一点就破了。6 字左端落在 x≈460，正好贴着角色框右沿
（007 的「七个人点同意」就是这个位置）。**改成 6 字，别改字号** ——
副标题小于主标题一半就托不住那圈白描边了。

#### 排不开就折行（2026-08-23 加）

**分段符是全角空格**，写成 `老马 · 工位　单子放三天`。
一行排得开就排一行（007/008/009 那种六字副标题一个字都不会变）；
排不开就**前一段单独一行**，剩下的合成第二行。只折一次 ——
折两次就是三行小字压在角色身上，那不叫封面叫说明书。

**「排不开」的判据是「要不要压字号」**：按 0.5 倍主标题字号排不下，就折。

⚠ **折行不是万能的，上面那条 6 字上限仍旧管每一行。**
010 就是这么炸出来的：初稿副标题十八个字，压到字号下限还差一大截，
**「老马」两个字直接掉出了画布左边**，缩略图上看着像渲坏了。
折行之后不掉出去了，但第二行「单子到我这儿，一般放三天」整行 946px，
**3:4 里横在他下巴上** —— 砍成「单子放三天」才干净。

> **`npm run cover` 现在会算这两条并报出来**（`laomaSubFit()`）：
> 排不排得下画布、压不压到角色（阈值 0.52 画布宽 ＝ 562px，就是那个 6 字）。
> **在这之前主标题有字数闸、副标题一个都没有。**

⚠ **副标题必须在 3:4 里能单独立住。** 九宫格裁的是 `crop=1080:1440:0:240`，
画面上边 240px 整条没了 —— 008 原来想写「这个数没动过」，可那块叫号屏（y 89–241）
在缩略图里正好被裁光，「这个数」就没有指代了。**副标题里的指代词，得看一眼它指的东西在不在 3:4 里。**

### 三、位置

**标题永远不能压住角色的脸。** 按角色站位取对侧：

| 角色站位 | 标题位置 | 对齐 |
|---|---|---|
| 左侧 | 右上 | 贴右边距，右对齐 |
| 右侧 | 左上 | 贴左边距，左对齐 |
| 中央 | 右上（**不是正上方**） | 贴右边距，右对齐 |

主标题首行基线：**画布高 × 0.22**。需要避让画面上方元素（比如电梯楼层屏）时，
整体下移到 **0.40** —— 稿件里写 `"cover": { "titleLow": true }`。

⚠ **2026-08-22 从 0.115 改成 0.22，因为 0.115 只顾了 9:16。**
个人主页九宫格裁的是 `crop=1080:1440:0:240`，只留 y ≥ 240；而 0.115 的基线下，
标题墨迹落在 y 55–243 —— **四字标题整行都在裁切线外，`-3x4.png` 上主标题一个字不剩，
只剩副标题**。§一 早就写着「关键内容必须落在 3:4 区域里」，是 §七之六 的自检表漏了这条。

0.22 是量出来的：

```
墨迹顶边 = 基线 − 字号 × (字面上伸 0.88 ＋ 描边往外那一半 0.075)
182 的字号下 = 基线 − 174   →   要让顶边落在 240 以下再留余量，基线 ≥ 419（= 0.218 × 1920）
```

⚠ **别用「不碰到角色的任何墨迹」去反推，那样算出来是无解的。** 角色墨迹最上一行在
y=328（头发尖），按那个当上界，可用带只有 240→328 共 88px，装不下一个 182px 的字。
但这一节说的是**不压脸** —— 耳朵尖和头发不是脸。实测 0.22 时标题落在他耳朵旁边，离脸还远。

验过两种：4 字一行（007《优化以后》）、5 字两行（005《对齐了三次》），
3:4 里标题、副标题、角色、署名全在。
⚠ **7 字标题**拆成 4/3，第二行位置最低，左端算下来会擦到他头右侧约 9px —— 写到时看一眼。

⚠ 老马线**不看 `cover.top`**。那个参数是给米白纸片定顶边的，这套的基线由规范定死。

### 四、三个实现陷阱

前两条是规范原文带的，第三条是这次实现时撞出来的。都不是审美问题，是不写清楚就会踩。

#### 陷阱一：贴边对齐，不是中心对齐

**错误做法**：把标题中心点定位在「画面宽度的 70% 处」。四个字看着没问题，七个字直接出血到画面外。

**正确做法**：贴边距对齐（右对齐或左对齐），字号由可用宽度反推。
这样字数怎么变，文字只会**往画面里长，不会往外顶**。

#### 陷阱二：描边要画两遍，不能用单层 stroke

**错误做法**：给文字直接加 `stroke` 属性 / `paint-order`。描边是从字形轮廓的中线
往两边长的，会吃掉一半字面。字号 150、描边 22 的情况下，笔画细的字（比如「没」「看」）
会糊成一团。`paint-order` 在部分渲染器里还不生效。

**正确做法**：同一段文字画两遍 —— 第一遍 `fill: none` 只有粗描边，第二遍纯填充、
位置字号完全相同，盖在上面。副标题同理（白描边 + 黑填充）。

⚠ **整块的描边要全部画完，再画填充。** 逐行「描边＋填充」交替的话，
**下一行的描边会啃掉上一行的填充** —— 行高 1.12、描边半宽 0.075 × 字号，够得着。
主标题和副标题之间同理。

#### 陷阱三：副标题的偏移量要补上中日韩字面的上伸量

规范写的是「副标题位置＝主标题末行基线下方 字号 × 0.4」。**按字面实现会压在主标题上。**

实测（主标题 182px）：基线下方 0.4 × 182 = 72.8px，而副标题自己的字面要往**基线以上**
长 0.88 × 91 = 80px —— 它的顶边落在主标题基线**上方** 7px，正好啃进大字的下半截。
第一版渲出来「老马 · 一个人住」整条横在「按时不去」的腰上。

**正确做法**：把 0.4 当作**间隙**用（主标题基线 → 副标题字面**顶边**），再补一段
`副标题字号 × 0.88` 的上伸量，落到副标题的基线。

### 五、文案规则

**主标题 4–7 字。** 超了就改标题，不要缩字号。

**副标题是补充信息，不是重复。** 主标题抛出问题，副标题给一个具体细节。

- ✓「电梯看哪儿」＋「七人同看数字」
- ✗「电梯看哪儿」＋「电梯里的尴尬」（同义反复，白占一行）
- ✗「按时不去」＋「老马 · 一个人住」（栏目标签，白占一行 —— 006 第一版就是这个）

⚠ **这一条 2026-08-23 撞上了一个没定的事，先记在这儿。**
用户要求副标题排不开时折行，并且**「老马 · 工位」单独一行** ——
那正是上面这条 ✗ 判掉的栏目标签。010 现在的副标题是
`老马 · 工位　单子放三天`：**上一行是栏目标签，下一行才是具体细节。**

两种读法，得选一个：
- **栏目标签是系列元素**（001–005 都有，像个台标）→ 那这条 ✗ 要改成「栏目标签只能单独占第一行，第二行必须给具体细节」
- **栏目标签仍旧是浪费**（006 那次的结论）→ 那 010 的副标题该只留 `单子放三天`，折行机制留着给真正两段的副标题用

**没定之前 010 按用户说的那个形状出的片。** 折行机制本身跟这条无关，
它解决的是「一行排不开」，不是「该不该写栏目标签」。

**标题不能剧透落点。** 主标题留悬念，副标题给场景。
反例：「最佳位置」＋「第三个」——「第三个」就是转折句本身，观众看完封面就不用看片子了。

### 一、这一档是什么

**片子里是什么样，封面就是什么样，上面压一块单点式的贴纸大字。**

| | |
|---|---|
| 底 | `horse/长片/longform.cjs` 的 `frame()` **直接出一帧** —— 场景、鱼缸、灯光、色温差全是那边定的 |
| 大字 | §七 那套贴纸描边字（`#FFD400` 填充 ＋ `#1A1A1A` 描边、Black 字重、描边画两遍） |
| 站位 | 角色站一侧、标题排对侧，贴边距对齐。判据仍是 §七之三「**绝不压脸**」 |
| 尺寸 | 1280×720，跟成片同一个尺寸 —— **封面就是第一帧**，不另做一个 |
| 署名 | **挪到左下角**（见下） |

⚠ **底不抄一份到封面脚本里。** 封面脚本只是调 `frame()`，多传三个参数
（`maX` 老马站哪儿 / `maH` 多高 / `overlay` 叠什么）—— **画法一个像素没动**，
出帧脚本不传它们，帧跟以前逐字节一样。抄一份的话，改了场景之后封面还是旧的，
而**两处一旦对不上，带图的那份看起来更权威**。

### 二、为什么不并进 V3（[`../YouTube封面规范.md`](../YouTube封面规范.md)）

V3 是「两个大字 ＋ 一个实心图形」，画面是**抽象**的。长片这条线本来就有一整套
画好的场景和角色，做成两个字加一个色块，等于把片子的长相扔了。

而 V3 §〇「缩略图与片头首帧是两回事」在这条线上也不成立 —— 长片首帧就是这一张，
**一种版式只有一处要维护**（同 YouTube封面规范 §十三 说书线那笔账）。

⚠ **但右下安全区那条归它管**：这是 16:9 缩略图，YouTube 的时长角标照样压在
x ∈ [1080,1280]、y ∈ [640,720]。

**署名仍旧署右下，只是让开那个角**（右端顶到 1055，留 25px）。
⚠ 这条 2026-08-26 改过一次：原先写的是「右下是角标的地盘，所以挪到左下」——
**把话说窄了**，角标只占那个 200×80 的角，右下大部分是能放的。
非要回右下的理由：竖版署的就是右下（§二），**做到第十条观众要认出这是同一个号，
两条线的署名得在同一个角才攒得起来**。

⚠ **署名的判据是「对六个场景都成立」，不是「这一张好不好看」。**
地面线 566 以下那条带六个场景都是空的（浅地板／暗地板）；右上不行 ——
`office_night` 那儿是窗、`street_dusk` 是远楼。
**署名是画布坐标，不跟着角色走** —— 跟着走就每期一个位置，攒不出台标。

### 三、版面（都是量出来的，不是估的）

| 项 | 值 | 为什么是这个数 |
|---|---|---|
| 画布 | 1280 × 720 | 跟成片一样 |
| 边距 | 画布宽 × 0.062 ＝ 79 | 跟竖版同一条 |
| **可用宽度** | 整幅 ＝ 1121（1280 − 边距×2） | **2026-08-26 从「左栏 663」放开** —— 用户定：盖住右侧图可以 |
| **字号上限／下限** | **150 ／ 109** | 见下 |
| 行高 / 字间距 / 描边 | 字号 × 1.12 ／ × 0.03 ／ × 0.15 | 跟竖版同一套（§七之一） |
| **折行** | 先按 §七之二 折半，**第二行开头是附着字就往后挪一格** | 见下 |
| **标题块垂直中线** | 画布高 × **0.46** ＝ 331 | 见下 |
| 老马缺省站位 | x = 800，高 470，**脚底落在地面线 y=566** | 改高度是从头顶往上长，不是把人抬起来 |

**字号上限 150，不是竖版那个 182 按宽度换算过来的。** 换算出来是 216，
216 的两行字在 720 高的画布上占 66%，场景就只剩一条边了。150 两行落在 63%，
四字一行 40%，两种都过第四节那条 30% 的下限。

#### 一行优先（2026-08-26 立）

**主标题尽量排一行；排不下就压字号；压到下限还排不下才退两行。**
用户 2026-08-26 定：**盖住右侧图也可以** —— 所以可用宽度从左栏（663）放开到整幅（1121）。

| 字数 | 一行字号 | 210px 下字高 | 描边在 210 上 |
|---|---|---|---|
| 4–7 | **150**（撞上限） | 24.6px | 3.7px |
| 8 | 137 | 22.4px | 3.4px |
| 10 | **109** ← 下限 | 17.9px | **2.7px** |
| 12 | 91 | 14.9px | 2.2px（糊） |

**≤7 字一行根本不用压字号。** 1121 ÷ 7.18 ＝ 156，仍旧撞 150 的上限 ——
「为了一行牺牲字号」这笔账 **8 个字才开始付**。001 那条 6 字标题是白赚一次放大：
两行 150 变一行 150，**字一个像素没小，视觉分量翻倍**。

**下限 109 是 210px 那张验收图定的，不是审美定的。** 贴纸感的来源是描边 ＝ 字号 × 0.15；
210 上那圈墨边要还看得见，描边至少 2.7px，反推字号 ≥ 109，换算成字数就是
**一行最多 10 个字**。再往下那圈边糊进字里，就不是贴纸了，是普通粗体字。

⚠ **竖版那条「>7 字改标题别硬塞」在这一档作废** —— 那是 1080 宽画布的账，
16:9 宽出 200px，闸位本来就不一样。这一档的闸**由字号定，不由字数定**。

**纵向是「整块居中」，不是竖版那个「首行基线钉在 0.22」。** 0.22 是为九宫格
`crop=1080:1440:0:240` 算的，**16:9 没有那条裁切线**；钉首行基线的话，四字一行
和七字两行的重心会差一大截（一个偏上、一个压到地面线上）。所以量出整块的外接高度
再居中。

#### ⚠ 一行之后，垂直中线从「随便居中」变成受约束的数

两行的时候标题是个**方块**，只能靠左栏界横着躲角色。一行的时候它是一条**横带** ——
避让从横向变成纵向。而这条缝很窄（老马站 x=800、高 470 时实测）：

```
老马眼白    y 173–213
（缝 110px）
鱼缸上沿    y 400
标题带高    161px（150 字号）   ← 装不下，必然压到一样
```

| 中线 | 标题带 | 压到 |
|---|---|---|
| 0.40 | y 144–305 | **横过眼睛**，人和字互相吃 —— 渲过，是反例 |
| **0.46** | y 187–348 | 下巴和胸口，眼睛擦到一点、鱼完好 ← **001 用的是这一版** |
| 0.50 | y 216–377 | 只压胸口，**眼睛和鱼都完好** |

0.46 是用户 2026-08-26 挑的（候选「甲」）。**想让开脸写 `cover.long.centerK: 0.5` 就行，
一个字段的事** —— 但那是换构图，不是修 bug。

⚠ **改老马的站位或高度（`maX`/`maH`），这张表要重量。**

#### 折行：折半会劈开词（2026-08-26 加）

§七之二 那条「5–7 字折两行，前行取 `ceil(n/2)`」**只管长短，不管断口**：

- 「我一直以为他傻」→「我一直以／为他傻」——「以为」被劈成两半
- 「老牛走的那天」→「老牛走／的那天」—— 第二行顶着一个「的」

所以这一档在折半之上加一条：**第二行开头不许是附着字**（的了着过地得们之），
是就把断点往后挪一格。「老牛走的那天」→「老牛走的／那天」。
挪之后**前行仍旧不短于后行** —— 只往后挪，不往前。

> 附着字得挂在前一个字后面才有意思。「的」「了」拎到行首，读者要往上一行找主人。
> **这跟好不好看无关，是读得动读不动。**

⚠ **只改了长片这一档。** 竖版那支 `splitTitle`（`cover.ts`）**一个字没动** ——
改它会改掉以后所有 7 字竖版标题的断口，那条线已经出了十条片，要动得单独过一遍。
001–010 都是 4–5 字，一次都没撞上这个坑。

### 四、程序自动做的五件事

1. **字数**：主标题 4–7 字，跟单点式同一条闸（§七之二）
2. **标题块的实际外接框**：把整块排版涂成一个纯色、铺在纯黑上单渲一次，扫像素量。
   ⚠ **不用公式反推** —— 公式是给「该多大」用的，「实际多大」得看像素
3. **高度**：外接高度 ÷ 720 < 30% 就报。跟 V3 §七.4 同一笔账，只是这一档量的是
   **整块**（标题＋副标），不是一个两字大字
4. **压到了什么**：**分级，不是一条 error**（2026-08-26 改）

   | 压到 | 判 | 为什么 |
   |---|---|---|
   | 场景（墙、窗框） | 不报 | 本来就是底 |
   | 老马的**身子** | 不报 | 用户 2026-08-26 定「盖住右侧图也可以」 |
   | 老马的**脸** | warn | 眼睛是这条线的辨识点，黄条横过去人和字互相吃 |
   | **那条鱼** | warn | 红点是 210px 下唯一还在跳的颜色，盖掉等于把缩略图唯一的色相扔了 |

   ⚠ **脸和鱼用两种量法，因为可靠的量法不一样。**
   脸从 rig 自己的几何推（`maX`/`maH` 是精确的，头占上面三分之一）——
   **不能靠颜色探针**：浅底场景（`office_dawn` 底 `#EFE7D8`）的背景本身就跟眼白同色。
   鱼靠颜色探针（`C_FISH` `#D94F2B` 是**全片唯一的高饱和色**，六个场景都不重样）——
   它的位置由 `fish` 参数在缸里游，**推不出来，只能量**。

   ⚠ **大字和副标涂两种探针色，分开量。** 头一版整块一个色，于是挂在左边、
   根本够不着角色的副标，跟着大字共用一个外接框，一起被算成「压到了」。
5. **右下安全区**：非底色像素 > 5% 就报（底色取当前场景的 `bg`）
6. **不剧透说破段**：拿成品目录 `发布文案.md`「中心思想」那一栏对一遍 ——
   大字或副标里有三个连着的字撞上说破句就报（[长片_出片方案.md](horse/长片_出片方案.md) §七 硬规矩一）。
   ⚠ 找不到那份就**不查、只提一句**：闸门宁可缺席，也不能编一个源出来

⚠ **没有一项在查「看不看得见」。** 跟 YouTube封面规范 §二 那条浅底档的教训一样：
四项全绿不等于这张图能看。**验收标准仍旧是 210px 那张**。

### 五、文案

跟 §七之五 同一套（主标题 4–7 字留悬念、副标题给具体细节不重复），加两条：

**一、大字里不许出现说破段的字眼。** 长片的支点是说破那一次，
「看得开」「没敢试」这类词一进封面，观众带着答案来看，那七句就白排了。
这条有代码在守（第四节第 6 项）。

**二、大字跟画面对得上。** 竖版那套是「大字卖惨、标题追问」的双簧；这一档的底
是片子里的真实一帧，**大字要说的是这一帧里的事**。

**三、人称要能在画面上落地。** 这一档的封面上**站着一个具体的角色** ——
写「他」的时候，观众会先把「他」认成画面里这一位。001 头一版是
「他走以后」＋「他写了十一页」，两个「他」都是老牛，而画面上只有老马：
- 「他走以后」还有个**自解的矛盾**撑着（他走了、画面里却站着一个），观众会察觉说的不是这位
- 「他写了十一页」**没有矛盾提示**，直接被读成这匹马写的

⚠ 这跟 §七之二 记的 008 那次是同一类：那次是**指代物被 3:4 裁没了**，
这次更糟 —— **画面上站着一个错的指代对象**。
判法：**把每个人称代词按「画面里那位」读一遍**，读不通或读反了就具名一次。
001 现在的「老牛走的那天」＋「他写了十一页」，具名一次，副标那个「他」就有主了。

### 六之二、方版（1:1，2026-08-26 加）

**同一张封面的第二种排法，不是第二张封面。** 微信那一路（公众号列表、视频号）
吃的是方图，16:9 传上去两边被裁 —— **裁掉的正好是左边那块标题**。

**缺省是竖排**（2026-08-26 用户定）：大字贴左边安全线排成**一列**，从上贯到下；
16:9 那一帧整个缩进来沉在底（1080×607.5，满幅出血）。

竖排比横排强在两处：一列字从顶走到底，**顺手把上半那块空白用掉了**；
缩到 200px 的时候，一竖列比一横行占的视觉面积大 —— 更认得出。
横排那一档留着（`sqText: "横排"`），它更规矩、字数多的时候更稳。

### 排版安全区：四边各 10%（108px）

⚠ **这一条是 §一 铁律 4 在方版上的落值。** 第一版竖排的字距画布左沿只有 56px（5%），
缩到 200px 只剩 10px —— **看着就是「字快掉出去了」**。

三样字全部落在框里，**一样都不许探出去**：

| | 怎么摆 |
|---|---|
| 大字 | 列心 ＝ 安全线 ＋ 描边外沿 ＋ 半个字身。⚠ **描边要算进去** —— 漏掉它，一列字正好探出一个描边宽（150 字号下 22px） |
| 副标 | 大字那一列的旁边，同在框内 |
| 署名 | 见下 |

**字号由安全区的高度反推**（竖排的约束在纵向）：
`(n−1)×字号×1.06 ＋ 字号×(1＋描边比) ≤ 864`。六个字算出来 134px。

⚠ **署名在方版里放不下「脚边签」，自动退回右下角。**
量出来的：画面沉底之后地面线落在 y=950，安全区下沿是 972 ——
**中间只有 22px，牌子有 63px 高**。硬塞只有两种下场：探出安全区，
或者被收进来压在鞋上 —— **后者正是「己」那一版判掉的做法**。
所以不是收进来，是换位置。**横版仍旧是脚边签，两个尺寸的署名位置不一样。**

⚠ **不裁画面。** 裁到 1:1 能让老马大一倍，但灯、桌子、鱼缸的相对位置全变了，
那就成了**两张不同的图**；缩进来是同一张图的两种排法。
而且 `side: 'left'` 的时候该裁哪边又是一套规则 —— 不裁就没有这个问题。

⚠ **上半那块底色取场景底色**，所以画面和标题之间**没有缝** ——
看着像画面往上长了一截，不像上下拼的两块。

| | 横版 | 方版 |
|---|---|---|
| 画布 | 1280×720 | 1080×1080 |
| 可用宽度 | 1121 | **946**（窄一档） |
| 标题落在 | 整幅，压在画面上 | 上面那条带（0–472）里居中 |
| 署名 | 版式库说了算 | 同一档，坐标乘 0.84375 再加带偏移 |
| 时长角标 | **要让** | **没有**（那是 YouTube 的事） |
| 验收图 | 210px | 200px |

**同一个标题，横版一行、方版可能两行** —— 可用宽度窄一档，掉档的位置也早一格
（横版一行撑到 10 字，方版 8 字）。这是知情的：**窄画布多一行，比把字压糊强。**

⚠ **字号下限方版要单独查一遍。** 横版那条查的是横版的字号（1121 反推的），
方版算出来是另一个数 —— **横版刚好卡在 109、方版已经掉到 92** 的情况是存在的
（18 字标题实测：横版过、方版 102 被拦）。同一类的漏法这一档栽过一次
（副标跟大字共用外接框，见第四节末），别再来第二次。

### 七、版式库（2026-08-26 立）

**这一档不是一种版式，是一个库。** 一期挑一档，稿件里写 `cover.long.layout`：

```jsonc
"long": { "layout": "一行·脚边签", "scene": "office_night", "side": "right", "fish": 0.72 }
```

代码在 [`src/laoma-long-cover.ts`](src/laoma-long-cover.ts) 的 `LAYOUTS`。
名字写错会打一行人话并列出现有的几档，不会甩栈。

⚠ **两层库别混：** 跨线那层（**哪条线用哪一档封面**）在
[`../YouTube封面规范.md`](../YouTube封面规范.md) §〇之二；**这儿是线内那层** ——
长片档内部的排法。一层一处，别互相抄。

#### 现有

| 名字 | 长什么样 | 代价 | 立于 |
|---|---|---|---|
| `一行·右下签` | 主标题一行贴左边距，署名钉在**画布右下角**（让开时长角标） | 署名孤零零挂在角上，跟画面没关系。**换来的是位置固定** —— 跟竖版 §二 同一个角，做到第十条观众认得出是同一个号 | 2026-08-26 候选「甲」 |
| **`一行·脚边签`**（缺省） | 主标题一行贴左边距，署名摆在**角色脚边的地面上**（脚正下方，不压脚） | ⚠ **署名跟着角色走** —— 改 `maX`/`maH`/`side` 或者换个站位，署名就换个地方，**攒不出台标**。换来的是署名落在画面里、跟角色有关系，不像一枚贴在角上的水印 | 2026-08-26 候选「庚」，001 用的这一档 |

`一行·脚边签` 有一条闸是它专属的：**署名滑进时长角标就报 error**
（老马站到 `maX` ≈ 907 以上就会）—— 跟着角色走的代价得有人盯着，
而角标是平台事后叠上去的，**画面上一点都看不出来**。

#### 反例（试过，不进库）

留在这儿是为了别再试一遍。

| 试过什么 | 为什么不行 |
|---|---|
| 标题带上移到 `centerK` 0.40 | **横过眼睛**，人和字互相吃。0.46 走下巴、0.50 走胸口，这两档才成立 |
| 署名**压在脚上** | 鞋实测 79×14，署名盒 160×63 —— **宽一倍、高四倍半**，压上去把鞋和小腿一起吞掉，人就浮起来了；210px 下那块蓝还贴着他的赭橙糊成噪点 |
| 署名接在**副标右边** | 跟副标抢同一行的小字，而且**副标长度每期变，署名跟着漂** |
| 署名放**右上角** | 六个场景的右上不都是空的 —— `office_night` 是窗、`street_dusk` 是远楼 |

#### 加一档要交代什么

往 `LAYOUTS` 里加一项，四个字段一个都不能省：

```ts
'两行·右下签': {
  what: '一句话，这一档长什么样',
  centerK: 0.46,
  sig: 'canvas-br',
  since: '2026-09-xx 谁定的',
  cost: '**代价**。没有代价的版式说明还没想清楚',
}
```

三条纪律：

1. **`cost` 是必填的，而且要写实话。** 版式库最容易烂成一张「都挺好」的清单 ——
   到时候挑不出来，因为看不出差别在哪。差别写在代价里，不在长相里。
2. **退役的版式不进这个表，进上面那张反例栏。** 表里每一项都是「现在能挑的」；
   掺进不能挑的，下一个人得先读注释才知道哪些是活的。
3. **别为一期加一档。** 一期不一样就用 `cover.long` 的单期覆盖字段
   （`centerK` / `sig`）；**同一种排法用到第二次，才值得进库** ——
   进库意味着以后每次改这一档都要想着别的期。

⚠ **版式库不是参数库。** 加一档的判据是「这是另一种看法」，不是「这个数不一样」。
`centerK` 0.46 和 0.50 不该是两档 —— 那是同一档的两个位置；
`canvas-br` 和 `feet` 是两档 —— 一个把署名当水印，一个把它当画面里的东西。
