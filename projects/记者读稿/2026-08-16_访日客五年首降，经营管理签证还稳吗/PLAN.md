## 二、实测数据（用本片真实文案跑出来的，不是估算）

**1. 现有成片的时间轴回归**（`projects/2026-08-15_二十三天，四家金融机构消失/`，55 个配音行）

```
时长 = 203.5 ms/字 × 字数 + 1147 ms/行
```

那个 1147ms/行 的固定开销就是逐行 TTS 的头尾静音。实测单段波形：
**头部静音 0.19s、尾部静音 0.90s**。59 行合计白搭 65 秒，占全片 29%。
这是「空白太多」的真正原因，不是 pauseAfterMs 设大了。

**2. 音色语速对比**（同一批 10 行、233 字实测）

| 配置 | 净语速 | 头尾静音 |
|---|---|---|
| 现在的 `zh-CN-YunjianNeural` `-4%` | 197 ms/字 | 0.99 s/行 |
| 建议 `zh-CN-YunyangNeural` `-2%` | 182 ms/字 | 0.73 s/行 |

Yunyang 是 Edge TTS 的新闻播报音色，比 Yunjian 的纪实旁白腔更贴「记者读稿」；
`-2%` 约 330 字/分，接近新闻主播实际语速。

**3. 竖版字幕现在是坏的**

`src/lib/ass.ts` 用 `WrapStyle: 2`（只认 `\N`，不自动折行），Sub 样式左右边距写死 60、
不随 fontScale 缩放。竖版 sub 字号 54×1.45=78px，可用宽度 1080-120=960px → **一行只放得下 12 个字**。
抽 `projects/2026-08-15_.../portrait.mp4` 的第 4 秒验证：
「这一天，日本的银行间市场出现了战后第一次违约」两头都被切出画。
本片 46 条 sub 里 **44 条会超宽**（最宽 2756px / 可用 960px），横版也有 1 条超（1901px / 1800px）。

## 三、要达到「记者读稿」必须动的三处

### 改动 1：`src/steps/tts.ts` —— 去掉每段的头尾静音

合成完、测时长之前，加一道修剪。两遍 `silenceremove` 夹一个 `areverse` 是标准做法，
`start_periods=1` 保证只削首尾，不会吃掉句内停顿：

```
-af silenceremove=start_periods=1:start_silence=0.05:start_threshold=-45dB:detection=peak,
    areverse,
    silenceremove=start_periods=1:start_silence=0.06:start_threshold=-45dB:detection=peak,
    areverse
```

头留 50ms、尾留 60ms，防止削掉起始辅音。修剪后再 `durationMs()`，时间轴自动对齐。
实测每行省 0.73–0.99 秒。句间留白改由 `pauseAfterMs` 显式控制。

### 改动 2：`src/lib/ass.ts` —— sub 自动折行

在 `buildAss` 里给 sub 分支加折行：按 `estimateWidth()` 估宽，优先在 `，、；` 处断，
其次按宽度硬断，插入 `\N`。竖版另给 sub 单独的字号系数（约 1.15，而不是 profile 的 1.45），
最多 3 行；横版最多 2 行。Sub 是 `\an2` 底部居中，多行往上长，不用改 MarginV。

**这条不改就没法写长句，也就没法连贯** —— 长句是「记者读稿」的前提。

### 改动 3：`.env` —— 音色语速

```
VG_VOICE=zh-CN-YunyangNeural
VG_RATE=-2%
```

### 配套的写稿约定（与 README 默认风格不同，已体现在 script.json 里）

- **一句话一行、20–31 字**，从句不拆行。句读交给标点在同一次合成里完成，跨行才是断点
- `pauseAfterMs`：段内 80–120，句末 200–260，段落切换 450
- 全片只留 **1 个 chip**（1.2s）和 **1 组 stack**（常勤职员／2名以上／或者资本金／**500万日元以上**）
- 其余全部连读

## 九、返工记录：音轨空洞（2026-08-16 第二次渲染）

**症状**：播放到 0:01 直接跳到 0:04，这三秒没有声音。不是播放器的问题。

**实测**：成片音轨里有两处 3.00 秒的空洞（横版 1.195s / 12.474s，竖版 8.384s / 21.461s），
另有一处 0.08s。整条音轨解码出来只有 201.88s，比 `voice.mp3` 的 207.93s 少 6.06 秒。
容器时长、文件大小、首尾同步全都正常，所以原有的时长自检拦不住。

**根因**：`loudnorm` 和 `libx264` 放进同一次 ffmpeg run 会丢音频。
逐项隔离验证（30 秒切片即可复现）：

| 组合 | 结果 |
|---|---|
| 纯音频 + loudnorm | 干净 |
| 视频 `-c copy` + loudnorm | 干净 |
| 视频全滤镜 + 音频不过 loudnorm | 干净 |
| **视频全滤镜 + loudnorm（原写法）** | **两处 3.00s 空洞** |

loudnorm 动态模式按 3 秒一块缓冲，视频编码拖慢管线之后整块被丢弃。
丢的位置取决于视频内容，所以横竖版各不相同 —— 这也是为什么 0815 那条片子
横版干净、竖版有五处空洞，一直没被发现。

**修复**（`src/steps/render.ts`）：

1. `buildAudioMix()` 把混音摘成独立的一遍 ffmpeg，产出 `voice_mix.m4a`，
   视频那一遍只 `-c:a copy`。横竖版共用同一条音轨，第二次渲染直接复用
2. 混音链尾加 `aresample=48000:async=1:first_pts=0`，补掉 loudnorm 收尾处
   那个几十毫秒的时间戳空洞
3. 新增 `assertAudioContinuous()`：渲染结束逐包检查音轨，间隔 >100ms 直接报错

**验证**：横竖版音频包数均为 9747/9747，零空洞；解码后 207.915s（≈ voice.mp3 的 207.933s）。

## 十一、开场标题卡（2026-08-16 第三次渲染）

**问题**：第一帧只有左中位的时空角标「2026年8月上半年 ｜ 访日客数」，
交代的是背景不是钩子，前三秒抓不住人。

**做法**（`src/lib/ass.ts`，不动稿件、不动配音、不动时长）：

- `titleKeywords()` 按标题里的逗号顿号拆行 —— 标题本来就是按语义断好的，不需要分词。
  本片「访日客五年首降，经营管理签证还稳吗」→ 两行，末行是落点
- 盖在第一个镜头上停 2.6 秒，跟开场白口重叠，不额外占片长
- 角标不配音，整块顺延到卡片淡出之后（2.74–4.06s），时长不变，时间轴不受影响
- 四套版式，由**标题哈希**在四套里挑，不用 `Math.random()` ——
  管线其余部分全是确定性的，同一份 script.json 重跑必须逐帧一致，
  横竖两版也必须是同一个版式。不同选题自然会换版式
- 自动挑的不满意，script.json 顶层加 `"hookLayout": 0`（0–3）手动指定，重跑 render 即可

四套版式：`0` 居中堆叠+末行红底反白（本片哈希落在这套）／`1` 左对齐+红竖线／
`2` 上下分置+红横线／`3` 压在下三分之一+红下划线。

**踩到的坑：scrim 的透明度不能按公式推。**
整帧压暗用的是 ASS 绘图矩形 + `\1a`。按 `(255-a)/255` 算，`&H72&` 应该是 55%，
实拍帧量出来只有 **37%** —— libass 实际压出来大约是名义值的六成。
标定表（无字区域，横版第一个镜头）：

| `\1a` | 实测压暗 |
|---|---|
| `&H72&` | 37% |
| `&H5A&` | 44% |
| `&H45&` | 49% |
| **`&H30&`（采用）** | **55%** |
| `&H20&` | 60% |

要再调就照着改完重渲一帧量亮度，别按公式推。

     角标不配音，压着下一句一起走即可
