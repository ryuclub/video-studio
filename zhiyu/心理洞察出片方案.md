## 〇、二版改稿带出来的一件事：加规则要回头看数

**2026-08-20 补规则 6–9 的时候，三个旧的数同时失效了**，而且三个都是硬闸门，
照新规则写出来的稿子会被自己的体检拦下：

| 数 | 旧值 | 新值 | 为什么非动不可 |
|---|---|---|---|
| 【确认】字数 | 80–100 | **110–150** | 规则 6 要段末预告一句中心思想句，那句本身就 40 字上下 |
| 【归位】字数 | 200–250 | **250–320** | 规则 8 把这段从「这是什么」扩到「＋可以放下什么」，规则 9 又把全篇最能安慰人的一句放这儿 |
| 「你」上限 | 5 | **16** | 上面两件活都是对着听众说的，一段下来自然七八次。二版全篇 11 次 |
| 「你」位置 | 代价／归位 | **＋确认** | 规则 6 那次预告就在确认段末尾 |
| 「你」下限 | 无 | **代价＋归位 ≥2** | 一版几乎零第二人称，体检全绿 —— 听众没有可以站进去的位置 |

**教训不是「区间定错了」，是加规则的时候只改了文档没回头看闸门。**
下次往 §三 加规则，先问一句：这条规则给哪一段加了活，那一段的数还够不够。

反过来也要防：**别每次写超了就把区间往宽改**。【归位】二版实测 332，比新上限还多 12，
这次就留成 warn 没再放宽 —— 一期不够定区间，见稿源 §十。

## 一、多一道体检闸，而且顺序不能反

**这是这条线跟治愈线最大的流程差别。**

```
稿件  →  ① 体检  →  ② 音频 → ③ 画面 → ④ 封面 → ⑤ 成片 → ⑥ 发布文案
         ↑
         有错就停，不往下跑
```

`xinli-check.ts` 挂在 `zhiyu-episode.ts` 起手，**拦在 TTS 之前** ——
那是这条链上第一个花时间的步骤。稿子不合格，一秒钟的音频都不会合成。

**E01 第一版是反着做的**，代价记在这儿：落稿 → 音频 → 画面 → 成片 → 量时长，
**这时才发现稿子从落笔就差 114 字**，命名段缺 35、展开段缺 79，两个核心段都没写够。
整条链白跑一遍。

稿源 §出稿检查表 里「结构字数落在区间内」本来就写着，但它是个复选框，
没有代码在守，所以没拦住任何人。通则见 [RUNBOOK 一之四](../RUNBOOK.md)。

### 命令

跟治愈线的链路一样（见主手册 §三点五），差别只有两处：**每条都要带 `--line 心理`**，
以及封面走这条线自己的脚本。

```bash
cd joke-video
npx tsx src/xinli-check.ts   --line 心理 --ep 已读不回   # ① 正常不用手敲，② 会自己跑
npx tsx src/zhiyu-episode.ts --line 心理 --ep 已读不回   # ②
npx tsx src/zhiyu-scene.ts   --line 心理 --ep 已读不回   # ③
npx tsx src/xinli-cover.ts   --line 心理 --ep 已读不回   # ④ ← 不是 zhiyu-cover
npx tsx src/zhiyu-video.ts   --line 心理 --ep 已读不回   # ⑤
npx tsx src/zhiyu-publish.ts --line 心理 --ep 已读不回   # ⑥
```

**不带 `--line` 就是治愈线**，会去 `projects/治愈/` 找期号然后报「没有这一本」。

「改了什么要重跑哪一步」那张表在主手册 §三点五，两条线通用；
这条线只多一行：**改 `coverTitle` / `motif` / `hook` → 重跑 ④ 再 ⑤**（片头那一帧变了）。

## 二、体检查什么（`xinli-check.ts`）

**✗ 错**会 `exit 1` 拦住出片，**! 提醒**只报不拦。

| 查什么 | 级别 | 依据 |
|---|---|---|
| 六段结构齐不齐 | ✗ | §三 |
| **各段字数在不在区间** | ✗ | §三 结构表 |
| 「你」只在确认／代价／归位段、总数 ≤16、代价＋归位 ≥2 | ✗ | §三 硬规则 5 |
| 禁用词（愿你/余生/看穿/识破/高情商/精神内耗…） | ✗ | §四 |
| 现象段有没有人称 | ✗ | §三 硬规则 1 |
| 归位段有没有滑出行动建议 | ✗ | §三 硬规则 3 |
| 残留编辑记号（`*` `_` `※` 之类） | ✗ | 念出来就毁一段 |
| 按实测语速折的预估片长 | ! | 见下 |
| ⏸ 是不是偶数（引句前后各一个） | ! | §三 |

**它只查得了一半。** 腻不腻、换气句有没有真的换到气、现象段够不够像监控录像 ——
只有人听得出来。体检过了不等于稿子好，只等于没有明显硬伤。

### 引句是独立的结构槽

§三 把「前置引句 / 中位引句」列成单独的行（各约 30 字）。稿子里要给它们各自的
`### 【前置引句】` 段标记，**否则引句会被算进前一段** —— 体检第一版就因此把
一段合规的【确认】（85 字）报成 108 字超标。

`###` 开头的行 `loadAct` 会丢掉，不进音频，只是给人和体检当分界用。

## 三、语速比治愈快，但不是音色调过

E01 实测 **1826 字 / 426.7 秒**（含全部停顿）→ **258 字/分**。
第一版 1647 字 / 383.3 秒，两次折算一致。`xinli-check.ts` 的 `CPM = 258` 就是这个数。

| 线 | 实测含停顿均速 |
|---|---|
| 治愈《方丈记》 | 226 字/分 |
| 治愈《枕草子》上篇 | 235 字/分 |
| **心理 E01** | **258 字/分** |

**同一条音色（cast「夜读」）、同一张节拍表、一个参数都没改**，差别来自文本：
短句多、逗号少。所以这条线**不需要为「快一档」去动音色** ——
稿源 §七之二 那句「比治愈档快一档」已经由文本自己实现了。

### 稿源那个「200–210 字/分」不要拿来折时长

那很可能是把「整期含停顿均速」当成了「说话速度」。治愈线在同一个坑里
废掉过六条候选音色，过程见主手册 §二。

§三 结构表末尾的「≈10.5 分钟」按 258 折算后已就地更正为 **7:22–8:08**；
要 10.5 分钟得写到约 2700 字，而字数区间是按每段的活定的、不是按时长定的，
**想加长要重新分配各段区间，不是在某一段注水**。

## 四、画面：五个现代空镜

骨架（和纸底 / 木格窗框 / 竖排标题 / 印章 / 进度线 / 蜗牛 / 右侧章节名）跟治愈线**是同一份代码**，
`zhiyu-scene.ts` 按 `--line` 取色板和镜位集。这条线不一样的只有两样：

- **色板**：把治愈那套的绿相推到石青灰，主色取自封面 series 的 `#4A5B66`
  （§七之二「色调压灰，比治愈档冷两档」）
- **镜位**：**工位 / 电梯 / 会议室 / 屏幕 / 车厢**，§七之二 点名的那五样。
  治愈是留白 / 远景 / 近景

**镜位名不跨线复用**：`发布.json` 里写「远景」而当前是心理线的话直接炸，
好过默默画成另一个镜位。

`MIN_DWELL`（150 秒，主手册 §三点五）在这条线上更吃紧，因为片长只有治愈的三分之一：

| 片长 | 最多几段 |
|---|---|
| < 300s | 1 段（不能切） |
| 300–450s | 2 段（切 1 次） |
| 450–600s | 3 段（切 2 次） |

E01 是 426.7 秒，**只能切一次**。

E02 是 462.1 秒，落在 450–600 那一档、按表能切两次，**实际还是只切了一次** ——
三个切点都得落在能用的段落开头上，而这一期想切的两处（317.3 的「有屏幕之后」、
302.9 的「到第三个人开口」）一个只剩 145 秒、一个跟第一刀只隔 114 秒。
**那张表给的是上限，不是排得下**：段落开头在哪儿是稿子决定的，不是时长决定的。

### 一个只有渲图才看得见的坑

车厢的吊环第一版用了 `C.ridge`，而车厢主体也是 `C.ridge` ——
**同色画同色，全部隐形，而且不报错**。新增镜位后一定要渲一张看，别只看代码。

### 唯一必须做的检查：看 `check-320.png`

## 七、文字版：正文上屏（`xinli-text.ts`）

**这是另一档产品，不是给常规版加特效。**

上面整份手册讲的是助眠档：画面几乎不动、字幕默认不烧（缺省，不是禁令）、所有参数都在往「无聊」上调，
就是为了不给人一个睁眼的理由。**全篇文字上屏是反着来的**，它服务的是**静音看**的人。
所以两版并存、各出各的文件，出片脚本不带 `--text-layer` 时行为一个字节都没变。

```bash
npx tsx src/xinli-text.ts  --line 心理 --ep e02              # ③.5 出 成片/<part>/文字.ass
npx tsx src/zhiyu-video.ts --line 心理 --ep e02 --text-layer # ⑤ 产物带 _文字版 后缀
```

**①②③④⑥ 一步都不用改**，背景图还是 `zhiyu-scene.ts` 出的那批。

> **这一份现在也服务禅佛典线**（跟封面 `xinli-cover.ts` 一样）。
> 墨色纸色原来是抄死的两个字面值（`#3F4A52` / `#F4F1EA`），注释写着
> 「改那边这儿要跟着改」—— 加第三条线的时候兑现了：那条线的景是赭石暖色，
> 抄来的冷灰字浮在上面像贴上去的，**而且不报错，只是看着不对**。
> 现在从 `zhiyu-scene.ts` 导出的 `C` 取，跟着线路走。

### 为什么是 ASS 而不是多渲一批图

逐句上浮做成 PNG 的话，一句一个入场 = 12 帧，E02 有 135 句、约 1500 张。
实测（resvg，这台机器）：带文字的帧 0.39–0.80 秒一张，8 路 worker 并行摊到 106ms。

| 路子 | 要渲几张 | 出图 | 磁盘 | 改一个字 |
|---|---|---|---|---|
| 常规版 | 96 | 约 50 秒 | 7.9M | 重渲 96 张 |
| 逐句上浮渲 PNG | ~1500 | 2.7 分钟 | 120M | **重渲 1500 张** |
| **ASS 文字层** | **0** | **0（只多一次编码）** | **25K 文本** | **重跑一次 ffmpeg** |

这套手艺仓库里早就有 —— 记者读稿线的 PPT 风整条就是 ASS 事件（`src/lib/slides.ts`），
动效参数照搬 `video-pipeline` 那套 fx-kit 移植（上浮位移 24、入场 450ms）。

### 屏上的字 ＝ 字幕的字

断句用 `packLines()`（字幕那套，一条最多 20 字，切在标点上），句内时间按字数比例分 ——
跟 `zhiyu-video.ts` 的 `subtitles()` 同一套算法。**两处各算一套的话，屏上的字和 .srt 会慢慢对不上**，
而那种错要等到有人开着软字幕看才会发现。

段级时间是准的（manifest 给的），句级是内插的，误差累到段末约半秒。
**整句上浮对它不敏感**（提前 0.28 秒浮出来就行）；**逐字打字机对它很敏感**，
一个字错拍就看得出来 —— 要做逐字，得先上波形吸附（`snapToDip`，说书线在用）。

### 题句卡那几段不写

引句和命名卡已经竖排画进背景图了，文字层再横排写一遍就是两层字打架。
所以落在题句卡时间窗里的段落这一层跳过（E02 跳了 7 段）。
**竖排＝古文与机制名，横排＝正文**，这个分工是有意的 —— 也顺带保住了硬规则 2 的命名卡。

### 四个坑

1. **ASS 字体名必须写全 `Noto Serif CJK SC Medium`。** OTF 的 family 名带 weight，
   写成 `Noto Serif CJK SC` 时 libass **静默 fallback 到系统黑体** —— 画面上有字，
   但不是这个频道的字，而且不报任何错。
   顺带：`--burn-sub` 那条路写的是 `FontName=Noto Serif SC` 且没给 fontsdir，
   **大概率一直在用系统字体**。那个 flag 平时不用，所以没人发现。
2. **filtergraph 里 Windows 盘符的冒号会把滤镜串解析炸掉。** 跟字幕那条同一个解法：
   cwd 切到片子目录，只传相对路径。
3. **ASS 颜色是 `&HBBGGRR`**，不是 RGB。写反了不报错，只是颜色不对。
4. **时间轴要加片头封面那几秒。** `文字.ass` 里写着 `; cover-sec: N`，
   跟出片时的 `--cover-sec` 对不上直接报错 —— 偏了的片子看起来完全正常。

### 字直接落在景上，不垫底板

第一版在字底下铺了一张纸色的半透明纸条（题句卡那个做法，约九成三不透明）。
它确实挡住了木格条和车厢的扶手，**但一段字对应一个矩形，看着就是一个贴上去的色块** ——
而且纸条是固定宽度的，短句一来右边空掉一大半，那块空白比格条更显眼。

**题句卡能用纸条，是因为它只占几秒、一期两三张**，那几秒本来就是要「停一下」。
正文这一层是全程在的，全程挂一个方块，等于给画面加了一件常驻家具。

现在改成**给字本身描一圈纸色的柔光**（`OUTLINE` 3 ＋ `\blur` 2.4，颜色取和纸底同色）：
挡格条是它原本的活，但作用范围只有一个字那么大，没有边界，也就没有「块」。
两个数一起调 —— 描边小于 2 挡不住格条，大于 4 笔画之间的白开始糊成一片；
`\blur` 给 0 就是硬白边，看着像给字幕加了描边，糊开才像纸在字后面透出来。
用纯白也不行，在这张低对比的图上会跳出来。


### 长段会被报出来

`xinli-text.ts` 对超过 6 行的段落报警（只报不拦）。E02 代价段有一个 121 字的长段，
屏上是 8 行一堵墙，**按它的提示在稿子里拆成了三段** —— 拆完最长 5 行，
顺带把「想了很久」那处的犹豫拆出了两个停顿，念起来更像真在想。
**要改就改稿子，别在这儿调字号** —— 字号是给全篇定的。
