## 一、它跟前两条差在哪

| | 单点式 | 累积式 | **长片** |
|---|---|---|---|
| 时长 | 25–31 秒 | 35–45 秒 | **5 分 48 秒**（001 实测） |
| 结构 | 铺垫—转折—落点 | 立—拆—错位—沉底 | **事件推进 ＋ 一次说破** |
| 老马 | 不说破 | 不说破 | **说破一次，然后收回来** |
| 音色 | 一个 | 一个 | **两个**（老马 ＋ 老牛） |
| 平台 | 竖屏短视频 | 竖屏短视频 | **YouTube / B 站横屏** |
| 收尾卡 | 必出 | 不出 | 不出 |
| 体检 | 走 `laoma-check` | 走 `laoma-check` | **走 `laoma:long-check`**（另一支，见 §四） |

**这是另一条产品线，不是现有节奏的延长。** 发布策略、封面、合集都要另算。

## 二、仓库这边支持了什么

`format: "long"` 一个字段分流，缺省不写的一切照旧：

| 做了什么 | 在哪 |
|---|---|
| 体裁分流 | `types.ts` 的 `JokeCfg.format = 'long'` |
| **节奏档 `longform`** | `pace.ts`：句间 0.6（0.2+0.4）、换镜 1.2。落在 `bedtime` 0.90 和 `standup-fast` 0.40 中间 |
| **句子级音染 `line.tone`** | `types.ts` ＋ `tts.ts`：叠在角色音色的 `tone` **后面**，不是替换 |
| **老牛音色** | `cast.ts` 的 `老牛`：云健压到 0.80/0.80、−15% |
| 成品单独一枝 | `preview.ts`：`projects/老马/长片/<id>/`，**不进段子那棵排期树** |
| 进汇总页，但**一张场景图都不渲** | `preview.ts` 的 `longSection()` —— 见下 |
| 稿子 → json | `tools/long-parse.mts` |

### 稿子是源，json 是产物

npm run voice          -- jokes/laoma-long-001.json
npm run audio          -- jokes/laoma-long-001.json   # → <id>-试听.wav ＋ <id>-试听.srt

### ⚠ 稿源救回来了（2026-08-26）

**出事经过**：抬头本来写着「稿件在素材包 `E:\ryu\laoma\长片001_定稿v3.md`，
以它为准」。**那个目录现在只剩一张 png。** 那份 md 从来没进过 git。

于是这条线同时处在两个危险里：

1. `long-parse` 是**覆盖写**。源没了还照着文档跑一次 —— **001 当场清零**
2. 文档说「稿子是源，json 是产物」，**可当时唯一的真相是那份产物**

**做法：写一个逆运算，把稿子从 json 里反出来，并且让稿源从此进仓库。**

```bash
npm run laoma:long-unparse -- jokes/laoma-long-001.json "horse/长片/稿件/laoma-long-001.md"
```

⚠ **判据是往返一致**：反出来的 md 再喂给 `long-parse`，除了 `dur`/`audio`
（那两个是 `align` 回填的，不从稿子来），**其余字段必须逐字节一致**；
不一致就不写盘。跟改渲染器之后 `md5sum -c` 验样张是同一条纪律 ——
**「搬完还一样吗」要能自动答，不能靠看。**

反出来之后真的用它重跑了一遍 `long-parse` ＋ `align`：**片长仍是 348.32 秒**。

⚠ **反出来的时候踩了一个坑**：带说明的静场**不能写成行内**。
`long-parse` 对行内 `⏸` 只取秒数，**`note` 只从单独成行的引用块
（`> ⏸**2.0 — 说明**`）来**，而且落到**上一句**头上。
头一版写成行内，往返回来两句的 `note` 全丢了 —— **而且不报错**，
因为秒数是对的，只是那句「为什么停这么久」没了。

### 字幕：`audio` 顺手出一份 `.srt`（2026-08-26 立）

**出音的同时就出字幕**，不用等出片。

⚠ **为什么挂在 `audio` 而不是 `build`**：字幕的时刻**全部来自配音的真实时长**
（`align` 回填的 `dur`），跟画面一点关系都没有 —— 出完音就已经算得出来了。
挂在出片那头的话，**只想听一遍的时候拿不到字幕**，而审稿常常只到试听为止。

⚠ **屏上的字和 `.srt` 是同一个来源**：`src/long-caption.ts`。
引号扶正／去句末标点／按标点断行／旁白摊小句，四条规则都在那儿，
出帧脚本（`tools/long-frames.mts`）也 import 它。
**各算一套的话两边会慢慢对不上，而且不报错** —— 只有把片子和字幕摆在一起看的人才发现。

⚠ **不要拿 `shuoshu-srt.ts` 的 `toSrt()` 出长片的 srt。** 那个函数里裹着
`tidyCaption()`，规则是「去尾标点 ＋ **句中句号换逗号**」——
那是短片／说书那条线的频道规范，**长片明文不照搬**（见 §四之三）。
套上去不报错，只是一整篇的句号被悄悄换成逗号。长片这边只借它的 `stamp()`。

**时间轴对得上成片**：`试听.wav`、`out.mp4`、这份 `.srt` 都从 0 起、没有前置偏移
（长片不像竖版那样在片头压一帧封面），所以**这一份可以直接当软字幕传上去**，
不用平移。⚠ 哪天真把封面压成第一帧了，**这条就不成立**，得跟着 `shiftSrt()` 平移。

001 实测 **112 条**（旁白按小句拆开、台词整句一条）。

⚠ **改稿改 .md 重跑脚本，别手改 json** —— 改了下次重跑就没了，而「下次重跑」总会发生。

⚠ **`long-parse` 是覆盖写，它会冲掉 `align` 回填的 `dur` 和 `audio`。**
那两个字段不是从稿子来的，是配音出完之后量出来的。所以**只改了标记、配音一个字没变**的时候，
也得把 align 补跑一遍（它认缓存里的 wav，几秒钟）：

```bash
npx tsx tools/long-parse.mts "horse/长片/稿件/laoma-long-001.md" jokes/laoma-long-001.json
npm run align -- jokes/laoma-long-001.json      # ← 这一步别省
```

没有 `dur`，出帧的时间轴就退回 `estimateDur` 的估算值 —— **它不报错，帧照出，只是嘴和声音差着**。
脚本现在会在冲掉的时候提醒一句，但提醒印在几十行统计中间，别指望它拦得住人。

配音稿把两件事标死了，**脚本一条规则都不发明**：

```
【马】/【牛】/【马·台】/【马·破】/【牛·回忆】   谁在说、哪一层（`破` ＝ 说破段）
## 一、早上                            章：换场景、换环境音都按它切
⏸0.5                                  这一句之后静音几秒（也可以单独成行）
```

⚠ **一段一句，别按句号拆。** 稿子把几句排成一段，是因为它们要一口气读下去
（旁白句长、台词句短，长短对比本身就是两个人的区分）；拆开等于在每个句号后面
塞进 0.6 秒，那不是稿子的意思。

### 三层音质（方案 §〇）

**说话人靠音色分，时态靠音质分，两件事分开解决，不互相挤。**

| 层 | 处理 | 现在上了吗 |
|---|---|---|
| 旁白 | 全干、全频 | — |
| 现场台词 | `aecho=0.85:0.35:18:0.06` | **没上**（稿子自己说的：先只做停顿和句长听一遍，**别一次上三层**） |
| 回忆段 | `lowpass=f=6500,volume=-1.5dB,aecho=0.9:0.25:28:0.05` | 上了，**两个音色都加** |

要上现场那一层，把 `tools/long-parse.mts` 里 `LAYER.台词` 指到 `LIVE_ROOM` 就行。

## 三、⚠ 三件跟方案不一致的，别照方案改回去

**一、老马不是晓晓。** 配音方案抬头写的是 `zh-CN-XiaoxiaoNeural`，那是把别的线的女声
当成了老马 —— **这条线的老马从 001 起就是云希 1.20/1.20**（`cast.ts`），
前面 18 条短片全是它，换了就是两个人。用户 2026-08-25 定：**老马坚持他原本的声色。**

**二、`mstts:express-as` 做不到。** 方案给老牛的是
`style="narration-relaxed" styledegree="0.5"`，而这条链走 `msedge-tts` 的
`toStream(text, {rate, pitch})`，**只接 rate 和 pitch 两个参数**，进不去 express-as；
Edge 那个免费端点对 SSML 一向挑（`<break>` 就是一律被拒的）。
所以**压解说腔只能靠语速 ＋ 变声 ＋ 音染**。先听「那你现在知道了」那一句 ——
带出解说腔的话，下一步是再降 rate，不是加 style。

**三、环境音这一层在管线外面。** `mixdown()`（`audio` 和 `build` 共用的那一步）
只认人声、`sfx.ts` 那几个合成音效、BGM —— **它没有「分场景的床音」这回事**
（`cfg.ambience` 是写死的草声＋蝉鸣两条）。

所以走 `tools/long-ambience.mts`，mixdown 之后用 ffmpeg 叠：

```bash
npx tsx tools/long-ambience.mts jokes/laoma-long-001.json \
  <干版>.wav <带环境音>.wav
```

⚠ **`npm run build` 出的成片里没有这一层。** 真出片的时候要么把它接进 mixdown，
要么在最后 mux 之前跑一遍这个脚本 —— **别以为出片时会自动带上。**

素材在**仓库根**的 `voice/*.mp3`（不是 `joke-video/voice/`，那是 TTS 分句），不进 git。
章 → 素材的对照表在脚本顶部，跟 §二 的六个场景对齐；
稿子 §五 那条「切窗外空镜、环境音换成车流」是一条**插入段**，按那句话的字面定位。

### ⚠ 这一层踩过的两个坑

**一、素材彼此差二十多 dB**（风声 −21.7 ／ 街道 −26.6 ／ 办公室 −42.3 ／ 键盘 −44.0）。
表里给的是**目标电平**，脚本自己量素材、算增益 —— **换素材不用重调表**。
用固定偏移的话，同一个 `-26dB` 铺出来街道能听见、办公室是死的。

**二、`办公室.mp3` 10.08 秒，内容到 8.4 秒就没了，尾巴 1.7 秒是静音。**
直接循环，每转一圈断 1.7 秒，听感是「房间的声音一会儿有一会儿没」。
**全片均值看不出来**（均值几乎不动），只有在句间静默处逐点量才露出来。
现在每个素材先掐掉首尾静音、两头补 10ms 淡入淡出再循环。

床音落在 **−43 ～ −50 dBFS**（人声 −22），听得出屋里有东西，一句话进来就退到背后。

### 汇总页上的长片（2026-08-26）

`projects/老马/index.html` 里长片有自己的区块（`preview.ts` 的 `longSection()`），
左边目录、体裁筛选条也都多了一档「长片」。

⚠ **它跟段子那种区块不共用一份代码，粒度也不一样。**
段子那份的骨架是「一句一张场景图」—— 八句、八张，扫一眼就是分镜表；
长片 82 句、分镜表上只有 16 镜，**逐句出图既没有意义、又是 82 次渲染**。
（这正是长片原先干脆不进汇总页的理由；理由没变，变的是结论 ——
不进页的代价是**片子出了却在页面上一个字都看不到**。）

所以换一层粒度，**一张图都不渲**：

| 给什么 | 从哪来 |
|---|---|
| 成片（横屏，`.joke.long` 单独一套宽度） | `out.mp4` |
| 标题 / 关键词 | `发布文案.md`，`readPublishInfo()` 抠的，**不做第二份** |
| 试听音轨 | 目录里带「试听」的 mp3 |
| **章表**：每章起于第几秒、几句、头一句 | 时间轴现算（`_sections` ＋ `buildTimeline`） |
| 三层各多少句 | `_layer` |
| 发布文案全文 | `发布文案.md` |

⚠ **章表的时刻一律向下取整** —— 它跟发布文案里那张章节表是同一个东西，
而**章节标记只能早不能晚**：进位之后跳过去，那一章的头一个字已经过去了。

⚠ **不在页面上列「哪一章用哪个场景」。** 那张表在 `tools/long-frames.mts` 里，
抄一份到预览页就是第二个真相 —— 两处一旦对不上，**错的那份看起来更权威**（它带图）。

「三层各多少句」那一栏不是装饰：老牛那 14 句一度全被标成旁白，
画面上看不出来、现场混响一接上就漏（见 [长片_稿件规范.md](长片_稿件规范.md) §八）。
现在老牛只要有一句标成旁白，那一栏旁边就出红字。

## 四、⚠ 这条线的闸（2026-08-26 立）

**以前一个闸都没有。** `laoma-check` **不查长片**（`cli.ts` 的 `laomaOk` 按
`format === 'long'` 跳过），它查的全是短片的东西 —— 落点、铺垫几句、物件、
日子牌、片长 18–45 秒；拿去判一条五分钟的稿子，**报出来的每一条都是错的**，
而天天报错的闸门只会教人加 `--anyway`（那样连另外两条有用的闸也一起失效）。

**所以另写了一支：**

```bash
npm run laoma:long-check -- jokes/laoma-long-001.json
```

它只查 [`长片_稿件规范.md`](长片_稿件规范.md) §九 那张表里**可判定的部分** ——
那张表现在每一条后面都标了「🤖 机器查」还是「👤 只有人能查」。

| 现在机器守得住 | 只有人能查 |
|---|---|
| 说破段（只一次／后有回收／句间停顿） | 对方有没有给安慰 |
| 书面概念词（看破／执念／意义／本质／状态／机制） | 有没有贯穿全片的物件 |
| 结尾不总结不升华（只查最后一章） | 结尾有没有回到开篇那个东西 |
| 判断句式的自我定义（半查） | 配角有没有一处不完美 |
| 静场 ≤1.5 秒（换章／有说明的豁免） | 说破段是不是整齐排比 |
| 台词 ≤10 字（**按小句，说破豁免**） | 每句台词接不接得住上一句 |
| 旁白无语气词（**引号内排除**） | 比喻之后有没有跟人话 |
| 老牛没有一句是旁白 | **平读测试** |
| `dur` 回填了没有 · 片长估算 | |

⚠ **写这支闸的时候，规范被改准了四处** —— 见
[`长片_稿件规范.md`](长片_稿件规范.md) §七 和 §九 末尾。最值得记的那一处：

> **「说破段句间 1.0 秒，一秒都不能压」跟已出片的 001 对不上**（八句里六句低于 1.0）。
> 用户 2026-08-26 听完定：**「001 的音频还可以，可能因为有场景音，没听出静场。」**
>
> 于是那条规矩的**前提**被找出来了 —— 它是在「声音是干的」那个假设下写的。
> 现在分两档：**干声 1.0 秒 ／ 有环境床音 0.5 秒**。

⚠ **但这一档有个能把它作废的陷阱，跟 §三 那条是同一个**：
**`npm run build` 出的成片里没有床音。** 环境音是 `long-ambience.mts` 在 mixdown
**之后**外挂的，`cfg.ambience` 在 json 里是 `'none'` ——
**体检看不出床音铺没铺**，所以那一条留作 `warn`，由人回答「这一版铺了吗」。

**001 就按现在这样定稿，不回改。**

## 四之二、画面：素材包那套渲染器接进来了（2026-08-25）

方案 §一 那套（`longform.js` ＋ `animatic.js`）现在在 `horse/长片/`：

| | |
|---|---|
| `longform.cjs` | 六个场景 / 两个 rig / 字幕 / 鱼缸 / 口型。**画法一个像素没动**，只改了四处接线 |
| `tools/long-frames.mts` | 出帧 ＋ 合成。**替掉了 `animatic.js`** |

```bash
node horse/长片/longform.cjs        # 六张场景样张 → out/长片样张/
npx tsx tools/long-frames.mts jokes/laoma-long-001.json <音轨>.wav <输出>.mp4
```

**接线改了四处，别的没动：**

1. **rig 用仓库里现成的**：`horse_only.svg` ＋ `bull-side/bull_stand.svg`
   （老牛的那份结构跟老马对等，五个口型齐全，见 `bull-side/BULL_HANDOFF.md`）。
   **不复制副本** —— 一份东西一个家。
2. ⚠ **字体跟方案给的不是同一批**：方案要思源黑 Black 当旁白，这台机器上没有，
   换成**微软雅黑 Bold**；台词那支站酷快乐体、备用的得意黑用仓库 `fonts/` 里的。
   **字族名要跟着改** —— resvg 按 family 名匹配，喂了雅黑却仍写 `Noto Sans CJK SC`
   **不报错，只是字全找不到**，帧上是空的。
3. **`.js` → `.cjs`**：`joke-video/package.json` 是 `"type": "module"`，
   原文件是 CommonJS，不改后缀 `require` 直接报错。
   顺带把样张那一段包进 `if (require.main === module)` —— 不然每次 require 它拿
   `frame()` 都会顺手重渲七张样张。
4. **`frame()` 多认三个参数**（2026-08-26，给封面用）：`maX` 老马站哪儿、
   `maH` 多高（**脚底永远落在地面线 y=566**，改高度是从头顶往上长）、
   `overlay` 最后叠一层 svg。出帧脚本一个都不传，**帧跟以前逐字节一样**。
   封面为什么走这个函数而不是另画一张：**片子里是什么样，封面就该是什么样** ——
   场景、鱼缸、灯光、色温差全是这儿定的，抄一份到封面脚本里就是第二个真相。

### seq 不再手写

素材包那份 `animatic.js` 手写了一个 `seq`，只覆盖 §六 傍晚一章、时长是估的。
方案 §六之四 自己写着下一步：**「用每句音频的实际时长替换 seq 里的估算值 ——
动态分镜就变成成片的时间轴。」** `long-frames.mts` 就是那一步：
谁在说、说什么、说多久、停多久，**全部从对齐过的稿件来**。

- **章 → 场景**按 §二 那张表；**八、晚上 `two:false`** —— 老牛已经走了，
  那一章画面上只剩老马和窗台上的鱼缸，**这是全片最后一个视觉事实**
- **嘴只在发声那一段动**（段的 end 含 padAfter，停顿里合嘴）
- **左上角一块场景标牌**（工位 · 清晨 ／ 楼道 ／ 饭桌 …）：底部中间是旁白、
  头顶那一带是台词，左上是全片唯一一直空着的地方

### ⚠ 头一版渲出来的四个 bug（都记下来，别再犯）

**一、每说完一句闪一下夜景，第 0 帧也是夜景。**
句与句之间那 0.2 秒（`padBefore`）**不落在任何一段里**，而我那句 `find` 找不到就
回退到了「最后一章」—— 也就是 `office_night`。现在空隙里**沿用上一帧的场景**，
开头沿用第一章。**场景是连续的，人不会因为停了半秒就换个屋子。**

**二、「老牛在这儿待了六年」被摆到了头顶当台词。**
稿子里明明标着 `【马】`（旁白）和 `【马·台】`（台词），而解析器**没把这个标记写进 json**，
出帧脚本只好按句长猜（≤12 字算台词）—— 那句 11 个字。
现在 `_layer` 一路传下去。**稿子里标死的东西，别在中途丢掉。**

**三、旁白显示标点。** 现在只去**句末**的，**句中的照留**（见 §四之三 字幕那一节）。
⚠ 中间还改错过一次：把逗号也换成了全角空格 —— 那是短片那条线的规矩，**长片不照搬**。
⚠ **改错过第二次**（2026-08-26 修）：逗号改对了，却顺手把**引号整个删掉**了，
理由写的是「屏上那对符号比它标出来的东西还显眼」—— 可引号是**句中标点**，规范说照留。
删掉的代价：「他没说"你别这么想"，也没说"其实你挺好的"」变成
「他没说你别这么想，也没说其实你挺好的」，引的话和说的话糊成一句。
现在是**照留，但扶正成「」**：稿子里写的是半角直引号 `"`（开合同形、半个字宽），
中文字幕上是坏字形 —— **稿子要的是「这是引用」，不是这个符号本身。**

**四、长旁白一次铺三行。** 现在**逐句上、从下往上浮**（0.28 秒浮完）：
小句按字数分时长（跟 `partSpans` 一个算法），念到哪句就上哪句。
顺带把 `narr()` 改成**整块往上顶**，最后一行永远落在 H−96 ——
原来是第一行钉死往下长，三行的第三行会掉出画外。

出帧约 110 ms 一帧，5 分 48 秒的片子 4180 帧、**渲十分钟上下**。

两处特殊机制：

### 鱼缸：全片的 object

`fishtank(x, y, scale, fishPos, dark)`

- 鱼是实体填充 `#D94F2B`，**全片唯一的高饱和色** —— 其余全在赭橙到褐灰的低饱和区间，
  所以视线自动落在它身上，**不需要加光效**
- 气泡五串共 25 颗，大小/速度/间距按固定种子（`90731`）随机；越升越大、近水面淡出
- 场景里**不写死** `fishPos`，由全局 `FISH` 接管；`TIME` 驱动气泡

**红点的移动轨迹就是故事线**：S1 老牛桌上（远、小）→ S5 交接（中）→ S6 老马窗台（大）。

### 字幕

| | 旁白 | 台词 |
|---|---|---|
| 字体 | 无衬线 Black（⚠ 见 §三之二） | 站酷快乐体 |
| 字号 | 40 | 50 |
| 颜色 | 白（深底转米白） | **角色本体色**：老马 `#C2793C` ／ 老牛 `#5A4A40` |
| 描边 | 深墨 8px | **场景底色 10px** |
| 位置 | 底部居中，**逐句上浮** | 说话人头顶上方，往上长 |

三条自动规则在代码里，不用手配：**描边取当前场景底色**（浅底柔光、深底暗描边）／
**字色按底色保证对比度**（WCAG ≥3.2 的 `ensure()`，夜景里老牛自动提亮到 `#948983`）／
**断行优先在标点后**。台词宽度上限 15 字/行，无气泡装饰。

⚠ **「断行优先在标点后」那一条，旁白一直没照做**（2026-08-26 修）。
台词那支（`longform.cjs` 的 `wrap()`）从头就是按标点断的，旁白那支
（`long-frames.mts` 的 `wrapOne()`）是**字数对半砍** —— 两条字幕线各断各的，
而只有一条合规。对半砍会劈开词：「他把这鱼养四年，也没指望这鱼能怎么样」
砍在「指」和「望」中间。现在从正中往两边找最近的标点，落在 [30%, 85%] 里才算数
（太靠边的标点断出来一长一短，比劈词还难看），找不到才退回对半砍。
**18 字那条上限是软的**：按标点断出来的两行可能是 11/19，19 字 × 40px ＝ 760px，
在 1280 的画布上宽度仍旧宽裕 —— **宁可行长不齐，也不要把词劈开。**

⚠ **旁白只去句末标点，句中的照留**（2026-08-25 用户定）。
短片那条线的规矩是「结尾不留标点 ＋ 句中句号换逗号」，**长片不照搬** ——
长句里逗号是断句的手，去掉之后一整行读起来是平的。

### 场景标牌（2026-08-25 加）

左上角挂一块木牌，写这一场是哪儿（工位 · 清晨／楼道／饭桌…）。
**照单点式那块牌匾的样子做**（`horse/plaque.mjs` 的 `style:"wood"`）：
两根挂绳从顶角斜上去、木色底、上下两道横木、墨色描边。

⚠ **不搬 `rough.mjs` 的手绘抖动** —— 长片这套画面是干净的细线，
抖出来的边在这儿是另一种笔触，两种线放一起就花了。**借的是样式，不是笔法。**

放左上角是因为：底部中间是旁白、头顶那一带是台词，**左上是全片唯一一直空着的地方**。

「照单点式那块牌匾的样子做」写在这儿，可实现的时候有四处没跟上 ——
**都不报错，渲出来还挺好看，只是不是那块牌子。**

| | 错在哪 | 现在 |

现在写进来了。

**还多修了一处，是这次才看见的**：夜景里整根挂绳看不见 ——
墨色 `#3B322B` 压在夜底 `#322E29` 上对比度只有 1.05，剩一块木牌浮在半空。

那儿一直是浅的。这不是新规矩，就是上面 §字幕 那三条自动规则里的

## 七、发布文案

落在成品目录里：`projects/老马/长片/<id>/发布文案.md`。
**是复制源，不是分析报告** —— 每个代码块整块粘到平台输入框，中间不用挑
（跟短片那条线同一个约定，见 `yiye-publish.ts` 顶上那段）。

⚠ **长片这一份手写。** `yiye-publish.ts` 是按短片的字段做的
（收尾卡、日子牌、逐句稿），长片那几样都没有。**改稿之后要手动跟一遍。**

### 六块内容

| 块 | 怎么写 |
|---|---|
| **标题** | **一个具体的事实，不剧透说破段。** 001 用「他在这儿待了六年，走那天留下一条鱼」—— 有人、有年头、有物件。备选留两条，换平台或数据不好时替 |
| **简介** | 头两三句就是稿子开头那几件事，**第一句要能单独立住**（列表页只显示一行）。末尾接「关于老马」那一小段，跟短片共用 |
| **章节** | ⚠ **长片独有**：`0:00 早上 / 0:29 老牛是谁 / …`，从 `_sections` ＋ 时间轴直接抠。YouTube 描述贴这一段就有章节条，B 站分 P 点也用它。**五分钟以上的片子，这一栏是留存率的实事** |
| **关键词** | **每个词自带 `#`**（见下）。前五个是内容本身（离职／同事／交接／六年／鱼缸），后面几个是观众会搜的（职场／打工人／原创动画）。B 站 TAG 另列一行，**第一个进推荐权重最高** |
| **置顶评论** | 老马的语气：**不解释视频、不共情、不谢观看**（BASE §五之三 那四条，长片照用）。001 是「那条鱼还活着。」—— 补一个后续事实，一句话 |
| **中心思想** | **给写稿的人回头核的，不进简介。** 长片的支点是说破那一次，简介里提前说出来，等于把观众来听的那一下先讲了 |

### 关键词用 `#` 分开（2026-08-26 立）

```
#离职 #同事 #交接 #六年 #鱼缸 #职场 #打工人 #中年 #原创动画 #老马
```

**理由是「复制源」那条约定本身**：这份文案的每个代码块都要能**整块粘进平台输入框、
中间不用挑**。空格分开的一串词粘过去还得人工逐个补井号 —— **既慢又会漏**，
而漏掉的那几个不报错，只是那期少了几个话题。

⚠ **这条规矩短片那条线早就有了，是长片没跟上。** `yiye-publish.ts` 的 `hashify()`
把方案里三个字段（各写各的分隔符）统一转成 `#词 #词` 并去重，注释里写着同一个理由。
**长片这份是手写的，所以规矩得靠人记着** —— 这正是 §七 抬头那条
「⚠ 长片这一份手写，改稿之后要手动跟一遍」说的情况，这次就是它漏的。

⚠ **B 站 TAG 框和 YouTube 的 tags 字段不吃 `#`**，所以同一批词还要一份不带井号的，
列在「标签」那一节。**词是同一批，只是渲两次** —— 别当成两组词各自维护，
维护两份的结果是过两个月它们就不一样了。

### 三条硬规矩

**一、标题里不许出现说破段的字眼。** 「没敢试」「看得开」这类词一进标题，
观众带着答案来看，那七句就白排了。

**二、简介不总结、不升华、不许诺。** 跟稿件规范 §五 同一条 ——
「从那以后我明白了」这种话，稿子里不许有，简介里也不许有。

**三、封面不剧透。** 001 建议的三帧（楼下傍晚一箱一缸／工位夜那盏灯和鱼缸／
清晨老牛在收东西）都停在事件里，没有一帧碰说破段。**这一条现在有代码在守**，见下。
