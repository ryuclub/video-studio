## 一、跟说书线的关系

**能整套搬过来的**（这条线最大的省事之处）：

| 能力 | 在哪 | 为什么能直接用 |
|---|---|---|
| 单人旁白的稿件结构 | `script.json`：`no / act / text / who / beat` | 说书本来就是一个说书人讲到底，治愈线只是**角色数退化到 1**，结构完全一样 |
| **房间底噪**（−62dBFS 粉噪） | `shuoshu-build.ts` 的 `pinkNoise` | 见下，这是治愈线的**前提条件**，不是可选项 |
| 实测式响度归一 | `shuoshu-build.ts` 的 `loudnorm(src,dst,target,ceiling)` | target 是参数，传 −21 就是治愈档。它不用 ffmpeg 的 loudnorm 滤镜（说书线试过，`linear=true` 在这种素材上不行） |
| **静态图 + ffmpeg concat 出片** | `shuoshu-video.ts` | 助眠档**必须**走这条。逐帧管线（joke-video）渲 21 分钟 = 3.8 万帧，按实测 60ms/帧要 38 分钟，而且没有意义——治愈线的画面本来就是静止的。拆成两期也不改这个结论 |
| SRT / 封面 / 发布文案 / 出片总装 | `shuoshu-srt.ts` `shuoshu-cover.ts` `shuoshu-ship.ts` | 换套模板即可 |

**必须另做的**：

| 要做 | 为什么不能共用 |
|---|---|
| **节拍表数值** | 说书的停顿被压到 ≤1.0s（频道规范「停顿不要太久」）。治愈档比它松，但**没有稿件写的那么松**（见下），`BEATS` 仍要新建一张 |
| **画面模块** | 说书是水墨（`style/inkwash.ts`），治愈是清新画风：米白和纸底、浅色木格窗框、左侧竖排标题、右侧竖排章节名、左下朱砂印、底部细进度线。这是新的一套 scene，不是改 inkwash |
| **主讲音色** | 聊斋那套多角色音色派生全部作废。见下 |

### 停顿：底噪解决的是「像不像卡带」，不是「该多长」

选题稿件给治愈档写的是段间 2.5–3.5 秒、硬切 4 秒，理由是：
**TTS 插的空白是绝对静音**（实测 −227dB），现实里不存在这种东西，
没有底噪时停顿越长越像「卡带」不像「酝酿」；说书线当年正是因此
把停顿从 1.2–2.2s 压到 1.0s 以内。而说书线后来补上了这一层
（全片垫 −62dBFS 粉噪），停顿里有了「房间」，所以治愈线可以停得更长。

**底噪这一层确实成立** —— 《方丈记》v1 试听的干声在停顿处实测 −61.5dB，
是房间声不是死寂。**但长停顿仍然被否了。**

| 试听 | 段间 / ⏸ | 反馈 |
|---|---|---|
| v1 | 1.25s / **3.0s** | ⏸ 处停得太久 |
| v2 | **0.6s** / 1.6s | 太紧（收过头 —— 挨批的只有 ⏸ 那一级） |
| **v3** | **1.25s / 1.6s** | **✅ 定稿** |

**结论：底噪解决的是停顿的「质地」，不是「长度」。** 两条线在长度上撞了同一堵墙。
稿件里那组 2.5–3.5s / 4.0s 的数字站不住。过程见
`../projects/治愈/2026-08-19_hojoki/listen/说明.md`，定稿值住在
`joke-video/src/zhiyu-beat.ts`（**全线唯一出处**，别在别处再抄一份常量）。

底噪本身照旧留着 —— 停顿短了它依然有用，只是作用从「撑住长停顿」
退回成「别让静音显得断电」。谁要把底噪关了，短停顿一样会露馅。

## 二、主讲音色（已定稿）

```
cast「夜读」　zh-CN-XiaoxiaoNeural
pitch 0.83 / formant 0.83 / tempo 1.0　朗读速度不动（无 rate）
段间停顿 1.25s / ⏸ 处 1.6s（见第一节）　房间底噪 −62dBFS 粉噪
后期：highshelf 8kHz −3dB → 窄压缩 2:1 (30ms/200ms) → 响度 −21 LUFS
实测：基频 202Hz　含停顿均速 226 字/分（拿幕一整幕测的）
```

**全季只用这一条音色 —— 2026-08-20 明确定下，不再考虑第二条女主讲。**
期与期的差别写在各期稿件配置里（主要是停顿），不要为单期新开音色；
调试用的临时变体听完就从 `cast.ts` 删掉。

**换书也不换音色。** 《枕草子》的叙述者是女的（清少纳言），《方丈记》是男的（鸭长明），
播出来都是同一个人在念 —— 稿子里用「她说」/「他说」区分，那是文本的事，不是音色的事。
听众认的是这个声音，一本一个声音等于没有频道。

### 定下来之前排除掉的，别再走一遍

| 试过 | 结果 |
|---|---|
| 小艺 / 晓萱（公开列表外，能合成） | 都比小晓更高更亮，不是成熟女声。晓萱另有随时被撤的风险 |
| 只压 pitch 不压 formant（0.78/0.83） | "年轻姑娘捏着嗓子往低了说"，不是阿姨 |
| formant 压到 0.79 | 同样 202Hz、数字上更厚，但**听感带回响** —— rubberband 拉狠了。**0.83 是底** |
| pitch 压到 0.7834（190Hz） | 偏沉、闷 |
| `rate −38%` | 每个字都被拉长，六条候选一起不正常。那个数是把稿件的「190 字/分」当成**说话速度**算的，而它是**整期含停顿的均速** |
| `aecho=...:12:` | 12ms 是梳状滤波不是房间反射（joke-video 的艳鬼预设用 22ms 做"一个人说话带出两个"）。已去掉 |

### 一条没解决的

**半音标准差 4.2，目标 1.5–2.5。** 这是 Edge 中文女声的韵律本底，
逐句测和整段测一致，压音高压不动（压了 3.2 个半音只从 4.47 到 4.25）。
唯一干净的解法是接 `mstts:express-as` 的 style（`calm`/`gentle`/`narration-relaxed`）
和 `styledegree`，但管线现在没这个接口。听感上不碍事就先不动。

### 字数配额（用实测语速反推，稿件要求的第 3 步）

单期 **20 分钟上下**，超了就分期（见下）。按《方丈记》整幕实测 **226 字/分**
（拿幕一整幕测的，不是样章外推）：

| 单期片长 | 字数 |
|---|---|
| **20 分钟** | **≈ 4500 字** |
| 22 分钟 | ≈ 5000 字 |
| 25 分钟 | ≈ 5700 字 |

比稿件原估（190 字/分）多约两成。

**这张表是用来核片长的，不是用来凑字数的。** 整本的总配额按内容定 ——
《方丈记》四幕写下来是 9049 字，比原先估的 9800 少 750，两期实测 18:53 / 21:22，
就不补。够不够长看时长，不看字数。

### 交付长度：单期 20 分钟上下，长的分期

稿件原来按「45–60 分钟助眠档」整支出，现在改成**每期 20 分钟上下，
超长的分成多期**。《方丈记》9049 字 → 上下两期：上期 18:53，下期 21:22。

**分期不是压稿件，配额也不是。** 总字数按内容需要定，切的是交付单元不是内容 ——
为了凑时长删段落，或者反过来为了填配额注水，都等于把这条线最值钱的东西
（慢、留白、不赶）先毁掉。

切点要落在**内容本来就收口的地方**，不是字数正好的地方，
而且上一期结尾**不做悬念**：这是助眠档，听众多半在上一期就睡着了，
下一期是给醒着听完的人准备的，不是给追更的人准备的。
《方丈记》的切法和理由见 `../projects/治愈/2026-08-19_hojoki/幕表.md`。

顺带：单期短了，但**一景要撑的时间反而长了**（11 分钟 → 21 分钟），
「静止耐受度」这条待验项只会更吃紧。

## 三、《方丈记》这一期的特殊约束

这一期在整份书目里是**画面可承载度最低的一本（★★☆☆☆）**，而且——

> **画面反过来锁死稿件结构，只能倒叙。**

- 前半的大火、旋风、迁都、饥荒、地震**一格都画不了**（这套画风不画人、不画事件、不画冲突），
  而且深夜档讲灾异会压人
- 所以结构是：**先讲小屋里的日子 → 中段回溯他为什么搬进来 → 末段回小屋**
- 画面全程锁在草庵一景，用五种镜位里的**「留白」**那一种
- 饱和度规则的**下限锚点**：内容越接近无常、越接近减法，饱和度越低、主体占比越小。
  这一期是全系列最低的那一档
- 音色**没有为这一期单独放慢**：定稿的「夜读」朗读速度不动，这一期的差别只在停顿（见第一节）

试听稿（`../projects/治愈/2026-08-19_hojoki/试听稿.md`）就是按倒叙写的开头，443 字。
那 443 字已经原样进了幕一，一个字没改 —— 它是听过并通过的调性，
**后面三幕都是照着它的调子写的**。

## 三点五、出片链路（2026-08-20 打通）

```
发布.json ─┬─ zhiyu-cover.ts    → cover/{总,上,下}/
           │                       横版上传 + 微信 1:1 + 片头 1920 版 + 两张自检
           │
幕*.md ────┴─ zhiyu-episode.ts  → 成片/{上,下}/{上,下}篇.wav + manifest.json
                    │              （两幕拼一期，幕间垫「幕末」，全期一条连续音乐床）
                    ├─ zhiyu-scene.ts → 成片/{上,下}/scenes/*.png
                    │                    一景不换，只有进度线在走
                    ├─ zhiyu-video.ts → 成片/{上,下}/*.mp4 + *.srt
                    └─ zhiyu-publish.ts → 发布文案.md（复制源，章节时间戳自动算）
```

音频公用件在 `zhiyu-audio.ts`（底噪电平、后期链、响度目标、音乐床）——
`zhiyu-listen.ts`（单幕试听）和 `zhiyu-episode.ts`（整期）**共用那一份**。
各抄一份的话试听件和成片会变成两个声音，而这种不一致要等到有人戴耳机对比才发现。

### 床音：`发布.json` 的 `bed` 字段

**两条线共用这一个开关**（心理洞察线也走这条管线，见文末）。

| 值 | 行为 |
|---|---|
| 不写 | `musics/1.wav` —— 一直以来的缺省，已出片四期都是这样 |
| `"空"` | 不垫床 |
| 其它 | `musics/<值>.wav` |

**不垫床 ≠ 静音。** −62dBFS 的粉噪底噪照旧，它跟音乐床是两件事：
底噪管「停顿里有没有房间」，音乐管「整条听下来有没有底」。底噪一关停顿立刻露馅。

#### 选床音先看长度

`master()` 是把**一个**文件反复跟自己做 2 秒交叉淡化、每次翻倍接到够长，
所以短素材会循环很多遍：

| 文件 | 长度 | 20 分钟循环几遍 | 7 分钟循环几遍 |
|---|---|---|---|
| `1.wav` | 10.3s | **117 遍** | 41 遍 |
| `The Enchanted Castle.wav` | 13.0s | 92 遍 | 33 遍 |
| `2.wav` / `Reveille…` / `Moments…` | 35–36s | 34 遍 | 12 遍 |
| `Cody_Martin_Pembrokeshire…` | 57.1s | 21 遍 | 7.5 遍 |
| `LNDO_Glorious_instrumental…` | 75.2s | 16 遍 | 5.7 遍 |

**音量一抬大，循环就更藏不住。** BGM 从 −42 → −40 → −38 一路抬上来之后，
10 秒一轮的重复会开始浮上来 —— 这是选长素材的直接理由，
《方丈记》《枕草子》四期用的都是 `1.wav`，重听的时候留意这一条。

带 `background_vocals` 的素材里有人声，压在旁白底下可能糊；
标 `instrumental` 的那两条没这个问题。

BGM 响度现在是 **−38**，四轮的账写在 `zhiyu-audio.ts` 的 `BGM_LUFS` 注释里。
要再动先读那段，**尤其不要在没听过的情况下往回跳档**。

### 整期不是把两条幕的 wav 接起来

那样会有两处淡入淡出的音乐、两次独立的响度归一、接缝处底噪相位跳变。
整期必须重拼：两幕的段落连成一条 → 幕之间垫「幕末」2.2s → 全期一层底噪
→ 一次后期链 → 一次响度归一 → **一条连续的音乐床**（只在片头淡入、片尾淡出）。

顺带出 `manifest.json`：每一段的 start/end。画面切点和字幕都从它来，
音频重出、时长变了两边自动跟着走，不用重新对时。这是从说书线搬的做法。

### 镜位轮换（《枕草子》逼出来的）

《方丈记》★★☆☆☆ 全程锁「留白」一景。《枕草子》★★★★★，
选题稿件写着「镜位在远景与近景之间轮换」。所以 `zhiyu-scene.ts` 长出了三样：

1. **三种镜位**：留白 / 远景 / 近景。片内这三张跟封面同名的那些**不是一个东西** ——
   片内要无聊（色阶 2–3 层、没有焦点），封面要被点开（4 层以上、日轮压在山脊线上）。
   拿片内那张当封面，缩到 210px 就是一片糊。
2. **切点跟着稿件走**：`发布.json` 的 `scenes` 写「那一段的开头几个字」，
   跟章节同一套定位 —— 改稿重跑，切点自动跟着走。定位不到直接炸。
3. **每个镜位至少撑 `MIN_DWELL`（150 秒）**，排密了报错。
   画面勤换在别的线是丰富，**在这条线是把人吵醒**。《枕草子》第一版排的切点
   有一处只撑 145 秒，就是这道护栏拦下来的。

**换镜位不硬切。** 深夜档里一次硬切就是一次睁眼，所以插 4 秒交叉淡化
（切成 8 张，每张把新旧两景按比例叠一次）。

因此**每张图的时长不再是固定的 `STEP`** —— 淡化那几张只有半秒。
`scenes/scenes.json` 里带每张的时长，`zhiyu-video.ts` 照它拼，
**不再自己按 STEP 推**（按 STEP 推会整条错位，而且照样不报错）。

### 画面为什么是一叠图不是一张

固定构件里有一条**底部细进度线**。静态图出片走 ffmpeg 的 concat，
一张图撑一段时长，所以进度线要动就得切成若干张 —— 每 30 秒一张，
二十分钟约四十张，每张只前进 2.5%，肉眼几乎察觉不到，
但想知道还剩多久时低头就能看见。**这条线是画面上唯一会变的东西。**

### 右边那一栏：章节名

2026-08-21 加的，《枕草子》重出的那一版是第一支带它的片子。
**从这里往后，新片一律带这一栏** —— 它是固定构件，不是某一本的特例。
没有 `chapters` 的期 `zhiyu-scene.ts` **直接出不了图**（老期用 `"免章节": "理由"` 豁免）。

**在这之前，「现在讲到哪儿了」只写在发布页的章节列表里，画面上没有。**
深夜档中途醒一下，抬眼看不出自己在第几节 —— 这一栏补的就是那一眼。

位置在窗框右边的空白带（正中 1778，顶对齐）：**左边书名，右边章节，一重一轻**。
章节是次要信息，所以比书名小一号、淡一档（`inkDim`）——
跟蜗牛同一条道理：**会变的那个不能比不动的东西更抢眼**。

**字号 46px / SemiBold**（2026-08-21 定）。第一版是 34px / Regular-Medium，
反馈是「调大加粗」——「不抢眼」不等于「读不出来」，深夜档抬眼那一下要一眼认出来。
**《枕草子》那两支片子没有回改**，它们是 34px 的那一版；新片按 46px 出。
字号改了 `chapterCol()` 里每列几个字会跟着算（`maxH / size / 1.35`），
**别把它写死** —— 写死的话长名字会去缩字号，正好把「调大」抵消掉。
一栏最多两列（窄栏只有 284px，第三列会压到窗框上）。

四件实现上的事：

1. **数据跟发布页是同一份**：`发布.json` 的 `chapters`，
   定位方式跟 `zhiyu-publish.ts` **一模一样**（那一段的开头几个字，取第一处匹配）。
   两边分叉的话，观众照简介里的时间戳跳过去、画面上写着另一节的名字，
   而这种错没人核得出来是哪边错的。
2. **屏上只取 `｜` 前那半**。后半（「天一点点白起来，山的边缘先亮」）
   是发布页列表里的说明句，挂到屏上就成了第二行字幕。
   要给画面单写一个短名字就加 `"屏": "…"`，发布页那条不动。
3. **换章节不硬切**：先淡出旧的（1.2s），淡完再淡入新的（1.2s），中间空一小下。
   **两条名字不交叠** —— 同一个位置叠在一起是一团糊字，比硬切更糟。
4. **顶对齐，不居中**；多出来的列往左长，第一列的位置钉死。
   居中的话每换一次名字整块字都要挪一挪，而「挪」在这条线上就是一次睁眼。

护栏两条：一个章节至少撑 `MIN_CHAP`（15 秒），屏上名字最多 `CHAP_MAX`（16 字），
破了直接报错。**15 秒这个数是照着现有稿子定的** ——《枕草子》下篇收尾那节 20 秒，
是四期里最短的一条，再往下就只看得见字在动、看不清写的是什么。

代价是**图变多了**：淡入淡出每 0.2 秒一张，《枕草子》上篇从 40 张涨到 260 张
（渲图 112 秒，出片没变）。图是 `.gitignore` 掉的，只吃磁盘。

### 进度线上的蜗牛

2026-08-20 加的。它同时是**标记和装饰**：想知道还剩多久，低头看它爬到哪儿了。
素材是 `zhiyu/pictures/snail.svg`，尺寸和颜色在 `zhiyu-scene.ts` 的
`L.snail.h`（露在线上方多高，34px）和 `C.snail`（#8A9184）。

选蜗牛不是随便挑的：这条线全部参数都在往「慢」上调，而进度线是画面上
**唯一会变的东西**。每 30 秒一张、每张前进 2.5%，本来就慢得看不出在动 ——
放一只蜗牛在上面，那个慢就从缺点变成了这条线在说的话。

三件实现上的事，改的时候别踩回去：

1. **素材里蜗牛头朝左，代码里镜像过来。** 进度往右走，让它背对着走的方向
   看着别扭。镜像只在 `snail()` 里做一次（`scale(-k, k)`），**素材本身不要改** ——
   改了素材，别处再引用就反了。
2. **`var()` 必须在装载时换成真值。** 素材写的是 `var(--mark, #7B8C7E)`，
   而 **resvg 不支持 CSS 自定义属性** —— 直接喂进去那两处颜色会丢，
   渲出来是一只黑蜗牛，**而且不报错**。`loadSnail()` 负责替换。
3. **位置取填充的前沿，不是中心**，身子压在已经走过的那一段上。
   起点处有个夹子（`Math.max`）挡着，防止整只越过轨道左端 ——
   第一张图的 p 已经有 2–3%，但那取决于首段多长，别指望它永远够。

素材缺了**直接炸**，不静默跳过。少一只蜗牛的片子看起来一切正常，
而这条线已经栽过两次「报成功的失败」（见下）。

### 字幕：翻倍了，而且两个数不是一把尺子

`FontSize` 13 → **26**（2026-08-24，三条线一起）。**在成片上量过**：

| | 倍率 | 落到 1080p |
|---|---|---|
| `FontSize=26` | ≈2.6 | 一个汉字宽 **67.5px** |
| `MarginV=34` | ≈3.77 | 字幕占 y **875–938** |

**同一串 `force_style` 里这两个数走的不是同一个缩放**（libass 对 4:3 脚本配 16:9 画面
做了横向补偿，字号额外挨了一次修正）。**别拿一个倍率去推另一个，要哪个量哪个。**

### 字幕：可以烧，命令行说了算

**2026-08-21 改：原来这条线禁止烧字幕，现在不禁了。**

原来的理由是：这是助眠档，片内所有参数都在往「无聊」上调，就是为了不给人睁眼的理由，
而烧进去的字幕每几秒换一次，会成为画面上最活跃的东西。**那个顾虑仍然成立** ——
它只是不再是一条禁令，而是一个要自己权衡的取舍：静音刷到这条片子的人，
没有字就没有任何东西可读。

现在三种出法，**都不覆盖彼此，文件名各不相同**：

| 出法 | 命令 | 屏上有什么 |
|---|---|---|
| 常规版 | `zhiyu-video.ts` | 只有画面。`.srt` 另出，平台软字幕自己开 |
| 烧字幕版 | `… --burn-sub` | 底部一条字幕，每几秒换一次 |
| 文字版 | `… --text-layer` | 正文逐句上浮、段内堆叠（见 [心理洞察出片方案 §七](心理洞察出片方案.md)） |

`.srt` 三种都照出（平台软字幕、检索、听障可访问性都要它）。
**烧字幕版和文字版不要一起开** —— 同一句话会在屏上出现两次，脚本会直接拦下来。

选哪一版还没有数。第一批（《方丈记》《枕草子》《陶庵梦忆》）已经各出了一份文字版，
等看过数据再定主推哪一种。

### 改了什么，要重跑哪一步

| 改动 | 要重跑 | 说明 |
|---|---|---|
| 幕稿 `幕*.md` 的文字 | `episode` → `scene` → `video` | 时长变了，画面张数和字幕都要跟着重算 |
| `zhiyu-beat.ts` 的停顿 | 同上 | 同上 |
| `zhiyu-audio.ts` 的链路 / 响度 | `episode` → `video`，**并重出试听件** | 试听件和成片必须是同一个声音 |
| 只换背景音乐 | `episode` → `video` | TTS 有缓存，重拼很快 |
| `zhiyu-scene.ts` 的画面 | `scene` → `video` | 音频不用重出。**已出片的那期不重出**，见下 |
| `zhiyu/pictures/snail.svg`（换素材） | `scene` → `video` | 同上。**注意素材里的朝向**：代码假设头朝左并镜像 |
| `发布.json` 的 `scenes`（镜位切点） | `scene` → `video` | 切点按段落定位，改稿也要重跑 |
| `发布.json` 的 `chapters`（章节） | `scene` → `video`，**再 `publish`** | 2026-08-21 起章节也上画面，不再只是简介里的一行 |
| `发布.json` 的封面字段 | `cover` → `video` | 片头那一帧变了 |
| `发布.json` 的标题 / 简介 / 关键字 | `publish` | 不影响成片。**别手改 `发布文案.md`**，那是生成物 |

**`scene` 依赖 `episode` 的 manifest**（张数从时长算），`video` 依赖两者。
顺序错了会报错，不会静默出错片。

**画面参数改了，已出片的那期不回改。** 2026-08-20 把片内标题从 54px/Regular 加到
72px/SemiBold，《方丈记》上下两期的 81 张场景图和两个 mp4 **没有重出** ——
那是用户的决定（跟发布文案改版同一条：新片按新的来，出过的不动）。
同一天给进度线加了蜗牛，同样**没有回改** ——《方丈记》两期、《枕草子》两期
一共 4 个成片、160 张场景图都保持原样。
下一期跑 `scene` 时自动就是新参数，不用特意做什么。

**例外：《枕草子》上下两期在 2026-08-21 重出过一版**（右边那一栏章节名）。
那是用户点名要的，不是顺手回改 —— 规矩没变，要回改就明说一次。
重出的只有 `scene` + `video`，音频没动（所以这两期的音乐还是 −40 那一档，
`BGM_LUFS` 抬到 −38 是听完这两期之后的事，要跟上得重跑 `episode`）。

### 两个静默失败的坑，都已经拦住

1. **concat 碰上分辨率不一样的图会静默丢掉。** 片头封面第一版用了上传那张
   （1280×720），接在 1920×1080 的场景图前面 —— ffmpeg 不报错、不警告，
   封面就是没进片子，成片时长照样对得上。是逐帧量亮度才发现前 3 秒画面没变的。
   现在封面另出一张 1920 的片头版，出片前还会校验所有输入尺寸一致。
2. **`ebur128` 的逐帧日志会顶爆 `spawnSync` 默认的 1MB stderr 缓冲**，
   末尾的响度汇总被截掉 → 解析出 NaN → `volume=NaNdB` → 0 字节的 wav，
   而脚本照样打印「done」。按片长触发：短的幕碰不到，长的幕必中。
   现在 maxBuffer 提到 64MB，解析不出直接炸，`ff()` 也查退出码了。

**一个报成功的失败比一个失败糟得多。** 这两条都是这么栽的，
所以现在宁可多几处断言，也不留静默通过的路。

## 三点六、发布文案：写法与备选

各期的 `发布文案.md` 是 `zhiyu-publish.ts` **生成**的，
**那份是复制源，不是分析报告** —— 打开就该整块选中粘到平台输入框里。
所以理由、备选、取舍全放在这一节，那边一个字不留。
改内容改各期的 `发布.json` 再重跑，别手改生成物。

### 标题：先给一句现在的人身上就有的事，再报书名

《方丈记》最容易被讲成「日本古典随笔」——那是介绍，不是共鸣。
真正接得上的是三件八百年没变的事：**房子越换越小、等的位置没轮到自己、
夜里怀疑自己是不是在自欺**。上期取第一件，下期取第三件。

定稿：

```
上　房子越住越小，他反而睡得着了｜《方丈记》上·三米见方｜深夜助眠
下　他问自己是不是在骗自己，没答上来｜《方丈记》下·山中一年｜深夜助眠
```

备选（做 A/B 或换封面时用）：

| | 标题 | 侧重 |
|---|---|---|
| 上·备1 | 他等了半辈子的那个位置，最后没轮到他 | 「没等到」那条线，共鸣更直接，但少了画面 |
| 上·备2 | 一个人住在三米见方的屋子里，是什么感觉 | 独居向。稳，但平 |
| 下·备1 | 山里住久了，鹿会走到门口 | 纯画面向，跟封面副题一致，适合换成安静路线时 |
| 下·备2 | 他说他只求两样：安静，和没有烦心事 | 最像「人生感悟」那一挂，也最容易显得鸡汤 |

**基调：不喊。** 这是深夜助眠档，标题一喊调子就散了，
而且会把片子推给短平快的流量池，完播率反而更差。
不用感叹号、不用问号、不用「震惊」「细思极恐」「真实还原」。
检索词该带的一个不少，但**长在句子里**，不堆在后面。

**不要用的写法**：`【治愈】`、`听完秒睡`、`人生必读`、`看完泪目`。
跟这套米白和纸的封面对不上。

### 关键字的取舍

- **第一个位置留给「方丈记」** —— 唯一没有竞争的精确检索词。
  「助眠 / 睡前故事」是这类内容真实的消费场景，必须带，但别放第一个。
- **「极简生活 / 断舍离 / 独居 / 中年危机」是真正的共鸣入口**，不是硬蹭：
  这本书写的就是一个人把生活一样一样减下来，减到最后发现自己什么也不缺，
  这批词的搜索人群跟内容是真的对得上。
- **「人生感悟」带上，但别写进标题。** 标题里出现这四个字会立刻显得像鸡汤号。
- 英文两个（`minimalism` / `japaneseliterature`）成本为零，中文频道也值得带。
- **不要堆无关热词。** 平台现在对标签堆砌的惩罚比奖励大。

### 章节：按段落定位，不写死时间

`发布.json` 的 `chapters` 里写的是**那一段的开头几个字**，不是时间戳。
生成时去 `manifest.json` 找那一段，取 start 再加片头封面的秒数。

这样改稿之后重跑一次，时间戳自动跟着走。
手写时间戳的那一版里，「章节要加 2 秒片头」是核对清单上的一条人工项 ——
**人工项迟早会漏**。定位不到的章节直接报错，不静默跳过。

片长也是**去量成片**，不是拿音频时长加片头算：concat 会把末张图补齐到整格、
编码又按 25fps 量化，算出来的跟文件差几秒，而这个数是要写给观众看的。

## 正音：多音字读错了怎么办

Edge 读多音字**只在小句开头出错**。句读一断，模型手上只剩这个字本身，
就挑那个更常见的读音。2026-08-20 拿基频探针量的同一个「假」：

| 上下文 | 实测 | 四声参照「架」 | 三声参照「甲」 | 判定 |
|---|---|---|---|---|
| 调半天假 | 344→256 | 338→236 | 212→175 | ✓ 读对 |
| 假也批了 | 233→317 | 333→221 | 235→314 | ✗ 读成 jiǎ |
| 假当然批 | 227→194 | 296→253 | 224→196 | ✗ |
| 语气正常，假也批了 | 209→168 | 289→275 | 209→168 | ✗ |

**正经做法用不了。** `<phoneme alphabet="sapi" ph="jia 4">` 这个免费端点直接拒，
`<sub>`、`<break>` 一样拒 —— 一个标签都不吃，只有纯文本能出音频。
所以只剩一条路：**送给 TTS 的文本里换成同音字**。

实现在 [`src/zhengyin.ts`](../joke-video/src/zhengyin.ts)，**只改送给 TTS 的那份** ——
字幕、manifest、题句卡上的字全都用原文。两条线共用，`zhiyu-episode.ts` 和
`zhiyu-listen.ts` 都接了（**只接一边的话试听和成片会是两个读音**，
就是 `zhiyu-audio.ts` 顶上警告过的那类分叉）。

`发布.json`：

```json
"正音": {
  "改": { "假批了": "架批了" },
  "免": ["假的东西"]
}
```

- `改` 人工替换，先跑，写什么是什么
- `免` 豁免自动规则 —— 自动规则赌的是「小句开头的多音字，要的不是那个默认读音」，
  这个赌绝大多数时候对，「假的东西」这种正好要 jiǎ 的就得手动刹车

**往 `POLY` 表里加字之前先量：**

```bash
npx tsx src/tone-check.ts --句 "假也批了" --字 假 --比 架,甲
```

参照字要在同一个位置上能整句通顺。**别拿调型判声调** ——
句末的三声读成「半上」，只降不升，第一版的判据就栽在这儿；
要比的是被测字跟哪个参照字的曲线更近。

## 题句卡：把一句话写到画面上

`发布.json` 的 `parts[].quotes`。窗里盖一层跟纸同色的半透明（0.86），
景压下去，字浮上来，1.6 秒淡入淡出。竖排断在标点上、从右往左，
超过两列自动转横排。

```json
"quotes": [
  { "at": "不患人之不己知", "第": 1, "前": 1.5, "后": 3.5 },
  { "at": "知人者智",       "前": 1.5, "后": 3.5 },
  { "at": "不患人之不己知", "第": 2, "前": 1.5, "后": 3.0 }
]
```

| 字段 | 作用 |
|---|---|
| `at` | 那一段的开头几个字。跟镜位、章节同一套定位 |
| `第` | 有多段以 `at` 开头时取第几段。**不写而又不止一段会直接报错** |
| `to` | 卡跨到这一段为止（含） |
| `文` | 改写上屏的字。**意思不许变** —— 屏上和耳朵里对不上，观众会以为自己听错了 |
| `前`/`后` | 话出口前多久浮出来、念完后停多久。默认 1.2 / 2.0 |
| `layout` | `竖`/`横`，不写按字数挑 |

### 心理线：机制名必须有一张卡

**「镜中我　库利 1902」这种比两句古文更该上屏。** 稿源 §三 硬规则 2 写着
「机制必须有名字」，理由就是名字是听众能带走的东西；古文引句是解释层，
机制名才是这一期的题目。所以命名段那一句要上一张卡，出处写进 `注`：

```json
{ "at": "1902 年，一个叫库利的美国人", "文": "镜中我", "注": "库利　1902" }
```

`注` 小一号、淡一档，竖排时排在正文左边、往下错一截，像题完字在旁边署名。
连着的数字会挤成一格横排（縦中横）—— 不然「1902」占掉半列，还读不出是一个数。

**这条现在是 `zhiyu-scene.ts` 的硬闸门**：心理线的 `quotes` 里没有一张带上
`epTitle`（那一栏就是机制名）就出不了图。E01 是出片之后才发现漏的，
写进文档说「下期注意」拦不住任何人。老期用 `"免命名卡": "理由"` 豁免 ——
让例外看得见，而不是没人记得。

### 别的句子不上

**只上引句和命名卡。** E01 试过给落点句也上一张，20 字断成三列变成横排，
还跟前一句挨得太近（8 秒，下限 20）；最后定成只上前置／中位／尾三处引句。
**这条线的画面纪律是「几乎不动」，字每多出现一次，「这一句要紧」这个信号就弱一分。**

护栏：一张卡至少 5 秒（闪一下比不上更糟），两张之间至少隔 20 秒，两条都是报错不是警告。
