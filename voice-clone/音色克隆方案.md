## 一、现有素材：不能用（2026-09-07 复测）

`E:\ryu\石总\石老板原音.m4a`，16.4 秒。跑体检：

```bash
node voice-clone/录音体检.mjs "E:/ryu/石总/石老板原音.m4a"
```

| 项 | 实测 | 要求 | |
|---|---|---|---|
| 时长 | **16.4s** | ≥ 600s | ❌ |
| 信噪比 | **12.6 dB**（语音 −44.0 / 本底 −56.6） | ≥ 30 dB | ❌ |
| 峰值 | **−21.6 dBFS** | −12 ~ −1 | ❌ |
| 整体响度 | **−48.0 LUFS** | −30 ~ −14 | ❌ |
| 有声占比 | **12%** | 45% ~ 95% | ❌ |
| 窄带啸叫 | **8078 Hz，高出本底 16.2 dB** | 无 | ⚠ |
| 削波 | 0 | 0 | ✅ |
| 频谱上限 | 15.5 kHz | ≥ 9 kHz | ✅ |
| 源格式 | aac 48000Hz 1ch 68kbps | ≥ 32kHz | ✅ |

**一句话：录得对（48k、没削波、没被微信压过），但录得太远。**
峰值 −21.6 而整体 −48，人离麦太远，房间噪声跟人声一起进来了。
信噪比 12.6 dB 的意思是：**噪声只比人声低四倍**，模型会把这团底噪当成音色的一部分学进去。

### 试过抢救，救不回来

不是没试。做了两版：

| | 处理 | 结果 |
|---|---|---|
| 轻 | 高通 75Hz ＋ 8078Hz notch ＋ `afftdn nf=-45` ＋ loudnorm −20 | 信噪比 12.6 → **14.2 dB**，还是不到 20 |
| 重 | 同上，`afftdn` 加到 `nr=30` 再叠一层 | 信噪比报 **141 dB** —— 停顿处被压成数字零，人声也削掉一半，loudnorm 都没法工作 |

第二版那个「141 dB」是这次做体检时最值得记的一件事：**降噪把噪声干掉之后，
信噪比会报出一个漂亮到不可能的数**。所以体检里单独加了一条「降噪痕迹」——
本底低于 −90 dB 就判不合格，理由是**训练要原始文件**。降过噪的听着干净，
但齿音和呼吸这些「像不像他」的细节已经被削掉了。

轻处理那一版留着当参考（试听用，不是训练用）：
`E:\ryu\project\vidgen\out\voice-clone\石老板原音_抢救版.wav`

### 顺带纠正一条旧结论

旧笔记里写「不要微信语音」，这条规矩仍然对，但**这份素材不是微信语音**：
频谱上限 15.5 kHz，是正经的 48k 录音。所以问题不在传输链路，在**录制距离**。
重录时该改的是站位和增益，不是换传输方式。

## 二、采集

### 录什么

**[`录音稿_石老板.txt`](录音稿_石老板.txt)** —— 为这件事写的，13 组，2349 字 / 118 句，
外加指定的三期现成口播稿 519 字。按老石线净语速 250 字/分算 11.5 分钟，
实际录出来 14~18 分钟。**不要跳组**，跳两组就掉到 10 分钟以下了。

分组不是凑字数，每组管一件事：

| 组 | 管什么 | 不录会怎样 |
|---|---|---|
| 一 暖场 | 最松弛的状态 | 全稿都是「播音腔」，克隆音永远绷着 |
| 二 数字 | 百分比、日元、面积、年份 | 讲数栏目占 40%，数字念崩就没法用 |
| 三 日语词 | 即入居可／礼金敷金／修缮积立金／再建築不可 | 这些词一期出现好几次，念错整期报废 |
| 四 疑问反问 | 语调往上抬 | **这条线唯一的「重音」来源**（见 §七） |
| 五 长句 | 一口气说长句的换气位置 | 长句会断在莫名其妙的地方 |
| 六 短句落点 | 每期最后一句 | 落点软，这条线的成败全在落点 |
| 七 调侃 | 轻度的无奈和揶揄 | 只会陈述，说不出「你说气不气人」 |
| 八 地名专名 | 东京各区、各条线 | 同上，念法要定死 |
| 九 合同流程 | 整串术语连读 | 最容易念崩的一组 |
| 十 时间数字串 | 日期、电话、邮编 | 这类念法不定，每期都得手动改 |
| 十一 转折递进 | 虽然／反过来说／也就是说 | 句子没有层次，全是平的 |
| 十二 自述 | 第一人称长段落 | 跟真实用途最贴的一组 |

⚠ **用口播的腔念，不要用朗读的腔。** 克隆学的是语气 —— 他念什么腔，出来就什么腔。
这是这一步最容易做错、且**做错了完全看不出来**的地方（体检也测不出来，体检只测物理量）。

### 怎么录

| | 要求 | 为什么 |
|---|---|---|
| 距离 | 嘴离麦 **15~20 cm** | 现有素材的病根就在这儿 |
| 电平 | 说话峰值落在 **−12 ~ −6 dBFS** | 再大容易削波，削了补不回来 |
| 房间 | 换个**没有 8kHz 啸叫**的房间；关空调、关风扇 | 先查源头，notch 是下策 |
| 格式 | **wav 最好**；m4a 要 128kbps 以上、48kHz | 68kbps 那份是能用的，但没必要冒险 |
| 处理 | **原始文件直接给，不要降噪、不要美化** | 见 §一「141 dB」那一段 |
| 一致性 | **一次录完**，中途不换位置、不调增益 | 换了就是两种音色混训 |
| 念错 | 停一下、重念那一句，**不要重录整段** | 切分是逐句切的，坏句丢掉就行 |
| 最后 | 单独再录 10 秒（稿子末尾那四句） | 这是推理用的**参考音频**，见 §五 |

### 验收：机器先说

```bash
node voice-clone/录音体检.mjs <录音文件>            # 训练集档
node voice-clone/录音体检.mjs <参考音频> --参考      # 那 10 秒的档
```

十条判据，任何一条 ❌ 就退回重录。**不要拿「大概能听清」当判据** ——
训练是云上跑几十分钟的事，素材不合格要到试听才暴露，一轮废掉半天。
闸装在录音这个最便宜的表示上，改一次的代价是「再念一遍」，不是「再训一轮」。

## 三、切分与标注

目标：把长录音切成 **3~10 秒**的小段，每段配一行文本。GPT-SoVITS 吃的是这个格式：

```
<wav 路径>|<说话人名>|zh|<这段的中文文本>
```

**在本机做，用整合包自带的 WebUI**（`0-前置数据集获取工具`：切分 → 打标 → 校对）。
做完只把数据集传上云，**卡只用来训练** —— 切分打标是 CPU 活，没必要按小时付钱。

> **2026-09-07 更正：原来这里写「本机打标可以用 koubo 的 whisper.cpp」，不用了。**
> 整合包里已经带了达摩 FunASR 的中文三件套（解压后实际看到的）：
>
> - `speech_paraformer-large_asr_nat-zh-cn-16k-common-vocab8404-pytorch` —— 中文识别
> - `speech_fsmn_vad_zh-cn-16k-common-pytorch` —— 断句 VAD
> - `punc_ct-transformer_zh-cn-common-vocab272727-pytorch` —— **标点恢复**
>
> 省掉了 koubo 那 1.6GB 的 whisper 模型和一份要单独配的 `config.json`。
> 最后那个标点恢复模型还是白捡的：打标出来自带标点，而**标点在这条线上是唯一的语气工具**。

⚠ **不管走哪条，打完标一定要人眼过一遍。** ASR 会把「即入居可」「修缮积立金」
这类词写错，标错的文本会让模型在这些词上学出错误的发音映射 ——
而这些词恰恰是这条线每期都要说的。

⚠ **切分之后把坏段删掉**：念错的、笑场的、咳嗽的、被外面车声盖住的。
留着不如删掉，训练集宁少勿脏。

## 四、微调（一次性）

> ⚠ **本节原来叫「微调（云 GPU，一次性）」，并且断言「训练依赖 CUDA，本机只能推理」。
> 那句话是错的，2026-09-07 查代码推翻了 —— 训练有完整的 CPU 分支，WebUI 也不拦。
> 详见 [§十三](#十三本地能不能训能2026-09-07-订正)。本节保留租卡这条路的做法，
> 但「在哪训」是个还没定的决策，不是既定事实。**

### 两条路，各自的代价

| | 云 GPU | 本机 CPU |
|---|---|---|
| 时间 | 训练 20~40 分钟，含开机上传 1~2 小时 | 见 §十三实测 |
| 成本 | 个位数 | 0 |
| **石老板的录音要不要出本机** | **要** | **不要** |
| 环境 | 现装（或用现成镜像） | **已经装好了** |

⚠ **「录音要不要出本机」这一条不该被「哪个快」压过去。** 那是他本人的声音。
本地只是慢的话（一次性的事，挂着就行），本地是更该选的那条。

### 怎么租（选了云才看这一节）

租一台带 CUDA 的卡，**跑一次，下模型，退掉**。候选（⚠ 都还没实际跑过，价格是公开报价）：

| 平台 | 卡 | 备注 |
|---|---|---|
| AutoDL | RTX 4090 | 有现成的 GPT-SoVITS 镜像，开箱即用；国内访问快 |
| Runpod / Vast.ai | 3090 / 4090 | 按秒计费，要自己装 |
| Colab | T4 | 免费档会掉线，训到一半断了就白跑 |

**总时长估计 1~2 小时**（含上传、装环境、切分标注、训练、试听），**成本个位数**。

### 训练要点

1. **先训 SoVITS，再训 GPT。** 两个模型分开训，产出两个文件。
2. **轮数别贪多。** 15 分钟的数据，SoVITS 8 轮上下、GPT 15 轮上下就够；
   再往上是过拟合 —— 表现是「念训练集里出现过的句子很像，念新句子就崩」。
3. **每隔几轮存一个 checkpoint，试听之后再选。** 最后一轮不一定是最好的一轮。
4. **采样率 32k**（体检脚本的分析采样率也定在 32k，就是对着它来的）。

### 要下载回来的东西

| 文件 | 大概多大 | 是什么 |
|---|---|---|
| `<名字>-e15.ckpt` | ~150MB | GPT 模型（管韵律、断句） |
| `<名字>_e8_s***.pth` | ~100MB | SoVITS 模型（管音色） |
| 参考音频 wav ＋ 它的文本 | 几百 KB | 推理时每次都要给，见 §五 |

**下完就可以退卡了。** 之后每期都不用再租。

⚠ **这两个文件要留档，且不要进 git**（仓库 `.gitignore` 已经挡掉 `*.wav/*.mp3/*.m4a`，
但 `.ckpt/.pth` 没挡）。放 `E:\ryu\石总\音色模型\`，跟素材放一起。

## 五、推理与接入

### 推理

云上下来的两个模型 ＋ 本机 CPU，起 GPT-SoVITS 的 `api_v2.py`，得到一个本地 HTTP 端点。

**每次推理要给三样东西**：正文、**参考音频**（5~10 秒）、参考音频的文本。

⚠ **参考音频定语气，不定音色。** 音色是模型里的，语气韵律是参考音频给的 ——
同一个模型，参考音频选得亢奋，整期就亢奋。所以录音稿末尾那 10 秒是**专门按
「片子里该听起来的样子」录的**：不亢奋，略带一点看破的松弛。选定之后就别再换，
换了就是两期两个人（跟 pitch 是同一类问题，见老石出片方案 §二之二）。

**本机 CPU 推理速度已实测（2026-09-07）：RTF ≈ 1.96，一期约 78 秒。**
见 §十「量出来了」。

⚠ 我之前按官方那个「M4 CPU RTF 0.526」推出「一期二十几秒」，**推错了，实测慢 3.7 倍**。
这条正好印证了那句话本身：**别拿别人的机器当自己的判据，自己量一遍。**

### 接进管线

> ✅ **已落地并出过片（2026-09-08）。命令怎么敲、实测多少，看 §二十。**

**老石线的 TTS 入口是根目录的 [`tts-match.mjs`](../tts-match.mjs)**，不是 `src/steps/tts.ts`
（那是记者读稿线的）。分流做在 `ttsEdge` / `ttsSovits` 两个函数上：

```js
const tts = BACKEND === "edge" ? ttsEdge : ttsSovits;
```

上下游一律没动 —— `manifest.json` 的结构、`seg{i}.mp3` 的命名、配音层的读法全照旧，
`envelope` / `shoot` / `build` 三步不知道后端换过。**这一点验过了**：换后端之后
后三步一行代码没改就跑通了。

⚠ **三个必须注意的**：

1. **输出还得是 mp3，编码参数要一致，而且 `-write_xing 0` 不能省。**
   GPT-SoVITS 出的是 wav，直接落盘的话 `build.mjs` 那句 `-c copy` 会**静默拼出坏文件**。
   转成 `24kHz 96kbps mono mp3` 只是第一层 —— **对齐了还是错的**，
   libmp3lame 的编码器延迟会让时间轴每段偏 52ms。**实测细节见 §十二。**
2. **`--rate` 的语义变了。** Edge 是 `+6%` 这种字符串，GPT-SoVITS 是 `speed_factor`。
   换后端之后**时间轴一定会变** —— **实测短 22%（§十二）**，所以整期要重跑
   `tts-match → envelope → shoot → build`，**动作表也得重核一遍**
   （走路距离、收脚提前这些都是挂在时间轴上的）。这不是可选项。
3. **配音层的停顿 —— 不是「要重量」，是「那种表不存在」。**
   写这条时我以为只是数变了。**实测之后发现更麻烦（§十一）**：
   GPT-SoVITS 的停顿由 GPT 模型看整句生成，同一个 `？` 在三个载句上是 0.00 / 0.76 / 0.04 秒。
   而且前端把 `、，：；` 合并成一个、把 `——` 整个删掉。
   所以「按秒数挑标点」这个动作本身作废，已经装成开跑前的闸。

正音层（同音字替身）不受影响，它是纯文本替换，换后端照样管用；
但换完要重跑一遍 `tone-check`，因为多音字的错法可能不一样。

## 六、验收：像不像，怎么判

试听是最终判据，但先过三条能量出来的：

1. **基频对得上。** 拿一段真人录音和一段克隆音，各自估中位 F0，差在 ±1 个半音以内。
   （老石线量过：pitch `-4%` 才降 0.83 个半音，所以 1 个半音是个不松的判据。）
   顺带 —— **这个数一直是老石线欠的那个输入**：出片方案 §二之二写着「pitch 已量、未采用，
   等一个输入：他真实的基频大概多少」。**录音一到位，这个数就有了。**
2. **训练集外的句子不崩。** 拿一份**没参与训练**的新稿子跑，听有没有吞字、飘调、
   突然换人。崩了就是过拟合，回去挑轮数小一点的 checkpoint。
3. **盲听 AB。** 真人一段、克隆一段，别人分不出来才算过。

## 七、这条路的边界（写在前面，免得又问一遍）

**克隆音仍然是 TTS。它没有重音控制，也没有情感 style。**

不是「还没接」，是这套东西就没有这个旋钮。所以老石线那几条从这里推出来的规范**不会变**：

- 标色只给信息词，语气归结构（[老石出片方案.md](../shi-2d/老石出片方案.md) §五）
- `配音.json` 的「重」这一栏**没人消费、以后也不会有** —— 它只是写稿时的备忘：
  想标重音，就说明那句话该改结构
- 能调的只剩标点。标点在这条线上不是排版，是**唯一的语气工具**

克隆音带来的**不是**表现力，是**身份**：铁律 2 要的是「这是老石本人的声音」。
表现力还是得靠稿子的结构。

## 八、不等录音，今天就能做完的七件事（2026-09-07 定）

原来这份方案写的是「第 1 步之前，其余七步一步都不用开始」。**那句话是错的，改掉。**
录音只卡住「音色像不像」这一件事，**链路、格式、时间轴、停顿表这四样跟音色无关**，
可以提前做完 —— 而且提前做完，省下的是录音到位之后的一整轮返工。

### 「训练环境」是三个环境，别混成一件事

| | 在哪 | 现在该不该搭 | 为什么 |
|---|---|---|---|
| 训练环境 | 云 GPU | ❌ **不该** | 一次性用 20~40 分钟，平台镜像开箱即用。提前开就是按小时白烧钱，镜像还会更新 |

### 关键：底模能做零样本，所以全链路现在就能跑通

GPT-SoVITS 的官方底模**不训练也能出声**，给一段参考音频就行。
所以整条链路今天能端到端跑通，等老石的只有「声音像不像他」这一件。

⚠ **但这一步的验收判据不是「像不像老石」。** 手上只有那份 16 秒的抢救版（信噪比 14 dB），
拿它做零样本，出来的声音会把底噪一起学进去，**听着一定不像**。
今天的判据是：**链路通不通、格式对不对、耗时多少、停顿表是多少**。
这条要先说死，不然听完试听会误判整个方案。

## 九、GPT-SoVITS 升级了怎么办（2026-09-07 定）

### 先分清升级会打断哪三层，代价差着数量级

| 层 | 升级会不会破 | 代价 |
|---|---|---|
| HTTP 接口（`api_v2.py` 的参数） | 会变 | **便宜** —— 改一个函数 |
| **模型权重** | **一定不通用**（v2 / v3 / v4 / v2Pro 四支的权重互不兼容） | **中** —— 要重训一次 |
| **韵律行为**（同一句话多长、一个逗号停多久） | **一定变** | **最贵** —— 停顿表整张重测 ＋ 全线旧期重出 |

第三层才是要害。它的意思是：**升级不是「跟进一个新版本」，是「把这条线重做一次」。**

### 所以默认答案：不升

满足下面任意一条才考虑，否则一律不动：

1. 新版本给了**这条线现在做不到的事**。具体值钱的就一件：**可控的重音或情感**。
   这一件如果成立，它会推翻「标色只给信息词、语气归结构」那条规范的前提（§七），
   那就值得整条线重做。
2. 当前版本**跑不动了** —— 依赖失效、Python/torch 升级之后装不上。
3. 用户明确要求。

⚠ **「音质更好」「更像一点」不是升级理由。** 理由跟 pitch 那条一模一样：
**音色是全线人设，不是单期旋钮**（老石出片方案 §二之二）。升完，新旧两期就是两个人。

### 真正要保住的不是模型，是素材

模型文件是**可再生**的 —— 只要素材还在，任何版本都能再训一次，**不用再找老石录第二遍**。
所以留档清单（放 `E:\ryu\石总\音色模型\`，跟素材放一起，**不进 git**）：

| 留什么 | 为什么 |
|---|---|
| **老石的原始录音（未处理）** | ← 唯一不可替代的东西 |
| 切好的 wav 分段 | 重训不用重切 |
| **人眼校对过的 `.list` 标注** | 校对日语词那半小时不用再花第二次 |
| 参考音频那 10 秒 ＋ 它的文本 | 换版本也照用，语气才连得上 |
| `训练参数.md`：版本号、轮数、选的第几个 checkpoint、日期 | **没有这个，「再训一次」复现不出同一个声音** |

**这是今天唯一必须定下来的纪律：其余都能重来，录音不能。**

### 三件工程上的事，让升级从「重做」变成「换个目录」

1. ✅ **后端写进 manifest** —— 已落，`tts-match.mjs` 的 `--backend` ＋ `manifest.backend`。
   字段记 `sovits-v2proplus` 这种**带版本**的名字，不是光秃秃一个 `sovits`。
   它拦的是「两个后端混着出一期片子」：这种错**在任何一步都不报**，只是听起来像两个人。
2. **升级 = 新装一个目录**（`D:\GPT-SoVITS-next`），**不覆盖现役那个**。
   整合包是绿色的，两版并存几乎不花钱，A/B 完了再决定。
3. **Edge 后端永远留着。** 升级期间要有个能跑的对照，别把老路拆了。

### 真要升，三样都过才准换

1. 拿 01-B 全稿跑一遍，**量时间轴偏差** → 定动作表要重核多少
2. **停顿对照表整张重测** → 写回老石出片方案 §二之二
3. **盲听 A/B：能听出前后是两个人，就必须全线旧期重出，否则不准升**

第 3 条会自动把大部分「手痒升级」挡掉 —— 这是故意的。

### 这也是今天就把版本钉死在 v2ProPlus 的原因

不钉的话，云上开镜像的人会顺手选最新的，本地推理加载不了 ——
**而这个错要到录音到位、训完、下载回来那一刻才暴露**，正好是最亏的时候。

### ⚠ 装完第一件事要验的（这条现在还没验）

**整合包的 CUDA 版 torch，在一台没有 N 卡的机器上能不能正常跑 CPU 推理。**

验的顺序是：`import torch` 不炸 → `cuda.is_available()` 报 False → WebUI 能起 → 底模零样本能出声。

**这一条炸了的话，退路是源码装 CPU 版**（Python 3.9 ＋ torch 2.2.2，官方矩阵那一行），
预训练模型可以从整合包里扒出来复用，8.19GB 不白下。

### 管线接入：已经写完了（等环境起来就能测）

`tts-match.mjs` 的 `--backend sovits` 已落地。走 `api_v2.py` 的 `POST /tts`。
三路都冒烟过：edge 回归（01-B 全稿 `--dry`，`total` 还是 40.32，没动）、
参数校验、未知后端拒绝。

⚠ **接口有两个默认值对我们是错的，而且错了都不报错。** 这是读 `api_v2.py` 才发现的：

| 参数 | 官方默认 | 我们必须设成 | 不改会怎样 |
|---|---|---|---|
| `text_split_method` | `cut5`（按标点再切一刀） | **`cut0`（不切）** | 我们是**逐行合成**、时间轴精确到行。让它再切一次，它会按自己的规矩插停顿，`seg{i}.mp3` 就不再等于「第 i 行」—— **字幕跟声音对不上，一步都不报** |
| `seed` | `-1`（每次随机） | **钉死（默认 42）** | 同一句话每跑一次时长都不一样。**什么都没改，重跑一次时间轴也会飘** —— 整条链路「改了什么要重跑哪一步」那张表直接失效 |

其余落地的几条：

- **语速走 `speed_factor`**，把 `配音.json` 里的 `+6%` 折成 `1.06`。
  这只是为了**不用改配音层的字段**，⚠ **不代表时长一样** —— 跟 Edge 不是同一套机制。
- **`--ref` / `--ref-text` 是必填**，缺一个就在开跑前停住。
  参考音频定语气不定音色，宁可在这儿停，也别让人跑完一整期才发现用的是默认参考音。
- **`--pitch` 在这条路上直接拒绝**。它是 Edge 的参数，克隆音要改音高只能重训或换参考音频。
- `ref_audio_path` 是**服务端**读的路径。服务挪到别的机器（`--host`）时，这个路径要是那台机器上的。
- manifest 多记一段 `sovits: { host, ref, refText, seed }` —— 这几个参数改了声音就变了，
  不记的话事后回答不了「这期到底是怎么出的」。

⚠ **`--sovits-ver` 这个字符串是人工维护的**，脚本查不到服务端实际跑的是哪一版。
换 GPT-SoVITS 版本必须跟着改 —— 忘了改，manifest 会理直气壮地记一个错的版本号，**比不记还糟**。

### ⚠ 但 `tts_infer.yaml` 的 `custom` 段是三重错的

**`api_v2.py` 默认读的是 `custom` 段**，而整合包发出来的 `custom` 段写着：

```yaml

  device: cuda          # ← 这台机器没有
  is_half: true         # ← CPU 不该 fp16
  version: v2           # ← 我们钉的是 v2ProPlus
  t2s_weights_path: .../gsv-v2final-pretrained/s1bert25hz-5kh-...ckpt   # ← v2 的底模
  vits_weights_path: .../gsv-v2final-pretrained/s2G2333k.pth           # ← v2 的底模
```

**三样全错，而且最坑的是第三样。** 前两样（cuda / fp16）在这台机器上会直接炸，
炸了至少知道要改；**`version: v2` 不会炸** —— 它会安安静静地用 v2 的底模跑出声音来，
你听着「哦跑通了」，其实**跑的根本不是你钉死的那一版**。
钉版本号那套纪律（§九）到这儿就被一行 YAML 悄悄绕过去了。

改法：把 `custom` 段改成 `v2ProPlus` 段的内容（`device: cpu` / `is_half: false` /
`version: v2ProPlus` / `s1v3.ckpt` ＋ `v2Pro/s2Gv2ProPlus.pth`）。
原文件已备份成 `tts_infer.yaml.orig`。

📌 顺带：`config.py` 里那行设备信息打出来是**日语**（`CPUトレーニング、速度低下`）——
i18n 认成日语了。不影响功能，但看日志时别以为装错了包。

### ⚠ 这台机器的系统区域是日语，Python 会用 cp932 —— 中文合成直接 400

**这条是本次搭建里唯一一个「不改就完全跑不了」的坑。**

```
locale.getdefaultlocale()      → ('ja_JP', 'cp932')
locale.getpreferredencoding()  → cp932
```

后果：`api_v2.py` 里有走默认编码的路径，喂中文进去就炸：

```
HTTP 400 {"message":"tts failed",
          "Exception":"'cp932' codec can't encode character '\u4f60' ..."}
```

`\u4f60` 就是「你」。**日语区域的 Windows 上，Python 默认编码编不出中文。**

**改法：起服务时带上 UTF-8 环境变量。**

```bash
cd /d/GPT-SoVITS-v2pro-20250604
PYTHONUTF8=1 PYTHONIOENCODING=utf-8 ./runtime/python.exe \
  api_v2.py -a 127.0.0.1 -p 9880 -c GPT_SoVITS/configs/tts_infer.yaml
```

加了之后 `getpreferredencoding()` 变成 `UTF-8`。

⚠ **`go-webui.bat` 也一样**，要跑切分打标那套 WebUI 得同样处理 ——
打标的输出是中文，同一个坑。

📌 这也解释了另外两件事：设备信息打出来是日语（`CPUトレーニング、速度低下`）、
参考音频超长时报的是日语（`参照音声が3～10秒の範囲外です`）。**不是装错包，是区域设置。**

### 要不要在本机装 Python：不用，而且建议别装

整合包自带 `runtime\python.exe` **3.9.13**，正好是官方矩阵 CPU 那一行。
推理、切分打标都用它；训练在云上。**系统 Python 一个用处都没有。**

而且 `go-webui.bat` 是这么调的：

```bat

```

**`-I` 是隔离模式**（＝ `-E -s`），忽略所有 `PYTHON*` 环境变量和用户级 site-packages。
好消息是**系统 Python 污染不了这个整合包**；坏消息是这个 `-I` 藏着下面这个坑。

### ⚠ `-I` 会吃掉 `PYTHONUTF8` —— 打标那一步会撞上同一个 cp932

前面 cp932 的解法是 `PYTHONUTF8=1`，那是给 `api_v2.py` 用的（它不带 `-I`）。
**WebUI 带 `-I`，环境变量直接失效。** 实测：

| 启动方式 | `getpreferredencoding()` |
|---|---|
| `-I` ＋ `PYTHONUTF8=1`（整合包原样） | **`cp932`** ❌ |
| **`-I -X utf8`** | `UTF-8` ✅ |
| 不带 `-I` ＋ `PYTHONUTF8=1` | `UTF-8` ✅ |

`-X utf8` 是**命令行开关**，隔离模式管不着它。

**已改**：`go-webui.bat` 那行加了 `-X utf8`，原件存成 `go-webui.bat.orig`。

📌 这个坑要是等到录音到位、正准备打标那天才撞上，就正好卡在最要紧的节骨眼上 ——

## 十一、⚠ 标点：GPT-SoVITS 把九档压成了六档（2026-09-07 实测）

**这一节可能要动老石线的规范，所以数据先摆全。**

用 [`停顿测量.mjs`](停顿测量.mjs) 量的：同一句话只换中间那个标点，
底模零样本，seed 钉死 42，参考音频是 Edge 拼的 7.7s。
载句「空一个月是正常周转 ◇ 空半年那就得问了」。

### 发现一：前端把五个标点合并成同一个

服务端日志会打「フロントエンド処理後のテキスト」，把它跟输出音频的 md5 对起来看：

| 稿子里写的 | 前端归一化后 | 音频 md5 |
|---|---|---|
| （无） | （无） | `5a875d…` |
| **`——`** | **整个删掉** | **`5a875d…` ← 跟无标点字节完全一致** |
| `、` `，` `：` `；` `,` | 全部 → `,` | `e0f593…` ← **五个共用同一份音频** |
| `。` `.` | → `.` | `65633e…` |
| `！` | → `!` | 单独 |
| `？` | → `?` | 单独 |
| `……` | → `…` | 单独 |

**十二种写法，落到模型上只有六种。** 而且 `——` 是**被删掉**的，不是「停顿短」。

⚠ **这是前端的行为，跟哪个模型无关。** 换成石老板微调后的模型，这张归一化表照样成立。

### 发现二：**「一个标点值多少秒」这张表，在 GPT-SoVITS 上根本不成立**

第一个载句量完，我以为结论是「停顿小一个数量级」。**换个载句复核，结论被推翻了。**
同一个标点、同一个 seed、同一个模型，只换载句：

| 标点 | Edge（老石线现在用的） | 载句 A | 载句 B | 载句 C |
|---|---|---|---|---|
| `……` | 0.29s | **−0.16s** | **+0.44s** | −0.04s |
| `，`（含 `、：；`） | 0.38~0.50s | **0.00s** | **+0.16s** | −0.04s |
| `。` | 0.79s | +0.08s | +0.12s | −0.04s |
| `！` | 0.79s | +0.20s | +0.20s | −0.04s |
| `？` | 0.91s | **0.00s** | **+0.76s** | **+0.04s** |
| 基准（无标点） | — | 3.580s | 3.620s | 2.780s |

> A「空一个月是正常周转 ◇ 空半年那就得问了」
> B「房子空着是要花钱的 ◇ 这钱他不会自己出」
> C「他答得含糊 ◇ 你就该多问两句了」

`？` 在三个载句上是 **0.00 / 0.76 / 0.04**，`……` 是 **−0.16 / +0.44 / −0.04**。
载句 C 干脆整列都在 ±0.04 —— **所有标点都没影响**。
**这不是测量噪声，是量级差别。**

**原因不难理解**：Edge 是拼接式 TTS，标点在它那儿约等于一条「插多长静音」的规则，
所以那张表是常数、可以列。GPT-SoVITS 的韵律是 **GPT 模型自回归生成的** ——
它看的是整句话，标点只是一个影响因素，**同一个标点在不同句子里本来就该停不一样长**。

⚠ **所以 `配音.json` 里「停：给秒数就挑最接近的标点」那套做法，
在 sovits 后端上失去意义。** 不是数变了，是**「按秒数挑标点」这个动作本身不成立** ——
你挑的那个标点，在这句话里停多久，事先不知道。

📌 载句 A 里逗号那组的时长跟无标点**一样是 3.580s，音频 md5 却不同**。
所以逗号**改了念法但没改长度** —— 它不是「不起作用」，是「不靠拉长时间起作用」。
这条正好是上面那个解释的佐证。

⚠ 这一节量的是**底模**。微调换掉的正是 GPT 模型，所以**具体的数肯定会变**；
但「停顿由整句决定、不是标点的常数」这件事是**模型架构层面的**，微调不会把它变回常数。

### 这对「标点是唯一的语气工具」意味着什么

老石线现在那条规范（[老石出片方案.md](../shi-2d/老石出片方案.md) §二之二
「标点符号调音师」）建立在两件事上：**九档可选**，以及**同样 0.38 秒是三种不同的戏**。
换到克隆音之后：

- **九档变六档** —— `、，：；` 之间的区别没了，`——` 直接消失（这条铁）
- **那张秒数表整个作废** —— 不是要重量，是**这种表不存在**

**但这条规范不会因此作废**，它的根基不是秒数，是「语气归结构」——
克隆音同样没有重音控制（§七），这一点没变。变的是**手法**：

| | 现在（Edge） | 换克隆音之后 |
|---|---|---|
| 想让这儿停久一点 | 挑个「值 0.79 秒」的标点 | **办不到** —— 改成**断句**：该断成两行就断成两行 |
| 想区分 `、` 和 `：` 的味道 | 有区别（0.38 vs 0.41） | **没区别**，前端合并了 |
| 标点还剩什么用 | 长度 ＋ 语调 | 只剩**语调**（`。` 收下去、`？` 挑上来）和换不换气 |

⚠ **我没有去改 §二之二。** 这一节的数是**底模 ＋ Edge 参考音**量的，
石老板的模型训出来之后要重跑 [`停顿测量.mjs`](停顿测量.mjs) 复核，再动规范。
**拿底模的数去改一条正在用的规范，是本末倒置。**

⚠ **但有一条现在就该记住**：这次差点犯的错是**只量一个载句就下结论**。
第一个载句给的是「停顿几乎为零」，听起来是个干净利落的发现，
写进文档就成了一条错的规范依据。**量韵律这类东西，一个样本等于没量。**

### ⚠ 格式对齐只做对了一半：mp3 编码器延迟

`-c copy` 那个坑我原来只写了「参数要对齐」。**对齐了，还是错的。**

音频参数确实一致（都是 mp3 / 24000Hz / 1ch / 96kbps），但实际拼一次：

| | 拼出来 | 时间轴说 | 差 |
|---|---|---|---|
| Edge | 40.320s | 40.32s | **0.000s** |
| sovits（第一版） | 31.884s | 31.36s | **+0.52s** ❌ |

**原因**：libmp3lame 会写 Xing/LAME 头，里面记着编码器延迟和末尾补白。
**ffprobe 读单个文件时按这个头把补白扣掉，`concat -c copy` 却是照搬帧的** ——
每段偏约 52ms，十段累积 0.52 秒。**字幕会整场慢慢飘。**

试了三种写法：

| 编码参数 | 逐段和 | 拼接后 | 差 |
|---|---|---|---|
| 默认 | 8.580s | 8.700s | +0.120s |
| `-flags +bitexact` | 8.580s | 8.700s | +0.120s |
| **`-write_xing 0`** | **8.760s** | **8.760s** | **0.000s** ✅ |

**已改**：sovits 后端的 ffmpeg 加了 `-write_xing 0`。重跑之后 **31.944 = 31.944**，dts 警告也没了。
代价是每段多几十毫秒静音补白 —— 句间多这点空隙无所谓，**时间轴对不上才要命**。

📌 这条是「`-c copy` 静默出坏文件」那个坑更深的一层，而且**更阴**：
混格式还能听出不对劲，累积 0.52 秒只是字幕慢慢飘，**试听一遍根本发现不了**。

### 已经在用的配音层里，有两处停顿到了克隆音上是白写的

01-B 的 `配音.json` 句3、句5 都用 `——` 顶一档停顿（「逗号 0.38 ＋ 破折号 0.38」）。

- 哪些停顿**跟逗号没区别**（`、：；`）

⚠ 配音层里那些理由文字（「逗号 0.38 ＋ 破折号 0.38」「冒号本身 0.41」）
**引用的是 Edge 那张表**。等模型训出来、规范定了，这些注释也要跟着改 ——

## 十三、本地能不能训？能。（2026-09-07 订正）

### 先纠正我自己写的一句话

§四 写着「GPT-SoVITS 的训练路径依赖 CUDA，本机只能做 CPU 推理」。**说得太绝对。**
读了实际代码：

```python
# s2_train.py（SoVITS）
device = "cpu"  # cuda以外的设备，等mps优化后加入
backend = "gloo" if os.name == "nt" or not torch.cuda.is_available() else "nccl"
....cuda(rank) if torch.cuda.is_available() else ....to(device)

# s1_train.py（GPT）
accelerator = "gpu" if torch.cuda.is_available() else "cpu"
devices    = -1    if torch.cuda.is_available() else 1
```

**训练代码有完整的 CPU 分支**，而且 `webui.py` **不拦** ——
`is_gpu_ok` 只用来决定默认 batch size（无 GPU 时按内存算，这台 32G → 8）。

所以问题从来不是「能不能」，是「多久」，以及**一个我之前完全没提的因素**：

⚠ **云上训练 = 把石老板本人的录音传到租来的机器上。**
这是他的声音，不是素材图。**这件事该由用户决定，不该被「哪个快」默认掉。**
如果本地只是慢（一次性的事，挂着就行），那本地反而是更该选的那条。

### ⚠⚠ 整合包里有个硬编码路径的地雷 —— 打标和训练全被它挡死

`runtime/Lib/site-packages/users.pth` 里写的是**打包者自己机器上的绝对路径**：

```

D:\BaiduNetdiskDownload\...\GPT_SoVITS
D:\BaiduNetdiskDownload\...\tools
```

## 十四、《老石原音.m4a》体检 ＋ 一个附带的收获（2026-09-07）

`E:\ryu\石总\老石原音.m4a`，11 分钟。**比上一份好太多**，但卡在噪声。

| 项 | 实测 | |
|---|---|---|
| 时长 | 663.6s（11.1 分钟） | ✅ 够微调 |
| 峰值 | −5.5 dBFS | ✅ 增益对了 |
| 削波 / 降噪痕迹 / 啸叫 | 全无 | ✅ |
| 频谱上限 | 16.0 kHz | ✅ 没被压过 |
| 有声占比 | 58% | ✅ |
| **信噪比** | **17.0 dB** | ❌ 下限是 20 |
| 整体响度 | −30.6 LUFS | ❌ 但这只是增益，归一化即可，无害 |

### 噪声是什么：查了三层，都排除了「能靠后期救」的可能

**一、不是编码噪声。** 拿一段干净音频压成同样的 67kbps AAC，本底仍是 −240 dB。
**所以那 17 dB 是真实的房间声音。**

**二、不是混响。** 量了 69 处「说话→停顿」的下降沿，平均衰减是
50ms 内掉 11 dB，然后**平在 −14 dB 不再降**。混响会持续衰减，这是稳态本底。

**三、低频占大头，但滤不干净。** 静音段的噪声谱：80Hz 以下占 36%，320Hz 以下占 66%，
2.5kHz 以上只有 3.6%。可高通只救回 **0.7 dB**（17.0 → 17.7 @80Hz）——
因为剩下的噪声压在 160~1280Hz，正是人声带。

| 高通 | 信噪比 |
|---|---|
| 原始 | 17.0 dB |
| 80Hz | 17.7 dB |
| 120Hz | 18.0 dB |

**四、没有「好段落」可挑。** 逐 30 秒看，22 个窗口的信噪比是 13~22.6 dB，
中位 15.0，**≥20 dB 的只有 1 个窗口（半分钟）**。不是某几段差，是全程一样。

### 病根：人离麦太远

**他的语音 RMS 只有 −31.9 dB，而峰值到了 −5.5 dBFS。**
增益是够的（峰值证明了），问题是**人声在整体里太小**。

**距离是唯一能改变「直达声/环境声」比例的变量。**
靠到 15~20cm，人声抬 10 dB 而房间噪声不动 → 信噪比直接到 27 dB 上下。
**同一个房间、同样设备，只改这一件事。**

### 📌 附带收获：老石本人的基频量出来了

老石出片方案 §二之二 挂着一句「pitch 已量、未采用，**等一个输入**：他真实的基频大概多少」。
这份录音把这个输入给了。

⚠ **自相关估 F0 对参数很敏感**（松参数会在他这种低音上发生倍频错判）：
同一段录音，参数从松到紧量出 111.5 / 121.2 / 130.1 / 131.1 Hz。
**所以绝对值不能单交**，要用同一套参数量两边、只取比值：

| 参数（阈值/搜索范围） | 老石 | 云希 | 差 |
|---|---|---|---|
| 0.45 / 60-300Hz | 111.5 Hz | 171.1 Hz | −7.42 半音 |
| 0.60 / 60-300Hz | 121.2 Hz | 171.1 Hz | −5.97 半音 |
| **0.60 / 80-300Hz** | **130.1 Hz** | **171.1 Hz** | **−4.75 半音** |
| **0.70 / 80-260Hz** | **131.1 Hz** | **173.0 Hz** | **−4.79 半音** |

最严的两组参数结果一致 → **老石比云希低约 4.8 个半音，本人 F0 约 130 Hz。**

⚠ 我这里量的云希是 171 Hz，而出片方案里记的是 156.9 Hz —— **方法和素材不同，绝对值不可跨方法比**。
所以上表只有「同一行内的差值」是可信的。

**这个数的分量**：4.8 个半音 ≈ pitch **−24%**。而出片方案里量过的 `-4%` 只有 0.83 个半音、
`-8%` 只有 1.31 个半音 —— **差了一个数量级**。

结论：**占位音（云希）跟老石本人差了将近半个八度，调 pitch 是补不回来的。**
这反过来说明克隆不是「锦上添花」，是这条线唯一的出路；
也说明现在 01-A / 01-B 里那个声音，听起来是个比他年轻很多的男人。

## 十六、降噪：能做，但差点做错（2026-09-07）

### 先纠正 §二 那条「不要降噪」

**上游 GPT-SoVITS 的 WebUI 里就有「语音降噪」这一步**（`tools/cmd-denoise.py`），
是官方数据准备流程的一环。我原来写「原始文件直接给，不要降噪」，
是从一次糟糕的 `afftdn` 实验推广出来的 —— **那是我用错了工具，不是降噪这件事不行**。

⚠ 但官方那个走不通，两个原因：

1. **依赖坏了**：整合包里 `modelscope 1.32.0` 要新版 `datasets`，包里是 `2.16.1`，
   报 `ImportError: cannot import name 'LargeList'`。**开箱即坏。**
   （`funasr` 不走这条链，打标不受影响。）
2. **模型是 16k 的**（`speech_frcrn_ans_cirm_16k`），会把频谱上限砍到 8kHz。
   而老石这份原音是 16kHz 全带宽 —— **齿音全在 5~16kHz**。

**改用 ffmpeg 自带的 `arnndn`（RNNoise）**：纯 ffmpeg、不碰 Python 依赖、48kHz 工作、不砍频宽。
模型从 `GregorR/rnnoise-models` 取，每个约 300KB。

### ⚠⚠ 我挑错了模型，因为判据本身是错的

五个模型都跑了，我按**信噪比**挑了 `sh`（17.0 → 23.4 dB，最高）。**这是个陷阱。**

用户听出来：**08:08 之后声音越来越小，基本听不清。** 一查：

| 时间 | 原始语音 | sh 降噪后 | 削掉 | 有声占比 |
|---|---|---|---|---|
| 00:00–05:00 | −31~−37 | −40~−45 | 8~12 dB | 52~63% |
| **08:30 之后** | −26~−35 | **−59~−64** | **24~37 dB** | **7~17%** |

**RNNoise 在后半段把人声整个当噪声压掉了**（小模型带内部状态，一旦判成噪声会自我强化）。

**而「信噪比」恰恰是被这个故障抬高的** —— 人声删得越多，信噪比越好看。
**按信噪比挑，就必然挑中最坏的那个。**

五个模型的逐段一致性：

| 模型 | 前 5 分钟削减 | 后 3 分钟削减 | 后段有声占比 | |
|---|---|---|---|---|
| sh（信噪比最高） | −9.9 dB | −30.1 dB | 13% | ❌ 崩了 |
| **bd** | −9.5 dB | **−13.7 dB** | **51%** | ✅ **全程一致** |
| lq | −10.0 dB | −21.8 dB | 41% | ❌ |
| cb | −8.5 dB | −17.8 dB | 29% | ⚠ |
| mp | −7.9 dB | −15.7 dB | 51% | ⚠ |

**定用 `bd`。**

### 闸补了一条：逐段一致

信噪比和有声占比都是**全片统计**，一半好一半坏就骗过去了 ——
而且信噪比还会因为后半段变安静而**更好看**。

[`录音体检.mjs`](录音体检.mjs) 加了「逐段一致」：逐 30 秒算有声占比，

📌 **这是这份体检脚本第二次因为「只看全片平均」而漏判**（第一次是「频谱上限」
测不出降噪削弱 —— 悬崖还在 16kHz，但那一段能量被削了 13.7 dB）。
**凡是「整体统计」的判据，都要配一条「最差的那一段」。**

## 十八、第一次真训的结果：流程全通，声音不能用（2026-09-07 夜）

**操作手册单独成篇：[训练手册.md](训练手册.md)** —— 拿到新录音照着走。这一节只记结论。

### 跑通了什么

| | |
|---|---|
| 训练 | SoVITS 8 轮 **88 分钟** ＋ GPT 15 轮 **27 分钟**，两段退出码 0，九个权重 |
| 管线 | `--backend sovits` **第一次接真模型就跑通**，`-write_xing 0` 在真模型上验证有效（拼接 44.112 = 时间轴 44.112） |
| 出片验收 | 01-B 全稿（**没参与训练**）10 句全出声，0 崩 |
| 语速 | **208 字/分**，比 Edge 占位音的 227.7 还慢 —— 学到了老石本人偏慢的节奏 |
| 基频 | 比本人低 1.27 半音；**占位音是 +3.76 半音**，克隆把差距缩到不足三分之一 |

### 但用户听下来：吐字不清晰

量出来是真的，不是错觉。按元音带对齐后的辅音/齿音能量：

| 频段 | 老石本人 | 训练素材 | **克隆音** | Edge 占位音 |
|---|---|---|---|---|
| 辅音 2.5-5k | −25.6 | −24.0 | **−27.3** | −15.5 |
| 齿音 5-10k | −30.4 | −27.8 | **−40.6** | −17.5 |

**克隆音的齿音比 Edge 低 23 dB，比老石本人低 10 dB。** 辅音和齿音正是「吐字清不清楚」的物理载体。

### 三个被否掉的解释

**① 「音量太小」** —— 否。克隆音 −25.9 LUFS，占位音 −24.0，只差 1.9 dB。

**② 「SoVITS 档位选早了，高频最后收敛」** —— 否，而且**方向反了**：

| SoVITS 档 | 齿音 5-10k |
|---|---|
| e2 | **−32.9**（最好） |
| e4 | −35.2 |
| e6 | −34.7 |
| e8 | **−37.1**（最差） |

**越训齿音越低。** 而且最好的 e2 仍比老石本人低 2.5 dB。**不是挑档位能解决的。**

**③ 「后期 EQ 补回来」** —— 补得回，但**带来呲呲声**。

提亮后辅音/齿音精确落到老石本人的水平（−24.7/−30.4 vs −24.7/−29.8），
可用户听出呲呲声。一量就明白：

| 频段 | 克隆音 | 提亮后 | Edge 占位 |
|---|---|---|---|
| 5-8k 语音/停顿比 | 12 dB | **12 dB** | 67 dB |
| 8-12k | 11 dB | **10 dB** | 71 dB |

**EQ 把人声和噪声一起抬，比例分毫不变。** 所以「提亮必带杂音」是数学必然，调参数解决不了。

加噪声门能压掉停顿处的呲呲（−1 → −12 dB，清晰度一点不丢），
但**压不掉说话时混在人声里的那 11 dB**。这是能做到的最好后期，不是修好了。

### 根因：录音离麦太远

**老石本人的录音在 5-10k 就比 Edge 低 13 dB。** 模型不可能生成训练数据里没有的高频。

后期 EQ 补的是**模型丢的那部分**（−40.6 → −30.4，补回 10 dB），
补不回**录音时就没进来的那部分**（−30.4 vs Edge 的 −17.5）。

**这一版走完了全部九步、每步都合格，最后仍然不能用。**

### 所以

用户定：**等一版清晰的原音再重跑。** 这是对的 ——
从体检那一刻起（信噪比 17.0，卡在 20 的下限之下），后面每一步都是在及格线附近挣扎，
而每一步的补救都在付代价（降噪削高频 → EQ 补回来 → 带出噪声 → 噪声门只能压一半）。

📌 **这一版的钱没白花**，它把三件原本只是推断的事变成了实测：

1. **本机 CPU 训练完全可行** —— 115 分钟跑完两段，训练时还能正常出片
2. **整条管线通了** —— 从体检到 `--backend sovits` 到拼接对齐，全部在真模型上验证过
3. **「录音质量决定上限」不再是口号** —— 有了一条完整的证据链：
   离麦远 → 高频缺 → 降噪再削 → 模型再糊一层 → EQ 补回来就带噪声

📌 **还有一个问题没答上**：这份素材是即兴口语（满篇 `呃/嗯/哎`），
原本想验证「口语素材能不能撑口播」（§二 那条「拿口播稿录」一直只是推断）。
**但清晰度问题盖过了一切，这个问题这一版没答成，留到下一版。**

### 下一版的三条硬要求

1. **嘴离麦 15~20 cm** —— 这一条解决信噪比、高频、以及「要不要降噪」三件事
2. **拿 [`录音稿_石老板.txt`](录音稿_石老板.txt) 念** —— 顺便把上面那个没答成的问题一起答了
3. 录完先跑 `录音体检.mjs`，**不过闸就退回重录**，别再像这次一样「勉强能用」就往下走

## 十九、素材里混进第二个人 —— 十一条判据一条都抓不到（2026-09-08）

用户听出《原音》那批视频里**开头有旁白的声音**，而 [`录音体检.mjs`](录音体检.mjs)
的十一条判据**全部放行**。

**因为那十一条全是物理量**（信噪比、有声占比、频谱上限、逐段一致…），
而「这是谁在说话」是**身份**，不是物理量。

⚠ **混进第二个人比噪声严重得多。** 噪声只是让数据脏；第二个人是
**教模型学一个不存在的混合音色** —— 训完之后你听不出「这是两个人混的」，
只会觉得「不太像他」，然后**无从查起**。

### 工具：[`说话人扫描.py`](说话人扫描.py)

用整合包自带的 **ERes2NetV2 声纹模型**（`pretrained_models/sv/`，v2Pro 训练本来就要用它）。
逐 2 秒算一个嵌入，跟全片重心比余弦相似度。

```bash
cd D:/GPT-SoVITS-v2pro-20250604
PYTHONUTF8=1 ./runtime/python.exe -s E:/ryu/project/vidgen/voice-clone/说话人扫描.py <音频...>
```

### ⚠ 先走过一条弯路：基频判不了说话人

第一次想拿 **F0** 判 —— 四个文件**全部误报**。因为正文里 F0 本身就在
**94~156 Hz** 之间跳（正常的语调起伏），跟「换个人」的幅度分不开。

**声纹嵌入才是为这件事做的**，而且模型现成。

### 判据是连续量，没有干净的分界线

实测（《原音》那批，全片中位相似度 0.82~0.84、MAD 约 0.026）：

| 相似度 | 是什么 | 怎么办 |
|---|---|---|
| **0.31~0.41** | **换人了** —— 跟中位差了 20 个 MAD | ❌ 删 |
| 0.52~0.73 | **多半还是他** —— 笑、叹气、压低嗓子学别人说话 | ⚠ 听一下，**倾向不删** |
| 0.75~0.90 | 正常说话 | ✅ 留 |

⚠ **别把 0.5~0.73 那一档一律删掉。** 那些笑声和气声正是让克隆音自然的东西，
删了会得到一个只会平铺直叙的模型。

📌 **这跟 RNNoise 那次是同一个教训**：上次降噪把后半段人声当噪声删掉，
**信噪比反而变好看了**。**「删掉可疑的」永远能让指标变漂亮，但删掉的可能正是你要的。**

### ⚠ 别按「每个文件都砍前 N 秒」处理

实测四个文件里**只有一个**开头有旁白（`入谁的乡` 那条，前 7 秒相似度 0.31~0.41），
另一个（`车库证明`）**一上来就是老石**（0.78 起步）。

**一刀切会既留下别人的声音、又白扔老石的。** 逐文件扫，按扫描给的区间删。

📌 顺带一个坑：文件是**按名字排序**读进来的，跟用户添加的先后顺序不一样。
报告里说「第几个文件」之前先核对文件名，别按添加顺序猜。

### ⚠ 一个自己踩的坑：靠文件名排序猜对应关系，猜反了两次

扫描报告原来只印 `v1.wav / v2.wav` 这种代号。我看到源文件名里「入谁的乡」
排在前面，就认定报告里的 `v1` 是它 —— **反了**。

而报告里其实印着**窗口数**：`v1` 是 264 个窗口 ＝ 265 秒 ＝「车库证明」。
**手上有能对上的数（时长、窗口数），我却去猜文件名的排序。**

后果：切掉了「入谁的乡」开头 7 秒（**那 7 秒是老石本人**），
真正的旁白在「车库证明」开头，**一秒没动**。

**是复扫抓到的** —— 切完之后再扫一遍，开头仍然是 `0.29 0.29 0.38`，当场暴露。

📌 **两条纪律**：
1. **报告要带能对上的数**（文件名 ＋ 时长 ＋ 窗口数）。已经改进 `说话人扫描.py`。
2. **切完必须复扫。** 这类「切错了对象」的错误，靠看切之前的报告是发现不了的 ——
   只有拿结果再过一遍闸才抓得住。所幸原始 `v*.wav` 都在，重切没有损失。

## 二十、用克隆音出片：全链路跑通了（2026-09-08）

**第一期用石老板本人音色出的片子：**
`projects/老石/20260907_即入居可这四个字/老石_即入居可这四个字.mp4`（38.76s / 12.2 MB）。

§五「接进管线」写的那套**全部落地并验过一遍**了。这一节记的是**照着做的命令**
和**实际量到的数**，不是设想。

### 六步，照抄就行

```bash
# 0) 起推理服务（要等 155MB 权重在 CPU 上加载完，别用 curl -m 60，见下面的坑 2）
cd /d/GPT-SoVITS-v2pro-20250604 && runtime/python.exe api_v2.py -a 127.0.0.1 -p 9880

# 1) 换权重（tts_infer.yaml 里默认的那两个多半不是你要的）
curl -X POST "http://127.0.0.1:9880/set_sovits_weights?weights_path=SoVITS_weights_v2ProPlus/laoshi2_e4_s152.pth"
curl -X POST "http://127.0.0.1:9880/set_gpt_weights?weights_path=GPT_weights_v2ProPlus/laoshi2-e12.ckpt"

# 2) 出配音（--ref 是**服务端**路径；--ref-text 必须是那段音频真念的字）
node tts-match.mjs --file "projects/老石/<期>/稿子.txt" \
  --配音 "projects/老石/<期>/配音.json" --out "projects/老石/<期>/vo" \
  --backend sovits \
  --ref "D:/GPT-SoVITS-v2pro-20250604/laoshi2/ref/ref.wav" \
  --ref-text "这个规矩是你看这是店家定的规矩，…"

# 3) ⚠ 出完配音**立刻关掉 api_v2.py**，再往下走（坑 1）
# 4) 拼 vo.mp3 → 出包络 → 出帧 → 合片
ffmpeg -f concat -safe 0 -i vo/list.txt -c copy vo.mp3
node 3d-render/envelope.mjs "projects/老石/<期>"
node shi-2d/shoot.mjs        "projects/老石/<期>"
node shi-2d/build.mjs        "projects/老石/<期>"
```

**换期只改三处**：`<期>` 目录、`稿子.txt`、`配音.json`。
**`--ref` / `--ref-text` / `seed` 一期都不要改** —— 改了就是两期两个人（§五）。

### 实测：《即入居可》这一期

| | Edge（原版） | 克隆音 | |

| 段数 | 10 | 10 | |

**「短 22%」那个数不通用。** §十二在 01-B 上量到 −22%，这一期只有 −3.8%。

⚠ **`manifest.json` 里 `voice` / `rate` 两个字段还是 Edge 的样子**

### 三个坑

**1. 内存：`api_v2.py` 跟出帧一起跑会双双被杀。**
推理服务常驻 3+ GB。这一期出帧时撞过一次，resvg 和 python 一起没的。
**规则是「跑重活之前关掉它」，不是「训练期间关掉它」** —— 我第一次把这条写窄了，
于是同一个坑踩了两次（训练一次、出帧一次）。
配音拿到手就该关，`envelope` 之后的三步都不需要它。

**2. `curl` 换权重超时，看起来像成功。**
155 MB 的权重在 CPU 上加载超过 60 秒，`curl -m 60` 直接超时；
用 `&&` 串起来的话后面的 `tts-match` 根本没跑 —— 但 `vo/` 里还躺着上一版 Edge 的
`seg*.mp3`，**目录看起来是满的、时长看起来是对的**。

📌 **判据只有一个：`vo/manifest.json` 的 `backend` 字段。**
是 `sovits-v2proplus` 才算换过；`undefined` 或 `edge` 就是没跑。别看目录、别看时长。

**3. 时间轴一变，动作表就得重核。**
走位距离、收脚提前、舞台段的起止都是挂在秒数上的，
这一期动作表是按 40.32s 排的，实际 38.784s。这不是可选项，见 §五注意事项 2。

### 还没解决：句间语气断

**用户听到的问题**（2026-09-08）：「每句之间断得很突然，没有语气」。

根子在**管线只能逐句合成** —— `seg{i}.mp3` 必须一句一个文件，
字幕、表情、动作表全挂在这个时间轴上。而 GPT-SoVITS 的韵律是**看整句生成**的，
一句一合成，它看不到上下句，句子之间就没有承接。

**整段合成（一次给全文）语气明显更好，但切不回逐句。**
试过按静音间隙切：第 9 长的间隙 0.24s、第 10 长 0.23s，**没有断崖**，
而且最长的几个间隙里有一个在句子内部。**切不出来。**

📌 **两个已经量出来的旋钮**（都只在整段模式下有意义）：

| `speed_factor` | 全文时长 | 语速 |
|---|---|---|
| 1.00 | 28.56s | 321 字/分 |
| 0.85 | 33.53s | 274 字/分 |
| 0.75 | 37.97s | 242 字/分 |
| 0.65 | 43.75s | 210 字/分 |

标点在**整段模式**下的净增（同一处换标点，减掉无标点的基线）：

| `，` `、` | `！` | `。` | `？` `……` | `——` |
|---|---|---|---|---|
| **+0.56s** | +0.12s | +0.05s | ≈0 | **0.00（被删）** |

⚠ 这张表**只量了一个载句**。§十一 的教训是同一个标点换个载句能差出十倍，
所以**这不是一张可以照抄的表**，只说明一件事：**整段模式下 `，`/`、` 是唯一有效的喘息工具**，
`。` 几乎不给停顿，`——` 被前端整个删掉。

**要不要为语气改管线（整段合成 ＋ 另想办法拿逐句时间轴），等用户看完片子再定。**
