# 夜听说书 · 出片手册

一期说书视频，从选题到能发，全流程在这儿。
**这份是系列级的规程**；某一期具体怎么做成的、踩了什么坑，在那一期目录里的 `方案.md` / `稿件分析.md`。

> 立此存照的两个数（E01 v2 / E02 实测，其余 15 期按这个配）：
> **稿件汉字 ÷ 228 = 成片分钟数**（误差 ±4%）　**片头封面 1.5 秒**

## 一、七步里，机器只包了五步

```
① 选题 + 扩写整稿    ← 人（或模型）。机器做不了
①.5 稿件闸          → npm run shuoshu:lint -- ../shuoshu/<稿件>.md     ← 2026-08-26 加
② 解析              → npm run shuoshu:parse -- ../shuoshu/<稿件>.md
③ 标注节拍          ← 人（或模型）。机器做不了
③.5 画面表 scenes.json（**稿件定稿之后再写**，见 §六）
──────────────────────── 以下一条命令 ────────────────────────
④ 体检 → ⑤ 音频 → ⑥ 场景图 + 封面 → ⑦ 成片 → 护栏 → 交付物核对
                    → npm run shuoshu:ship -- --ep E03
────────────────────────────────────────────────────────────
⑧ 试听 + 人工核对    ← 人。机器做不了
⑨ 发布文案 + 上传            ← 人（封面 ship 全包了，见 §六）
```

### ①.5 为什么单开一道闸（2026-08-26 加）

原来只有一道闸（第 ④ 步体检），可它查的东西横跨两类：

| | 属于哪一步 | 在哪儿能查 |
|---|---|---|
| 总时长 / 分幕下限 | ① 的产物 | **markdown 上就能算** |
| needsReview / 节拍占比 / 场景段号 / 封面字段 | ②③ 和画面表的产物 | 得等 script.json |

两类塞进同一道闸的后果是：**稿件级的问题必然等到标注做完才暴露，而补稿恰好会打乱标注和画面表。**
这是个环 —— 稿子出问题 → 改稿 → 冲掉两样已经做完的东西。

> E06 就在这个环里走了一圈。写完 5126 字，体检才说分幕下限没过；补到 5785 又超了
> 24 分钟；后来又发现「人味儿」四条判据缺一条，补了三段，193 之后的段号全移位，
> 节拍要重贴、scenes.json 要手工后移 68 张再逐条核。

**一句话原则：每个判据的闸，要装在能改它的最便宜的那个表示上。**
字数是 markdown 的属性就在 markdown 上查；构图边界是代码里的常数就在代码上查
（§六末「护栏｜构图」）；只有「一张图挂了多少秒」是真的非等音频不可。

稿件闸查得了什么、以及它印出来的那张**必答清单**（人味儿四条 / 平读测试 / 说破层五条），
见 `joke-video/src/shuoshu-lint.ts` 的文件头。**清单比查得了的那几条重要** ——
机器判不了「意思还在不在」，但可以让这些问题在**正确的时刻**出现在眼前。

**为什么① ③ ⑧ 机器包不了，说清楚免得反复问：**

| | 为什么 |
|---|---|
| ① 写稿 | 3800 字要能听。这是写作，不是模板填空 |
| ③ 标注 | 哪一句压低、哪一句停死，是编剧判断。体检拦得住「一段没标」，拦不住「标得不对」 |
| ⑧ 试听 | 音色撑不撑得住长段，只有耳朵知道。E01 跳过这步，主讲人机械偏慢，**全片重来一遍** |

`shuoshu:ship` 跑完，**成片是能看的，但不代表能发。**

## 一之二、档期与目录命名（2026-08-23 立）

### 频道一周五更，说书占三档

```
周二 18:00  说书          周三 18:00  小故事大道理（禅佛典）
周四 18:00  说书          周六 18:00  说书
                          周日 18:00  治愈
```

**改排期改 `joke-video/src/schedule.ts` 的 `LINES`，不改别处。**
看往后几周排成什么样：`npm run schedule`（`-- --weeks 8` 看更远）。

- **心理洞察不进档期**（2026-08-23 定），理由是稿子写不好 —— 加档、囤稿都解决不了。
  已出的两期留着不撤。顺带记一笔：**心理洞察和「小故事大道理」是两条线**，
  周三那一档归禅佛典向。
- **老马是另一个频道**（碎嘴老马），它的档在 [`../joke-video/horse/SCHEDULE.md`](../joke-video/horse/SCHEDULE.md)：
  周二 / 周四 / 周日 **21:00 JST**。同日不同时，不打架。
- **一档只发一条，但不限定哪条线** —— 谁的片子都能占任意一档。
  2026-08-26 周三（本该是小故事大道理）就被治愈线的《不归你管》占了。
  `npm run schedule` 会在那一行后面标 `← 治愈线占了这一档`（2026-08-24 加）。
  **在这之前它只印篇名**，那一行看着就是「小故事大道理 别人怎么看你-E01」——
  一支治愈线的片子被印成了禅佛典线的期。**账本印错比空着更糟。**

⚠ **一周三期说书 = 一周一万五千汉字。** 瓶颈从来不在机器（`ship` 一次 8 分钟），
在写稿。§十 那两条路（甲·囤稿定时跑 / 乙·每天叫模型）在这个频率下不再是选择题 ——
**得先囤够**，不然某个周四晚上会发现今天没稿。

### 目录名分两半

```
2026-08-25_1800JST_说书_婴宁-E05
└── 可变，负责排序 ──┘ └类型┘ └ 身份 ┘
```

这条规则是从老马线搬过来的（[`horse/SCHEDULE.md`](../joke-video/horse/SCHEDULE.md) §〇）：
**别把可变状态编进不可变标识里。** 档期会挪，期号不会。

| 段 | 规则 |
|---|---|
| 日期 | `YYYY-MM-DD`，**发布日**（不是制作日。这一条 2026-08-23 改的） |
| 时间 | `HHMM` 四位 ＋ `JST`。跟老马线同一条理由：人在日本，**记的是墙上钟那个时间** |
| 类型 | 线名：`说书` / `治愈` / `小故事大道理`。**一眼看得出这一档是哪条线的** |
| 篇名 | 中文篇名（婴宁），不是拼音。目录名是给人看的 |
| 期号 | `E05` |

**项目目录和交付包是同一个命名**（`projects/醒木不响/_待发/` 里那些），
所以从交付包名一眼能回推到项目目录，反过来也一样。

**成片和字幕只按「身份」那一段命名**（`婴宁-E05.mp4` / `.srt`），
不带日期，**也不带类型** —— 一个说书目录里的片子标着"说书"是废话。
所以**挪档只是给目录改个名** —— 不用重出片，发布文案里的文件名也不用跟着改。

**`--ep E05` 照旧能用**（松匹配认得出目录名里的 `E05`）。

### 档期是自动挑的，不用手填

`shuoshu-parse.ts` 建目录的时候，从 `schedule.ts` 取**说书线下一个没被占的档**，
篇名从稿件第一行 `# 第 5 期《婴宁》` 里读。

**账本就是目录树本身，没有第二张表。** 谁占了哪一档，判据只有目录名 ——
两头记迟早对不上，这一条也是从老马线搬的。

⚠ **E01–E04 不改名**（已发布），它们还是 `<制作日>_liaozhai-EXX` 的老格式。
`parseDir()` 拆不动老格式就返回 null，`slugOf()` 退回「去掉日期就是身份」。

⚠ 目录名里的类型跟它所在的线对不上时（多半是手改目录名改错了），
`npm run schedule` 会**说出来**，不默默按目录走。

⚠ **治愈 / 禅佛典两条线还没接自动建目录**（那两条线本来就没有建目录的代码路径，
目录是手建的）。**手建的时候照同一条规则命名**，`npm run schedule` 就能把它们算进账。

### 上传的时候只开一个文件夹

`projects/醒木不响/_待发/` —— 三条线的片子收在一起，**一个包 = 一次上传**，
按名字排就是上传顺序。一个包里只有上传要的六样：
mp4 / srt / 横版封面 / 微信方版 / 自检小图 / 发布文案。

`npm run deliver` 重建（幂等，重跑不重复），`shuoshu:ship` 跑完会自动收一次。
里面是**硬链接**不是拷贝 —— 62 MB 的 mp4 不会变成两份，发布文案改哪边都是同一个文件。

发完把整个包挪进 `_已发`。没排档的叫 `未排期_`，改前缀就是排期。
细节见 [`../projects/README.md`](../projects/README.md)。

### 一页看完：`projects/醒木不响/index.html`（2026-08-24 加）

成片能直接播、旁边是**发布文案**（标题 / 简介 / 关键字三块原样端出来，
整块选中就能粘到平台）、头上标着**视频类型**和**发布状态**，
最后跟一张往后四周的**档期表**。双击打开就行。

跟交付包一起由 `npm run deliver` 重建；只想重出页跑 `npm run xingmu:index`。
**出页这一步挂在 deliver 里面，不是另一条命令** —— 分开的话总有一次收完包忘了出页，
那张页就开始说假话，而它看着一切正常。

**它不是第二本账，一个字段都不自己存**：

| 页上的 | 从哪来 |
|---|---|
| 发布状态 | 包在 `_待发` 还是 `_已发`，**只看它在哪个文件夹** |
| 视频类型 | 包名第三段（线名）＋ 文件名后缀认版本（常规 / 文字版 / 烧字幕） |
| 发布文案 | 包里的 `发布文案.md`，现读现解析 |
| 档期 | `schedule.ts` 的 `upcoming()`，**跟 `npm run schedule` 同一份数据** |
| 项目目录 | 包里的 `来源.txt` |
| **话题** | 发布文案里的 **`中心思想`**（说破句）；没有那一块的老期退回标题里最长的那一段 |
| **稿件库** | 各条线自己的**选题文档**（`topic-library.ts` 现读现解析）—— 这一栏是唯一一个不读交付包的 |

最后一条是有讲究的：排期表原来只有 CLI 那一份打印逻辑，网页要用就得再抄一遍循环 ——
**两处各算一套，迟早出现「命令行说空着、网页说排上了」**，而那种不一致没人核得出来
是哪边错的。所以先把它抽成 `upcoming()` 返回数据，两边各自去印。

页上从上到下：统计 → **档期**（往后四周）→ **话题**（做过什么）→ **稿件库**（还能做什么）→ 待发 → 已发。
左边一栏目录，滚到哪条高亮哪条；档期和话题两块是 `<details>`，嫌占地方点一下收起来。

**「稿件库」那一栏回答的是「还能做什么」**，四条线的选题表现读现解析：

| 线 | 读哪份 | 条目 | 话题那一列 |
|---|---|---|---|
| 说书 | [`liaozhai-17-cards.md`](liaozhai-17-cards.md) | 17 张选题卡 | 说破句 |
| 小故事大道理 | [`禅佛典向_小故事大道理_书目与稿件.md`](../zhiyu/禅佛典向_小故事大道理_书目与稿件.md) §四 | 24 期标题表 | 道理落点 |
| 心理洞察 | [`心理洞察向_书目与稿件.md`](../zhiyu/心理洞察向_书目与稿件.md) §9.4 / §四 | 24 期 ＋ 题库 53 条 | 取向 / 机制 |
| 治愈 | [`治愈系旁白书目_选题稿件.md`](../zhiyu/治愈系旁白书目_选题稿件.md) | 书目 20 本 | 治愈点 |

**治愈那一架的单位是「一本书」不是「一期」** —— 陶庵梦忆一本约 14 期。别拿那个 20 当期数。

三件要知道的：

- ⚠ **不读 [`禅佛典向_旁白书目_选题稿件.md`](../zhiyu/禅佛典向_旁白书目_选题稿件.md) 的首月 12 期排期。** 那份开篇就写着
  「本文替换前一版的 §五排期」—— 心经、信心铭那批抽象文本不再单独成期，
  降级成了每期收束的那一句引文。列出来等于给一堆做不了的选题。
- **「已出」是猜的，不是记的**：拿选题名字去已出片那堆（篇名＋标题＋说破句）里找。
  所以标的是「已出」不是「已完成」—— 没有第二本账记这件事，也不该有。
- ⚠ **解析的是人写的 markdown。** 每一架抓不到条目会**报出来**（页面上红字）：
  「这一架是空的」和「这条线真没选题了」长得一模一样，而前者是解析器坏了。

**话题那一栏按「一期」列，不按「一个包」列** —— 同一期出了常规版和文字版是两个包
（两次上传），但话题只有一个，版本收成一排小标签。一期占两行的话，那张表就从
「频道讲过什么」变成「传过几个文件」，而后者是上面那张表的活。

⚠ **改页面改不到源头。** 要改内容改 `发布.json` 重跑 `publish`；要排期给项目目录改前缀。

## 二、① 选题 + 扩写整稿

选题清单在 [`liaozhai-17-cards.md`](liaozhai-17-cards.md)。每一期先出一张内容卡片，再扩写。

### 怎么写，全在《说书稿件规范》里

**2026-08-26 起，稿件怎么写只有一份权威**：
[`说书稿件规范.md`](说书稿件规范.md)（全系通用，聊斋 / 怪谈 / 哥特线共用）。

这一节原来有三千多字的写作规范，**已经整段搬过去了** —— 留在这儿只会变成第二份，
而两份规范打架的时候没人核得出该听谁的（这个仓库在排期表、阈值上都吃过这个亏）。

规范里跟出片直接相关的几条，这儿只提醒**它们的下游代价**：

| 规范条目 | 不守的话，下游付什么 |
|---|---|
| §四.5 对白写「某某说：」用冒号 | 解析器认不出说话人，标注那一步要人逐条判（E01 十八段） |
| §二.1 一条 line ≤24 字 | 24 = 字幕一行的宽度（1920÷79）。超了 libass 折两行，字块长到 200px 高 |
| §五 beat 只用六种 | 十二种那版写稿时要纠结，而纠结的成本每期都在付 |
| §四.3 出声角色 ≤3 | 每多一个角色，配音和混音各翻一道 |
| §〇之二.1 字数按**实测 CPM** 折算 | 照规范表里的 190 写，中篇会做成 15 分钟，撞体检那条「短于 18 分钟」 |

**动笔之前先跑一遍稿件闸**（§一 的 ①.5）：

```bash
npm run shuoshu:lint -- ../shuoshu/liaozhai-E07-xifangping.md
```

它把规范 §九 那十几条全查了，**还会把机器判不了的那张必答清单印出来**
（人味儿四条 / 平读测试 / 说破层五条）。

## 四、③ 标注节拍

改 `script.json` 里每一段的 `beat`。**只用六种**（2026-08-26 从十二种砍下来的，
规范 [§五](说书稿件规范.md)）：

| beat | 作用 | 语速 | 句后静音 |
|---|---|---|---|
| `常规` | 推进 | 基准 | 0.3s |
| `顿` | 停一下 | 基准 | 0.8s |
| `贴近` | 拉近、细节特写 | −5% | 0.4s |
| `提速` | 连着推 | +8% | 0.15s |
| `落定` | 一段收尾 | −10% | 1.0s |
| `揭底` | 说破、翻转 | −15% | 1.2s |

三条硬约束，体检都查：**同一 beat 不许连续超过五句** ／ **`揭底` ≤12%** ／
非「常规」不低于 35%（低于这个基本等于没标，E01 就是这么翻过一次）。

⚠ **退役的六种（`扣子` `悬` `收` `点评` `引述` `引文`）新稿件不许用**，
但节拍表里**必须留着** —— E01–E05 的 script.json 全是老名字，删了那五期连体检都过不去。
归并去向见规范 §〇之二.3。解析器 2026-08-26 起自动打的是 `落定`（幕末）和 `贴近`（`「」`）。

⚠ **`落定` 1.0s 和 `揭底` 1.2s 超过了旧表「压到 1.0 秒以内」那条上限。**
那条上限有来历（绝对静音，长停像卡带；治愈线拿底噪验证过放长，实听被否）。
1.2 只比旧上限多两成，跟治愈线那次 2.5–3.5s 不是一个量级，值得试 ——
**但这是未经试听验证的放长，试听时专门听这一条。**

### 标注时的几条定规

- **冷开场照这个结构**：`顿` → `贴近` → `顿` → `揭底`。吊住 · 停死 · 平着揭
- **正面人物的台词一律 `揭底`**，不拔高。**正气一演就假**
- **长自陈用 `贴近`**，中间插说书人的 `常规` 断开，别让一个声音连讲两分钟
- **打斗只给三拍**：`提速`（光）· `提速`（声）· `顿`（静）。写多了就散
- **收束一路 `常规` 打底**，落点用 `揭底`，不复述剧情

### 五百多段怎么标（E06 的做法）

一条 line ≤24 字之后，一期从三百多段涨到五百多段，逐句手标不现实。
E06 用的是两层，脚本随期存档在 `节拍标注.mjs`：

1. **规则层**：按句长 / 位置 / 说话人给一个底，再强制打散连续超五句的
2. **覆盖层**：手挑的一百来处（冷开场结构、每幕的揭底点、说破、收束落点）

**规则层给的是底，不是判断。** 体检拦得住「一段没标」，拦不住「标得不对」——
所以试听那一步照旧要人，**重点听规则层给的那些段**。

标注落盘成 `节拍.json`（**按文本前缀存**），补稿之后重跑一次就能重新贴上，
段号移位一段都不会错。

## 五、④–⑦ 一条命令

```bash
npm run shuoshu:ship -- --ep E03
```

| 参数 | 干什么 |
|---|---|
| `--check` | 只体检，什么都不出 |
| `--from 场景` | 从这一步往后跑（音频 / 场景 / 封面 / 成片） |
| `--cover-sec 2` | 片头封面时长，默认 1.5 秒 |

跑之前 `scenes.json` 要写好，见下一节。整套约 **8 分钟**（音频 3 分 + 场景图 1.5 分 + 编码 3 分）。

### 体检拦的是什么

这条线最贵的失败**不是报错**，是「跑完了、文件都在、但东西是错的」——
只有出片之后用眼睛耳朵才发现，而那时候音频场景编码全白跑了。所以体检只看结果对不对：

- **节拍基本没标**（非常规 < 35%）→ 出来是全程一个调。**头号静默失败**
- 说话人还挂着 `needsReview` → 对白会按旁白念
- 场景段号超出稿件 → 那张图排在音频结束之后，等于没有
- 场景段号不递增 / 构图名不存在 / 题字超 14 字
- 封面缺字段 / 符号不存在 / 强调字不在钩子里
- （出了音频之后）**某张图挂超过 75 秒** → 观众盯着一张静止画面

有 `✗` 就停，不往下跑。`!` 是提醒，会继续。

### 护栏｜构图（2026-08-26 加）

```bash
npm run scene:check                 全部 84 个构图扫一遍（约 65 秒）
npm run scene:check -- --ep E06     只查这一期用到的（约 11 秒，ship 跑的是这个）
npm run scene:check -- 东廊 背像      只查这几个
npm run scene:check -- --png        顺带把越界的存到 out/构图越界/
```

量的是文件头那条硬约束：**x > 1620、y 90–1050 不要放深墨**（右栏两列竖排字和朱印的地盘）。
做法是把右栏摘掉渲一张，数那块区域里的深墨像素。

**这条规矩撞过四次才进机器**（E05 三次、E06 差点第四次），跟分幕字数是同一个病：
规范写在文档里、机器不查，等于只防君子。

⚠ **判据是标定出来的，不是推出来的。** 头一版按「浓墨叠在宣纸上」的公式取了亮度 150，
当场翻车 —— 夜路和路上各报四万像素，而那两张右边什么都没有。原因是 `mountains()` 画三层、
**层与层是叠加的**，三层合起来亮度落到 ≈152，正好压在界上。压到 110 之后两类差开一个数量级。
**要知道多少算多，就在渲出来的图上量。**

**它不掐断**（`--strict` 才掐）：E01–E05 里有一批越界的构图，那几期已经发布、不回改，
掐断的话这条护栏一天都活不下去。它的活是「说出来」，不是「拦住」。

## 六、scenes.json 怎么写

```json
{
  "seal": "聊斋",
  "cover": {
    "series": "liaozhai", "title": "聶小倩", "hook1": "她殺過兩個人",
    "hook2": "沒人要她償命", "accent": "殺", "seal": "其二",
    "epLabel": "夜聽說書 · 第二則", "motif": "孤灯"
  },
  "scenes": [
    { "anchor": "有一种人，过了半", "act": "冷开场", "comp": "空桌", "title": "这个女鬼杀过人" }
  ]
}
```

- `anchor` = **这一段开头的几个字**（全篇唯一），段号由它派生。**2026-08-26 加。**

  规范一直写着「按文本前缀定位，别写死段号 —— 补稿之后段号全移位，标注会静默错到别的句子上」，
  可 `SceneSpec` 里只有 `no`：**规范和 schema 是打架的**。节拍那边早就另存了一份前缀键的表
  （所以 E06 补稿之后一条没错），画面表没有，只能手工后移 68 张再逐条核 ——
  而「只核幕名」是不够的，E06 有一张的题字当场就对不上了。

  前缀在全篇必须**恰好命中一段**。命中 0 段或 2 段以上一律报错，**不挑一个凑合**。
  取到唯一为止通常三五个字就够（E06 六十八张，最长的前缀 5 个字）。
  段号跟锚点算出来的不一样时，体检和渲图**都会说出来**，不默默改了就走。

- `no` = 从第几段开始。**有 anchor 就不用写**；E01–E04 那几期只有 no，照旧能跑
- `comp` 见 `shuoshu-scene.ts` 的 `COMPOSITIONS`。**不够用就新增，别改已有的**
  （E01 的构图 E02 一个没动）
- `title` = 右侧竖排题字，**只写一句**，14 字以内。
  **写到 12 字以内**：13 字起字号从 60 掉到 50（不掉的话朱印会顶出画面下沿），
  掉下去之后就比字幕还小了
- `act` 只有「幕X」会打在画面上。「冷开场 / 引入 / 收束」是写稿的脚手架，不给观众看

**密度**：一分钟 2.5–3 张。16 分钟大约 40–45 张，24 分钟大约 **60–70 张**。

### 加新构图：别渲整期（2026-08-26）

```bash
npx tsx src/shuoshu-scene.ts --only 东廊,背像,两副碗筷
```

渲到 `out/构图预览/`，**不碰期目录里的 scenes/**（往那儿塞半套图，
出片会照单全收 —— 正是这条线最贵的那类失败）。

**为什么要有它**：新构图的坑只有渲出来才看得见，SVG 代码看不出「这个碗会被读成一把勺」。
反馈环原来是「改代码 → 渲整期 68 张 146 秒 → 看」；E06 那四个坑
（坐姿锥子 / 碗成勺 / 背像两个脑袋 / 墙横切塑像）每个都要走一轮，光渲图烧掉七分多钟。
现在三张 5.4 秒。

⚠ **这类坑消不掉。** E01 是人影 320px，E05 是花瓣/灯笼/墙三个，E06 是四个 ——
「渲出来会被读成什么」没有静态判据，只有眼睛能判。能做的是让每一轮便宜二十倍，
不是指望某一天不再踩。

### 画面上的字（2026-08-24 定）

右栏是**两列竖排**，加上底部的字幕，画面上一共三处字，**全部白字黑边**：

| | 字号 | 字重 | 颜色 | 在哪儿 |
|---|---|---|---|---|
| 字幕 | **79**（`FontSize=30`，倍率实测 ≈2.63） | Bold | 白字 + 黑描边 | 底部居中 |
| 题字（`title`） | 60（超 12 字降 50） | 700 | 白字 + 4.2px 墨色描边 | 右栏，x=1740 |
| 幕名（`act`） | 50 | 700 | 同上 | 右栏更右一列，x=1836 |

几条说明：

- **幕名从左下角挪到了右栏**（原来 30px / 0.45 透明度）。左下角那一版又小又淡，
  十七分钟里几乎没人注意到它，「让观众知道自己走到哪儿」等于没做。
  竖排从右往左读，所以幕名在题字**右边** = 先读到它，再读题字
- **字幕是画面上最大的东西**（112px）。原来的规矩是「字幕必须比题字小一档」，
  2026-08-24 作废：字幕翻倍，主次改由颜色和描边分。
  ⚠ 一行最多 24 字（1920÷79）。E05 最长一条 23 字，左右各剩 30px 正好塞下；
  再长 libass 自动折两行，字块往上长到 200px 高
- **字号不是像素，而且换算倍率不是 3.75。** 代码里原来写着「force_style 的数 ×3.75」，
  实测是 **≈2.63**（`FontSize=15` → 字宽 39.5px，30 → 79px）。**要知道多大就在成片上量。**
- **白字黑边的承重墙是那圈黑。** 宣纸底上白字本身等于没有。
  SVG 那头**一个字要画两遍**（先 stroke 后 fill）：stroke 是骑在轮廓线上的，
  只画一遍会把宋体的细横吃掉。写法见 `inkwash.ts` 的 `vtext`
- **加粗要喂字重文件，两处各喂一次。** 系统里装的思源宋是可变字体
  （`NotoSerifSC-VF.ttf`），resvg 和 libass 拿到它都只有默认实例，
  `font-weight="700"` / `Bold=1` **静默失效、不报错**（实测两个字重渲出来
  字节数一模一样）。所以场景图喂 `INK_FONT_FILES`、字幕喂 `fontsdir`，
  都指到 `fonts/NotoSerifCJKsc/OTF/`。**那个目录不在 git 里**（162M，见
  `fonts/README.md`），缺了会打一行 `!`，片子照出，只是字不粗

### 音波层（2026-08-24 加，四条线共用）

左上角一条跟着声音跳的方块柱（`src/wave.ts`，原型来自 `醒木不响/waveanim6.mjs`）。
**说书 / 治愈 / 小故事大道理 / 心理洞察四条线共用** —— 它们的画面都是静止的 PNG，
二十分钟一张脸不动最怕「像张图不像个片子」，这是唯一一个动的东西。

- **柱子高度 = 循环随机 × 音量闸门**（原型的 gated 版）。闸门直接从整期那条 wav 算，
  音频重出波形自动跟着变，不用对时
- **增益自动定**，不是原型里写死的 ×6：按「说话帧的 90 分位 ≈ 0.9 开度」反推。
  写死的话响度不同的线要么整条贴顶、要么整条趴着，**两种坏法都不报错**
- **颜色分两截**：深色 `#8C6A4A` 是听过去的，浅色 `#C4A882` 是还没到的 ——
  它顺带是个进度条。⚠ 原型里这一段是坏的（比例被乘了两次画布宽，结果整条永远深色），
  这里按它本来的意思实现。不想要就把 `wave.ts` 的 `PROGRESS` 关掉
- **位置分两套，不是一套**：
  · 说书线 `WAVE_POS`（左上角 72,58，22 根 640px）—— 右栏是题字、底部是字幕，左上是唯一剩下的留白
  · 治愈 / 小故事大道理 / 心理洞察 `WAVE_POS_ZHIYU`（贴下沿**占满一整行**，65 根 1920px），
    **字幕排在音波上面**（那三条线的 `MarginV` 跟着从 18 提到 34）
- **要占满一行就加根数，别把 640 那版拉宽** —— 拉宽会把 16px 的方块拉成长条，块感就没了
- 关掉：`--no-wave`
- 帧缓存落在 `audio/_wave/`（去重之后两万张小 png，约 30M），**已在 .gitignore 里**，
  每次出片先清空再建

⚠ **`loadSystemFonts: false` 是这层的性能命门。** resvg 默认每次实例化都扫系统字体，
这台机器一次半秒 —— 而这里要渲两万张。第一版没关，实测**每秒只出 2 张**，
二十分钟的片子要跑四个钟头；关掉之后 **350 张/秒**。音波层一个字都没有，字体一个都不用。

### 封面：一种版式，六个文件

**2026-08-23 改：以前有两套封面版式，现在只有一套。**

以前是这样 —— `shuoshu-cover.ts` 出七个文件（渐变靛青底 + 繁体竖排篇名），
管片头首帧和 B站/西瓜横版；YouTube 缩略图是**另一套版式、另一个脚本**，还得人工上传。
两套并行的结果是**缩略图那条从来没真跑过**：规范立在仓库根，五期一张图都没有。

现在成片第一帧、上传横版、微信 1:1，全部由 `yt-cover.ts` 那一套版式出，
数据写在 `scenes.json` 的 `yt` 块里：

```json
"yt": {
  "kicker": "聊斋 · 婴宁", "big": "不笑",
  "hook": ["压垮她的不是{官司}", "是婆婆那句{好话}"],
  "motif": "smile_flat", "palette": "ink"
}
```

| 文件 | 干什么用 |
|---|---|
| `cover.png` | 1920×1080，**成片第一帧**，出片那一步要用 |
| `YT_<篇名>.png` | 1280×720，**上传用**。YouTube / B站 / 西瓜同一张 |
| `YT_预览210.png` | **横版先看这张**，210px = 信息流里的实际大小 |
| `cover/wechat-1080x1080.png` | **1:1，微信公众号 / 视频号** |
| `cover/check-square-200.png` | **方版先看这张**，200px = 微信列表里的实际大小 |
| `cover/cover.svg` / `cover-square.svg` | 矢量源，出专辑封面或印刷尺寸时不用重画 |

⚠ **代价记在这儿，别当它不存在。** 规范 §〇 本来把两张图分开，因为任务不同：
缩略图要在信息流里让人点，首帧要接住已经点进来的人。并成一张之后，
**片子第一帧是主字（「不笑」）而不再是篇名（「嬰寧」）**，篇名只剩眉标那一行小字。
说书这条线篇名是身份，这是实打实的损失 —— 是知情的取舍，不是疏漏。
哪天觉得亏了，`shuoshu-cover.ts` 还在仓库里，把「封面」那一步换回去就行。

**方版是另排的一版，不是把横版裁方。** 横版主字占左边、图形占右边一整块，
裁成方的图形就没了一半。方版把图形挪到右上、主字压到中段、副标垫底 ——
元素一个不少，纵向排开。

### 版式规则在规范里，不在这儿

主字怎么取、副标怎么写、`{}` 怎么圈、motif 要满足哪六条契约，
全文见 [`../YouTube封面规范.md`](../YouTube封面规范.md)。**这儿不重复**，免得两处打架。
说书线只需记住三件事：

| | |
|---|---|
| 配色档 | `ink`（底 `#141C24` + 朱砂 `#D6452F`） |
| **主字** | **两个字、写简体、是钩子不是书名。**「嶗山道士」→「撞墙」。**体检会拦跟篇名重字的** |
| 验收 | 看 `YT_预览210.png` 和 `cover/check-square-200.png`。**在 1280 上好看不算数** |

钩子（副标两行）写**故事里最反常的那个动作**，不写形容词，
圈的是**对照关系的两端**（官司／好话、蟋蟀／孩子），不是形容词。
**别沿用上一期的句式** —— 同一个构造用第二次就成了套路。

### 体检在音频之前就拦

`yt` 块写错的话，**音频会白跑十几分钟才炸在封面那一步**。所以这几条挪进了体检：
没有 `yt` 块 / 缺字段 / motif 或配色档不存在 / 主字超过 3 字 / 主字跟篇名重字 /
副标不是两行 / 单行超 10 字 / 重点词圈超过两处。

## 八、⑨ 发布文案

跟封面一样是**频道规范，每期必出**，不是事后补的。

### 新期照治愈线那套写：发布文案是复制源，不是分析报告

**打开就该整块选中、粘到平台输入框里。** 只出四样：

| | 内容 |
|---|---|
| 标题 | 一行 |
| 简介 | 前两行（列表页只显示这些）+ 正文 + 章节 + 频道介绍 + 出处，**一整块** |
| 关键字 | `#` 间隔，一整块 |
| 文件 | 成片 / 字幕 / 封面 / 微信 1:1 的路径表 |

外加发片前的核对清单（那是待办不是分析，留着）。

**备选标题、关键字取舍、写法上的理由**全部不进这份文档 —— 那些放在
`shuoshu/出片手册.md`（也就是这儿）或各期的 `方案.md`。
混在一起的话，人一边滚一边挑，挑的时候就容易连说明文字一起复制进去。

治愈线是**生成**的（`joke-video/src/zhiyu-publish.ts` 读各期 `发布.json`），
顺带解决了两个人工项：章节时间戳按段落定位自动算（不用手加片头秒数），
片长去 ffprobe 量成片（不是拿音频时长加片头算，那个差几秒）。
说书线做 E03 的时候可以把那个脚本推广过来 —— 现在它还是治愈线专用的。

**E01 / E02 那两份是旧格式（带备选表和大段说明），不回改。**
已经出过的片子不动，新期按上面这套走。

**章节时间戳要算上片头 1.5 秒。** 手写的话这是最容易漏的一条。

**标题不用感叹号、不用「震惊」「细思极恐」。** 检索词该带的一个不少，
但要长在句子里，不是堆在后面。

## 九、目录里应该有什么

一期做完，`../projects/说书/<档期>_<篇名>-EXX/` 里少一样就是没做完
（档期长这样：`2026-08-25_1800JST`，见 §一之二）：

| 文件 | 是什么 |
|---|---|
| `<篇名>-<期号>.mp4` | 成片（片头 1.5 秒封面）。**不带日期** —— 挪档不用改名 |
| `<篇名>-<期号>.srt` | **跟成片对齐**的字幕，传平台用这份 |
| `cover.png` | **成片第一帧**，1920×1080。2026-08-23 起跟上传那张同一套版式 |
| `YT_<篇名>.png` + `YT_预览210.png` | 上传用的横版 1280×720 + 210px 自检 |
| `cover/` | `wechat-1080x1080.png` + `check-square-200.png` + 两个 svg 源 |
| `audio/全片.wav` `.srt` `.manifest.json` | 音频 + **跟音频对齐**的字幕 + 时间轴 |
| `scenes/` | 场景图 |
| `script.json` / `scenes.json` | 标注过的稿件 / 画面清单 |
| `发布文案.md` | 标题、简介、标签、核对清单 |

`ship` 最后会逐项核对，并验一次「字幕首条 = 封面时长」。**现在这些全在它手里了** ——
`YT_*.png` 以前不归它管，是因为那张图另一套脚本、另一套版式；并成一种之后就没这个缝了。

## 十、想做成每天一期？

**能自动的是 ②④⑤⑥⑦，也就是 `shuoshu:ship` 那一条。**
① 写稿、③ 标注要模型，⑧ 试听要耳朵。所以只有两条路：

**甲 · 存稿 + 纯定时**（真无人值守）
先把 N 期的稿子写完、标注完，每天定时跑一次 `shuoshu:ship`。
出片全自动，**但发布仍然要人过一遍**。适合「攒够一批，稳定日更一个月」。

**乙 · 每天叫一次模型**（写稿也自动）
定时任务里跑一个 agent：从 17 张卡片里取下一期 → 写稿 → 标注 → `shuoshu:ship`。
好处是不用囤稿；代价是**稿子质量每天都在赌**，而说书的成败九成在稿子上。

**建议走甲。** 这条管线的机器部分已经很稳（体检 + 护栏 + 交付物核对三道），
不稳的是写作。囤稿是把不确定的那部分留在人手里，而不是每天赌一次。
