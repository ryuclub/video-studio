# 儿童故事出片方案

> 《一页故事》这类**旁白叙述型儿童故事**的完整流程。
> 段子（对话反转）看 [README.md](README.md)，说书（聊斋）看 [../shuoshu/出片手册.md](../shuoshu/出片手册.md)。
>
> 第一条走通的片子：第 01 页《乌龟为什么不搬家》，2:36.3 / 34 句 / 449 字。
> 落在 `projects/2026-08-19_page-01-turtle/`，可以直接照着抄。

---

## 一、一条命令

```bash
npm run ship -- jokes/page-02-cat.json
```

站位 → 配音 → 对齐 → 音画同步核对 → 试听音轨 → 逐镜静帧 → 成片 + 封面，
一步失败就停在那里，不往下走。**每一步都吃上一步的产物**，
带着错误往下跑只会把错误摊到更贵的地方。

常用变体：

| 命令 | 用在什么时候 |
|---|---|
| `npm run ship -- <稿件> --check` | 跑到试听为止，不渲片。**新稿件第一次都该这么跑** |
| `npm run ship -- <稿件> --from 成片` | 听着对了，接着渲 |
| `npm run ship -- <稿件> --from 站位` | 中间某步挂了，修完从那步续 |
| `npm run ship -- <稿件> --keep-voice` | **只改了画面**，配音原样复用，省两分钟合成 |

⚠ `--keep-voice` 在**台词改了的时候绝对不能用**——音轨是旧的、字幕是新的，对不上。

步骤名：`站位` / `配音` / `对齐` / `同步` / `试听` / `静帧` / `成片`。

## 二、这条命令不负责的两件事

### ① 写稿

`jokes/*.json` 要先有。从脚本集的故事本体（300–400 字）扩写成配音稿、拆分镜、
标念法，是编剧判断不是规则——体检拦得住「字段写错」，拦不住「这一镜不该切」。

**字数按 450–520 字写。** 脚本集写的是「2.5–3 分钟 / 600–750 字」，
但实测语速 **4.26 字/秒**（《小老鼠做蛋糕》473 字 / 111s 纯配音），
加上 `bedtime` 的三层停顿，700 字会跑到 3 分 40 秒以上，超出它自己定的片长。
**以片长为准，不是以字数为准。**

估算公式：`片长 ≈ 字数 ÷ 4.26 + 句数 × 0.9 + 换镜数 × 1.05 + intro + hold`
（第 01 页：449 字 / 34 句 / 6 镜 → 实测 156.3s，留白占 31%）

### ② 试听

跑完这条命令**成片是能看的，但不代表能发**。节奏对不对只有耳朵知道，
`--check` 就是为这一步留的。说书线 E01 的教训：跳过试听直接出全片，
主讲人机械偏慢，全片重来。

## 三、稿件长什么样

照抄 `jokes/page-01-turtle.json`。关键字段：

```jsonc
{
  "type": "B",                 // 旁白叙述。不是 A（对话反转）
  "scene": "pond",             // 主场景，逐句可以用 line.scene 换
  "pace": "bedtime",           // 三层停顿一次配齐，别自己试数值
  "intro": 3,                  // 片头卡停 3 秒（系列规定）
  "hold": 3.2,
  "series": { "name": "一页故事", "no": 1 },   // 片头卡「一页故事 / 第 01 页」
  "hook": "家不是一个地方，是你愿意每天背着走的那样东西",  // 片尾金句
  "cover": { "title": "我一直在搬", "at": 135.35 }        // 封面大字 + 取帧时刻
}
```

**角色**：旁白用 `"rig": "none"`（只有声音）。其余见 [分镜手册-SHOT.md](分镜手册-SHOT.md)。

**念法**：旁白**只用 `叙缓` / `叙平` / `叙快`**——这三个只动语速、pitch 恒为 0。
一旦用了带 `pitchHz` 的念法，同一个旁白会「串音」，听着像换了个人。
角色台词不受这条限制。

## 四、今天踩出来的几条，别再踩

### 1. 三个角色横排放不下

实测包围盒：兔 236px + 猫 322px + 龟 360px = 918px，1080 宽只剩 162px 分三道空隙。
**三人同框一集用一次就够**，其余拆成两人镜。`npm run layout -- <稿件> --fix`
是实测光栅化量出来的，不是按 `length/2` 估的，信它。

### 2. 场景里的固定物件会挡住角色

第 01 页的石头第一版顶边横穿龟壳，出来是「小龟站在石头上」。
**地上的东西要压到贴地**，顶边只比角色脚底高一点。

### 3. 旁白不能断言画面里没有的东西

写过一句「壳上有一道新的划痕」想给「我一直在搬」补物证，但龟壳上并没有划痕。
**要么画出来，要么别说。**

### 4. 角色的技术限制要变成人设

`cat` rig 的嘴不能动（原稿胡须鼻子嘴在同一条路径里）。解法不是硬给它台词，
是让旁白转述，并在词里写成「猫不爱说话，只说了四个字」——限制变成性格。

### 5. 白天戏用白天的形象

猫有 `night`（深紫渐变 + 橙色发光眼）和 `day`（橘猫 + 墨绿眼）两个变体。
夜猫摆进晨光池塘边一眼穿帮。`"variant": "day"`。

### 6. 发布文案在写稿阶段就填

`方案.md` 第四节。**标题、封面大字、收尾金句是同一个钩子的三种长度**，
分开想必然对不齐。而封面是从成片里取帧的，等渲完才发现封面该换就得重渲。
没填完 `build` 会直接拦住（`--anyway` 可强过）。

第 01 页的三个尺寸：
> 金句「家不是一个地方，是你愿意每天背着走的那样东西」
> → 标题「一页故事 01｜大家都搬走了，只有乌龟一动没动」
> → 封面大字「我一直在搬」

## 五、改了什么，要重跑哪一步

| 改了 | 最省的跑法 |
|---|---|
| 台词 / 念法 / pace | `npm run ship -- <稿件>`（全套，配音必须重来） |
| 站位 / 尺寸 / 场景 / 形象 | `npm run ship -- <稿件> --keep-voice` |
| 只改 `hook` / `cover` / 字幕文案 | `npm run ship -- <稿件> --keep-voice --from 静帧` |
| 管线代码（rig / scene / render） | 先 `npm run scene -- <场景>` 或 `npm run shotdoc` 单看，再全套 |

## 六、时间账

一条 2 分半的片子，机器时间约 **10 分钟**：

| 步骤 | 耗时 |
|---|---|
| 配音（34 句 Edge TTS + 变声） | 约 2 分钟 |
| 对齐 / 同步核对 / 试听音轨 | 各几秒 |
| 逐镜静帧 + 预览页 | 约 1 分钟 |
| **成片（4690 帧）** | **约 8 分钟**（6 线程；单线程要 30 分钟） |

真成本是**审稿**，不是机器。

渲染慢的原因只有光栅化：单帧 240ms 里拼 SVG 占 1ms、resvg 占 99.6%。
已经改成多线程（`JOKE_WORKERS=N` 可调，`=1` 退回单线程），
并行不改画面——同代码单线程 vs 6 线程，406 帧逐帧 md5 完全一致。

> 说书线（`shuoshu-*`）不吃这个成本：那边是现成 PNG 交给 ffmpeg 按时长拼，
> 一次光栅化都不做，所以 16 分钟的片子反而比这里 2 分半的还快。
> 两条线的差别是设计上的——儿童故事的口型、呼吸、眨眼、三层视差推镜都在逐帧变，
> 没有「静止的那张图」可以预渲。

## 七、发片前的人工清单

机器查完之后，剩下三件只有人能做（`ship` 跑完会再打印一遍）：

- [ ] **试听** `<项目>/<id>-试听.wav`——节奏赶不赶、换镜那一拍够不够长、落点句有没有慢下来
- [ ] **逐镜** `<项目>/index.html`——画面和台词对得上吗
- [ ] **内容风控**

发布文案在 `<项目>/方案.md` 第四节，直接抄。
