## 0. 一句话定位

一个用公开事实与官方文件、以冷面口吻拆解发达国家制度荒谬的英文短视频频道。

它不是新闻频道，不是评论频道。它是**制度荒谬观察员**——只讲事实，让荒谬自己说话。

**元规则**：所有工程规范服务于一件事——**每一句陈述都能指回一个公开来源**。注意这句话不等于"每条视频都得有统计数据"——见 §3.2。

---

## 1. 边界

**做什么**

- 美、加、英、法、西等发达国家的政府政策、公共服务、基础设施、监管失灵、公共生活中的荒谬现象
- 欧盟层面的通用槽点
- **日本、韩国、新加坡、澳洲**的同类题材——常备线，不是补充

**不做什么**

- **不涉及中国**（唯一的硬边界）
- 不做政治人物的人身攻击。骂制度，不骂人
- 不做突发新闻，不抢时效
- **不裁定有争议的因果与责任归属**——见 §3.2

**【v4 修订】关于治安、犯罪率这类题材**

v3 把"城市治安与犯罪率"整块划进禁区，是我收得太紧了。这类现象本身是公共生活的一部分、有大量公开报道、本国人天天在谈，一刀切排除掉是没道理的。

真正需要守的界线不在**题材**上，而在**层次**上：

| 层次 | 例（以"超市锁柜"为例） | 能不能做 |
|---|---|---|
| **现象层** | 牙膏被锁进玻璃柜；要按铃等员工；十年前不是这样 | ✅ 可做。看得见、拍得到、多方报道一致 |
| **数字层** | 损耗率百分之几；防损投入多少钱；平均等待几分钟 | ✅ 可做，但数字要有来源与时点 |
| **因果层** | 是因为盗窃猖獗？还是企业夸大？还是执法松弛？ | ⚠️ 有分歧时**不裁定**，把分歧本身当内容 |

守住这条，治安题材完全可以做，而且做得比一般吐槽更狠——见 §3.4 的改写案例。

## 2. 频道识别

**名称方向**（待定）

| 思路 | 例 |
|---|---|
| 账本感 | The Line Item / Receipts |
| 官僚感 | Department of Obvious / Section 4 |
| 中性冷 | Stated Figures / As Reported |

硬标准：英文母语者一眼能读能拼、不像翻译腔、不含国别暗示。

**视觉识别**：红 `#ff4757`、蓝 `#3742fa`、边框 `#111111`，粗黑边 + 块状硬阴影。全片**只有一种颜色是活的**：强调红。数字用等宽（JetBrains Mono），标题字幕用无衬线粗体（Archivo）。

**主讲人**：无脸叙述者（剪影 / 只有手 / 帽子在画角），现有速写小人骨架改造。只需四个动作：站立待机、说话、点头摇头、一个手势。

## 3. 选题

### 3.1 六条常备线

| 线 | 高确定性痛点 |
|---|---|
| 美国 | 医疗账单、救护车费、小费通胀、政府停摆、航空附加费、超市锁柜 |
| 英国 | 水务排污与分红、NHS 指标、HS2、邮局冤案、路面坑洞 |
| 加拿大 | 家庭医生短缺、电信资费、政府 App 造价 |
| 法国 | 罢工、退休改革、行政手续、大型工程超支 |
| 西班牙 | 青年失业、住父母家、旅游过载、通勤铁路 |
| 亚太 | 日本传真与印章、韩国加班、新加坡罚款清单、澳洲跨州规章 |

### 3.2 【v4 重写】两级来源规则

v3 要求"每条都得有一手统计数据"，这条太重了，会把大量真实、可讲、观众有共鸣的现象挡在门外。**这个频道的核心不是做统计，是讲事实。** 但"讲事实"要成立，得先分清在讲哪一种事实。

**A 级 — 现象性陈述**（"这件事在发生"）

- 门槛：**两个以上相互独立的公开来源**，或一个官方通告，或可拍到的实景
- 可用：主流媒体报道、企业公告、地方政府通知、行业协会声明、实地照片
- 例：牙膏被锁柜、火车常年晚点、办一件事要交十份材料

**B 级 — 数字性主张**（"规模是多少"）

- 门槛：**一手来源**（政府部门、监管机构、审计机构、议会文件、行业年度调查、企业财报），且**必须带时点**
- 媒体转述的数字要回溯到原始文件再用
- 非美元/英镑的数字，台词里紧跟一个**可验证的日常物价**参照（房租、月票、一顿饭、一年电费）

**C 级 — 因果与责任归属**（"为什么会这样、谁的错"）

- **共识性的**（如"HS2 超支源于设计变更与通胀"，官方审计报告已认定）：可以讲，注明出处
- **有分歧的**（如"锁柜是因为盗窃猖獗"）：**不裁定**。做法有二——
  - 要么略过成因，只讲现象与后果
  - 要么**把分歧本身当成内容**：把两边各自的官方说法并排放出来，一个字不评论。这往往比选边更有力

**立项前问四句话**

1. 这是 A 级还是 B 级陈述？来源够不够？
2. 有没有不知不觉滑进 C 级？
3. 有没有一个能砸屏幕的细节（数字、时长、荒谬对比）？
4. 本国人自己是不是已经在谈这件事？

### 3.3 事实核查规程

- A 级两源、B 级一手源，全部记进来源表
- 数字带时点
- 至少一条**反面事实**（支持者的理由，或数据在改善的部分）
- 来源进**置顶评论 + 画面角标**

**画面角标规格**：陈述出现时右下角常驻一行小字，如 `Environment Agency, 2024 storm overflow data`。字号 28px，`#8a8a8a`，右边距 60px，**底边距 320px**，与该陈述同生同灭。合成脚本用 `credit` 字段实现（§7.3）。

底边那个 320 不是随便定的：要在字幕底边（MarginV 520）**之下**，又要在 Shorts 底部 UI（约 250px）**之上**，中间可用的区间就这么窄。原先写的是 560，跟字幕必然重叠 —— 见 §6.6。

### 3.4 【v4 改写】案例：超市锁柜怎么做才对

v3 把这条稿整个否掉了，判重了。选题没问题，**问题在于原稿跳进了 C 级并选了一边**。

**原稿的致命句**："真正的小偷提着垃圾袋大摇大摆走过保安。" —— 这是在断言"盗窃猖獗且执法失灵"，属于有分歧的因果判断，且来源是流传的视频画面而非任何文件。

**改写方向：把分歧本身做成内容。**

素材是现成的、双方都是公开记录：一家大型连锁药房的财务高管曾在财报电话会上说公司此前"哭得太凶"，损耗率已从约 3.5% 回落到 2.5% 上下，并承认花重金请的私人保安"基本无效"；同一家公司后来换了管理层，新任高管又公开表示损耗"仍是系统性问题"；另一些零售商则始终坚称问题严重。这些全部是可查的公开表态。

于是稿子可以这么走（T6 骨架）：

```
1  现象：牙膏被锁在玻璃柜里。你得按铃，然后等。
2  官方理由：公司说，这是为了防盗。
3  "And they are right."
4  硬事实并排放：同一家公司的财务高管说过"我们哭得太凶"，
   损耗率在回落，重金请的保安"基本无效"；
   两年后同一家公司又说这是"系统性问题"。
5  一个字不评论 → 柜子还锁着。
```

**这个版本比原稿狠得多**，因为它没有指控任何人，只是把同一家公司自己的两套说法摆在一起。而且它全程停在 A 级和 B 级，一步都没踏进 C 级。

**这就是这个频道该有的做法**：不裁定谁对，只呈现"官方说法自己在打架，而现实一动不动"。

## 4. 稿件

### 4.1 结构

```
0–3s    钩子：一个砸屏幕的数字或一句荒谬陈述，无铺垫
3–15s   升级：三个事实，一个比一个荒谬
15–25s  转折：对比 / 时间线 / 反面事实
25–30s  落点：一句冷收 + 引导问题（走 §8.1）
```

### 4.2 六个模板

| 编号 | 名称 | 做法 |
|---|---|---|
| T1 | The Receipt | 全程只念一张真实账单，每项停一秒 |
| T2 | Two Countries, One Task | 同一件事在两国的步骤对比，不下结论 |
| T3 | The Bureaucrat | 扮演极度平静的官僚，合规地解释荒谬 |
| T4 | Number Cold Open | 第一秒只有一个数字，三秒后揭晓 |
| T5 | Timeline Escalation | 承诺→涨价→再承诺→罚款→照旧 |
| T6 | The Defense | 认真为该政策辩护，理由一条比一条站不住 |

**T6 的可复用骨架**

```
1  提出官方理由（原话转述，不加工）
2  "And they are right."          ← 真心承认，不阴阳怪气
3  "Because …"  接一条同样来自公开记录的事实
4  这条事实自己击穿了第 1 条，你一个字评论都不加
```

第 2 步的真诚是关键——一旦带上讽刺腔，结构就塌成普通吐槽。第 3 步必须是硬事实，不能是段子。**当官方自己有两套说法时，第 3 步直接引用另一套，效果最好**（§3.4）。

### 4.3 语气与例外

默认：**冷面播报，靠停顿制造笑点，不靠形容词**。

例外：涉及真实受害者的题材（冤案、事故、致死）一律不搞笑——全程克制陈述，不出角色，不加音乐，结尾不放引导问题。这类篇目是频道的可信度锚。

### 4.4 三份稿

| 稿 | 用途 |
|---|---|
| **稿面 EN** | 进字卡、进字幕、进来源核对，含 `‖` 停顿标记 |
| **TTS EN** | 只进引擎（现在是本地 Kokoro，§5.1），数字已文本化，**无任何方括号以外的自造标记**。这一份要跟 `分句.mjs` 的 `text` 逐字一致，`配音.mjs --check` 会比 |
| **中文校对版** | 只给自己看，不进音频、不进字幕 |

### 4.5 TTS 文本预处理与停顿

**数字文本化**（不要把符号扔给引擎）

| 稿面 | TTS 稿 |
|---|---|
| £102.7bn | One hundred and two point seven billion pounds |
| 7.28m | Seven point two eight million |
| 2036–2039 | Twenty thirty-six to twenty thirty-nine |
| A&E | A and E |
| NHS / HS2 | N H S / H S two |

顺带解决了另一件事：**字卡显示阿拉伯数字（眼睛读得快），音频读英文全称（耳朵听得懂）**。

**停顿：三层做法，一层比一层可靠**

1. **标点**——v3 引擎的停顿主要由标点与断句决定。句号、逗号、省略号本身就是最自然的控速手段，写稿时就该把节奏写进标点里
2. **分句生成**——按稿面的 `‖` 标记切分，一句一个音频文件
3. **ffmpeg 插静音**——在合成阶段按 `‖0.4` / `‖0.8` / `‖1.2` 硬插纯静音切片

**绝对不要用自造的方括号标记控制停顿。** 引擎不认识的方括号内容有被直接念出来的风险，整条音频作废。方括号只用于确认存在的情绪标签（如 `[sighs]`），前后各留一个空格，一句一个，全稿不超过 3–4 个；不确定是否被支持的就不用。

## 5. 音频

### 5.1 规格

**引擎是 Kokoro，跑在本地，不是 ElevenLabs**（2026-09-09 定，理由见下）。

| 项 | 规格 |
|---|---|
| 引擎 | **Kokoro-82M v1.0 ONNX**（`kokoro-js`，q8 / CPU），本地跑，零调用成本 |
| 音色 | **`bm_george`** —— 英式男声，Kokoro 里质量最高的一档（B / C） |
| 速度 | **`speed: 0.9`**，实测净语速 **1.71 词/秒** |
| 文本 | 走 §4.5 的 TTS 稿，**逐段**生成，文本写在 `分句.mjs` 里（§5.2） |
| 停顿 | 标点 + 分句 + `配音.mjs` 段间插静音 |
| 人声响度 | **−16 LUFS**（双遍 loudnorm，TP −1.5） |
| 采样率 | 48kHz 单声道 PCM（Kokoro 原生出 24kHz，`配音.mjs` 转码时归一） |
| 音乐 | 比人声低 18–22dB。**`db` 是相对那首曲子原始电平的衰减，不是绝对目标** —— 见下 |
| 版权 | 音乐只从 YouTube 音频库 / Epidemic / Artlist 取；人声本地生成，无版权问题 |

**逐段验收**：每段生成后先听再入库，重点听长数字与专有名词。批量生成后统一听，返工成本翻倍。

#### 背景音乐怎么配（2026-09-09）

曲子放**全频道共用库** `projects/高总/_音乐/`，时间表这么写：

```js
music: { file: '_音乐/zhege-hao.mp3', db: -22 }
```

`_音乐/` 开头走共用库，其余相对本条工作目录 —— 跟 `clip` 的 `_素材/` 同一个约定，
解析只在 `自检.mjs` 的 `音乐路径()` 一处。

⚠ **`db` 必须按那首曲子实测的 LUFS 算，不能照抄。** 它是 `volume` 滤镜的衰减量，
相对的是**这首曲子自己的电平**：

```
db =（人声 LUFS − 差值）− 音乐原始 LUFS
```

`zhege-hao.mp3` 实测原始 **−14.03 LUFS**，人声归一在 −16，取 20dB 差 →
目标 −36，衰减 **−21.94 → db: -22**。换一首曲子原始电平可能差十几个 dB，
照抄这个数会让音乐要么听不见要么盖住人声。`自检.mjs` 拦两件事：
没写 `db`（硬伤）、`db > -12`（提醒，衰减太小）。

**混音链**：`-stream_loop -1` 循环填满 → `volume` 衰减 → `atrim` 裁到片长 →
**淡入 0.8s ＋ 淡出 0.8s** → `amix …:normalize=0` 跟人声混。
（淡入是 2026-09-09 加的，原来开头是硬切 —— 音乐突然出现比没有音乐更显眼。）

**怎么验证音乐真的混进去了**：数静音段。人声轨在停顿处是数字静音，加了音乐就不是了 ——
实测 `silencedetect` 从 **9 段降到 2 段**（剩下的是首尾淡入淡出）。
整体响度几乎不动（−15.97 → −15.99），因为衰减 22dB 的音乐对 LUFS 贡献很小 ——
**所以「响度没变」不能当成「音乐没进去」的证据，得数静音段。**

⚠ **版权**：音乐是 Content ID 命中率最高的一类素材，比画面更容易被打。
每首都要在 `_音乐/来源.md` 里记清来源和授权，**那一栏空着不能发片**。

#### 为什么是 bm_george

Kokoro 全部 28 个音色里，**英式男声只有 4 个**。同一句 12 词、同为 `speed: 0.9` 的实测：

| 音色 | 质量 / 总评 | 时长 | 净语速 | |
|---|---|---|---|---|
| **`bm_george`** | **B / C** | **7.00s** | **1.71 词/秒** | **在用** |
| `bm_fable` | B / C | 6.20s | 1.94 词/秒 | 音质同档，但快 13% |
| `bm_lewis` | C / D+ | 6.95s | 1.73 词/秒 | 语速接近，音质低一档 |
| `bm_daniel` | C / D | 5.85s | 2.05 词/秒 | 最快，音质最低 |

选 george 的理由是**它最慢**。这条线靠反话吃饭，「To be fair, budgets rose seventeen percent.」
这种句子得说得慢才有反讽的味道 —— 语速慢在这儿是优点不是缺点。fable 音质同档但快 13%，
听感更像正常播报，反讽的落点会滑过去。

> ⚠ **换音色 = 改片长 = 时间码全部作废。** 四个音色的语速差最多 16%（george 1.71 →
> daniel 2.05 词/秒），整片估算 50s ↔ 43s。任何时候换 `分句.mjs` 的 `voice`，
> 都必须重跑 `出声.mjs` ＋ `配音.mjs`，拿新的实测时间码重排 `时间表.mjs`。

#### 烟嗓做不出来，别再找了

**Kokoro 里没有烟嗓 / 沙哑音色，靠挑挑不出来。** 它的音色元数据只有
`name / language / gender / traits / targetQuality / overallGrade`，其中 `traits`
只是几个 emoji（❤️🔥🎧🚺🚹），没有任何音质描述字段。四个英式男声全是中性播报底子。

美式男声里 `am_onyx`、`am_fenrir` 更低沉，但**英国题材绝不用美音**（这条不因音色难找而放宽）。

试过用变声层后期做（`joke-video/src/audio/morph.ts` 的 `TONE.raspy` / `thick` / `aged`，
`rubberband` 在，pitch 与 formant 能解耦），产物在 `projects/高总/_试音/烟嗓/`。**结论是不用**，
正片保持 george 原声。两条实测记录留在这儿，省得下次重走：

- 变声链对时长的影响是 **−0.01s**，四个音色都一样 —— 变声不会破坏时间码，这一点是安全的；
- `TONE.thick` 里的 `lowpass=f=9000` 和压缩器，会把 `TONE.raspy` 的 exciter 刚加上去的高频泛音
  又削回去。**烟嗓的「砂」住在 2–5kHz，压暗和加砾是打架的** —— 要叠这两个得重调 lowpass，
  不能直接 concat。

真要烟嗓只有两条路，都不在当前方案里：GPT-SoVITS 克隆一段有授权的英式烟嗓参考音
（链路是通的，见仓库 `voice-clone/`），或回到 ElevenLabs 的 voice library / Voice Design。

#### 语速实测推翻了 §4.1 的长度设定

两个引擎独立测出同一个数：

| 引擎 | 音色 / 参数 | 净语速 | 坑洞篇整片 |
|---|---|---|---|
| Edge TTS | `en-GB-RyanNeural` `+0%` | 1.99 词/秒 | 50.48s |
| **Kokoro** | **`bm_george` `speed 0.9`** | **2.00 词/秒** | **50.15s** |

（这两个是整片 88 词的净语速；上面那张表是单句 12 词的，句子越短拖腔占比越高，所以数值略低。）

两个引擎差 0.01 词/秒、整片差 0.33 秒。**这个数可以当结论用了。**
而 §4.1 仍按「30 秒」写，交接稿 v5 给的「2.5 词/秒」也偏乐观。88 词的稿子实际要 **50 秒**。
§4.1 的修正还没并进来，见文末待并清单。

### 5.2 音频链路

原方案只写了规格，没写「逐段 TTS 怎么变成一条 voice.wav」—— `build.mjs` 是直接假设它已存在的。
这个断点由两个脚本补上，共用同一份配置：

```
                    gao-2d/稿件/<slug>/分句.mjs        ← 音频侧的机器事实源
                        ↓                   ↓
        node gao-2d/出声.mjs <slug>    node gao-2d/配音.mjs <slug>
        Kokoro 本地逐段生成            拼接 → 插静音 → 双遍 loudnorm → 回吐时间码
                        ↓                   ↓
   projects/高总/<slug>/audio/段/    projects/高总/<slug>/audio/<slug>_voice.wav
        01.wav … 09.wav                        ↓
                                        填回 时间表.mjs → build.mjs
```

**分句清单** `gao-2d/稿件/<slug>/分句.mjs`：

```javascript
export default {
  slug: 'uk_potholes',
  dir: 'audio/段',                       // 相对 projects/高总/<slug>/
  out: 'audio/uk_potholes_voice.wav',    // 必须跟 时间表.mjs 的 audio 一致
  targetLUFS: -16,
  voice: 'bm_george',                    // §5.1；换它就得重跑整条链
  speed: 0.9,
  segments: [
    { file: '01.wav', pauseAfter: 1.2, text: 'Ninety-seven years.' },
    // …
    { file: '09.wav', pauseAfter: 0.0, text: 'Three times. One hole. How long has yours been there?' },
  ],
}
```

`pauseAfter` 对应稿面里**落在段尾**的 `‖` 标记。**改节奏只改这一列**，不碰音频也不碰画面配置。

#### text 为什么在这儿，工作表 §3 也有一份

方案 §7.2 说工作表是「唯一的中枢文件」，交接稿 v2 说分句清单是「音频侧的单一事实源」——
两个「唯一」不能都成立，所以分工：

- **工作表 §3 给人看**，跟稿面、来源表排在一起，改稿在那儿改；
- **分句清单给机器读**，脚本不去解析 markdown（那太脆）；
- **两份会不会飘 —— 交给闸**：`配音.mjs --check` 逐段比对文本，不一致就报硬伤、退出码 1。

所以改文本要两处一起改，改完跑一次 `--check`。

#### 出声.mjs

```
node gao-2d/出声.mjs --音色                列出全部音色，英式男声单独拎出来
node gao-2d/出声.mjs --试音                一句话跑遍英式男声，出到 projects/高总/_试音/
node gao-2d/出声.mjs uk_potholes           批量出 01.wav…09.wav
node gao-2d/出声.mjs uk_potholes --only 7  只重出第 7 段
```

每段落盘后当场量时长与词速并汇总 —— §4.1 的长度设定要靠这个数攒出来（见 §5.1 末）。

> ⚠ `kokoro-js` 的 **`list_voices()` 返回 `void`**，只往 stdout 打印。要拿数据得用
> `tts.voices` 这个 getter。交接稿 `tts_kokoro.mjs` 在这儿会 `Object.keys(undefined)` 直接抛。
>
> ⚠ 筛性别不能用 `/male/i` —— **它会把 `Female` 也匹配上**。要整串匹配 `/^male$/i`。

#### 配音.mjs 做四件事

1. **核对**分句清单跟工作表、时间表对不对得上（见下）
2. 按顺序拼接，段间硬插纯静音（48kHz 单声道 PCM）
3. 双遍 loudnorm 归一到 −16 LUFS（先测再套；单遍是盲的，会偏 1–2 LUFS）
4. **回吐每段的实测起止时间码**，并跟 `时间表.mjs` 的预填值比总长

第 4 件是这个脚本存在的理由 —— 它闭合了「时间码从音频来」那条规矩（§7.2）。工作表 §5 那一列是按语速估的，不跑这一步，预填值会一路带到成片里。

```
node gao-2d/配音.mjs uk_potholes --check   只核对，不碰音频
node gao-2d/配音.mjs uk_potholes --dry     量时长、算时间轴，不合成
node gao-2d/配音.mjs uk_potholes           合成
```

**第 1 件（核对）是入库时新加的，原稿没有。** 三样东西必须自洽，任何一处对不上，出来的片子都是错的**而且不报错**：

| 比对 | 对不上的后果 |
|---|---|
| 分句清单的 `out` ←→ 时间表的 `audio` | `build.mjs` 找不到音频 |
| 分句清单的段数 ←→ 工作表 §3 的段数 | 漏段或多段 |
| 分句清单的 `pauseAfter` ←→ 工作表 §2 的 `‖` | **差额落在段内，没有任何机制实现** |

第三条是实际踩到的：坑洞篇稿面有 15 处 `‖` 合计 9.4s，切成九段后只有 8 处落在段末（6.2s），**剩下 7 处、3.2s 段内停顿没人实现**，只能指望引擎从句号里读出来 —— 而引擎的句间停顿约 0.25–0.35s，比稿面要的 0.4–0.8s 短一截。工作表 §6 却写着「按 `‖` 插静音」，承诺了做不到的事。

两条路，各条稿件自己选，`--check` 只提醒不拦：

- **认了** —— 把稿面里段内的 `‖` 数值删掉，别承诺做不到的事
- **要那 3.2 秒** —— 把段内的点也切成独立段（九段变十六段）。**本地生成不计费，切多切少不花钱**，代价只是多七个文件。坑洞篇的 Edge 试听版实听下来，第 7 段那两处段内停顿明显不够，反讽的落点是软的 —— 这条稿建议走切分

**一段音频对应两个画面块**时（比如一句话前半配角色、后半配实拍），把回吐的那一行拆成两行，**拆点落在句号处，别落在句子中间**。

## 6. 视觉

### 6.1 四层结构与配比

| 层 | 内容 | 占比 |
|---|---|---|
| **A** | 数字卡 / 文字卡 | 35% |
| **B** | 主讲人角色 | 25% |
| **C** | 实拍空镜 / 地图 / 图表 | 25% |
| **DOC** | 官方文件录屏 | ≥15% |

**四条硬阈值**（`--check` 自动核对）

- **图层互斥**：任一时刻只有一个主体层。A 层满屏字卡激活时，B 层必须为 `none`
- 字卡连排不超过 **2 张**
- 主讲人每条至少出现 **3 次**：开场建立人称、中段转折、结尾落点
- DOC 层 ≥15%

### 6.2 运镜

角色是 SVG，**动 viewBox 就是无损变焦**，不用 ffmpeg zoompan。竖屏 0.5625 比例（宽 = 高 × 0.5625）。

**景别按脸高算，不按整体墨高。** 交接稿里给的是 man3 的四组绝对 viewBox 数值，那套换个角色就作废；
高总这边改成**从脸框反推的系数**，六种姿势通用（实现在 `gao-2d/出帧.mjs` 的 `取景()`）：

| 景别 | 画面高 = 脸高 × | 头顶余量 |
|---|---|---|
| WS 全身 | 13.7 | 2% |
| MS 中景 | 7.1 | 4.5% |
| MCU 近景 | 4.8 | 6% |
| CU 特写 | 2.85 | 以脸心为准 |

系数从 `正面站立.svg` 实测反推：全高 891 / 脸高 69 = 12.9，头顶在脸框上方约 1.63 个脸高。

⚠ **不能按整体墨高算** —— 抬单手那两张手举过头，墨高里含着手，按它算一换姿势人就矮一截。
⚠ 裁切**只能改顶层 viewBox**。套一层嵌套 `<svg>` 会让落在可视区外的 clipPath 包围盒变成空，
resvg 直接 panic 在 `geom.rs:27` 的 unwrap 上（README §六）。

规则：只在句子之间切；一条最多用三档；景别单向收紧，回拉只在最后用一次。缓动 easeInOutCubic，1.2–1.6 秒推完。

### 6.3 节奏

**每 2–3.5 秒必须有一次画面变化。** 一条 30 秒视频需要 9–13 个画面事件。**转场只用硬切**。唯一例外：克制型篇目段落间 0.6 秒黑场。

### 6.4 素材红线

**不做**：可辨识的真人面孔 / 任何新闻画面（含截图）/ 商业品牌标识 / 暗示与机构有关联。

**官方公开文件可以入镜，且应该多用**：政府报告、审计文件、监管公告、议会文书、企业财报与电话会记录的原件页面——PDF 翻页、表格滚动、关键数字红框圈出（`#ff4757`，4px，0.3 秒动画）。理由是它就是可信度本身，且顺带解决 C 层素材荒。机构抬头出现在文件原件里是正常引用，但不要单独放大 Logo、不进封面片头。各国版权规则不同（英国政府文件多为 OGL，美国联邦文件多属公有领域，其余逐一确认），确认后记入来源表。

### 6.5 统一调色

C 层实拍统一过一道：

```
hue=s=0.18, eq=contrast=1.15:brightness=-0.04,
colorbalance=rs=0.03:bs=-0.02, setsar=1
```

**DOC 层不走这套**——本来就是黑白版面，压暗反而看不清。只做一件事：纸底从纯白压到 `#f4f4f2`。

### 6.5b 文档标注（红笔痕迹）

档案画面上的标注不再用 ffmpeg 的 `drawbox` —— 那个滤镜**只画得了矩形，也只能硬闪一下**。
改成 SVG → PNG 序列 → overlay 之后，五种标注都能画，而且能一条接一条扫出来
（每条错开 0.12 秒，像有人一处处圈过去）：

```js
标注: [
  { 型: 'box',       x, y, w, h },          // 框住一段，宽度从左往右扫
  { 型: 'underline', x, y, w, h },          // 下划线
  { 型: 'arrow',     x, y, 朝: 'right', 长 }, // 箭头，朝 = 指的方向
  { 型: 'bang',      x, y, h },             // 页边感叹号
  { 型: 'circle',    x, y, rx, ry },        // 椭圆圈住一个词
]
```

老的 `box` 字段自动转成 `[{型:'box', …}]`，两套不并存。

⚠ **不做手绘涂鸦的笔触。** 方案 §2 的视觉是「粗黑边 ＋ 块状硬阴影，不用圆角」——
「有人在审这份文件」的感觉靠**位置和时机**（画在关键处、跟着台词出现），
不靠假装是手写。硬朗的几何形状才是这套视觉的语言。

⚠ **页边感叹号要留边距**：摘录卡的正文从 x40 起，左边只剩 30px，
`bang` 塞进去会压在字上（2026-09-09 实测）。窄版面就只用 `box`。

### 6.5c 封面（Shorts 竖版）

`node gao-2d/封面.mjs` 从**成片**里抽一帧，出两个文件：

| 文件 | 尺寸 | 干什么 |
|---|---|---|
| `<slug>_cover.png` | 1080×1920 | 上传用 |
| `<slug>_cover_1x1.png` | 中心 1080×1080 | **校验用，拿眼睛看一遍** |

⚠ **为什么要多出一张 1x1**：《YouTube 封面规范》§十一 —— Shorts 的首页卡片是**裁过的**，
关键信息必须收进正中间的 1080×1080（y ∈ [420, 1500]），上下各 420px 是牺牲区。
而这条线的画面里，**页眉标题在 y≈300、来源角标在 y≈1570，两样都在牺牲区**。
机器判断不了「关键信息」是哪一块，所以出一张裁好的让人看。

**抽帧时间写在时间表里**（`封面: { at: 2.6 }`），不写就取第一个 DOC 块的 `start + 2.5` ——
标注是 1 秒画完的，2.5 秒时红框已经停稳。写进时间表而不是命令行参数是为了可复现：
换了素材重跑一条命令就回来。

**挑哪一帧**：挑 DOC 块。档案画面比角色画面有辨识度，而且封面上有字（红框圈住的原文 ＋ punch），
首页卡片上一眼就知道这条片在讲什么。

### 6.6 字幕

英文硬字幕，全大写，每屏 3–5 词。ASS 的 PlayResX/PlayResY 必须等于 1080/1920，MarginV 520 避开 Shorts 底部 UI。**A 层不配字幕**。

⚠ **「3–5 词」不是排版偏好，是硬约束**：MarginV 是**底边**，多出来的行往上长。
一行约 70px，3 行就顶到距底 730px —— 而来源角标的底边在距底 320px（§3.3），
字幕再长就会盖住它。2026-09-09 实测：坑洞篇第 6 块 12 个词排了 5 行，把角标压掉一半。

`自检.mjs` 现在会数词数（超 5 词报提醒）。**词数是这件事最便宜的判据** ——
行数得等 libass 排完才知道，那时候片子已经渲出来了。

纵向分层，从下往上：Shorts UI（约 250px）→ 来源角标（底边 320）→ 字幕底边（520）→ 字幕往上长。

### 7.1 目录

**技术和结果分开**（仓库通例）：代码与稿件在 `gao-2d/`，产物在 `projects/高总/`。

```
gao-2d/                       ← 进 git
  英文频道出片方案.md          这份
  角色集成规范.md              B 层帧序列的规格
  README.md                   角色素材层（五官 / 表情 / 头动 / 闸）
  自检.mjs                    八项自检，唯一一处算配比和阈值
  numcard-core.mjs            字卡渲染核心
  build.mjs                   合成脚本
  出声.mjs                    Kokoro 本地逐段生成人声（§5.2）
  配音.mjs                    拼接 → 插静音 → 归一 → 回吐实测时间码（§5.2）
  试听.mjs                    Edge TTS 出试听版，交叉验证语速用，不进正片
  出帧.mjs                    出 B 层帧序列
  稿件/<slug>/
    工作表.md                 中枢文件（§7.2）
    分句.mjs                  文本／停顿／音色／语速，音频侧的机器事实源（§5.2）
    时间表.mjs                合成配置（§7.3）
  素材库/svg/                 12 张角色 SVG

projects/高总/                ← 不进 git（除 index.html）
  index.html                  稿件库汇总页
  _帧/<组>/00000.png…         B 层帧序列，**全频道共用**，出一次到处用
  _素材/<题材域>/*.mp4         C 层通用空镜，**全频道共用**，攒一次多期用（说明见该目录 README）
  <slug>/
    audio/段/01.wav…          出声.mjs 本地生成的分段原件
    audio/<slug>_voice.wav    配音.mjs 拼好并归一到 −16 LUFS 的成品
    audio/_试听*              试听.mjs 的产物，不进片，可随时删
    media/                    C 层素材、DOC 录屏、音乐

```

判据还是那条「**删了还跑不跑得出来**」：`_帧/` 三百多张 1080×1920 的 PNG 一条命令全回来，
所以不进 git；素材库的 SVG 是美术给的原件，回不来，所以进。

### 7.2 单条工作表：唯一的中枢文件

一条视频一张，`gao-2d/稿件/<slug>/工作表.md`，七节：

```
1. 来源表          编号 / 陈述 / 级别 / 来源 / 时点，外加「反面事实是哪条」
2. 稿面 EN         带 ‖ 停顿标记，进字卡、字幕、核对
3. TTS EN          按 ‖ 切成段，无标记、数字已文本化，直接喂引擎
4. 中文校对版      不进音频、不进字幕
5. 六列时间表      时间 / 台词 / 重音与语气 / 层 / 画面 / 来源角标
6. 素材清单        **不手写** —— 指向生成物，正文见下
7. 出片前待办      勾选框
```

**§6 是生成的，不是写的。** 每块 C / DOC 要准备成什么样，写在 `时间表.mjs` 那一块的
`素材` 字段里（跟 `clip` 名挨着），由 `build.mjs --check` 打成备料单、由汇总页渲成表。
这样改了文件名而忘了改说明的那种不同步，从数据结构上就不可能发生 ——
跟 §7.3 那句「配比只算一处」是同一条道理。工作表 §6 只留一句指路。

**台词、语气、时间码、画面、层、来源，一眼全在。** TTS 分句按第 2 列切，
`时间表.mjs` 从第 1、4、5、6 列生成，事实核查照第 6 列走。

⚠ **小节标题别改。** `gao-2d/index.mjs` 按 `## 1. 来源表` / `## 2. 稿面 EN` / `## 7. 出片前待办`
这三个标题抓内容上稿件库那张页。改了**不报错**，页面上那一块会空掉。

### 7.3 时间表驱动的配置规范

一条视频一个 `gao-2d/稿件/<slug>/时间表.mjs`：

```javascript

  slug: 'uk_potholes',
  题: '英国路面坑洞',
  线: '英国',
  模板: 'T5',
  状态: '待配音',          // 立项 / 待审 / 待配音 / 待素材 / 待出片 / 已出片
  克制型: false,
  工作表: '工作表.md',

  audio: 'audio/uk_potholes_voice.wav',   // 相对 projects/高总/<slug>/
  music: null,

  timeline: [
    { id: 1, start: 0.0, end: 2.0, layer: 'A', anim: 1.0,
      card: { type: 'bignum', theme: 'dark', accent: '#ff4757', value: 97, label: 'years' } },
    { id: 2, start: 2.0, end: 6.0, layer: 'B', frames: 'ms_talk', loop: true },
    { id: 6, start: 23.5, end: 29.5, layer: 'C', clip: 'media/road_crew.mp4', in: 1.0,
      credit: 'ALARM Survey 2026: budgets +17%' },
    { id: 4, start: 12.5, end: 19.0, layer: 'DOC', clip: 'media/alarm2026_potholes.mp4', in: 0,
      box: { x: 210, y: 820, w: 680, h: 130 }, credit: 'ALARM Survey 2026' },
  ],

  captions: [ { t0: 2.0, t1: 6.0, text: "THAT'S HOW OFTEN A BRITISH ROAD\nGETS RESURFACED" } ],
}
```

**素材路径有三种形状，别混**（解析在 `自检.mjs` 的 `素材路径()`，**只有那一处**）：

| 写法 | 落在哪 | 什么时候用 |
|---|---|---|
| `frames: 'ms_talk'` | `projects/高总/_帧/` | B 层帧序列，全频道共用 |
| `clip: '_素材/road/asphalt_01.mp4'` | `projects/高总/_素材/` | C 层通用空镜，全频道共用 |
| `clip: 'media/xxx.mp4'`、`audio` | 本条工作目录 | DOC 录屏、跟本期绑死的实拍、人声 |

前两条是仓库版跟交接稿的不同 —— 交接稿里全都相对同一个目录写，那样每条片子
都得把帧序列拷一份，通用空镜也存不下来。**为什么 C 层要有共用层**：DOC 录屏跟本期
数据绑死攒不了，但路面、车流、街景、排队这类空镜多期反复要，而 C 层每期预算 60 min，
是单条里第二贵的素材工序（§17）。存**原件**不存调好色的 —— §6.5 那道调色是出片时过的。

**每块 C / DOC 还要写 `素材` 字段**，说明这块要准备成什么样：

```js
{ id: 6, layer: 'C', clip: 'media/road_crew.mp4', in: 1.0,
  素材: { 源: '图库', 要: '道路施工队铺沥青',
          检索: 'road repair crew asphalt / pothole patching workers' } },

{ id: 4, layer: 'DOC', clip: 'media/alarm2026_potholes.mp4', in: 0,
  素材: { 源: '录屏', 要: 'ALARM 2026 报告中「填补坑洞数量与费用」那一页',
          备注: '红框由 box 字段自动画，录屏时不要自己画' } },
```

`源` 用 `图库` / `录屏` / `自拍`；`检索`（图库检索词）和 `备注`（录屏要点、红线提示）二选一或都写。
`build.mjs --check` 把缺件连同说明打成**备料单**，汇总页渲成表 —— 备料的时候看那两个就够，
不用回头翻工作表。

**上屏的英文都要配中文注**（`card.中`、`captions[].中`、`credit中`）：

```js
card: { type: 'statement', lines: 'Three times.\nOne hole.', 中: '三次。一个坑。' }
credit: 'AA: 137,000 pothole call-outs, Jan–Feb 2026',
credit中: 'AA：2026 年 1–2 月坑洞救援出动 13.7 万次',
captions: [{ t0: 2.0, t1: 6.0, text: "THAT'S HOW OFTEN…", 中: '英国的路，就是这么个重铺间隔' }]
```

⚠ **中文只上汇总页，不进片子。** 这是英文频道，画面上不叠中文（§6.6）。
它解决的是另一件事：审稿的人读中文。字卡和字幕是真正印在画面上的英文，
汇总页原先只显示「字卡 statement」这种类型名 —— 看不见卡面写了什么，就审不了。
汇总页新增的「上屏文字」一节把三样并排列出来，没写中文的那几处会点名。

**互斥原则写进 schema**：`layer` 是单值字段而不是 `layerA/layerB/layerC` 三个并列字段 ——
**从数据结构上就不可能同时给两层分配内容**，比写一条「记得设成 none」的纪律可靠得多。
真正需要叠加的只有 `credit` 角标、`box` 红框和 `lower` 数据条，它们是字段不占层。

### A 层已废弃（2026-09-09）

**字卡显示的就是台词，而字幕本来也在显示台词** —— 为此牺牲一整块画面是纯损失。

病根在四层结构本身：A/B/C/DOC 是按「这一秒的画面来自哪一层」划的，A 层被当成一种
**画面来源**，所以它必然独占。可 A 层的内容是**字** —— 字不是画面，是叠在画面上的信息。
**把文字当画面用，是设计上的错位。**

改完之后：

| | 原来 | 现在 |
|---|---|---|
| 画面层 | A 字卡 / B 角色 / C 空镜 / DOC 档案 | **B / C / DOC**（只有这三个是真画面） |
| 句子 | A 层 statement 卡，独占一屏 | **`punch` 强调字幕**，叠在画面上 |
| 数字 | A 层 bignum 卡，独占一屏 | **`lower` 数据条**，叠在画面上 |
| 配比参考 | 35/25/25/15 | **B 45 / C 25 / DOC 30**（DOC ≥15% 硬阈值不变） |
| 「字卡连排 ≤2」 | 硬阈值 | 自然失效 |

三条片实测：A 层 25% / 32% / 41% → **全部归零**。

⚠ **代价是每一块都要有画面素材**，而 B 层帧序列是共用的、成本为零 ——
所以没有 C 层空镜的片子会变成**角色独角戏**：
`asylum_wording` B 68%、`nature_security` B 69%，而有 C 层的 `uk_potholes` 是 48/25/27，结构健康得多。
**这把共用素材库 `projects/高总/_素材/` 从「锦上添花」变成了必需。**

**`lower` 数据条**：一条数字叠在主讲人身上。

```js
{ id: 5, layer: 'B', frames: 'ms_talk', loop: true,
  lower: { value: 14, label: 'pages', accent: '#ff4757' } }
```

**`punch` 强调字幕**：把 statement 卡的视觉（大字 ＋ 红底扫开）搬到叠加层上。

```js
{ id: 1, layer: 'B', frames: 'ms_talk', loop: true,
  punch: { lines: 'Every critical ecosystem\nis on a pathway to collapse.', highlight: 2 } }
```

两者都**不占层**，不参与配比 —— 跟 `credit` / `box` 同类。`自检.mjs` 拦四件事：

| 拦什么 | 为什么 |
|---|---|
| `punch` 配 MCU 帧组 | punch 中心在 y1020，MCU 特写脸占到 y1150 —— **字必然盖住眼睛**，实测过 |
| 同一块既有 punch 又有 lower | punch 两行占 y794–1246，数据条占 920–1120，**纵向必然重叠** |
| 带 punch 的块又配字幕 | punch 已经把整句摆上画面了，再叠字幕是同一句话说两遍 |
| 还在用 A 层 | 提醒改成 punch / lower |

**纵向位置全是算出来的**，从下往上：
Shorts UI（约 250）→ 角标（底边距底 320）→ 字幕（MarginV 520 是底边，三行往上长到 y≈1190）
→ **数据条 920–1120 ／ punch 中心 1020** → 角色的脸。

MS 景别下巴到 y≈800、衣领 850，所以叠加层落在胸口才不压脸；再往下就撞字幕区 ——
**可用窗口就这么宽**，这也是 punch 和 lower 不能同块的原因。
（自检里还留了一条：配置中出现 `layerA` 这类废弃字段直接报硬伤，防的是从旧稿抄过来。）

时间块首尾相接、无缝无叠。**时间码从音频来** —— 预填的估算值在跑完 TTS 之后必须回改，
工作表 §5 和 `时间表.mjs` 两处一起改。

**`--check` 八项自检**（实现全在 `gao-2d/自检.mjs`，`build.mjs` 和稿件库页 import 同一份）：

| # | 查什么 | 判定 |
|---|---|---|
| 1 | 时间轴连续性 | 硬伤：块与块之间有缝或有叠 |
| 2 | 图层互斥 | 硬伤：`layer` 非法值，或残留 `layerA` 这类废弃字段 |
| 3 | 四层配比 | 参考 35/25/25/15，B 层低于 20% 只提醒 |
| 4 | 字卡连排 | 硬伤：超过 2 张 |
| 5 | 主讲人出现次数 | 硬伤：少于 3 次 |
| 6 | 素材齐备 ＋ 备料说明 | 硬伤：帧目录 / clip / 人声 / 音乐任一不存在；C / DOC **缺件又没写 `素材.要`**（既没素材也不知道要找什么）。提醒：文件在但没写说明 |
| 7 | DOC 占比 | 硬伤：低于 15% |
| 8 | **字卡字体装没装** | 提醒：缺了 resvg **不报错**，只是静默回退到 Consolas / Segoe UI |

第 8 项是仓库版换掉的 —— 交接稿这一项是「SVG 转换器可用」，而转换器现在是 npm 依赖，
缺了 import 就炸，不需要一道闸。**需要闸的是那些缺了不出声的东西。**

另外，`克制型: true` 的篇目多两条硬伤：出现 B 层、或配了音乐。

### 7.4 十三步

1 选题立项 → 2 过 §3.2 四问 → 3 建来源表 → 4 写稿面 EN + 中文校对 → 5 事实复核 → 6 **母语者审稿（§12）** → 7 生成 TTS 稿 → 8 写 `分句.mjs`（文本／停顿／音色），`node gao-2d/配音.mjs <slug> --check` 核对 → 9 **`node gao-2d/出声.mjs <slug>`** 本地逐段生成 + 逐段验收 → 10 **`node gao-2d/配音.mjs <slug>`** 装配人声轨，拿回实测时间码 → 11 填工作表 / 配卡 / 备素材（帧序列出一次即可） → 12 按实测时间码写 `时间表.mjs` → 13 `node gao-2d/build.mjs <slug> --check` 八项全过后合成

第 9、10 步是原稿缺的那一环（原十二步直接假设 `voice.wav` 已存在）。**第 12 步的时间码必须来自第 10 步的回吐，不能用工作表 §5 那一列预填值** —— 那一列是按语速估的，见 §7.2。

本地生成不计费，所以第 9 步可以随便重跑；但**换音色要连第 10、12 步一起重来**（§5.1 那条 ⚠）。

## 12. 英文语感审核（TTS 前的唯一安全阀）

数据可以核，语感没法核。讽刺是对母语直觉要求最高的文体，差一点就从"冷面高级"滑到"翻译腔尬"，写的人自己感觉不到。**审稿必须在跑 TTS 之前**——跑完再改，音频全部作废。

**三项审核指标**

| 项 | 查什么 |
|---|---|
| **去主观形容词** | 稿里有没有 horrible / shocking / outrageous / dynamic 这类情绪词。有则删，换成事实本身。这个频道的力量来自零形容词 |
| **英式用词纯度** | 英国题材误用美式词汇：lift 写成 elevator、pavement 写成 sidewalk、queue 写成 line、petrol 写成 gas、council 写成 city hall。一个词就能让本国观众出戏 |
| **反讽锐度** | 有没有"一本正经说反话"的留白。英式讽刺靠的是把话说完就停，不解释、不补刀。检查是不是解释过头了 |

**执行**：英/美籍母语者按条审，前 10 条每条必审，之后抽审。渠道：Fiverr 按条计费，或在日的母语朋友。

**要问的三个问题**：① 哪一句读起来像翻译？② 哪个笑点没笑出来？③ 语气是冷静还是像在生气？

**算法侧的验证**：前 3 条的完播率与评论语气就是反馈。评论里出现 "the narration sounds off" 一类的话，立刻停更改稿。

## 13. 法务红线

英国的诽谤法对被告的举证要求比美国严得多，而稿子里会点名具体企业和机构。四条自查：

**1. 主语转嫁给公开文本**

所有涉及具体主体的陈述，主语必须是文件而不是你：

```
✅ The regulator's decision notice states …
✅ According to the parliamentary committee's report …
✅ The company told analysts on its own earnings call …
❌ This company polluted the river for three million hours.
```

**2. 只引用受保护的来源**

归因能降低风险，但降不到零——**转述别人的诽谤性陈述，在英国法下你也是发布者**。所以第 1 条要配第 2 条一起用：优先引用**议会文件、法庭记录、监管机构的正式决定书、公司自己的公开表态**这几类。它们本身就受较强的保护，而且是公开档案，事后可查。避免把"某媒体报道称……"当成主要依据。

**3. 不做动机推断**

"他们明知故犯""为了利润不惜……"一律删。只说做了什么、结果是什么、数字是多少。事实排列本身已经足够。

**4. 区分事实与评论**

讽刺是评论，评论要建立在已陈述的事实之上，且看得出来是评论。"三倍的钱、一半的铁路"是对已列事实的概括，安全；"这是一场骗局"是指控，不安全。

**收到通知怎么办**：不删视频（删了等于承认），先核对原始来源；确实错了就置顶更正并在描述里说明；来源无误则保留完整证据链（截图 + 归档链接）。

我不是律师，这四条是常识性防线不是法律意见。频道开始有商业收入后，值得花钱做一次真正的合规咨询。

按预估一条约 7.5 小时，每周 3 条就是 22 小时，接近半份全职。三条实测完之后：**砍掉最贵且收益最低的那一步**，并按实测重定频率。宁可每周 2 条稳定，不要 3 条断更。

可复用资产是唯一的降本手段——数字卡模板、角色帧库、**C 层共用素材库**（`projects/高总/_素材/`）、DOC 录屏流程，做一次用很多次。第 10 条之后单条应能降到 4–5 小时。

C 层那 60 min 是这张表里第二贵的素材工序，而且**它是唯一一项越攒越便宜的**：路面、车流、街景、排队、货架这类空镜跨期通用，攒够之后多数篇目直接从库里挑。DOC 录屏跟本期数据绑死，攒不了——所以 §6.4 那句「多用官方文件顺带解决 C 层素材荒」和这个库是同一件事的两头。

## 16. 变更记录

### 仓库版变更（v4 交接稿 → 入库版，2026-09-08）

交接过来的是一套「零 npm 依赖、`channel/` 独立目录、脚本按路径找配置」的通用方案。
入库时按仓库实况改了这几处，代码注释里引的就是这一节：

| 改了什么 | 为什么 |
|---|---|
| SVG→PNG 一律走 `@resvg/resvg-js`，不再探测 rsvg-convert / Inkscape / ImageMagick | 仓库里所有渲图都用它。为一条线多养三条外部依赖没道理，而且「探测到哪个用哪个」意味着**换台机器出来的图不一样** |
| 第 8 项自检从「转换器可用」换成「**字卡字体装没装**」 | 转换器现在是 npm 依赖，缺了 import 就炸；字体缺了 resvg **不报错、只是悄悄换一个字族**。闸要装在不出声的那一头 |
| 配置按 slug 找（`gao-2d/稿件/<slug>/时间表.mjs`），不再手写 `shots/xx.mjs` 路径 | 一条片子的稿面、工作表、时间表捆在一个目录里 |
| `frames` 写组名、指向全频道共用的 `projects/高总/_帧/`；`clip`/`audio` 才相对本条工作目录 | 帧序列是一次性资产（规范 §7），不该每条片子拷一份 |
| 配比与阈值全部收进 `自检.mjs`，`build.mjs` 和稿件库页都 import 它 | 两处各算一套，迟早一边绿一边红 |
| §6.2 的四组绝对 viewBox 换成**按脸高算的系数** | 交接稿给的是 man3 的数值，换个角色就作废。高总这套系数六种姿势通用 |
| 目录改成「代码 `gao-2d/` ／ 产物 `projects/高总/`」两分 | 仓库通例，判据是「删了还跑不跑得出来」 |
| **引擎从 ElevenLabs 换成本地 Kokoro**（`tts_kokoro.mjs` 入库为 `gao-2d/出声.mjs`），音色定 `bm_george` | 零调用成本、无版权顾虑、可无限重跑。选 george 是因为它在四个英式男声里**最慢**，反讽需要慢（§5.1）。原稿的 `list_voices()` 返回 `void`、`Object.keys(undefined)` 直接抛，得改用 `tts.voices`；筛性别的 `/male/i` 会匹配上 `Female`，要整串匹配 |
| 新增 `gao-2d/试听.mjs`（Edge TTS），**不进正片** | 交叉验证语速用。Edge `en-GB-RyanNeural` 测出 1.99 词/秒、Kokoro `bm_george` 测出 2.00 —— 两个引擎独立互证，这个数才敢当结论用（§5.1） |
| `assemble_voice.mjs` 入库为 **`gao-2d/配音.mjs`**：配置按 slug 找（`稿件/<slug>/分句.mjs`），目录按代码／产物两分，`sh()` 失败即抛 | 前两条跟 `build.mjs` 同一套通例。第三条是原稿跟 `build.mjs` 犯了同一个错：`spawnSync` 不看返回值，ffmpeg 挂了照样往下走，concat 拿到上一次的旧段子 |
| **新增 `核对()`** —— 分句清单跟工作表、时间表三方比对（§5.2） | 原稿只做拼接不做核对。三处对不上都是**静默出错**：`out` 跟 `audio` 不一致 → build 找不到音频；段数不一致 → 漏段；`pauseAfter` 跟稿面 `‖` 不一致 → 段内停顿没人实现。坑洞篇实测差 **7 处、3.2 秒**，而工作表 §6 写着「按 `‖` 插静音」 |
| 分段编码从 `preset medium -crf 18` 换成 **`preset ultrafast -crf 14`** | 分段是**中间产物**，concat 之后整条还要再编一次（终片 `preset slow`），第一遍编得精细纯属白烧。实测 90 帧 1080×1920，两种中间 preset 各自再过一遍终编：medium **1122 ms / 终片 PSNR 47.52**，ultrafast **312 ms / 终片 PSNR 48.70** —— 快 3.6 倍，而且**终片质量更好**（中间码率高，留给终编的信息多） |
| `层A` / `层B` 的帧目录改成**先清空再建**（`重建()`，不是 `ensure()`） | 跟 `出帧.mjs` 防的是同一个坑，只是那儿防 `_帧/`、这儿防 `_tmp/a* b*`。把某块时长改短再重建，旧帧还躺着，`%05d.png` 一路读下去 —— **段子比时间表长，还不报错** |
| `sh()` **失败就抛**，不再忽略 `spawnSync` 的返回值 | 原先 ffmpeg 挂掉（缺素材、滤镜写错、不在 PATH）脚本照样往下走，最后 concat 按完整时间表列 seg，拿到上一次留下的旧段子 —— 出来一条看着正常、其中一段是上回内容的片子。Windows 会把负退出码回成无符号，报错前换回有符号 |
| `build.mjs` 的 `png()` **点名字体文件**，`loadSystemFonts: false` | A 层是逐帧渲的（uk_potholes 一次出片 103 次），而 `new Resvg()` 每次重建一遍字体库。实测 12 次 1080×1920：开系统字体 **3013 ms / RSS +166 MB**，点名文件 **584 ms / +108 MB** —— 慢 5.2 倍，就为了在 665 MB、165 个字体文件里找 Archivo 和 JetBrains Mono，而这两个**多半没装**（`缺字体()` 会报），找不到再回退。⚠ 不能只写 `false` 不给 `fontFiles`，那样一个字体都没有、文字直接不渲，回退字族必须一起点名 |

**没改的**：选题规则、两级来源、稿件模板、语气纪律、法务红线、配比阈值本身。那些是内容侧的判断，不因仓库而变。
