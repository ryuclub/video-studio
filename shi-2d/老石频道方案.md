# 老石数字人 · 短视频制作方案 v2

---

## 〇、项目定义

**一句话人设**

> 在日本做了十几年房产的出海老炮。松弛、有见识、说人话，用漫画形象和自己的声音，讲只有他知道的数。

关键词：**亲和力、商务感、出海老炮、松弛感**。要刻意避开传统虚拟主播那种二次元低幼感——靠三件事避开：真人质感的声音、成年人的语汇、不卖萌不喊口号。

**三条铁律**

1. **数字分身这件事：不主动强调，也不否认。** 被问到就如实说这是老石的漫画形象。但**第一人称的经历必须归属老石本人**——「我那套房当年是 0.3%」是他的经历，不能改写成数字人的叙述。这条是整个账号信任的地基，破了就没了。
2. **声音只能是老石本人。** 本人录制，或经他同意后克隆**他自己**的音色。绝不用通用 AI 客服音，也绝不克隆第三方的声音。他那种略带沙哑、语速沉稳的中年男声配上卡通形象，反差本身就是记忆点。
3. **不喊口号、不上价值。** 情绪可以有起伏，但落点必须是事实句，不是感慨句。

**明确不做的内容**

- 需要「我亲眼见过」的第一人称口述，而老石本人没有对应经历的 —— 要做就转成第三人称或情景演出
- 情绪浓的内容（愤怒、悲情、共情）—— 这个画风的表情做不到，做了会尬。轻度的调侃、无奈、揶揄可以
- 超过 60 秒的推理链（短视频里）—— 画面撑不住，会退化成念稿

### 0.3 栏目结构

四个栏目，配比按周分配。前两个是主力，后两个控量。

| 栏目 | 内容 | 周配比 | 为什么适合这个形象 |
|---|---|---|---|
| **① 老石讲数** | 一条只讲一个数字：10 倍、0.3%、125%、3% | 40% | 信息主体是数字，角色只当导览，机械感被完全吸收 |
| **② 中介不说的事** | 行业内幕、合同陷阱、带看话术 | 30% | 卡通有距离感，说得出真人不方便说的话 |
| **③ 海外冷知识 / 社会潜规则** | 「读空气」到底怎么运作、日本社会里没写出来的规矩、外国人踩过的坑 | 20% | 受众面比房产宽得多，是拉新的主力；且这类内容天生带「揭穿」爽感 |
| **④ 老板视角** | 创业、雇人、跟日本客户打交道的现实经验 | 10% | **限额栏目**。「富人思维/普通人差在哪」这类是红海，且不需要老石也能讲。只做他真有经历的那部分——雇过人、被坑过、谈崩过 |

栏目 ③ 是这一版新增的，它把受众从「想在日本买房的人」拓宽到「在日本生活的人」，量级差一个数量级。但它的内容仍要遵守铁律 1：讲潜规则可以，编亲历不行。

## 一、画面规格

### 1.1 两套构图

竖版 1080 × 1920。台词在上、画面在下。

| | **标准版** | **展开版** |
|---|---|---|
| 用于 | 八成的条：讲数、揭穿、反常识 | 走进数据、时空错位、一人分饰多角 |
| 字幕区 | y 300–560，最多三行 | 底部一行，y 1620–1720 |
| 角色 | 半身取景，切到大腿 | 全身，可缩放走位 |
| 角色可视区 | y 600–1560 | y 560–1620 |
| 角色画面占比 | 45–60% | 15–40%（按内容缩放） |

**一条片子里最多切一次构图。** 来回切会乱。

> **⚠ 2026-09-06 起实际出片走「舞台演讲模式」，角色可视区跟上表不一样。**
>
> 人物站在一块画出来的发光台上，**脚底落在 1751**（不是 1560）——
> 故意压到平台 UI 遮挡线（1620）以下，让「脚和地面的接触点」出画。
> 这是根治「人悬在半空」的那一刀，见 [老石出片方案.md](老石出片方案.md) §二「舞台演讲模式」。
> 头顶还钉在 600，字幕带一点没动，所以 §1.2 的其余安全区照旧有效。
>
> 背景也不再铺满整幅：只占 **y240–1560**，上下留暗底。

### 1.2 安全区

| 区域 | 说明 |
|---|---|
| y < 260 | 平台标题栏、关注按钮会盖住，任何内容不要放 |
| y 300–560 | 字幕带（标准版） |
| y 600–1560 | 角色主区 |
| y > 1620 | 平台 UI 遮挡区，只放展开版的单行字幕 |
| x > 900 | 右侧点赞/评论/分享按钮列，避开 |

### 1.3 字幕规格

- 字号：主台词 68–76 px，关键数字单独放大到 120–150 px
- 字重：粗体，双层描边（黑边 + 白/黄内填）
- 逐句整句出现，**不做逐字打出**（逐字打字机效果会拖慢阅读，短视频里是减分项）
- 关键数字标黄或标红，一条里最多标三处

### 1.4 角色镜头语言

五个定格姿势对应五个结构位。**切镜头必须落在结构点上，不能随机切。**

| 结构段 | 姿势 | 景别 |
|---|---|---|
| 钩子 | 抬手比划 | 中景，占 55% |
| 常识铺垫 | 双手插兜 | 中景 |
| 拆解/数据 | 切数据板，角色缩到右下 | 占 25% |
| 落点 | 单手插兜 | 中近景，回到 55% |
| 收尾 | 斜靠 | 全景 |

角色微动：呼吸、眨眼（随机化，不要均匀）、口型、偶尔点头或扶帽檐。**大动作全部交给切镜头。**

### 1.5 数据板层规格

数据板（S-12）**不是生成的、不是实拍的**，是自己渲染的一层图形，叠在场景视频之上、角色之下或之上（按类型定）。它必须在三十条视频里长一个样——这是账号的视觉签名。

#### 1.5.1 设计变量

> **先做一件事**：从 `资源_1.svg` 里取样角色的西装藏蓝、衬衫粉、裤子灰的实际色值，替换下表中标 `※` 的默认值。数据板必须和角色同一套颜色，否则会像两个软件做的。

```
/* 底 */
--board-bg:        #F4EFE7   /* 暖白，与场景暖色调统一 */
--board-bg-alt:    #EAE3D7   /* 分区底、表格隔行 */
--board-grid:      #D8CEC0   /* 网格线、辅助线 */

/* 主色 */
--ink:             #2A2622   /* 主文字、主描边 */
--ink-weak:        #6E6459   /* 次级文字、单位、说明 */
--primary:         #26355C   /* ※ 取角色西装藏蓝 —— 主数据色 */
--primary-weak:    #7F8AA8   /* 对比项、次要序列 */

/* 强调 */
--accent:          #C4452F   /* 高亮、变红、关键数 —— 一屏最多一处 */
--accent-soft:     #E8A99B   /* ※ 取角色衬衫粉 —— 柔性强调、渐显 */
--muted:           #B9B1A6   /* 已失效、变灰的部分 */
```

**一屏最多一个 `--accent`。** 两处以上强调等于没有强调。

#### 1.5.2 字体与尺度

按 1080×1920 画布：

| 用途 | 字号 | 字重 | 颜色 |
|---|---|---|---|
| 超大数字（单数字展示） | 220 px | Bold | `--ink`，关键位 `--accent` |
| 图表主数值 | 96 px | Bold | `--primary` |
| 图表标签 | 48 px | Medium | `--ink` |
| 单位、说明、脚注 | 36 px | Regular | `--ink-weak` |

字体：思源黑体 / Noto Sans CJK，**数字部分用等宽数字字形**（`font-variant-numeric: tabular-nums`），否则数字跳动时宽度会抖。

#### 1.5.3 版面与安全区

数据板占用的是**角色让出来的空间**：

```
y 300–560     字幕带（数据板不进入）
y 600–1400    数据板主区  ← 图形画在这里
y 1400–1560   角色缩小后的落脚区（右下角，x 620–1000）
```

- 数据板主区内左右各留 80 px 边距，实际可用宽 920 px
- 图形不要压到角色身上；角色缩到右下 25% 时，占 x 620–1000 / y 1080–1560，这块区域数据板要空出来
- 底板不做满屏纯色块——用 `--board-bg` 加 12% 透明度盖在场景视频上，**让背景微微透出来**，这样和场景的过渡不生硬

#### 1.5.4 线条与形状

| 属性 | 值 |
|---|---|
| 主描边 | 3 px，`--ink` |
| 辅助线 / 网格 | 1.5 px，`--board-grid`，虚线 6-6 |
| 圆角 | 8 px（柱状、条形、卡片统一） |
| 阴影 | 不用。平涂，与角色画风一致 |
| 渐变 | 不用。单一填充色 |

**不要用任何图表库的默认样式。** Chart.js、Recharts 的默认观感和这个手绘感角色是两个世界，全部手写 SVG。

#### 1.5.5 动画规格

这是最容易做歪的部分。数据板的动画节奏必须跟台词咬合，不能自己跑。

| 动作 | 时长 | 缓动 |
|---|---|---|
| 元素入场（淡入 + 上移 20px） | 0.35 s | ease-out |
| 柱/条生长 | 0.6 s | cubic-bezier(.22,.9,.3,1) |
| 数字滚动（从 0 到目标值） | 0.8 s | ease-out |
| 变色（高亮 / 变灰） | 0.25 s | linear |
| 元素退场（淡出） | 0.3 s | ease-in |

三条规矩：

1. **动画起点对齐台词，不对齐 beat 起点。** 说到「一百二十五」那三个字的第一个字时数字才开始滚，不是这个 beat 一开始就滚。
2. **同时最多两个元素在动。** 三个以上眼睛跟不上。
3. **动完就停住。** 不做循环呼吸、不做持续脉动——静止的图比一直动的图更好读。

#### 1.5.6 组件清单

八条稿里用到的只有这五种。做完这五个，后续基本不用新增。

| 组件 | 干什么 | 用在哪条 |
|---|---|---|
| `bigNumber` | 一个超大数字 + 单位 + 一行说明 | 全部（开场数字） |
| `bar` | 横条 / 进度条，可分格、可标记当前位置、可延伸出画面 | 02-A 五年格、04-B 三十年条 |
| `compare` | 两到三项柱状对比，可指定高亮项 | 01-A 房子对比、02-A 月供对比 |
| `stack` | 两层堆叠面积（本金/利息这种此消彼长） | 02-A 一摞钱 |
| `iconGrid` | 图标阵列，可逐个点亮、可最后聚合成一个轮廓 | 03-A 三十套、03-B 三次被拒、02-B 两分支 |

每个组件必须支持的通用能力：**入场**、**高亮某一项**、**置灰某一项**、**退场**。



### 2.1 场景视频的定位

**只当背景和空镜，不当叙事画面。** 角色站在前面，它在后面动。真正承载信息的画面（数字、图表、文件、户型图）由自己渲染。

理由：生成结果不可控、每次生成都不一样、时长短。定位成背景之后场景可以复用——不需要每条稿生成新场景。

**一次做完 12 个场景 × 2–3 变体 ≈ 30 个片段，后续反复用。**

### 2.1b 双来源：生成 + 实拍

场景库有两个来源，**优先用实拍**：

| 来源 | 用在 | 优势 | 代价 |
|---|---|---|---|
| **手机实拍空镜** | S-03 东京街头、S-04 住宅区、S-06 公寓外观、S-08 站台、S-10 夜景 | 「这人真的在日本」的实地感，是生成画面给不了的；且零版权风险 | 要出门拍，受天气和时间限制 |
| **Meshy 文生视频** | S-01 办公室、S-02 会议桌、S-05 空房间、S-09 文件特写、S-11 雨窗 | 随时可出、可控、不用借场地 | 缺实地感，只适合室内和抽象场景 |

**分工原则：凡是「证明人在日本」的画面，一律实拍；室内和情绪转场用生成。** 东京涩谷、银座、住宅区这些有地理识别度的场景，观众一眼能看出是不是真的，生成的骗不过去。

实拍要求和生成一致：无人入镜、无可辨认招牌、镜头基本静止、竖版 9:16、每个场景拍 15–30 秒备用。手机稳定器就够，不用无人机。

### 2.2 通用规格

所有场景生成时统一带上：

```
no people, no text, no signage, no logos,
static camera or very slow drift,
shallow depth of field, background softly blurred,
consistent even lighting, no dramatic light changes,
cinematic, vertical 9:16, seamless loop
```

**必须避免**

| 避免什么 | 为什么 |
|---|---|
| 画面里出现文字/招牌 | AI 生成的日文招牌基本是乱码，一眼假 |
| 人物 | 会跟角色抢注意力，且 AI 生成的人脸经常崩 |
| 强烈光影变化 | 角色的光是固定的，背景光变了会露馅 |
| 快速运动物体 | 与静态角色不匹配 |
| 硬边、高对比背景 | 角色是硬边，背景必须软，否则角色会「浮」 |

### 2.3 后期处理（必做三步）

生成出来的片段不能直接用，进库前统一过一遍：

1. **虚化**：高斯模糊半径 8–14 px（本来就有景深的也要再加一层）
2. **降饱和 + 压暗**：饱和度 −25%，亮度 −15%
3. **统一色温**：全库统一叠一层暖色（角色是暖色调，背景必须跟上）

再加两件合成时的事：**角色脚下加椭圆软阴影接地**、**角色和背景叠同一层色调层**。这两步不做，2D 平涂角色贴实拍会明显浮起来。

## 三、稿件格式

### 3.1 三行式

每个 beat 三行，需要时加第四行：

```
[时间]
台词  实际念的内容
画面  角色姿势 + 构图 + 数据板/图形
场景  场景 ID + 备注
大字  （可选）需要单独放大的数字或短语
```

### 3.2 硬性约束

| 约束 | 值 |
|---|---|
| 单条时长 | 45 秒 |
| 字数 | 320–380 字 |
| 单句字数 | ≤ 26 字 |
| 画面事件密度 | 每 3–8 秒一个 |
| 场景切换 | 一条最多两次 |
| 构图切换 | 一条最多一次 |
| 姿势连续相同 | 不得超过两段 |
| 开场 | 第 0.0 秒出声，无片头、无自我介绍、无标题卡 |

### 3.2b 情绪起伏与口语化

稿子不能全程平铺直叙——那是数字人最容易暴露机械感的地方。但情绪要靠**语汇 + 动作**双层承载，只有语汇没有动作会尬。

**可用的口语化插入**

| 用在 | 例句 | 必须配的动作 |
|---|---|---|
| 揭穿之后 | 「这不就结了。」 | 摊手 / 斜靠 |
| 否定观众预设 | 「别天真了。」「你先别急。」 | 抬手掌心向下 |
| 转折 | 「问题就在这儿。」 | 单手插兜转正视镜头 |
| 自嘲 | 「我当年也这么想的。」 | 扶帽檐 |
| 收尾 | 「就这么回事。」 | 斜靠，全景 |

**每条最多用两处。** 用多了会从「有血有肉」变成「油」。

**禁用**：哈哈哈之类的笑声（这个画风做不出配套神态）、网络热梗（半年就过期）、感叹号堆叠。

### 3.2c 封面规范

上一版定的是纯数字。这一版改成**混合式，并列入 A/B 测试**：

| 版式 | 构成 | 例 |
|---|---|---|
| **A 纯数字**（原方案） | 4–6 字，必含阿拉伯数字 | `第1套` / `不是最好的` |
| **B 数字 + 情绪词**（新增） | 数字 + 一个短促的判断词 | `别买这3种` / `125%` |

第一批八条里，四条用 A、四条用 B，同机制内部保持一致。**这是第一批唯一允许变动的第二个变量**，因为封面直接决定点击率，值得单独测。

不用的：`全是坑`、`暴跌`、`求你别买` 这类纯情绪、无信息量的词。理由是账号数据本身——纯情绪化的条（举报文化 207、基本人权 304）在这个受众里是垫底的。但「别买这 3 种」这种**带数字的祈使句**是可以的，它同时有情绪和信息。

### 3.2d 两套画面节奏

短视频和长视频的画面事件密度差一个量级，别混用：

| | **短视频（≤60s）** | **长视频（≥8min）** |
|---|---|---|
| 画面事件 | 每 **3–8 秒**一个 | 每 **6–10 秒**一个 |
| 切 B-roll / 数据图 | 随结构走，无固定间隔 | 每 **15–20 秒**必切一次 |
| 角色出镜占比 | 45–60% | 30–40% |
| 角色连续出镜 | 不限 | 单次不超过 20 秒 |

长视频那一列的 15–20 秒切换，作用是**掩盖口型和动作的重复感**——这是 2D 数字人在长视频里最容易翻车的地方，必须靠切换稀释。

### 3.3 结构

```
0–3s    钩子     一个数字或一句反常识
3–10s   常识     把观众心里的默认答案说出来
10–25s  拆解     2–3 个事实，每个带来源或亲历
25–38s  落点     一句能被截图的话
38–45s  收尾     钩子回收 + 一个问题
```

**写稿顺序：先定落点，再倒着往回搭。** 落点写不出来，说明这个选题还没想清楚。

机制号：01 揭穿 / 02 反常识 / 03 代入痛点 / 04 身份认同

### 3.5 `fx` 字段结构

写稿的人只描述「画面上发生什么」，渲染端按 `type` 查组件。这是 Claude Code 实现时的唯一接口。

```jsonc
{
  "t": 11.5,
  "line": "变动利率有个规矩，很多银行叫它五年规则。",
  "pose": "walk",          // 五个定格姿势之一 + walk
  "shot": "wide",          // close | mid | wide | corner
  "scale": 0.28,           // 角色在画面中的高度占比
  "bg": "S-12",
  "fx": {
    "type": "bar",
    "segments": 5,
    "label": "年",
    "marker": 0,           // 角色/标记停在第几格
    "value_fixed": true,   // 条上的数值不随格子变化
    "enter_at": 11.9       // 动画起点，对齐台词而非 beat 起点
  }
}
```

**五种组件的参数**

```jsonc
// bigNumber
{ "type":"bigNumber", "value":"125", "unit":"%", "note":"月供上涨的上限",
  "roll":true, "accent":true, "enter_at":31.4 }

// bar
{ "type":"bar", "segments":30, "label":"年", "marker":3,
  "filled_to":3, "muted_after":3, "overflow":true, "enter_at":11.9 }

// compare
{ "type":"compare", "items":[{"label":"现在","value":85000},
  {"label":"最坏","value":106000}], "unit":"円", "highlight":1, "enter_at":37.5 }

// stack
{ "type":"stack", "layers":[{"label":"本金","growth":0.05},
  {"label":"利息","growth":0.9}], "steps":6, "enter_at":26.4 }

// iconGrid
{ "type":"iconGrid", "icon":"house", "count":30, "reveal":"sequential",
  "merge_into":"outline", "annotations":["阳台","地段","价格"], "enter_at":16.9 }
```

**通用可选字段**（所有类型都支持）

| 字段 | 说明 |
|---|---|
| `enter_at` | 动画起点秒数。**省略则等于 beat 的 `t`**，但推荐显式写，对齐到台词里那个词 |
| `exit_at` | 退场秒数。省略则持续到下一个带 `fx` 的 beat |
| `accent_index` | 用 `--accent` 高亮第几项 |
| `mute_index` | 置灰第几项 |

**校验规则**（写进 check 脚本）

- 一条稿里 `fx` 为 `null` 的 beat 不超过三分之一
- 同一时刻最多两个 `fx` 处于动画中
- `accent` 高亮一屏最多一处
- `bg: "S-12"` 的 beat 必须有 `fx`（数据板背景却没有数据，说不通）
- `scale < 0.4` 时必须有 `fx`（角色缩小是为了让位给信息）

### 3.6 给本地实现的交付清单

Claude Code 拿这份文档做实现时，需要产出的东西：

| 文件 | 内容 |
|---|---|
| `board/tokens.js` | §1.5.1 的色值 + §1.5.2 的字号，单一来源 |
| `board/components/*.mjs` | 五个组件，各导出 `render(params, t)` 返回该时刻的 SVG 字符串 |
| `board/anim.mjs` | §1.5.5 的缓动函数与时长常量 |
| `board/preview.html` | 单文件离线预览器：五个组件的参数可调、时间轴可拖、导出当前帧 SVG |
| `board/render.mjs` | 读 `script.json`，逐帧输出数据板层的透明底 PNG 序列 |

**先做 `preview.html`。** 五个组件的样式必须先在浏览器里调到对，再接进渲染管线——直接对着 ffmpeg 输出调样式，一轮迭代要好几分钟。

## 五、出片流程

```
稿件 script.json
  ↓ 老石克隆音（GPT-SoVITS；2026-09-06 定：不做本人成品录音，录音只用来训模型）
  ↓ 剪语气词（长视频档位不同，短视频可以剪狠一点）
  ↓ 词级时间戳 → 驱动口型与切镜头点
  ↓ 角色逐帧渲染（透明底 PNG 序列）
  ↓ Meshy 场景库片段（已后期处理入库）
  ↓ 合成：场景（虚化底） + 角色（带接地阴影） + 数据板/图形
  ↓ 烧录字幕（上方 y300–560）+ 封面数字大字
  → 竖版 45s 成品
```

**三个要注意的点**

1. **口型别硬做音素。** 这个角色的口型是贴片，能做的开合度就那么几档。用音频 RMS 包络驱动开合、辅以词边界做闭合，比对齐音素划算得多。

2. **切镜头点由稿件决定，不由音频决定。** `script.json` 里每个 beat 标 `pose` 和 `shot`，渲染时按段读。自动切出来的一定像 PPT 翻页。

3. **`fx`（画面事件）字段建议设为必填、允许 null 但 null 率不超过三分之一。** 这个约束会逼着写稿的人一直想「这里画面上在发生什么」，比写规范文档管用。

### 5.1 声音的两阶段

| 阶段 | 做法 | 产能 |
|---|---|---|
| **第一阶段（前 20–30 条）** | 老石本人录，按条录、分批录 | 一次半小时约十条 |
| **第二阶段（可选）** | 经他书面同意后，用这批录音克隆**他本人**的音色 | 稿子写完当天出片 |

第二阶段的前提是三件事都做到：**书面授权**、**只克隆他本人**、**成片他有终审权**。这三条缺一个就不做。

克隆的价值不只是省时间——它解决的是「他忙起来账号就停更」这个结构性问题。日更或隔日更的账号，卡在真人档期上迟早会断。

**但第一阶段不能跳过。** 克隆需要足够的高质量样本，而且前 20 条的语气节奏会成为整个账号的声音基调，这个基调必须由真人定。

**永远不用的**：通用 AI 客服音、第三方音色克隆。前者一听就假，后者是权利问题。

## 六、数字核对表

稿件里标 `※` 的数字，**发布前必须由老石本人核对**。财经类内容出错一次，账号的信任成本很难补回来。

| 稿件 | 需核对的内容 | 风险点 |
|---|---|---|
| 02-A | 五年规则、125% 规则 | **这两条不是法律规定，是各家银行的惯例条款。** 相当多的网络银行不设这两条规则。稿子里说的是「很多银行」，这个措辞不能改成「所有银行」或「日本的规定」 |
| 02-A | 三千万贷款、八万五月供、十万六上限 | 月供数字依赖利率和年限假设，需按当前实际利率重算，或改成「假设」措辞 |
| 04-B | 年收一千万算高收入 | 需要一个可引用的统计口径（国税庁的民間給与実態統計調査之类），否则会被质疑 |
| 全部 | 涉及具体房源、具体银行、具体中介的描述 | 不点名，不给可识别的细节 |

另外两条通用的：

- 老石的第一人称经历（「我见过不少」「我那套房」）**必须是真的**。这是账号信任的地基，编一次被拆穿就没了。
- 涉及外国人待遇差异的内容，用数据说话、不用情绪。这类题材容易爆，也容易被平台判定为敏感。

## 七、验收与迭代

**第一批八条，同一周发完。** 只看两个数：

| 指标 | 阈值 | 说明 |
|---|---|---|
| 2 秒跳出率 | < 40% | 压不下去就是开场问题，题材再换都没用 |
| 完播率 | 越高越好，横向比 | 跳出低但完播差 = 中段松了 |

**归因规则**

- 四种机制的跳出率差异 → 决定后续哪种机制加码
- 同机制两条之间的差异 → 决定开场写法（数字前置 / 否定观众 / 直接进场景 / 结论倒置）
- 完播率的分布 → 决定画面事件密度要不要再提高

**别在第一批里同时改多个变量。** 八条的开场写法要保持同一套逻辑，否则跳出率的差异归因不到机制上。

## 八、长视频形态的解锁条件（不是现在做，是排进计划）

短视频跑通之后，长视频有两条路。**第二条需要补素材，值得现在就去约。**

### 8.1 路线 A：调查式解题（现有素材就能做）

一个具体问题，12–18 分钟真的把它答完。角色站姿，出镜占比 30–40%，只在章节转折处出现。

结构：抛问题 → 排除三个常见错误答案 → 找到真正的机制 → 验证 → 落点。

节奏按 §3.2d 的长视频列走：画面事件 6–10 秒一个，15–20 秒必切一次 B-roll。

### 8.2 路线 B：播客 / 围炉煮茶（需补素材）

温暖的办公室或茶室背景，桌上一杯冒热气的茶，角色坐姿、松弛地聊 20–40 分钟。这个形态的好处是**内容成本极低**（不需要图表、不需要密集画面事件），且最贴合「出海老炮跟你聊天」的人设。

**挡路的只有一件事：现有素材没有坐姿。** 角色是全身正面立绘，坐姿必须重画，不是调参数能解决的。

要向原作者约的素材清单：

| 文件 | 内容 | 用途 |
|---|---|---|
| 坐姿全身 | 坐在桌后，双手放桌上，与现有立绘同一画风、同一配色 | 主姿势 |
| 坐姿手臂 A | 单手端杯 | 喝茶动作 |
| 坐姿手臂 B | 抬手比划 | 说到重点 |
| 坐姿手臂 C | 双手交叠 | 倾听 / 停顿 |

要求：与现有立绘**同一光源方向、同一线宽、同一配色**，透明底，手臂与主体分离导出（不要合并在夹克路径里）。这四个文件到位，播客形态就能做。

桌上的茶杯热气、光线变化这些细节，用叠加动效做，不需要角色本身支持。

### 8.3 长视频不做的

- 时事快评 —— 过期不候
- 漫谈式无结构长聊 —— 没有悬置结构，观众撑不过 5 分钟
- 短视频拼接 —— 长视频是独立选题，不是合集
