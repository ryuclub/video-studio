## 一、这个系列是什么

第三人称转述的说书，**音频为主，视频只放关键场景静态画面**。

素材：`shuoshu/` 下有 91 部书目的评估表（带公版状态和 fit 评分）、
首月 17 期排播卡、E01 整稿。

| | |
|---|---|
| E01 稿件 | 2905 汉字 / **165 段** / 7 幕 |
| 预计成片 | 15.3 分钟（按 190 字/分） |
| 合成耗时 | **约 4 分钟**（实测短段 0.64s、中段 1.28s、长段 1.40s） |

### 为什么这个形式成立

按 joke-video 的逐帧管线，15 分钟 = 27,540 帧 × 0.48s = **3.7 小时/期**，17 期 63 小时，直接死。

但「音频为主 + 静态画面」把这个断点消掉了：**帧数由画面切换次数决定，不由时长决定**。
20 张关键场景图 = 渲 20 帧（约 10 秒）+ ffmpeg 一遍编码。15 分钟和 2 分钟成本一样。

## 二、音色定案（7 个，17 期通用）

聊斋的角色原型（书生 / 老道 / 女鬼…）在 17 期里反复出现，所以做成通用音色，
定义在 `joke-video/src/cast.ts` 末尾的「说书」那一组。

| 音色 | 基础音色 | 语速 | pitch/formant | 基频 | 用在哪 |
|---|---|---|---|---|---|
| `说书人` | **云健** | **+19%** | **0.92 / 0.94** | **112Hz** | 叙述基准，占全片八成（08-19 返工，见第七节） |
| `书生` | 云希 | −2% | 0.94 / 0.96 | 182Hz | 王生 / 宁采臣 / 成名 |
| `妇人` | 晓晓 | −4% | 1.00 / 1.03 | 247Hz | 陈氏 |
| `艳鬼` | 晓伊 | −2% | 1.10 / 1.13 | 333Hz | 女鬼的美人相 |
| `厉鬼` | 晓伊 | −16% | 0.95 / 0.97 | 289Hz | 女鬼现形 |
| `老道` | 云扬 | −10% | 0.86 / 0.91 | 96Hz | 道士 / 老者 |
| `乞丐` | 云健 | +10% | 1.06 / 0.94 | 137Hz | 乞人 / 市井 |

试听样本在 `voice-samples/`，全部用剧本里真实会用到的台词。

### 跟稿件卡片不一致的地方（刻意的）

卡片给的是**单旋钮半音**（男主 −2、女主 +3、老者 −4…），假设所有角色共用一个基础音色。

这里改成**先用不同的基础音色拉开距离，morph 只做微调**。理由：morph 拉得越狠
rubberband 的金属味越明显，而说书是十几分钟连着听，一点点 artifact 都会被放大。

### 两条量化红线

| | 怎么量 | 红线 | 现状 |
|---|---|---|---|
| **① 可懂度** | 2–8kHz RMS 相对全带 | 不得比叙述者低 8dB | 全部通过 |
| **② 分离度** | 基频差 / 低高频差 | ≥25Hz **或** ≥6dB | 两两都过 |

**顺序不能反。** 踩过的坑：为了让分离度过线，把厉鬼压到 `pitch 0.50 + lowpass 1500 + 长混响`，
指标漂亮了，**人完全听不清说什么**——低通 1500 把中文辅音（s/sh/x/c/q，能量在 2–8kHz）全砍了。
优化指标优化到听不懂，是本末倒置。

同角色的不同状态（艳鬼 ↔ 厉鬼）**排除在分离度检查外**——它俩本来就该像。

### 厉鬼为什么是这一版

曾有一版「变形版」（pitch 0.67 + 重低通 + 混响），试听淘汰。**方向错了**：
「低沉 + 大混响」是卡通怪兽的路子，回响 = 远，远就不威胁。

而《画皮》的题眼是**那个美人就是那个东西**。鬼音做成通用怪物，这层联系就断了。
定稿版音高几乎不动（听得出还是她），靠三件事做恐怖：**慢（−16%）、
压平动态（没有情绪起伏）、22ms 梳状回声（一个声音带出第二个）**。

台词是幕三门外那句：「道士吓唬我？笑话。我到嘴的东西，还能吐出来不成。」
可怕之处在于**轻蔑和从容**，不在音色。

## 三、节奏定案：C 版

试听过三个版本，**选 C**。

| | 时长 | 最长空白 | 空白合计 | 音量 | 语速 |
|---|---|---|---|---|---|
| A-默认节奏 | 21.5s | 0.82s | 5.9s | 全程一致 | 全程叙平 |
| **C-紧凑版（选定）** | 23.2s | **0.98s** | 7.3s | 0.70–1.08 | 三档混用 |
| B-手工调过（作废） | 25.5s | 1.54s | 9.2s | | |

样本在 `ab-test/`。

### 为什么砍掉长停顿

B 版的长停顿（1.2–2.2s）试听反馈是「有明显的停留空白，不舒服」。

根因不是长度，是**我们插的是绝对静音**——实测 **−227dB**，现实里不存在这种东西。
真人停两秒，听众听得到换气和现场；广播里的长停底下永远垫着环境声。
**没有底噪时，停顿越长越像「卡带」，不像「酝酿」。**

还有一个结构问题：B 版在「往里看 →〈1.28s〉→ 他看见 →〈1.48s〉→ 屋里坐着一个鬼」
连着挂了两个大停，**2.76 秒静音夹着 3 个字**。说书的扣子应该只有一个：
正常 → 正常 → 停住 → 揭开。

### 为什么保留音量和语速

C 不是「退回 A」。B 比 A 多三样，只有停顿那一样有问题：

- **停顿给多了会「卡」**，是听得见的破绽 → 砍掉
- **音量、语速给多了最多是「起伏小了点」**，不会翻车 → 保留

15 分钟全程一个响度一个语速是另一种失败：**单调**。恐怖故事听到第五分钟走神，
不是「稳」，是「平」。

### 节拍表（`joke-video/src/shuoshu-beat.ts`）

标注稿件时只写标签，数值集中在一处——**改一个数，全片 165 段跟着变**。
这套抽象是被反复调停顿逼出来的：第一次调整如果散落在 165 段里，要改三十处。

| 节拍 | 念法 | 停顿 | 音量 | 用在哪 |
|---|---|---|---|---|
| `常规` | 叙平 | 0.6s | 1.0 | 默认，不用写 |
| `提速` | 叙快 | 0.45s | 1.0 | 动作句连着推 |
| `顿` | 叙快 | 0.6s | 1.0 | 动作落下来留半拍 |
| `贴近` | 叙缓 | 0.6s | **0.78** | 压低嗓子把听众拉近 |
| `扣子` | 叙缓 | 0.7s | 0.72 | 吊住 |
| `落定` | 叙缓 | 0.8s | 0.92 | 发现不对劲 |
| `揭底` | 叙平 | 0.8s | **1.08** | 揭开，平着说别演 |
| `点评` | 叙缓 | 0.8s | 1.05 | 说书人跳出来对听众说话 |
| `悬` | 叙缓 | 0.9s | 0.70 | 全片最长的停 |
| `引文` | 叙缓 | 0.9s | 1.0 | 文言直引 |
| `收` | 叙缓 | 1.0s | 0.95 | 一幕收尾 |

## 四、这套控制的天花板

**能控**：停顿位置和长度、整句快慢、整句音量、整句高低（有死区，+20Hz 以内无反应）。

**控不了**：一句话内部哪个字重读、句内音高曲线、气口。
Edge 的中文只有一种「念稿」腔，这三样是它自己生成的。

所以成品会像**干净的有声书朗读，不像评书**。差的那一截是 TTS 给不了的。

要再往上推只有三条路：Azure 的 `style="story"`（有专门的讲故事韵律模型）、
本地大模型 TTS（这台机器没有 NVIDIA，CPU 推理比实时慢 3–10 倍）、真人录音。

## 五、标注（2026-08-19 完成）

165 段全部标完，展开成 **174 个声部**——「声部」是合成的最小单位，
一段里可能有两个声音（说书人报「他说：」，角色接台词）。

| | |
|---|---|
| 说书人 | 148 声部（85%） |
| 老道 | 9 ｜ 书生 8 ｜ 艳鬼 3 ｜ 乞丐 3 ｜ 妇人 2 ｜ 厉鬼 1 |
| 带设计节拍 | 103 声部（59%），其余 71 段走 `常规` |

### 18 段代词对白，外加机器漏掉的 2 段

`needsReview` 那 18 段逐条定了说话人。另外两段是**自动识别本身漏掉的**，
标注时顺手揪出来的——这类才是真正危险的，因为它们没有任何标记：

- **第 21 段**「她说，我原是大户人家买来的妾…」——用的是**逗号不是冒号**，
  解析器的对白正则只认 `[说问道][：:]`，整段就当旁白过去了。
  漏了它，女鬼那段身世自白会用说书人的嗓子念完。
- **第 51 段**「惑哉！世固有死将临而不悟者。」——机器认出是引文（打了 `引文` 节拍），
  但**没认出是谁说的**，挂在旁白名下。这句是全篇分量最重的一句，是**道士的原话**，
  音色试听里 07-老道 用的就是它。

### 一条规则：光报名的引述扔掉，带信息的留着

- **扔掉**「他说：」「她说：」「它说：」——角色的声音一出来就知道是谁了，
  再报一遍是冗余。解析器对明确点名的对白（「王生说：」）本来就是这么处理的，
  这里只是把同一条规则铺到代词那 18 段。
- **留着**「姑娘摇头。」「但嘴上还是硬。」「他对自己说：」「道士看了她半晌，说：」——
  这些有动作、有态度，扔了就丢内容。留下来的用说书人念，走新加的 `引述` 节拍。

新节拍 **`引述`**：停 0.3s（全表最短）、音量 0.95。报完名**马上**接台词，
中间空半秒听感就散成两句无关的话了。

### 节拍怎么铺的

`悬`（0.9s，全片最长的停）只用了 **4 次**——65「他看见」、90「停了很久，一点声音都没有」、
137「她愣住了」、146「她张开嘴」。这东西给多了就不值钱。

固定套路是**扣子 → 悬 → 揭底**：吊住、停死、然后**平着说**。
64/65/66 那三段（往里看 → 他看见 → 屋里坐着一个鬼）是 A/B 试听里验过的原型，
148/149（陈氏低头一看 → 是一颗心）是同一套的重演。

`点评` 8 处全部给了说书人跳出故事直接对听众说话的地方（14「请你记住这一下心动」、
收束那几段），这是说书跟有声书朗读唯一拉得开距离的手段。

## 六、整期合成器 `shuoshu-build.ts`

```
npx tsx src/shuoshu-build.ts --ep E01              全片
npx tsx src/shuoshu-build.ts --ep E01 --preview    前三幕试听（约 4 分钟）
npx tsx src/shuoshu-build.ts --ep E01 --acts 幕二,幕三
npx tsx src/shuoshu-build.ts --ep E01 --to 幕一
```

### 期号是参数，不是常量（2026-08-19）

原来 `EP` 硬编码在五个文件里，跑 E02 会**把音频写进 E01 的目录**——数据损坏，不是麻烦。
现在统一走 `shuoshu-ep.ts`：`--ep` 认全名也认简写（`E01`），**没有默认值**。
默认成 E01 的话，跑 E02 忘了加参数就会覆盖掉一期成品而且不报错；多敲六个字符换掉一整期返工。

解析那一侧不用给 `--ep`：`shuoshu-parse.ts` 从稿件文件名推期号
（`liaozhai-E02-nie.md` → 找带 E02 的目录，没有就按今天日期建一个）。

### 人名表跟着稿件走，不在代码里

稿件头部 `---` 之前写一行：

```
- 选角：王生=书生 · 陈氏=妇人 · 道士=老道 · 乞丐=乞丐 · 姑娘=艳鬼 · 女子=艳鬼 · 蒲松龄=说书人
```

左边是稿子里的称呼（一个人有几个称呼写几条），右边是选角表里的音色名，
**写错的音色名在解析时就炸**，不会等到合成。

原来这张表写死在 `shuoshu-parse.ts` 里，等于每期改一次源码；更糟的是**忘了改也不报错**——
E02 的对白会安静地全部退化成「需要人工判断」，而那正是整条管线唯一的瓶颈。
改完拿 E01 验证过：解析结果跟原来逐字一致（159/3/2/1 段，18 段待确认）。

**断点续传不落自己的文件**：`tts.ts` 那两级缓存就是断点——
`base-*.mp3` 按「台词+音色+韵律」做键，`mix-*.wav` 按变声参数做键。
跑到一半挂了直接重跑，合成过的秒过。真正要防的是 Edge 偶发网络失败，
那个在段落级重试三次、退避 2/4 秒。

顺带白送一条：**改一句台词只有那一句重新联网**，因为台词本身在缓存键里。

### 送进 TTS 之前的清洗

- **句尾「——」删掉**，句中「——」换成逗号。Edge 完全不认破折号（实测 1.763s → 1.760s），
  句尾那个「话没说完」的停顿由节拍给（`顿`/`悬`），留着破折号只会被念成什么都没有。
- **「」删掉**：引号念不出来，留着只是给人看的。

- `audio/<范围>.manifest.json`——每个声部的 `start`/`end`/`who`/`beat`/`text`。

## 七、主讲人返工（2026-08-19，前三幕试听之后）

前三幕试听的反馈：**角色都好，主讲人机械、偏慢。** 这一节是这次返工的完整记录——
调成现在这样不容易，下一期直接照抄结论，别重走一遍。

### 诊断：慢和机械是两件事，得分开修

**慢**——量出来主讲是全场最慢的一个：

| 说话人 | 净语速 | 语速链路 |
|---|---|---|
| 书生 | 258 字/分 | −2% + 叙平 −10% = −12% |
| 艳鬼 | 240 | −12% |
| 妇人 | 237 | −14% |
| **说书人（旧）** | **230** | **−6% + −10% = −16%，比谁都低 2–4 点** |

更要命的是**全片主讲有 40% 的字挂在 `叙缓`**（净 −28%），实测只有 178–203 字/分。
「偏慢」的主要来源是这一档，不是平均值。

**机械**——根因是音色选型，不是参数：

- `说书人` 旧版用**云扬 = 微软的新闻播报音色**，设计目标就是「平稳、可信、不带个人色彩」，
  这几乎就是机械的定义。而它的 morph 是 `0.97 / 0.97`，**几乎等于原声**，播音腔一点没改掉
- 角色好听不是偶然：晓晓、晓伊、云希都是**对话向**音色
- `TONE.broadcast` 里有个 **2.5:1 的压缩器**，把节拍表用 gain 做的 0.70–1.08 音量起伏按平了一部分
- 71 段常规**参数完全相同**，每段又独立合成 = 165 条一模一样的语调弧线

> 顺带记一条**别再走的弯路**：想用「语调跨度（基频 10–90 分位）」量单调，
> 主讲测出来 30.8 半音——低男声上自相关跳倍频了。**这个指标在低男声上测不准，别信。**

### A/B：四条，只改主讲人

`shuoshu-narrator-ab.ts`。素材用**剧本原文**第 1/2/24/59–66 段，不另写试听句。

| 版本 | 改了什么 | 主讲净语速 | 结论 |
|---|---|---|---|
| 0-现状 | 云扬 + 播音音染 | 243 | 对照 |
| V1-提速 | 音色不动，+12% + 微抖 | 276 | 不够，还是播音腔 |
| **V2-云健** ✅ | **换云健压成沉稳中年 + 卸掉播音压缩器** | **272** | **定稿** |
| V3-云希对调 | 主讲云希、书生云扬 | 264 | 淘汰 |

**关键一步是把四条的语速配平再听。** 云健在同一个 rate 设定下**比云扬天生慢 13%**
（+6% 时 239 字/分，云扬同设定 276）。不补上这 13%，V2 会因为「慢」被误杀——
而慢正是我们要修的毛病，不是它的问题。**A/B 只能有一个变量。**

### 定稿参数

```
说书人: base 云健(YunjianNeural) · rate +19% · pitch 0.92 / formant 0.94
        tone: 低频托底 +1.5dB @240Hz + acompressor 1.6:1
```

- **+19%** = 补云健天生慢的 13% + 要提的速。落地实测 **274 字/分**，跟你认可的角色语速在一条线上
- **不用 `TONE.broadcast`**，换 1.6:1 的轻压缩，把音量起伏还回来
- **没有新增 `说缓/说平/说快`**：rate 加在 cast 上，三档 `叙缓/叙平/叙快` 整体上移 25 点，
  跨度不变。以后要单独收窄跨度再加新档——**绝不能改那三档本身**，
  `jokes/mouse-cake.json` 直接按名字引用它们

### 句子级微抖动（`shuoshu-build.ts` 的 `jitterOf`）

每段按 `(段号, 声部号)` 取 ±3% 的语速偏移。**按段号定，不用随机数**：
随机的话每次跑出来不一样、缓存全废，而且 A/B 两版的差别会混进抽签噪声。
**只给说书人上**，角色那二十几段不动。

### 换完之后新出现的问题（已定案：走丙）

```
✗ 老道 ↔ 说书人　Δ基频 17Hz　Δ低高频 1.8dB
```

云健比云扬低，主讲从 134Hz 掉到 **112Hz**，跟老道（95Hz）挤到一起了（旧版 Δ38Hz）。
红线要求 Δ基频 ≥25Hz **或** Δ低高频 ≥6dB，现在两条都不过。

三条路，**还没定**：

| | 做法 | 代价 |
|---|---|---|
| 甲 | 老道再压低 pitch 0.86 → 0.79（约 87Hz） | 动已认可的老道，且它已是变声最狠的一个，再压有金属味风险。**要写成内联滤镜链，不能改 `TONE.aged`** |
| 乙 | 主讲抬回 pitch 0.92 → 0.98（约 120Hz） | 动刚认可的主讲 |
| 丙 | 不改，靠语速差分辨（+19% vs −10%，近 30% 速度差，红线里没算这一项） | 赌耳朵比指标准 |

倾向丙，但要**先出一条幕二 43–46 段（说书人 → 老道 → 书生 → 老道 交替）的对照**用耳朵定。
这个项目踩过一次「优化指标优化到听不懂」的坑（厉鬼那版低通 1500 砍掉辅音），
**指标是 proxy 不是目的**。

> **定了：走丙，不动音色。** 对照片段出在 `voice-samples/10-三男声对照.wav`，
> 听下来三个男声分得清（细节见第十二节「新角色二郎」）。红线口径也修了一处：
> 基频要用**同一句探针**量，各念各的台词量出来的差值不可比。
> **这条只对 E01 的戏份成立**——老道全片 17 段 61.7 秒。哪一期他的戏份重起来，
> 得重新拿耳朵过一遍，别把这个结论当通行证。

## 八、选角表护栏 `npm run cast:check`

**选角表是跨类型共享的基础库**，段子视频和说书都从这里取音色。共享的不只是这张表，
还有底下的 TONE 预设：

| 预设 | 说书在用 | joke-video 也在用 |
|---|---|---|
| `aged` | 老道 | 老爷爷 · 老太太 · 沙哑老头 |
| `raspy` | 乞丐 | 沙哑老头 |
| `bright` + `thin` | 艳鬼 | 童声 · 童声奶 · 女童 · 精灵 · 干练女 |
| `broadcast` | —（主讲已经不用了） | 旁白 |

所以「把老道调沉一点」如果顺手改了 `TONE.aged`，**老太太会跟着变**，
而老太太在 `jokes/` 里是活的——下次出片才发现，那时候早忘了是这一改动的。

### 规矩

1. 调一个角色，只改**它自己那一块**
2. 共享预设（`TONE` / `DELIVERIES`）**只读**。要不一样的音染就**新增**一个预设，
   或者像「厉鬼」那样把滤镜链内联到角色自己身上
3. 改完跑 `npm run cast:check`。报出来的每一行都该是你**打算**改的，多出来的就是连带影响
4. 确认无误：`npm run cast:check -- --update`

不合成、不联网，只对配置算指纹，一秒跑完。基线在 `src/cast-baseline.json`（50 条：
角色 29 / 念法 14 / 音染 7）。

实测有效：试着给 `TONE.aged` 加一条滤镜，它报了 5 条——
`老爷爷 / 老太太 / 沙哑老头 / 老道` 加 `tone:aged` 本身，并点名「牵连 4 个角色」。

### 字幕怎么生成的（`shuoshu-srt.ts`）

段落是按呼吸写的不是按屏幕写的，一段五十多字直接上屏就是一堵墙。所以：

1. 按标点打包成每条 ≤20 字，**优先在句末（。！？）断**
2. 内部边界先按字数比例算，**再吸到波形里最近的能量谷**（±0.45s 内找）

第 2 步是关键：纯比例分是「平均语速」假设，实际句尾会拖、逗号会停，误差累到段末能有半秒，
字幕比声音早半秒出就是抢拍。而 Edge 在标点处本来就插了静音，谷底找得到。
**不需要 Edge 的 wordBoundary，也就不用为了字幕去动 `tts.ts` 的缓存结构。**

字幕用**原文**（带破折号和「」），不是送 TTS 的清洗版——那两样是给眼睛看的，只是嘴念不出来。
文件带 UTF-8 BOM，否则 Windows 上一堆播放器会按 GBK 解成乱码。

### 响度链路（2026-08-19 定型）

```
逐段 gain（节拍表） → 拼接 → 峰值归一化 −1dBFS
  → 量 → 固定增益整片抬 → 前瞻限幅 −3dBFS → 真峰超标就再整片降一点
```

产物：**−17.2 LUFS / 真峰 −1.0 dBFS / LRA 5.0**（原来 −23.4，听众每次都要手动加音量）。

**踩到两个坑，都记下来：**

**① ffmpeg 的 `loudnorm` 不能用。** 它的 `linear=true` 在这种素材上根本生效不了——
整片要抬 7dB 而峰值本来就在 −1dBFS，抬上去必然过顶，于是它**悄悄退回动态压缩**
（只在 info 级日志里说一句，而我们跑的时候用 `-v warning` 把那句压掉了，等于没检测）。
代价是可量的：逐节拍量下来，**「扣子↔揭底」的音量跨度从 3.87dB 被压到 2.61dB，
节拍表的音量设计被吃掉三成**。

换成自己控（量 → 固定增益 → 只削瞬间峰）之后是 3.87 → **3.37dB**，损失 13%。
固定增益不改变任何两段的相对关系，那才是节拍表的全部价值。

**② 限幅器管的是采样峰值，真峰会超。** 限在 −1.5，真峰实测跑到 **+0.8 dBFS**——
转 mp3/aac 会破音。现在限幅留到 −3，超标再整片降（纯增益，不花动态），
最后卡在 −1.0 dBFS。

**③ `spawnSync` 的 maxBuffer 默认只有 1MB。** ebur128 每 100ms 打一行，
12 分钟七千多行正好冲爆，**丢掉的恰好是末尾的 Summary**，表现成「量不出真峰」。
调到 256MB。

**为什么是 −17.2 而不是 −16**：真峰要守住 −1.0，最后那一下整片降了 1.2dB。
再往上推只能靠更狠的限幅，那就要拿节拍表的音量设计去换。Apple Podcasts 的
−16±1 差 0.2，YouTube 只往下压不往上抬，**这个位置不亏**。

> 原来这里挂着「整体响度 −23.4 LUFS 偏小」，08-19 已解决，上面就是解决过程。
> 落点在 `shuoshu-build.ts`，**没有动 `config.ts` 的 `PEAK_DBFS`**——那个段子视频也在用。

## 十、出视频（2026-08-19）

E01 到这一步走完了整条路线：**稿件 → 音频 → 字幕 → 画面 → 成片**。
产物 `2026-08-18_liaozhai-E01.mp4`，1920×1080 / 12:32.8 / 约 33 MB。

### 为什么是横版

joke-video 那条线是 1080×1920 竖版（Shorts）。说书是十几分钟的长视频，
**竖版根本进不去 Shorts（上限 3 分钟）**，所以这条线自己定 1920×1080，
不复用 `config.ts` 的 W/H。

### 水墨风格模块 `style/inkwash.ts`

剪纸风不能用：那是**平涂色块 + 明亮配色**，做儿童向段子对，鬼故事配上朱红嫩绿当场垮掉。

新模块的三条规矩：

1. **留白是主角。** 画面七成是空的宣纸，主体只占一角
2. **只有一个颜色——墨。** 深浅靠透明度不靠色相，唯一的例外是印章的朱红
3. **边缘要湿。** 干净的矢量边看着像 PPT 剪贴画。靠 `feTurbulence + feDisplacementMap`
   把边推乱——**这一步是像不像的分水岭**

跟剪纸风相反的一点：**这里用 SVG 滤镜**。剪纸风刻意不用（每帧都渲，滤镜慢十倍），
但说书是静态画面，一期只渲二十来张，慢十倍也就一分钟。

一方红印的作用被低估了：**有它和没它差别极大**，一方印立刻把「抽象墨块」变成「一张画」。

### 踩到的：人影必须是中远景

第一版把执笔的鬼画到 430px 高，出来是一尊塑像——**每一处粗糙都被放大**。
同一套代码画 300px 高的行人却完全成立。

所以定一条硬规矩：**人影一律 ≤320px（1080 高的画布），近景不画人。**
这不是审美偏好，是这套技法的边界。近景要交代的东西交给题字。

还有两条同类的：

- **人皮要横躺。** 第一版竖着画，跟旁边站着的人影一个姿态，读出来是"两个人站着"，
  恐怖点整个没了。它的可怕之处是**平**——一个人形摊在榻上，没有厚度，像件脱下来的衣裳
- **人影画的是袍子外轮廓，一条闭合路径**，不是骨架拼装。
  第一版拿 `brush()` 在「肩—腰—脚」上拉宽笔触，出来是几块浮着的矩形，脑袋还跟身子分家

### 画面切点不用另外对时

`scenes.json` 里每张图只写**"从第几段开始"**，切点从 `audio/全片.manifest.json`
的时间轴取。音频重出、时长变了，画面自动跟着走。

E01 排了 **26 张**，平均一张 29 秒。

### 出片 `shuoshu-video.ts`

```
npx tsx src/shuoshu-scene.ts --ep E01     渲静态图（26 张约 70 秒）
npx tsx src/shuoshu-video.ts --ep E01     拼片 + 烧字幕（约 5 分钟）
                            --no-sub      不烧字幕
                            --drift       加缓慢推镜
```

不走 joke-video 的逐帧管线：那条 12.5 分钟要 22,500 帧 × 0.48s ≈ **3 小时**。
这里图是现成的 PNG，ffmpeg 的 concat 解复用器按时长拼，整片编码 5 分钟。

**三个坑：**

**① concat 的最后一张要写两遍。** 解复用器把 `duration` 理解成"这一条什么时候结束"，
最后一条的 duration 被忽略，画面会停在倒数第二张。

**② 字幕的 FontSize / MarginV 不是像素。** libass 把 srt 转 ass 时用默认的
PlayRes 384×288，`force_style` 里的数值在那个坐标系里，渲到 1080p 要乘 3.75。
第一版写 `FontSize=21` 出来是 79px 的巨字，`MarginV=58` 把字顶到画面 3/4 高的位置压在画上。
现在按 ÷3.75 反推：14 → 约 52px，16 → 约 60px。

**③ 字体名要用系统里真有的族名。** 写 `Noto Serif CJK SC`（思源的旧名）匹配不上，
libass **静默回退到黑体**，跟题字的宋体对不上。这台机器上是 `Noto Serif SC`。

顺带一个省事的做法：`subtitles` 滤镜里 Windows 盘符的冒号要三重转义，
与其跟转义较劲，不如把 ffmpeg 的工作目录切到音频目录，只传文件名。

## 十一、封面图（频道规范，每期必出）

**不是可选项。** 平台抓缩略图取的就是第一帧，缩略图决定点不点开——
正片做得再好，封面糊了就没人看见。**每一期都要出，不用等人提醒。**
`shuoshu-video.ts` 找不到 `cover.png` 直接报错，跑不动。

```
npx tsx src/shuoshu-cover.ts --ep E01
  → cover.png                   1920，视频第一帧
  → cover/upload-1280x720.png   平台上传
  → cover/check-320.png         **先看这张**
  → cover/cover.svg             矢量源，出专辑封面/印刷尺寸时不用重画
```

### 第一版为什么推倒重来

第一版是拿正片那套宣纸水墨改大字号做的，出来是"浅底淡墨"，
**缩到手机信息流里整张发白**，什么都看不出。

**封面和正片是两个东西**：正片求耐看（十七分钟连着看），
封面求一眼抓住（0.5 秒，指甲盖大小）。同一套视觉语言撑不了这两件事。

现在这版把 `E:\ryu\project\liaozhai-cover` 那个原型的思路整套搬过来了。

### 版式

```
夜靛青渐变底
├ 左三分之一：篇名繁体竖排巨字（畫皮 / 聶小倩）
├ 中间：一笔画的主体符号，穿过整个画面
├ 右侧一栏：书系名 / 细线 / 两行钩子 / 期号
└ 右上角：一方朱印
```

E01 的符号是**画到一半的侧脸**：额头起笔米白（皮已成形），
到唇下转朱砂并渐渐化空（**正在被画出来**）。整张封面的意思全在这一笔上。

### 四条铁律（照搬，别自作主张改）

1. **元素不超过四个**：篇名、符号、钩子、印章。想加东西之前先删一个
2. **强调色只用在一个地方**。缩到 320px 读者只来得及看一个焦点，
   同一张图两处强调 = 两处都失效。E01 是钩子里的「鬼」字
3. **标题按左缘定位，不按中心线**。两字和三字字号不同，按中心排会让边距忽宽忽窄
4. **先看 320 那张再上传**。在 1280 上好看不算数

### 书系（换书只换这一处）

版式骨架全频道统一，一个书系 = 一套配色 + 栏目名 + 印章形制：

| key | 用于 | 调子 | 印章 |
|---|---|---|---|
| `liaozhai` | 中国志怪 | 夜靛青 + 朱砂 | 方印（白文） |
| `kaidan` | 日本怪谈 | 墨黑 + 胡粉 + 朱 | 方印 |
| `gothic` | 西方志怪 | 暗墨绿 + 旧金 | 圆章（描边） |

**为什么不全系列共用一套色**：靛青+朱砂是很正的中式志怪调子，
用在西方哥特上会张冠李戴。丛书的通行做法是骨架统一、按类别换色。

### 数据在 scenes.json

```json
"cover": {
  "series": "liaozhai",
  "title": "畫皮",              // 繁体，2~6 字，字号按字数自动切换
  "hook1": "他明知她是鬼",       // 各 6 字最整齐
  "hook2": "還是帶她回家",       // **写故事里最反常的那个动作，不写形容词**
  "accent": "鬼",               // 强调色，一个字就够
  "seal": "其一",
  "epLabel": "夜聽說書 · 第一則",
  "motif": "侧脸"               // 见 shuoshu-cover.ts 的 MOTIFS
}
```

加一期 = 在 `MOTIFS` 里加一个符号函数 + 在 scenes.json 里填这一段。

### 两个实现上的坑

**① 可变线宽要分段。** SVG 单条 path 的 `stroke-width` 是常量，做不出笔锋。
`catmullSegments()` 把曲线切成十几段，每段给自己的宽度和颜色，
`stroke-linecap="round"` 让接缝看不出来。侧脸从米白渐变到朱砂就是这么来的。

**② resvg 对可变字体的 weight 轴支持有限。** 只有 `NotoSerifSC-VF.ttf` 时，
写 `font-weight="900"` 实际渲出来是 Regular，标题在 320 自检图上细得发飘。
先前的对策是**给文字加一圈同色描边**撑粗笔画——次优解，把「畫」这种密笔画的字内白糊住。

**2026-08-19 换成了真字重。** 静态 OTF 放进仓库 `fonts/NotoSerifCJKsc/OTF/SimplifiedChinese/`，
封面渲染只认这七个文件（`loadSystemFonts: false`，免得系统里的同名族来抢）。
七个文件的 typographic family 都是 `Noto Serif CJK SC`，fontdb 按 OS/2 的 weight 值分字重，
所以**族名只写一个**，900 拿到真 Black、500 拿到真 Medium。描边随之关掉
（`BOLDEN = FONT_FILES.length ? 0 : 0.021`，字体没跟着走时退回老办法）。
E01 封面已按这一版重出，「畫」的字内白开了，钩子那行也压得住 320。

### 片头压 1.5 秒

最早只给封面 1 帧（33ms），理由是"肉眼看不见、平台取得到"。**那是错的**——
打开文件根本看不到封面，等于没做。长视频的开头本来就该有一张定场的题图。

**2026-08-19 从 2.5 秒收到 1.5 秒。** 被否的是"看不见"，不是"短"；
2.5 秒压在十七分钟的片子前面显得拖，1.5 秒足够看清封面又不让人干等。

**三样东西要一起挪**，少一样就错位：

| | 怎么挪 |
|---|---|
| 画面 | 封面占 1.5 秒，后面的场景图时长不变 |
| 音轨 | `adelay` 往后推 1.5 秒（片头是静的，不是把开场白盖掉） |
| 字幕 | 整条时间轴平移 1.5 秒，否则比声音早出来 |

字幕因此有两份：`audio/全片.srt` 跟**音频**对齐（音频的产物），
`<期号>.srt` 跟**成片**对齐（放在 mp4 旁边，传平台用的是这份）。

`--cover-sec 4` 改时长，`--cover-sec 0` 不放。

### 影响范围

**只有说书线。** 段子视频的封面在 `cover.ts`，那条线一个字没动；
说书封面的配色自成一套，也不碰 `style/palette.ts` 和 `style/inkwash.ts`
（后者是正片画面的浅底水墨，封面是深底，两码事）。

### 标注迁移 `shuoshu-migrate.ts`

按段落文本**逐字匹配**，把 v1 的 who/beat/parts 搬到 v2：232 段里搬走 103 段（44%）。
**这 103 段连合成都不用重跑**——TTS 缓存也是按台词做键的。

**不做模糊匹配。** 试过按相似度搬，但"相似"的两段往往是改了语气或拆了句子的，
那恰恰是节拍要重新判断的地方，搬过去等于埋一个不会报错的雷。

### 新角色二郎

男角色变成四个，而 Edge 中文男声实际可用只有三个。二郎跟老道**同底**（云扬），
靠反向拉开：老道低慢苍（0.86 / −10% / aged），二郎高快亮（1.14 / +6% / 提亮）。

**分离度必须用同一句探针量。** 一开始拿各角色自己的台词量，老道 125Hz、二郎 127Hz，
差 2Hz 判"撞车"；换同一句量是 119 vs 146，差 27Hz 过线。基频跟说了什么字强相关，
台词不同就没有可比性。对照片段在 `voice-samples/10-三男声对照.wav`。

六对里五对过线，只剩 **说书人 ↔ 老道**（Δ基频 9Hz / Δ低高频 3.7dB）——
但同一句话说书人念 3.74 秒、老道念 4.77 秒，**差 28%**，红线里没算这根轴。
听过对照之后确认**三个声音分得清**，维持现状不动音色。

### 房间底噪

全片垫 −62dBFS 的粉噪。**这是让停顿听着像停顿，不是为了把停顿放长**——
节拍表的停顿数值一个没动，最长还是 1.0 秒（频道规范：停顿不要太久）。

电平是量出来定的：−50dBFS 那一版实测停顿 −42.1 / 人声 −17.7，**只低 24dB，
戴耳机听得见嘶嘶声**。降到 −62 之后信噪比 36.4dB：停顿不空了，但不会注意到有噪声在响。

### 字幕不留尾标点

**频道规范**：每条字幕结尾的标点一律去掉（`shuoshu-srt.ts` 的 `trimTailPunct`），
句子内部的照留——那是节奏。`.srt` 文件和烧进画面的都走这个函数。

### 左下角只显示幕名

「冷开场」「引入」「收束」不打在画面上——那是**写稿的结构标签，不是章节名**，
露出来等于把脚手架给观众看。「幕二 · 疑」这类保留。
