> 拿一套 2D 矢量形象 + TTS 配音，出竖屏口播短片。
> 第一条落地的是《AI 智能体越狱》，成品在 `projects/老石/20260905_AI智能体越狱/`。
>
> **这份管「怎么跑」：链路、素材库、踩过的坑。**
> 「怎么排」—— 镜头语言、转场、分镜怎么配 —— 在 [老石出片方案.md](老石出片方案.md)。
> 「做什么」—— 人设、四个栏目、稿件格式、数据板规格、验收 —— 在 [老石频道方案.md](老石频道方案.md)。

⚠ **这条线跟「醒木不响」也没有关系** —— 那是说书／治愈／心理洞察那几条线的频道，

## 一、链路

```
稿子.txt（一行一句，短句切）
   │  node tts-match.mjs --file 稿子.txt --配音 配音.json --out <项目>/vo
   ▼
vo/seg1..N.mp3 + vo/manifest.json（每句真实起止时间）
   │  ffmpeg -f concat -safe 0 -i vo/list.txt -c copy vo.mp3   ⚠ 手工一步，忘了 build 会拦
   │  node 3d-render/envelope.mjs        逐帧 RMS → 张嘴权重
   ▼
envelope.json
   │  + 动作表.json（每句配一个动作和一个表情）
   │  node shi-2d/shoot.mjs <项目目录>    逐帧摆姿 → 透明 PNG（1080×1600）
   ▼
frames/f%05d.png
   │  node shi-2d/build.mjs <项目目录> 成片.mp4
   ▼  背景 ＋ 舞台 ＋ 人物帧 ＋ 开场卡 ＋ 烧字幕 ＋ 配音 ＋ 背景音乐
MP4（1080×1920 / 30fps / H.264 crf19 / AAC 192k）
```

`envelope.mjs` 读的是 **cwd 下的 `vo.mp3`**，写 **cwd 下的 `envelope.json`** ——
所以那一步必须先 `cd` 进项目目录再跑。

### 一条 49 秒的片子实测

| 步 | 耗时 |
|---|---|
| 配音（12 句，Edge TTS） | 约 40s |
| 出帧（1465 帧，resvg） | 52s |
| 合片（ffmpeg，crf19 slow + 高斯虚化） | 约 60s |

出帧那 1465 张 PNG 是 200M 出头，`.gitignore` 里已经挡掉了。

## 三、素材库

**动作、表情、姿势、衬衫配色、替身、装配参数都在 `shi-2d/素材库/` 里，不在代码里。**

### `装配.json` —— 可驱动骨架

哪几个图元是头、是腿、是前臂，胳膊腿挂在哪儿，关节支点在哪儿。
整片站姿那张（`资源 1.svg`）**没有任何图层名**，177 个图元平铺，
能拆开只是因为绘制顺序恰好按部位聚类。

**序号是量出来的，不是猜的**：`node shi-2d/asset-scan.mjs "…/资源 1.svg"`。

挂载偏移的标法：**在两个文件里找同一个图元**（尺寸和颜色完全一样的那个），
两处包围盒一减就是偏移。2026-09-05 美术给裤腰补了三个图元（175–177），
整片和迈腿两张里是同一份，拿它当基准比量腰头行宽准得多。

### `动作.json` —— 骨架能做的动作

| 动作 | 样子 |
|---|---|
| `走` | 三张腿姿轮换 + 摆臂，同时从画面偏左走到中轴，走到位提前收脚 |
| `站定` | **手完全不动**，只有呼吸、重心转移、头微动 |
| `示意` | 抬一下手就收回来 —— 见下面「手势拍」 |

外加三段公共层：`底座`（呼吸 + **重心左右转移**）、`说话叠加`（包络过阈值时头和五官多动）、`眼神微动`。

⚠ **摆手只属于走路。说话的时候手就该垂着不动。**
第一版给双臂加了常驻正弦摆动（幅 1.4），出片一看是两只手在那儿上下浮，很假 ——
真人站着说话，动的是重心和头，手是垂着的，偶尔抬一下强调而已。
所以站定和示意的关节表**留空**，「站着不动但活着」全靠底座那条重心转移（幅 3.2、频 0.42）。

**「示意」是拍，不是段。** 起 0.28s / 停 0.34s / 收 0.5s，**一共 1.12 秒抬完就回到垂手**。
一句最多两拍，两拍之间至少隔 2.2 秒，左右手轮着来。
第一版是「这一整句手都举着」，僵，而且把注意力从字幕上拽走。

### `表情.json` —— 表情表（骨架和定格姿势共用一份）

一个表情 = **眼珠 + 眉毛 + 眼睑 + 嘴** 四组数。八个情绪 + 四个纯视线。
调数值：`node shi-2d/face-probe.mjs projects/老石/_表情`

**「表情通用一套」这件事，分两层看**：

| | 通用吗 |
|---|---|
| **表情的数**（眉抬多少、嘴角歪多少） | ✅ **一直是通用的** —— 就这一份 `表情.json`，骨架和所有定格姿势都读它 |
| **脸上的零件**（眉毛是哪几条路径、在哪儿） | 一张一个样，写在 `姿势.json` 各自的条目里 |
| **眉毛的形状** | ✅ 插兜那一族 2026-09-06 起**借同一条**（见下面「一套通用眉毛 ＋ 洗掉眼睑面」） |

⚠ 定格姿势只吃得到**眉毛和嘴角**两项 —— 眼珠和眼睑动不了（脸是画死的），
所以同一个「生气」，骨架脸上是四样在动，定格姿势上只有两样。**这个差别改不掉**，
排片时要眼神戏的句子就用骨架或 `思考姿势`。

### `姿势.json` —— 定格姿势（跟骨架是两回事）

美术另外单独画的**十五张**整图（说话 ×4、思考、坐姿上半身 ×2、坐姿下半身、
代表性站姿、插兜站姿 ×2、**插兜走路**、**单手插兜站立**、**单手插兜抬手**、**插兜侧走**（三张整片））。
**头的角度、身体比例、手的姿势全是画死的，套不进关节骨架**，它们的用法是**换镜头**：
骨架是全身远景，这些是半身近景（也有几张是全身的）。

**能驱动的：口型、眨眼、眉毛、嘴角。做不了的：眼珠、眼睑、手和身体。**
两张例外 —— `插兜走路` 带 `腿` 配置**能走**；`单手插兜站立/抬手` 带 `臂` 配置**手能转**（都见下）。

⚠ **双手插兜那一族（`插兜走路`／`插兜站姿` ×2／`代表性站姿`）的手是画死在兜里的。**
别想着给它加手势 —— **要手就切镜头换别的动作**（`说话姿势3` 摊手／`思考姿势` 托下巴／坐姿，
或者换到下面那两张单手的）。反过来用就是一条排片规则：这一族只接「不用手」的句子。正文在
[老石出片方案.md](老石出片方案.md) 的「插兜族没有手 —— 要手就换镜头」。
口型和眨眼是补丁盖住原画再画；**眉毛是挪原画**（眉毛下面是纯肤色，怎么挪都没接缝），
是这几张脸上最有效的一根表情杠杆。眼珠要重画整只眼球、需要杏仁的轮廓路径，还没做。

标定用 `pose-calib.mjs`，**每加一张跑一次**：

```
node shi-2d/asset-scan.mjs "…/插兜站姿.svg" --face     # 先报瞳孔候选，肉眼挑一对
node shi-2d/pose-calib.mjs 插兜站姿 343 345            # 量眼距/眼眶/肤色/嘴/眉，写回库
```

⚠ **嘴心的 y 是算出来的，不是量出来的**：`眼线 + 0.835 × 眼距`
（0.835 是拿骨架那张脸标的基准：眼距 57.5、嘴在眼线下 48）。
量出来的嘴框会把下巴那道折线也圈进去，框心比真嘴心低一截，口型补丁就盖歪了。

眉毛**必须成对挑** —— 一边一边地挑最宽的，很容易一边挑到眉毛、另一边挑到帽檐；
判据是「两条高度差不多、宽度差不多」。有一张（`说话姿势`）右眉在原画里**没有独立路径**，
配不上对，那张就只剩嘴角一根杠杆 —— `pose-calib` 会把候选摊出来，**不静默写 null**。

⚠ **同一条路径不能既当左眉又当右眉。** 跨过两只眼的大件（帽檐的暗边最常见）会同时进两边的
候选，自己跟自己配分数是 0、必赢，库里就写进一对 `[174,174]` —— 出片时两条眉毛一起按左眉那套
转，看着像整个额头在动。2026-09-06 标 `单手插兜站立` 时踩到，现在 `pose-calib` 里加了两条：
**左右不能是同一条**、**两条的包围盒不许横向重叠**（眉毛中间隔着鼻梁）。

#### 眉毛这一根杠杆上，2026-09-06 又踩了两个（出片才看见）

**① 一条眉毛不止一条路径。** 插兜这一族的眉毛是「深色底 ＋ 浅色面」两条叠着画的
（`单手插兜站立`：画面左 135＋301、画面右 131＋133）。库里只记深色那条，
挪的时候浅色那条**留在原地** —— 看着就是**双层眉毛**。
所以 `眉[s]` 现在收**一个数组**，`pose-calib` 挑完主眉会自动把「包围盒落在主眉里面、
而且比肤色暗」的一起收进去。老那批图（说话姿势／思考／坐姿）本来就是一条，写法兼容。

**② 眉毛底下不是肤色，是个洞。** README 原来那句「眉毛下面是纯肤色，怎么挪都没接缝」
**只对老那批成立**。插兜这一族的**脸路径在眉毛处缺一块**，眉毛正好盖住 ——
一挪就露出背景（渲在白底上是一条白，观众读成「双层眉」）。
修在 `pose.mjs`：挪之前**先拿眉毛自己的形状填一层肤色贴在原位**，形状严丝合缝、只补那个洞。

两个都是**不报错、只是难看**那一类，而且**单看静帧看不出来** —— 得挑着眉那一句渲出来才现形。

#### 最后的答案：**一套通用眉毛 ＋ 洗掉眼睑面**（`_脸件`）

上面两条补完，插兜这一族的眉毛**还是双层** —— 而且只有右边那条是。查到最后是第三件事：

**这一族的右眼上面有一大块「眼睑面」**（`单手插兜站立` 的 #134，35×9），底下压着一道深色褶。
眉毛一抬，那块面的下沿就读成**第二条眉毛**。左眼没有这块面 —— 所以只有一边双层，两边还不对称。
**这不是分组能解决的**：褶跟着眉走眼睛会变形，留在原地就拉出一道缝。

`代表性站姿` 那张的眉毛是**一条实心形状**，没有这块面，怎么抬怎么压都干净。所以整族这么办：

```json
"_脸件": { "来源": "代表性站姿", "眉": [147, 148] }
```

姿势条目上写 `"脸源": "通用"` ＋ `"洗"`（要抹掉的图元清单）就切过去了。

| | |
|---|---|
| 洗什么 | **眉毛到眼眶上沿之间**那一带：眉 ＋ 眼睑面 ＋ 褶，一张 6~11 条 |
| 怎么洗 | **抹成肤色留在原位**，不能删 —— 删了露出脸路径上的洞 |
| 贴什么 | 来源那张的眉，按**瞳孔对位**（瞳孔 = 眼中 ± 眼距/2，眼线），缩放按眼距比例 |
| 眼睛 | **不动**。⚠ 试过整只借，眼白是分片画的，拼过去只剩一团暗 —— 别再走这条 |
| 用了的 | 单手插兜站立／抬手、插兜走路、插兜站姿 ×2、插兜侧走（**全族六张**） |

⚠ **`眉` 那一组要连描边一起收。** 有的图是「深色底包着浅色面」，有的是
「深色描边包着浅色面」—— **两个方向都得查**。只查一个方向，描边会漏在外头，
借来的眉一挪，原地就留下一个**空心眉框**（`插兜侧走` 的左眉就是这么漏的）。
`pose-calib` 现在两个方向都扫。

顺带一个好处：**这一族的表情从此长一个样** —— 换镜头时眉毛不会跟着换形状。

#### 手能转的姿势（单手插兜那两张）

`单手插兜站立`（垂手）和 `单手插兜抬手`（摊掌）在库里带一段 `臂`：

```json
"臂": { "图元": [[360, 373]], "支点": [249, 293], "可转": [-45, 0], "肘": [268, 383] }
```

**「图元」是那条臂在绘制顺序里的区间，在最末尾一整段。** 这是 2026-09-06 美术重导的关键改动 ——
在那之前臂是散在各处的，而且**拿掉臂之后腋下是个洞**（描摹图没有被遮挡的图层，胳膊底下从来没画过西装）。
现在拿掉臂身子是完整的，所以臂能整组绕肩转，底下不会露白。

| | 图元区间 | 可转 | 说明 |
|---|---|---|---|
| `单手插兜站立` | 360–373（14 条） | **-45°～0°** | 负=往外抬。到 -45° 是平举。**正的不行**，往里转胳膊会压到身上 |
| `单手插兜抬手` | 379–411 ＋ 317/318 | **0°（锁死，不能转）** | ⚠ 它的**内侧轮廓线（410／411）是贴着躯干画的** —— 一转，上臂从躯干侧面荡开，那两条线就悬在背景上成一道黑线（2026-09-06 出片 00:14）。等美术把内侧轮廓拆出来再开 |

⚠ **两张只有垂手那张能转。** 差别在轮廓怎么画：垂手那条臂**整个悬在身体轮廓外**（x≥248，身体右缘 243），转起来底下什么都不露；抬手那条的上臂**贴着躯干走**，内侧轮廓线是照着躯干边缘画的，一转就穿帮。

两张同坐标系，所以肩支点共用 `(249,293)`。用法是 `renderPose(名, { 臂角: -20 })`，
排片时写在动作表逐句的 `"臂": -20` 上。超出 `可转` **当场停**（再转肩口就脱开了）。

⚠ **这是「换个姿势」，不是「做个动作」** —— 一整句都是那个角度，不会摆回来。
臂是一整块、**肘弯不了**，摆幅再大也只是整条胳膊划弧；真要一拍还是用骨架的「示意」。
`肘` 那两个数是量好的，**等美术在肘那儿分件**（上臂／前臂各一段连号，关节处留 8–10px 搭接）才用得上。

⚠ **跨文件换臂（站立的身 ＋ 抬手的臂）没做**，虽然试过、能看。两张是各自描摹的，
逐图元比**没有一条是同一份**、平均色差 14.6，肩那儿会有一道淡淡的明暗差。
「站着抬手」走的是**换腿**（见下），缝落在裤子上、还能羽化，比换臂干净得多。

#### 组合姿势 —— 上半身一张、腿另一张

美术没画「站着抬手」这张：`单手插兜抬手` 的腿是**迈步相**，当静止镜头用像定格在半步上。
但那一族（`单手插兜站立`／`单手插兜抬手`／`插兜走路`）是**同一个坐标系**画出来的
（眼距都是 58、眼线 116.8~117.5，躯干逐像素叠上去只差几十个点），所以**换腿不用标偏移**，
按坐标把腿那一带切开、两张各出一半就行。

```json
"站着抬手": { "组合": { "身": "单手插兜抬手", "腿": "单手插兜站立" }, "类型": "全身", "机位": "全身" }
```

| 名字 | 身 | 腿 | 会走 |
|---|---|---|---|
| `站着抬手` | 单手插兜抬手 | 单手插兜站立 | — |
| `走着抬手` | 单手插兜抬手 | 插兜走路 | ✅ |
| `走着垂手` | 单手插兜站立 | 插兜走路 | ✅ |

五官、机位、臂**全跟身走**（眉毛的序号是身那张的），画布高度**跟腿走**（脚在腿那张上）；
腿源会走，这张就跟着会走 —— `POSE[名].腿` 是从腿源抄过来的，所以 `shoot.mjs` 一行没改。

接缝参数在 `_组合` 里，四个数都是量出来的：

| 数 | 值 | 怎么来的 |
|---|---|---|
| 切口 | **512** | 夹克下摆最低点：走路 498／抬手 504／站立 513 —— 切在正下方，缝落在裤子上，不落在夹克的明暗过渡上 |
| 羽化 | **14** | 硬切会看见色阶（两张各自描摹，同一条裤子色值都不一样）；羽 14 就看不出来 |
| 腿带 | **x 44–246** | 右边界给站立那张垂着的手让路 —— 那只手伸到 x295／y577，切进去会削掉半只手 |
| 让手 | **y 580** | 过了它放开全宽。站立那双脚岔到 x20 和 x291，一直按腿带切会漏出两只鞋尖 |

⚠ **拼在一起的两块要叠 2px。** 遮罩和裁剪都是两个矩形拼的，resvg 会各自把边抗锯齿一遍，
合起来在接边上只有半个像素的覆盖 —— 出来是一条**贯穿整条裤子的浅色细线**，
不报错，单看一帧还以为是裤缝。叠 2px 就没有了。

顺带：`单手插兜抬手` 两腿之间那块黑楔在组合里**自动没了** —— 腿从别处来，压根不渲它那半。

#### 会走的姿势 —— 两套走法

| | 谁 | 怎么换 | 相数 |
|---|---|---|---|
| **换腿** | `插兜走路`（正面，走向镜头） | 整片自带一相，另一相是单独一张腿贴回原位 | 2 |
| **换相** | `插兜侧走`（四分之三侧身，走向画面右） | **三张整片轮换**，乒乓着走 1→2→3→2 | 3 |

两套共用同样三个数（`步长秒`／`颠幅`／`收脚提前秒`），`shoot.mjs` 里 `P.腿 || P.相` 一句就分流了。

##### 换相：三张整片轮换

```json
"相": { "张": [ {"文件":"插兜侧面走路1.svg","dx":0}, {"文件":"插兜侧面走路2.svg","dx":0},
                {"文件":"插兜侧面走路3.svg","dx":-13} ], "序": [0,1,2,1], "步长秒": 1.0 }
```

**整片轮换能成立，全靠一条：三张是同源导出的**（美术在同一个文件里只改腿、再导一次）。
逐像素量过：

| | 上半身平均色差 | 差>16 |
|---|---|---|
| 插兜侧面走路 相1 vs 相2 | **0.05** | 0.1% |
| 插兜侧面走路 相1/2 vs 相3 | 4.9 | 9.3% |
| ⚠ 侧身走路全身 1/2/3（各画各的） | **13.4 ~ 24.5** | 19~30% |

⚠ **各画各的三张不能做循环 —— 会闪。** 这批图每次单独画就是一次重新描摹，
色值和轮廓每张都不一样；一秒轮两三次，观众看到的是人在抖。
`侧身走路全身1/2/3` 就是这种，**没有入库**（单张当静态姿势倒是可以）。
判断办法：逐图元比色比位，同源导出的会有大批「同色同尺寸、偏移一致」的图元。

⚠ **相3 整体右移了 13px**，`dx` 把它拉回来。这个数是量出来的 ——
图元偏移直方图的峰在 `(13,0)`，帽心 169 vs 156 也对得上。

⚠ **换相那套不给颠幅。** 三张的帽顶都在 y0、身子在竖直方向完全不动，
**走路的起伏本来就画在腿里了**；再叠一层颠会变成人在跳。
（换腿那套相反，两相之间身体不动，全靠 6px 颠补那口气。）

三张的墨迹高度是 946／891／891 —— 不是画错了。这是**四分之三视角**：
脚往前迈的同时也朝镜头来，落点在画面上更低。所以**按身子对齐，不要按脚底对齐**。

#### 会走的姿势 · 换腿

`插兜走路` 在库里带一段 `腿` 配置：

```json
"腿": { "隐藏": [[105,160]], "右": { "文件": "插兜走路右脚.svg", "dx": 49, "dy": 471 },
        "步长秒": 1.0, "颠幅": 6 }
```

**整片自带的腿就是「左脚」那一相** —— 左脚那张是从整片里裁出来的，56 个图元一个不差地对上了，
所以换相只需要一张右脚。挂载偏移 `dx=49 dy=471` 是拿四个共有图元各自减出来的，四处一致。

⚠ **换腿的部件必须插在原位，不能追加到末尾** —— 腿在图层顺序里压在西装下摆底下。
⚠ **换腿和转眉毛必须在同一次遍历里做、按原始序号判断** —— 换完腿数组长度就变了
（藏掉 56 个、插进 1 个），再按下标找眉毛全错位。

切镜头**尽量踩在换背景那一句上** —— 同景别硬切姿势会像跳帧，跟着换景才读成剪辑。
景别有变化的（全身↔半身）不用等背景，本身就读成剪辑。

定格图放四五秒会「冻住」，所以出片时给一个**缓推**：一整句推 3.5%（`shoot.mjs` 里的 `zoom`）。
单帧看不出来，连起来是镜头在缓缓靠近。

**全身按身高对齐，半身按眼距对齐 —— 两种机位的锚点不一样，这是故意的。**

这几张姿势图的身材比例跟骨架不同：骨架 身高/眼距 = 16.04，插兜那三张是 16.8~17.1（头小腿长）。
一套缩放对不齐两样东西，只能挑一样：

| 对齐方式 | 代价 |
|---|---|
| 按头 | 眼距都是 74.75px，但新姿势比骨架**高 54~76px**，切一下人突然长高一截 |
| **按身高** | 身高都是 1199px、脚踩同一条地平线，代价是头小 3~4.5px 眼距（4~6%） |

全身镜头观众看的是整个人站在那儿，**身高和地平线最扎眼**；半身镜头看的是脸，眼距和眼线最扎眼。

量的时候**按两只瞳孔**：眼距和眼线是所有换算的基准。
`node shi-2d/asset-scan.mjs <素材> --face` 会报候选，**结果要肉眼过一遍**
（自动找瞳孔会把鼻孔、纽扣、袖口的暗块也报出来）。

调机位：`node shi-2d/pose-probe.mjs projects/老石/_素材对照`（第一张是骨架，用来比景别）。

### `衬衫.json` —— 一期一个颜色

八个配色（粉／天蓝／嫩绿／墨绿／砖红／草绿／米白／杏橙），写在项目的
`动作表.json` 里：`"衬衫": "天蓝"`，也可以直接给 `#RRGGBB`。不写就是原画那件粉的。

**换色是渲染时按色值替换，不是给素材另存十份** —— 十份素材就是十份要跟着美术改的东西。
走 HSL：色相和饱和度换成目标色的，**明暗关系原样保留**，所以阴影、高光、领口的折线都还在。

⚠ **明度是重映射不是平移。** 目标色一深（墨绿 `#2E5252`），平移会把所有阴影压成纯黑，
衣服上只剩几块死黑。现在是拿「基色 → 目标色」当锚点，比基色暗的往 0 拉伸、亮的往 1 拉伸。

⚠ **原色表是量出来的，美术重导要重跑**（`node shi-2d/shirt-scan.mjs --json`）。
一件衬衫在原画里是 5～31 个色（本色＋阴影＋高光＋领口边＋褶子暗线），判据两条：
**绿色分量最低**（肤色是橙的，g>b，一刀分开）＋ **彩度 ≥ 12**（挡住近灰，不然裤子和牙齿也会跟着变）。
色值一变表就对不上，**表现是「换了色但有几块还是粉的」，不报错**。

出帧时会扫一眼同级别期用过什么，撞了提醒 —— **只提醒不拦**：撞色不是错，是「你可能忘了换」。

### `<项目目录>/动作表.json`

顶上几个字段管整条片子：

| 字段 | 干什么 |
|---|---|
| `类型` | **这一期是哪一类话题**：`内幕` / `博弈` / `认知`（写 `一二三` 也行）。切封面的重音色、副标色、背景光晕，**以及片子里的字幕标色**。表在 `色系.mjs`。⚠ **必写，不写当场停** —— 不给默认值猜，猜错了整张封面的颜色都在说错话 |
| `衬衫` | 这一期穿什么颜色，见上。**出帧和封面读同一个**，不会片子和封面穿两件 |
| `背景目录` | 这一期的场景图从哪儿取。不写就是试片那批 |
| `音乐` | 背景音乐文件名（`"老石背景音4.mp3"`）。不写就没有音乐 |
| `音乐目录` | 默认 `E:/ryu/石总/背景音乐` |
| `音乐压低` | 音乐比人声低几个 LU，默认 **18**。⚠ **不是 dB 增益** —— 增益是拿两个文件现量 ebur128 算出来的 |
| `开场卡` | 写 `false` 关掉片头那张卡（默认开）。⚠ **卡会把句1 的字幕整条替掉** —— 所以**句1 不能有 `标`**，有就当场停 |
| `标色` | ⚠ **一般别写** —— 不写就跟着 `类型` 走，那才是对的（封面承诺一个色、片子标另一个色是穿帮）。只在要**故意**跟封面不一样时写，现在只认 `红` |
| `入画起点` | 走路从画布哪个 x 走到中轴 540 |
| `稿件` | 这一期拍的是稿件库里哪一条（`"01-A"`）。**汇总页的「已出片」状态就是拿它比的，不手写** |
| `测试片` | 写了就是试片，汇总页打红牌，**不作这条线的样片** |

`逐句` 一句一行，从库里挑：

```json
{ "句": 7, "动作": "示意", "表情": "生气", "标": ["125%"], "_": "「更可怕的是」情绪起来了" }
```

`动作` 写骨架动作名就走骨架，写姿势库里的名字就直接换镜头，
写替身表里的名字（`斜靠`／`扶帽檐`）就用替身顶上。**三个库都查不到就当场停**。
`标` 是这一句里要标出来的词，**用当期类型的重音色**，整条片子最多三处。

配法上的三条：

1. **信息最密的那句用「站定」** —— 手一动观众就去看手了，字幕反而漏读
2. **生气一条片子最多两句**，连着用会腻
3. 「示意」是抬一下就收，不是举着说完一句

## 四、几个真踩过的坑

### 1. 美术换导出设置，不报错，只是颜色没了

见过两种：`.cls-1{fill:#0b142a;}` 和 `.st0{fill:#0B142A;}`，后者还多了 `<polygon>`。
类名前缀、色值大小写、图元类型全变了。写死正则的代码**匹配不上就退成黑色**，
渲出来是一片黑剪影。`素材.mjs` 就是为了不再踩这个 —— 查不到颜色的 class 会**抛错**。

2026-09-06 又见一种：`.cls-264{fill:none;}`。**闸拦住了**（当场抛错，没有变成黑剪影）——
但这条不该拦：`none` 是美术明写的「这条不画」，跟「查不到颜色」是两回事。现在 `load()`
收 `fill:none` 并且**直接不收进 shapes**，返回里带一个 `空` 计数。

⚠ **空路径的加减会把后面所有序号顶掉一位**，而分组（`装配.json`）、换腿、切臂全是按序号来的。
美术重导之后 `空` 变了，这几处的区间都要回来核。

### 2. 关节的正负号不能凭直觉猜

| 关节 | 正 | 负 |
|---|---|---|
| `armL`（角色左手＝**画面右**） | 往身侧收 | **往外抬** |
| `armR`（角色右手＝画面左） | **往外抬** | 往身侧收 |
| `elbowL` | 小臂往下垂 | 小臂往外伸 |

**这套骨架只在画面平面里转，做不出「手伸到胸前」那种带透视的动作** —— 抬手只能往身侧张开。
超过 46° 手会顶到画布边。（想要「手托下巴」只能用 `思考姿势` 那张定格图。）

### 3. 口型要拿声音驱动，不能按拍子轮播

骨架自带的那套 SEQ 是固定轮播 —— 不看声音，**静音的时候嘴照样在动**。
`shoot.mjs` 改成按包络的逐帧响度分档挑（见 `LADDER`），**低于 0.11 直接闭嘴**。

### 4. 动作和表情之间都要过渡

直接换会「啪」地跳一下。关节过 `EASE = 0.22`（约 0.15 秒），表情过 `EASE_F = 0.13`（约 0.3 秒）——
换表情比换姿势更该渐变。**低通要逐帧推**，所以 `--probe` 抽帧时前面每一帧照算，只是不落盘。

### 5. 眼珠不能直接挪原画那几条路径

这版眼睛的画法是：**一整块深色杏仁**打底，左右各盖一牙白，
**中间露出来的那块底就是虹膜**，再压一个瞳孔和一个高光点。
虹膜不是独立的圆 —— 只挪瞳孔的话虹膜留在原地，看着像瞳孔从眼球上滑下去了。
所以 `face.mjs` 是**裁到杏仁形状里整只眼球重画**。

**眼珠的活动范围只有 ±6 / ±4.5**（虹膜跟杏仁一样高，纵向全靠裁一截来读）。
「向左上方看」做得了，「翻白眼」做不了。

眉毛相反 —— 眉毛下面是纯肤色，整条包进 `<g>` 里怎么转都没接缝，挪原画就行。

### 6. 眨眼别压扁眼球；定格姿势的眼睑不能给小值

眼白是分片画的，压扁会散架。**拿肤色从上往下盖住眼眶、下沿画一条睫毛线**就行 ——
眼周围本来就是同一块肤色，看不出接缝。骨架和定格姿势两边都是这个做法。

定格姿势的眼眶和肤色量在 `姿势.json` 里。量脸的时候注意：
**只按颜色挑肤色块会挑到粉衬衫**，得加一条「必须把两只眼睛都包住」。

⚠ **但定格姿势这边只能眨眼，不能做「半睁」。** 骨架的眼睑是画好的一片、压下来多少就是多少；
定格姿势是拿肤色盖，**一盖就把原画自己那道上眼睑线抹掉了**，换成我画的睫毛线，
位置和粗细都跟原画对不上 —— 哪怕只盖 0.12，眼睛也立刻读成「半睁着」。
（第一版把表情的眼睑也喂进去了，结果 00:37 那一段整段睡眼惺忪。）

所以两处一起改：`shoot.mjs` 只喂真正的眨眼、不掺表情眼睑；
`pose.mjs` 的 `BLINK_GATE = 0.22`，低于它一律不画，超过之后从 0 重新起算
（真眨眼一路冲到 1，不受影响）。

### 7. 背景最后**不虚化** —— 分层靠的是暗底，不是糊

**人物是纯色平涂的矢量图，背景是照片级的 3D 渲染。** 放一起背景那些高对比的霓虹环比人物还抢眼。
花了五版才明白**这不是「糊多少」的问题**：

| 版本 | 做法 | 结果 |
|---|---|---|
| 一 | 不糊 | 背景抢镜 |
| 二 | 全画面 sigma 14 | **糊过头**，认不出是什么地方，像蒙了层脏 |
| 三 | 全画面 sigma 8 | 能看，但整体发闷 |
| 四 | 上下 sigma 12、中间清楚（移轴） | 当时觉得对了。但清晰带正好落在人腰上，**跟人抢注意力** |
| 五 | 整块均匀 sigma 10（舞台模式初版） | 幕是块平的屏、整块离得一样远，糊法讲得通了，可是**场景看不清了** |
| **六** | **sigma 0，改成上下留暗底** | 对了 |

**结论：分层要的是「这是另一个平面」这个信号，虚化只是实现它的一种手段，而且是有代价的那种。**
背景收进 y240–1560 那条带、上下露出中性暗底之后，**那条带本身就是信号**，
再糊一道纯粹是把场景的信息糊没了 —— 而场景是有内容要传达的（数据板就长在上面）。

压暗（-0.16）和降饱和（0.88）留着：人物是纯色平涂，背景不压还是会抢。

⚠ 虚化遮罩那套（SVG `linearGradient` 出遮罩 ＋ `alphamerge`）连同代码一起撤了。
真要找，在 git 历史里。**`BG.虚化` 还留着这个开关**，给非零值就会重新走 `gblur`。

### 7 之二、`--静帧`：别拿合片当调试手段

改了字幕层或者叠加层，合一次 40 秒的片要几分钟，而要看的其实只有一帧。

```
node shi-2d/build.mjs <项目目录> --静帧 0.52,1.50,3.40
```

出到 `<项目目录>/静帧/NN.png`。⚠ 它走的是**同一条 filter 链**，只是末尾加了个 `select` ——
另起一条预览路径是会骗人的，那正是「报成功的失败」最爱长的地方。

两个当时踩的：

- **挑帧用 `select` 不用 `-ss`** —— `-ss` 会跳过前面的解码，而 `xfade` 和 `zoompan`
  的输出依赖从 0 开始连续走，跳着来那几帧是错的。
- **filter_complex 里带标签的输出必须全部 `-map` 出去**，剩一个没接的整条就报错退出
  （静帧不要声音，所以音轨那一段是单独拼的，别并进 `filter`）。

### 7 之三、加背景音乐踩的三个（全是不报错的）

1. **`amix` 的 `normalize` 默认是 1**，会把每一路都除以路数 —— 人声凭空低 6 dB，
   听着闷，但**不报错**。必须显式写 `normalize=0`。
2. **两路进 `amix` 之前要先统一格式。** 人声是 Edge 出的**单声道 24kHz**、音乐是立体声 44.1k，
   不统一的话 amix 按第一路来，**音乐被压成单声道 24k = 砍到 12kHz 带宽**，发闷。
   两路都先过 `aformat=sample_fmts=fltp:sample_rates=48000:channel_layouts=stereo`，
   输出再带 `-ar 48000 -ac 2`。⚠ 这个坑光有人声时不存在 —— 24k 单声道对说话没问题。
3. **`ebur128` 的汇总写在 stderr 上**，`execFileSync` 只拿得到 stdout，返回是空的。
   走 `spawnSync` 读 `stderr`。

**音量为什么是「比人声低 18 LU」而不是一个 dB 数**：五首素材的响度差了 10 dB
（-10.5 到 -20.5 LUFS）。写死增益的话，**换一首歌音乐就突然大一档，而这个错误在合片之前
一步都不会报**。所以两个文件都现量、增益算出来 —— 换歌自动跟上。

⚠ **不做 ducking。** 这条片子是满口播、句间只有零点几秒空隙，压下去就再也没抬起来，
白搭一层复杂度。

### 8. ffmpeg 的 ass 滤镜找不到字体不报错

按字体名找靠 fontconfig，Windows 上多半找不到 —— **找不到会自己换一个字体接着渲**。
所以一律带 `fontsdir`。而且 **filter 参数里不能出现盘符的冒号**，字体目录和字幕文件都用相对路径。

### 9. 人得有影子；字幕不能从西文词中间断开

接地影用径向渐变画，**别用 `feGaussianBlur`** —— resvg 的滤镜支持不全。

折行踩过三次，全是**不报错、只是难看**那一类：

| 折出来的样子 | 判据 |
|---|---|
| `OpenA / I` | 字母数字连成的一串必须整块走，汉字哪儿都能断 |

### 11. 片名别从命令行传 —— Git Bash 会静默改字

### 配音层：送给 TTS 的文本 ≠ 屏幕上的文本

`稿子.txt` 是**观众看到的**那份 —— 它同时是字幕的源（`build.mjs` 直接
`wrap(tidyCaption(seg.text))` 上屏）。所以「念的时候在这儿停一下」「这个字念错了」
**不能写进稿子**，写进去就上屏了。这些写在 `<项目目录>/配音.json`，只改送给 TTS 的那一份。

```json
{
  "音色": "zh-CN-YunxiNeural", "语速": "+6%", "音高": null,
  "逐句": { "3": { "停": [["叫", "——"]], "重": ["定锚"] } }
}
```

| 字段 | 干什么 | 谁消费 |
|---|---|---|
| `停` | 在某个词后面加停顿。**给秒数就挑最接近的标点**，也可以直接写标点 | TTS |
| `音` | 同音字替身（多音字念错时用）。⚠ 必须完全同音、且替身本身不是多音字 | TTS |
| `重` | 哪几个词该重读 | **没人消费，而且以后也不会有** —— 克隆音同样是 TTS，一样没有重音控制。这栏只是写稿时的备忘：**发现自己想标重音，就说明那句该改结构**（见出片方案「标色」那节） |

⚠ **`<break>` 和 `<mstts:express-as>` 在 Edge 这个端点上是被拒的。**
2026-09-06 实测：连接直接断在 `Stream closed before the synthesis completed` ——
**不是「不生效」，是「合不出来」**。Azure Speech Service 那个订阅端点支持，但我们不在那上面。
所以配音层存的是**意图**（停多久），落地方式按端点来；哪天换 Azure，同一份 JSON 出真 SSML。

⚠ **稿子里出现 `<` 会当场停**（`tts-match.mjs` 的 `查标签()`）。这条闸是防「有人把 SSML
写进稿子」—— 那玩意会**原样烧进字幕**，而在合片之前一步都不会报。

⚠ **实测值不是承诺值。** 标点值那张表量的是「两个普通词之间」；01-A 句3 在 `叫` 后面插
`——`，表上是 0.38s，**实际只多了 0.10s**（后面紧跟着一个 `「`，本来就带停顿）。
**加完要看 tts-match 打出来的时长**，别照表算。

⚠ **改了配音层要走完三步**：重跑 tts-match → 重新 concat `vo.mp3` → 重跑 envelope 和 shoot。
前两步 `build.mjs` 都有闸拦（`manifest.配音层` 为空、`vo.mp3` 比 manifest 旧）。

### 未知的动作名和表情名会当场停

`shoot.mjs` 原来是 `LIB.动作[名] || LIB.动作['站定']`、`EXPR[名] || EXPR['中性']` ——
**名字写错，或者稿子照频道方案点了一个还没素材的动作（「斜靠」「扶帽檐」），
出来是个站着不动、脸上没戏的骨架，不报错、帧数照对、片子照合。**
一千四百多张帧渲完再发现是这条线上最贵的一种返工，所以现在两处都改成先查替身表、
再认不出来就退出。替身生效时命令行会逐条打出「用了谁、差在哪、在等哪张图」。
