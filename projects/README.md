## 醒木不响：上传的时候只开这一个文件夹

上面那几行是**项目目录**（稿件、音频、场景图、成片，什么都有）。
`醒木不响/_待发/` 是**交付包**：说书 / 治愈 / 小故事大道理三条线的片子收在一起，
一个包 = 一次上传，按名字排就是上传顺序。

```
醒木不响/
├─ _待发/2026-08-25_1800JST_说书_婴宁-E05/
│    婴宁-E05.mp4 · 婴宁-E05.srt · 封面-横版1280.png
│    封面-微信1080.png · 自检-小图.png · 发布文案.md · 来源.txt
└─ _已发/
```

`npm run deliver` 重建（幂等）；`shuoshu:ship` 跑完会自动收一次。

**里面是硬链接，不是拷贝。** 同一个卷上 `link()` 出来的是同一份数据 ——
62 MB 的 mp4 不会变成两份，发布文案改哪一边都是改同一个文件。

实测（2026-08-23）：两个路径 inode 相同、链接数 2；`du` 把四个目录一起量（按 inode 去重）
时交付包只剩 **89K**，`projects/` 总量含不含它都是 4.8G。**净增量约等于零。**
单独量交付包会显示几百 MB —— 那是重复计数，别拿那个数下结论。

⚠ **磁盘上不重，git 里会重。** 封面 / 字幕 / 发布文案在各自项目目录里已经跟踪过一遍，
包里再跟一遍就是同一份内容占两个路径，diff 里凭空多一倍噪声。
所以 `.gitignore` 把包内文件挡掉，**只放行 `来源.txt`** ——
目录结构（哪个包、排哪一档、在 _待发 还是 _已发）是账本，要留在版本库里；
内容是产物，`npm run deliver` 随时重建。102 个跟踪文件因此降到 17 个。

⚠ 硬链接的另外两个性质，用之前知道：**删掉一边不会释放空间**（数据活到最后一个链接消失为止）；
**打包/复制整个仓库时，有些工具会把硬链接摊成两份真文件**。

**为什么不把项目目录整个搬进来**：一个说书项目目录里躺着 `audio/全片.wav`（115 MB）
和 60 张场景图，搬过去等于把中间产物搬进要上传的文件夹；而且发布文案里的
`../../../` 相对链接会集体指错（见下面那条）。

**为什么一个包不是一个项目目录**：治愈线一个项目目录里有好几条片子 ——
方丈记有上篇下篇，每篇还各有一个文字版（那是另一档产品）。四条片子四次上传，
就该是四个包。

**包名跟项目目录名是同一套**：`<日期>_<时刻>JST_<类型>_<稿件名>-<序号>`。
从包名一眼能回推到项目目录，反过来也一样。

**没排档的叫 `未排期_<类型>_<名字>`**（跟老马线一个写法）。要排期**给目录改前缀**，
改完 `npm run schedule` 就认得。发完把整个包挪进 `_已发`。
**目录树本身就是账本，没有第二张表。**

## 改路径要改两个地方

- `src/config.ts` 的 `projectsDir` —— 记者读稿那条线
- `joke-video/src/paths.ts` 的 `OUT_*` —— 其余三条线

**别在别处再写路径字面量。** 这两个文件就是技术和结果之间的那道门。

## 为什么段子和《一页故事》在同一个文件夹

它们**共用同一条管线**：稿件都在 `joke-video/jokes/` 一个平目录里，
`preview.ts` 也把它们汇总成同一个画廊（`段子与儿童故事/index.html`）。
按内容拆成两个文件夹的话，画廊和稿件源就对不上了 ——
要拆得先把 `jokes/` 和预览页一起拆，那是另一件事。

## 发布文案的约定（2026-08-20 起的新片）

各期的 `发布文案.md` 是**复制源，不是分析报告**：打开就该整块选中、
粘到平台的输入框里。只出标题、简介（含章节）、关键字、文件路径四样，
外加发片前的核对清单。

**备选标题、关键字取舍、写法上的理由**放各条线的手册或各期 `方案.md`，
不进这份文档 —— 混在一起的话人一边滚一边挑，挑的时候就容易连说明一起复制进去。

治愈线已经改成**生成**的（`joke-video/src/zhiyu-publish.ts` 读各期 `发布.json`），
顺带解决了两个人工项：章节时间戳按段落定位自动算、片长去量成片。

**之前已出片的不回改**（说书 E01/E02、记者读稿那几期还是旧格式）。
新片按这套走。

## 版本库里留什么

**留**：稿件、`script.json`、`方案.md`、`发布文案.md`、封面 PNG、字幕 `.srt`、
`manifest.json` —— 这些要么是人写的，要么小且是发片的依据。

**不留**：成片、音轨、配音分句、场景图、逐帧素材 —— 全部可以重新跑出来，
加起来十几个 G。复现方法写在各条线的手册里。

`.gitignore` 里有一条**不要犯的错**：别写 `/projects/` 把整棵树排除掉。
那是重整前的写法（当时这儿只有记者读稿一条线），现在一刀切会把四条线的
稿件和方案一起吃掉，而且父目录一旦被排除，子目录的 `.gitignore` 想再放行也放行不了。
