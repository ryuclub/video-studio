## 〇、核心原则

**别把可变状态编进不可变标识里。**

发布时间会变（频率手动控，必然会挪），期号不会变。目录名把两样分开写：

```
2026-08-25_2100JST_段子_工位_对齐了三次_1851
└── 可变，负责排序 ──┘ └─── 给人看 ───┘ └身份┘
```

**改期只动前缀，期号永不改动。** 目录一旦连身份一起改名，渲染日志、封面、
素材引用、已上传记录全部断链。

**目录树本身就是排期账本** —— 不另建一张表。表和目录两头记，迟早对不上。

## 一、目录结构

**排期树就是成品树，不是两棵。**

```
projects/老马/
├─ index.html                    ← 老马自己的汇总页（跟段子与儿童故事那张分开了）
└─ 段子/
   ├─ _待发/
   │  └─ 2026-08-25_2100JST_段子_工位_对齐了三次_1851/
   │       publish.json   排期与身份
   │       out.mp4        成片
   │       thumb.png      发布用竖版封面
   │       方案.md        这一条为什么这么做
   │       发布文案.md    复制源
   │       index.html     单条预览页
   │       stills/  cover/  laoma-005.json（渲染时留的快照）
   └─ _已发/              ← 发布后整个目录 mv 过来，**只移动，不改名**
```

### 稿件不在里面

`jokes/laoma-00N.json` 还在原地 —— 体检、TTS、渲染、预览全按那个平目录跑。
`publish.json` 的 `script` 字段指过去。
**一份东西一个家**：复制一份稿件进期次目录的话，改哪一份都对，那就是两份稿子了。

### 成品文件名

| | 老马 | 别的线 |
|---|---|---|
| 成片 | `out.mp4` | `<id>.mp4` |
| 无声快版 | `draft.mp4` | `<id>-draft.mp4` |
| 音轨 | `audio.wav` | `<id>-audio.wav` |
| 竖版封面 | `thumb.png` | `cover/<id>-9x16.png` |

**目录名已经带了身份和标题**（`…_段子_工位_对齐了三次_1851`），文件名再重复一遍 id 是噪音。
要改就改 `src/preview.ts` 那四个函数（`filmFile` / `draftFile` / `audioFile` / `coverFile`），
**别在各处拼字符串**。

### 还没定发布日的：`未排期_段子_<栏目>_<稿件内容>_<天数号>`

出片在前、排期在后，中间那段时间目录就叫这个名。**这是正常状态，不是错** ——
定了日子 `mv` 成 `<日期>_2100JST_段子_<栏目>_<稿件内容>_<天数号>`、把日期写进 `publish.json` 就行。
校验会一直提醒还有几条没排期。

⚠ **不替人挑一个日期。** 出片时自动填一个「下一个空档」看着省事，
但那种日期日后没人记得是谁定的、为什么是那天。

### 跟原始规范的两处不同

原始规范（`老马_目录与排期规范_v1`）§2 还要 `script.json` 和 `frames/` 进期次目录 ——
稿件的理由见上面；`frames/` 这个仓库不留（逐帧素材可以重新跑出来，见 `projects/README.md`）。
`_共享/` 那一层也没建：数字账本在 `horse/used-numbers.json`，
人设在 `horse/CHANNEL_LAOMA.md`，都已经是唯一一份了。

## 二、命名规则

```
<日期>_<时刻>JST_段子_<栏目>_<稿件内容>_<天数号>

2026-08-25_2100JST_段子_工位_对齐了三次_1851
未排期_段子_工位_对齐了三次_1851          ← 出了片还没定日子
```

| 段 | 规则 |
|---|---|
| 日期 | `YYYY-MM-DD`，**YouTube 首发日**（国内平台的错峰日期不进目录名） |
| 时间 | `HHMM` 四位 ＋ `JST` |
| 系列 | `段子` |
| 名称 | 稿件的 `cover.title`。**只给人看**，滤掉 `\/:*?"<>|` 和空格，超过 24 字截断 |
| 天数号 | `1851`（收尾卡上那个数）——**目录名里唯一不变的那一截** |

### ⚠ 反查只认最后那个天数号

前面三截都会变：改期改日期时刻，改标题改名称。**身份只有天数号。**
拿名称或栏目去反查的话，改一次标题、换一个场景就找不到自己的目录了，然后建一个新的
（`src/preview.ts` 的 `findProjectDir`）。

**稿件内容和栏目都是 2026-08-23 加的** —— 原来叫 `段子-1851`，一排目录看过去全是数字，
哪条是哪条得挨个点开；加了栏目之后，配比失衡也是 `ls` 一眼的事。

### 时区写死成 JST

排期锚的是 UTC+8，人在日本，墙上钟差一小时。**目录名一律记 JST**
（实际操作时看的那个时间），免得某天照自己的表发早一小时。

| 档 | **JST（写进目录名，也是实际发布时刻）** |
|---|---|
| 周二 | **21:00** |
| 周四 | **21:00** |
| 周日 | **21:00** |

⚠ **这三个 21:00 是 JST**，也就是你墙上钟看到的那个时间。
排期档 2026-08-23 从「周三 2200 ／ 周六 1900 ／ 周日 2200」换成现在这样，
**已排的五条全部改过期**（只改了目录名前缀和 `publish.json` 里的时刻，期号一个字没动）。
要是这三个 21:00 说的其实是 UTC+8，那目录名该写 `2200JST` —— 说一声，改名就行。

## 三、期号规则：跳号 2–4

每期跳 **2–4 天**，不规则：1856 → 1859 → 1863 → 1864 → 1868。
偶尔来一次大跳（1871 → 1880），在 `publish.json` 里标 `"big_jump": true`，校验放行。

> **段子的号是工龄，不是集数。** 跳号暗示我们只看到他被抽出来的几天，
> 中间那些日子照样在过。

### ⚠ 001–009 是 +1 连号时代的，不回改

`laoma-001`–`009` 按「一稿一天 +1」排的（1847–1855），**成片已经把收尾卡烧进去了**。
它们在 `publish.json` 里标 `"legacy": true`，跳号那条提醒对它们不报。

**`legacy` 不是给新稿子的开关**：新稿子步长不对就是不对。
**010 起按跳号走** —— 009 是 1855，下一条落在 1857–1859。

⚠ 这条规则**推翻了** `CHANNEL_LAOMA.md` §五之二 原来那句「一稿一天 +1」，
那一节已经改过来了。两处说法不一致的时候以这份为准。

## 四、`publish.json`

```json
{
  "series": "段子",
  "id": 1851,
  "legacy": true,
  "big_jump": false,
  "script": "joke-video/jokes/laoma-005.json",
  "platforms": {
    "youtube":  { "at": "2026-08-26T22:00:00+09:00" },
    "douyin":   { "at": "2026-08-30T21:30:00+09:00" },
    "channels": { "at": "2026-09-01T21:30:00+09:00" }
  }
}
```

| 字段 | 说明 |
|---|---|
| `series` | `段子`，要跟所在目录一致 |
| `id` | 期号，要跟目录名和稿件收尾卡上那个天数三处一致 |
| `script` | **稿件在哪**，仓库根相对路径。期号跟稿件的对应关系只有这一处记着 |
| `legacy` | +1 连号时代的历史条目（001–009） |
| `big_jump` | 有意的大跳号 |
| `platforms.<平台>.at` | 发布时刻，带时区 |

- **目录名只记 YouTube 首发**，其余平台全在这儿
- 国内两平台**延后 3–7 天**，不与 YouTube 同天
- **成片路径不写在这儿** —— 它就在 `publish.json` 边上（`out.mp4`）

### ⚠ 标题和标签不进 publish.json

原始规范 §5 的例子里带 `title` / `tags`。**这儿不带**：
文案的唯一出处是各期成片目录里的 `发布文案.md`（`projects/README.md`「发布文案的约定」——
那份是**复制源**，打开就整块粘进平台输入框）。

两处都写标题的话，改一处忘另一处是必然的。这份只管**时间和身份**。

### 国内两平台的时刻是我按窗口取的

规范只给了「延后 3–7 天」的窗口，没给具体档。现在填的是**抖音 +4 天、视频号 +6 天，
都在 21:30 JST** —— 取的窗口中间值。要改直接改 `publish.json`，校验只管窗口。

## 五、流转

```
_待发/  →  发布后整个目录 mv 到  →  _已发/
```

**只移动，不改名。** `_已发/` 就是发布日志，按日期天然排序。

### ⚠ 改了目录名（改期、改标题、mv 进 `_已发`）之后要重跑 `npm run preview`

汇总页 `projects/老马/index.html` 里的图片和成片链接是**写死的相对路径**。
改完名不重跑，那一条的缩略图和视频就全是死链 —— 而汇总页看着一切正常，
点下去才发现。**校验不查这个**（它只管排期），只能记着。

### 三个白捡的收益

- **库存肉眼可见**：`_待发/` 里几个目录 = 还剩几期。低于 7 个补产
- **断更预警**：`_待发/` 里最早那个日期早于今天 → 有一期漏发了
- **编号自动校验**：目录树本身就是账本，扫一遍就能查重、查漏、查倒序

## 六、校验：`npm run laoma:schedule`

FAIL 退出码 1（给 CI 或重跑钩子用），只有 WARN 退出码 0。

| 级别 | 检查项 |
|---|---|
| FAIL | 目录名格式不合规 |
| FAIL | 期号重复 |
| FAIL | 天数号没有严格递增 |
| FAIL | 缺 `publish.json`（期次目录里只有它，缺了这个目录就没有意义） |
| FAIL | `publish.json` 的 `id` / `series` / YouTube 时间跟目录名对不上 |
| FAIL | `script` 指的稿件不存在，或稿件收尾卡上的天数跟目录期号对不上 |
| FAIL | `_已发/` 的条目没有 `out.mp4` 或 `thumb.png` |
| FAIL | 发到了这个专辑不该发的平台 |
| WARN | 跳号步长不在 2–4（`big_jump` / `legacy` 放行） |
| WARN | 发布日或时刻不符合排期表 |
| WARN | `_待发/` 里有过期未发的条目 |
| WARN | `_待发/` 库存 < 7 |
| WARN | `_待发/` 的条目还没出片 |
| WARN | `_待发/` 里有 `未排期_…`（出了片没定日子） |
| WARN | `_已发/` 里有没记发布日的（汇总一行，见下） |
| WARN | 国内平台与 YouTube 间隔不在 3–7 天 |
| WARN | 天数号跟台词数字账本撞号 |

**它不拦出片。** 排期是发布那头的事，`voice` / `build` 前面那道闸是稿件体检
（`laoma-check`），两回事，别接在一起 —— 稿子还没排期就不能渲，那是没道理的。
