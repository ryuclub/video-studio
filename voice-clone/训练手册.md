## 〇、五个环境地雷（已经改好了，换机器要重改）

这台机器上都已处理，**留档是为了换机器或重装时不用再踩一遍**。

| # | 地雷 | 症状 | 改法 |
|---|---|---|---|
| 1 | `runtime/Lib/site-packages/users.pth` 写的是**打包者机器的绝对路径** | `ModuleNotFoundError: No module named 'text'`，**打标和训练全跑不了**（推理却正常，因为 `api_v2.py` 自己 append 了 sys.path） | 改成本机路径。⚠ 便携 Python 有 `python39._pth`，**PYTHONPATH 被完全忽略**，绕不过去 |
| 2 | 系统区域 `ja_JP` / `cp932` | 喂中文进去报 `'cp932' codec can't encode character '你'` | 所有命令加 `PYTHONUTF8=1 PYTHONIOENCODING=utf-8` |
| 3 | `go-webui.bat` 用 `-I` 隔离模式 | 上面那个环境变量**被忽略** | 改成 `runtime\python.exe -I -X utf8 webui.py zh_CN`（`-X` 是命令行开关，隔离模式管不着） |
| 4 | `tts_infer.yaml` 的 `custom` 段是 `cuda`/`fp16`/**`version: v2`** | 前两个会炸；**第三个不炸**，安静地用 v2 底模出声，你以为跑通了其实版本不对 | 改成 `cpu` / `false` / `v2ProPlus` ＋ v2Pro 的权重路径 |
| 5 | 便携 Python 是嵌入式发行版 | — | 用绝对路径调 `./runtime/python.exe`，别指望 PATH |

原文件都留了 `.orig`。

## 一、素材体检（不过不要往下走）

```bash
node voice-clone/录音体检.mjs <录音文件>
node voice-clone/坏段扫描.mjs <录音文件>
```

**十一条判据，任何一条 ❌ 就退回重录。** 尤其看这三条：

- **信噪比** ≥ 30 dB（< 20 一定不行）
- **逐段一致** —— 抓「后半段被吃掉」，全片平均看不出来
- **频谱上限** ≥ 9 kHz

⚠ **闸放行不等于能用。** 2026-09-07 那份 21.3 dB 的过了闸，训出来「吐字不清」——
根子是录音离麦太远，高频从源头就没进来，后期补不回（见方案 §十八）。

### 要不要降噪

**先跑体检看信噪比。** ≥ 30 dB 就别降，直接用原始文件。

要降的话用 `arnndn`（不是 `afftdn`，也不是官方那个 —— 官方的依赖坏了而且是 16k 模型）：

```bash
# 五个模型都试，然后**逐段比**，别只看信噪比
ffmpeg -y -i 原音.m4a -af "arnndn=m=<模型>.rnnn" -ar 32000 -ac 1 -c:a pcm_s16le 降噪.wav
node voice-clone/录音体检.mjs 降噪.wav     # 重点看「逐段一致」
```

模型从 `github.com/GregorR/rnnoise-models` 取（每个约 300KB，各在自己的子目录里）。
⚠ **ffmpeg 滤镜参数里不能有 `:`** —— Windows 盘符会被当成分隔符，把模型拷到相对路径下。

⚠⚠ **不要按信噪比挑模型。** 2026-09-07 踩过：信噪比最高的 `sh` 恰恰是把后半段人声
整个删掉换来的。**按「逐段一致」挑** —— 实测 `bd` 全程稳定，`sh`/`lq` 后段崩。

降完补增益（`arnndn` 会把电平拉低约 10 dB）：

```bash
# 先量峰值，再算增益，落到 -3 dBFS。别拍脑袋给，会削波
ffmpeg -hide_banner -nostats -i 降噪.wav -af astats=metadata=1 -f null - 2>&1 | grep "Peak level dB"
ffmpeg -y -i 降噪.wav -af "volume=<-3减去峰值>dB" -c:a pcm_s16le 成品.wav
```

## 五、格式化四步

```powershell
$r='D:\GPT-SoVITS-v2pro-20250604'
Push-Location $r
$env:PYTHONUTF8='1'; $env:PYTHONIOENCODING='utf-8'; $env:OMP_NUM_THREADS='6'
$env:inp_text="$r\laoshi\train.list"; $env:inp_wav_dir="$r\laoshi\sliced"
$env:exp_name='laoshi'; $env:opt_dir="$r\logs\laoshi"
$env:bert_pretrained_dir='GPT_SoVITS/pretrained_models/chinese-roberta-wwm-ext-large'
$env:cnhubert_base_dir='GPT_SoVITS/pretrained_models/chinese-hubert-base'
$env:sv_path='GPT_SoVITS/pretrained_models/sv/pretrained_eres2netv2w24s4ep4.ckpt'
$env:pretrained_s2G='GPT_SoVITS/pretrained_models/v2Pro/s2Gv2ProPlus.pth'
$env:s2config_path='GPT_SoVITS/configs/s2v2ProPlus.json'     # ⚠ 不是 s2.json
$env:i_part='0'; $env:all_parts='1'; $env:is_half='False'; $env:version='v2ProPlus'
foreach($s in @('1-get-text.py','2-get-hubert-wav32k.py','2-get-sv.py','3-get-semantic.py')){
  & '.\runtime\python.exe' -s "GPT_SoVITS/prepare_datasets/$s"
}
Pop-Location
```

**四类特征各应有 N 个**（`3-bert` / `4-cnhubert` / `5-wav32k` / `7-sv_cn`），少一个就是有段没处理。

⚠ **产物带分片后缀，要手工合并**（WebUI 会自动做，命令行不会）：

```bash
cd logs/laoshi && cp 2-name2text-0.txt 2-name2text.txt && cp 6-name2semantic-0.tsv 6-name2semantic.tsv
```

⚠ **`s2v2ProPlus.json` 不能用 `s2.json`** —— 会报 `ref_enc.fc.fc` shape mismatch（1024 vs 512）。

**实测**：131 段 / 9.6 分钟 → 47 + 87 + 154 + 9 = **297 秒**。

## 六、训练

### 先建目录（漏了会在保存时才炸，白跑一整轮）

```bash
mkdir -p logs/laoshi/logs_s2_v2ProPlus SoVITS_weights_v2ProPlus GPT_weights_v2ProPlus
```

### 生成两份配置

```bash
node voice-clone/_mk_s1.mjs        # GPT 的 yaml
# SoVITS 的 json 见方案 §十七，关键字段：
#   train.epochs=8  batch_size=4  fp16_run=false
#   save_every_epoch=2  if_save_every_weights=true      ← 必开，见下
#   pretrained_s2G = v2Pro/s2Gv2ProPlus.pth
#   pretrained_s2D = v2Pro/s2Dv2ProPlus.pth             ← ⚠ 必须配套
#   model.version = 'v2ProPlus'                          ← ⚠ 是 model 段不是顶层
```

⚠ **v2ProPlus 要四件配套**：`s2v2ProPlus.json` ＋ `s2Gv2ProPlus.pth` ＋ **`s2Dv2ProPlus.pth`** ＋ sv 模型。
混一个 v2 的就在加载权重时炸（G/D 的配对规则是 `名字.replace("s2G","s2D")`）。

### 连跑

```bash
bash train_laoshi.sh
```

脚本里钉了 `OMP_NUM_THREADS=4` —— 实测限 4 线程训练只慢 4%，
但**出片编码完全不受影响**（13.4s vs 空闲 13.5s）。日志落 `laoshi/训练日志.txt`。

**实测耗时**（131 段 / 9.6 分钟 / batch 4 / 8 核 CPU）：

| | 轮数 | 耗时 |
|---|---|---|
| SoVITS (s2) | 8 | **88 分钟**（约 11 分钟/轮） |
| GPT (s1) | 15 | **27 分钟**（约 2 分钟/轮） |

📌 GPT 比 SoVITS 轻得多（不碰音频解码）。**别按 SoVITS 的速度估 GPT**。

## 七、挑档位（**这一步不能省**）

⚠ **`if_save_every_weights` 必须开。** 2026-09-07 实测：

- **GPT `e9` 是个坏档** —— 训练集外的句子全部输出静音（0.8s / −60 dB）。
  而 `e3` `e6` `e15` 都正常。**不是「越训越崩」的单调过拟合，是单档随机坏。**
  只存最后一轮就发现不了；只存 e9 就会误判「这条路走不通」。
- **SoVITS 越训齿音越低**（e2 −32.9 → e8 −37.1），跟直觉相反。

**挑法**：起推理服务，用 `/set_gpt_weights` 和 `/set_sovits_weights` **热切换**，
拿**没参与训练的稿子**逐档试。判据两条：

```bash
node voice-clone/_ck.mjs    # 崩不崩（静音 = 崩）
node voice-clone/_sv.mjs    # 齿音亮度（越高越清晰）
```

## 八、验收

```bash
# 起服务（改 tts_infer.yaml 的 custom 段指向选中的两个权重）
cd /d/GPT-SoVITS-v2pro-20250604
PYTHONUTF8=1 PYTHONIOENCODING=utf-8 ./runtime/python.exe api_v2.py \
  -a 127.0.0.1 -p 9880 -c TEMP/tts_infer_laoshi.yaml

# 拿训练集外的稿子出全片
node tts-match.mjs --file <稿子.txt> --backend sovits \
  --ref <参考音频3~10秒> --ref-text "<参考音频念的是什么>" --out <输出目录>

# 基频对得上吗（±1 半音）
node voice-clone/基频对比.mjs <本人录音> <克隆音>
```

⚠ **参考音频要从训练素材里挑**，3~10 秒（硬约束，超出直接 400），挑说得连贯、无长停顿的。

**验收四条**：

1. 链路 —— 逐句都有声（RMS > −45 dB），没有 0.8 秒的静音段
2. 基频 —— 差 ±1 半音以内
3. 训练集外不崩
4. **听感** —— 像不像、吐字清不清楚。**这条只能靠耳朵，前三条全过也可能不能用**

2026-09-07 那一版走完了上面全部九步、每一步都合格，最后仍然不能用 ——

## 十、训完之后：拿去出片

**训练到此为止，出片是另一条链路。**
完整命令和实测数在 [音色克隆方案.md](音色克隆方案.md) **§二十**，这里只留三条最容易忘的：

1. **权重要换两次**（SoVITS 管音色、GPT 管韵律），
   `set_sovits_weights` 和 `set_gpt_weights` 各调一次。
   ⚠ **别给 `curl` 设 60 秒超时** —— CPU 加载 155 MB 要更久，超时之后
   用 `&&` 串的后续命令根本不跑，而 `vo/` 里旧文件还在，**看起来像成功**。
2. **出配音就一条命令**：`tts-match.mjs … --backend sovits --ref … --ref-text …`，
   下游 `envelope` / `shoot` / `build` 一个字都不用改。
3. **拿到 `vo.mp3` 立刻关掉 `api_v2.py`**（见开头那条规矩）。

**训好的模型归档在 `E:\ryu\石总\音色模型\`**，附 `说明.md`（版本、怎么训的、
为什么挑 e4/e12、已知短板）。换机器重装之后把那几个文件放回去就能用。
