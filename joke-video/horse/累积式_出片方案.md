## 〇、它和单点式差在哪

| | 单点式 | 累积式 |
|---|---|---|
| 结构 | 铺垫 → 转折 → 落点，**一个笑点** | 立人设 → 自己拆掉 → 状语结果错位 ×3–4 → 沉底，**笑点分布** |
| 落点 | 事实句，≤15 字，反应句判废 | **感想句**「不过这样也挺好」，≤20 字 |
| 片长 | 25–31 秒 | 35–45 秒 |
| 日子牌 | 有 | **无** |
| 收尾卡 | 有配额（近 4 条 ≤1） | **不出，黑场**（沿用 002 的做法） |
| 物件 `object` | 必填，≥2 句出现 | **可选** |
| 钩子回收 | `hookLine`/`payoffLine` 字面重叠 | **首尾扣合**，宽松比对 |
| 句间停顿 | `pace.ts` 缺省 | **0.35–0.45 秒**，另开预设 |
| 字幕 | 防剧透 | **造节拍** |
| 分镜 | 按站位 | **按节拍** |

**两种笑法不一样：单点式是「你以为是 A，其实是 B」，累积式是「一件比一件离谱，最后我认了」。** 把累积式塞进 `typeA`，要么稿子被砍废，要么体检形同虚设。

## 一、稿件结构

```
立      1 句     立一个人设
拆      1 句     下一句自己拆掉
错位  3–4 句     状语和结果对不上（这一层是密度所在）
沉底    1–2 句   「不过这样也挺好，……」
```

**错位层最多五句，超了就腻。** 写法是先想结果，再倒推一个最不搭的状语。

**沉底句不许翻身、不许励志。** 老马的立场是看破不说破，不是看破了还要赢——结尾往下沉半寸，不往上扬。

## 二、节奏：另开预设 `standup-fast`（2026-08-25 已建）

| | `bedtime`（一页故事） | 单点式缺省 | **`standup-fast`** |
|---|---|---|---|
| 句内 | 0.55 / 0.3 | — | **0.25 / 0.15** |
| 句间 | 0.90 | — | **0.35–0.45** |
| 换镜 | 1.95 | — | **0.8** |

**排比段内部还要更紧**，三句同构句之间几乎不能停（0.25 上限）。

### 「留一拍」标记（必须新增）

累积式的笑点和苦味全在落点前那一拍上——「我心里松了一下，然后又空了一下」之后、「跟练过似的」之前、「特别噎」之后。

时间轴若全部由节奏预设自动算，**没有地方表达「这里单独停 0.8 秒」**。所以稿件里加了一个记号（**2026-08-25 已实现**）：

```jsonc
"beatPause": true    // 挂在该句上，表示这一句说完之后额外停 0.8 秒
```

**不加这个，35 条会被全部读平。**

⚠ **字段名不是方案原来写的 `beat`。** `LineCfg.beat` 已经是 `setup / reply / punch` 那个节拍枚举了，
同名写进 JSON 会把节拍值覆盖掉，**而且从 JSON 上看不出来是哪一个赢了**。改叫 `beatPause`。

⚠ **它是加在 `padAfter` 上的，不是替换**（`beats/typeA.ts` 的 `BEAT_PAUSE = 0.8`，不可调）。
不做成可调参数是有意的：可调的话它迟早被用来凑片长，而那正是这条规矩要挡的事。

## 三、字幕

**单点式的字幕在防剧透，累积式的字幕在造节拍。** 目标不同，规则反过来。

### 六条

**1. 排比句一句一屏，绝不合并。**

```
✓  第一趟少一张复印件 / 第二趟章盖错了地方 / 第三趟系统在升级   （三屏）
✗  第一趟少一张复印件，第二趟章盖错了地方，第三趟系统在升级     （一屏）
```

合并之后排比就成了一段话。**重复要看得见，才有累积感。**

**2. 状语和结果必须同屏。** 「认认真真地犯了很多错」不能拆两屏——那个错位就是笑点，拆开等于切成两半，前半屏还剧透了后半屏。

与第 1 条合起来：**分屏按语义单元切，不按字数切。** 一屏放不下就改写句子，不靠拆屏解决。

**3. 位置锁死，一格不动。** 排比段每屏出现在完全相同的 y 上，**竖向对齐是「这是一串」的唯一视觉信号**。

**4. 最短驻留 0.6 秒（硬底线）。** 句间压到 0.35–0.45 之后，字幕若严格跟着语音起落会出现 0.4 秒一闪。做法：**早于语音 0.1 秒出，晚于语音结束 0.15 秒撤**，用重叠换驻留。

**5. 数字用阿拉伯数字。** `600 多` / `2800` / `17 个`；**序数仍用汉字**（第一趟，不写「1 趟」）。

**6. 落点拆两屏，理由不是防剧透。**

```
屏 A   不过这样也挺好          ← 停一拍
屏 B   至少死的是绿萝，不是我   ← 驻留 1.2 秒，全片最长的一屏
```

拆的目的是给那一拍腾出位置。

### 签名屏

「不过这样也挺好」在 35 条里逐字相同，反复出现会长成频道的记忆点——像个签名。

**成立的前提是完全一致**：位置、字号、入场方式、驻留时长四项锁死，任何一条飘了就只显得偷懒。

**2026-08-25 落地了，四项是这么锁的**（没有另写一套样式 —— 现有的渲染层已经锁住了前三项）：

| 项 | 怎么锁的 |
|---|---|
| 位置 | 侧栏定位，按角色框算，同一个站位（`x: 290` ＋ `keepX`）逐条相同 |
| 字号 | `sideText` 按**这一屏的文字**自适应 —— 同一句话每次都得到同一个字号；落点档再大 25%（琥珀色） |
| 入场 | 老马线的字幕本来就**没有入场动画**（`dialogueStrip` 那套弹入不在这条线上） |
| 驻留 | **体检每次量出来打在报告里**（`签名屏「不过这样也挺好」驻留 1.68s（实测）`）—— 量得出来才叫锁死，「建议 0.9 秒」锁不住任何东西 |

体检还拦两条：**落点必须拆两屏**（硬伤），**第 1 屏不是逐字「不过这样也挺好」就报提醒**。

⚠ **实测这一屏会折成两行**（「不过这样 / 也挺好」）—— 落点档字号大 25%，七个字排不进侧栏一行。
**折行本身是稳定的**（同样的字、同样的栏宽 → 每条都折在同一处），所以签名照旧成立；
但**换了站位就会换个折法**，累积式的角色站位因此也是锁死的那一份。

字号、字体、描边、安全区沿用 BASE，本节不重定义。

## 四、分镜：按节拍，不按站位

单点式按站位换镜（一人 → 一屋子人 → 又一人）。累积式**一个人从头说到尾，没有站位变化**，所以靠景别走节拍：

| 节拍 | 景别 |
|---|---|
| 立人设 | 中景 |
| 错位段 | 推近一档 |
| 落点前那一拍 | 近景 |
| 沉底 | 拉回中景 |

三到四镜，仍守 BASE 里「一条片子镜别切换不超过 3 次」的上限。

⚠ **依赖 `camera: static` 开例外**（BASE §八 的未完项）。在那之前累积式只能全程锁死，40 秒一个景别会闷，**建议这条先修**。

35 条里只有 3 条（老牛系列 3 / 23 / 35）需要双人镜，其余全是单人。

## 五、收尾与发布

- **不出收尾卡，黑场。** 沿用 002《天气预报》的做法，不另设计。
- **不带日子牌。** 单点式是老马的日记，有连续性；累积式是他随口说的，不占时间轴——**什么时候发都不突兀，发片节奏可自由掌控。**
- 目录命名里的天数号改为体裁标记：`<日期>_2100JST_段子_<栏目>_<稿件内容>_闲聊-<稿件号>/`
  （出片时是 `未排期_段子_工位_我都点头_闲聊-017/`）

  ⚠ **最后一截带稿件号，比方案原来写的光一个「闲聊」多一段，是有意的。**
  那一截是**身份**，反查只认它（`preview.ts` 的 `laomaKey`／`findProjectDir`）。
  光写「闲聊」的话，同栏目第二条累积式跟第一条只差中间那截标题，
  而**中间几截全是会变的**（改期、改标题、换场景）—— 反查一对不上就会再建一个新目录，
  同一条片子从此有两个家。

  排期校验（`npm run laoma:schedule`）认这两种身份：数字的进期号那套检查（递增、跳号 2–4、
  重号、跟数字账本撞号），**`闲聊-` 的一条都不进** —— 它没有期号。
  目录说自己是闲聊、稿件却不是 `format: "cumulative"`（或反过来），**判硬伤**。
- `publish.json` 加 `format` 字段（排期时补，出片这一步还没有 publish.json）。**两种体裁完播率没有可比性**（25 秒单点笑话 vs 40 秒排比自嘲），统计时分开看，别混进同一张表。

⚠ **日子牌推进会变慢。** 累积式发得多的话，两个月才走到第三十天。跳号本来就不等于真实日期，但日子牌是观众唯一能感知的连续性，**推得太慢会失去「在往前走」的感觉**——心里有数。

## 六、体检：`format: "cumulative"` 分流（2026-08-25 已实现）

> **不写 `format` 就是单点式**，已出片的 16 条一个字都没动 ——
> 改完拿那 16 条的体检输出跟改之前逐字节对过，一行不差。

### 新增三条

| 拦什么 | 级别 | 判据 |
|---|---|---|
| 一屏驻留 < 0.6 秒 | ✗ | 按 `partSpans` 算每一屏；**最后一屏算上这一句的停顿**（字幕盖到 padAfter 结束才换） |
| 排比段合并成屏 | ✗ | 同一屏内出现 ≥2 个序数标记（`第一…` / `一趟一次一回一遍`） |
| 状语与结果被拆开 | ! | 一屏以「地」「得」结尾，且它不是这一句的最后一屏 |

> 同构分句机器不好判，先用序数词表兜着，跑一阵看漏多少再补。
>
> ⚠ **驻留那条在 `align` 之前是按字数估的**（报告里会标「估算」还是「实测」）——
> 估算跟实测差得不小（laoma-017 估 36.6s、实测 28.7s），**配音前别拿它下结论**。

### 从单点式显式停用（写成关闭，不是漏填）

- 落点整句一次性打出的拦截
- 转折句一屏 ≤12 字的上限
- **尾卡那一整组五条**（人称／解释词／超长／allowBoth／使用率）
- 落点必须是事实句（`差点|居然|忍不住…` 词表）——**累积式的落点就是感想句**
- `object` 必填、`hookLine`/`payoffLine` 字面重叠

### 放宽

| 项 | 单点式 | 累积式 |
|---|---|---|
| 落点字数 | ≤15 | **≤20**，且要求前面有 ≥3 句事实型错位兜底 |
| 单句字数 | >24 硬伤 | 不变 |
| 停顿符号阈值 | ≥0.8 秒，全片 ≤2 | **≥0.5 秒，全片 ≤3** |

⚠ **停顿符号阈值不放宽的话，累积式会一个符号都挂不上**——句间压到 0.35–0.45，没有 0.8 秒的窗口。那样 1863「太冷场」的问题会原样复发，而且 40 秒的片子比 25 秒更扛不住。
